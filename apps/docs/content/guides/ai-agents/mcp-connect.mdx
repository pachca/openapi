# Подключение к MCP

Программа подключается к MCP-серверу Пачки по адресу `https://mcp.pachca.com/mcp` одним из трёх способов:

| | [Через браузер](#vhod-cherez-brauzer) | [Персональный токен](#token-v-zagolovke) | [Токен бота](#token-bota) |
|---|---|---|---|
| Кому подходит | [Claude Code](#claude-code), [Claude](#claude), [VS Code и GitHub Copilot](#vs-code-i-github-copilot), [Codex](#codex) | [Cursor](#cursor), [SourceCraft Code Assistant](#sourcecraft-code-assistant), [Qwen Code и GigaCode CLI](#qwen-code-i-gigacode-cli), [OpenCode](#opencode), [Devin Desktop](#devin-desktop), [Cline](#cline), [Kilo Code](#kilo-code), [Gemini CLI](#gemini-cli), [запуск без браузера](#claude-code-bez-brauzera) | агенту, который работает без участия сотрудника, например в [Yandex AI Studio](#yandex-ai-studio) или на [GigaChat](#agent-na-gigachat) |
| От чьего имени | сотрудника, который подтвердил вход | владельца токена | бота |
| Как подключить | программа открывает экран согласия Пачки | токен в заголовке `Authorization` | токен в заголовке `Authorization` |
| Права | те, что попросила программа, обычно весь каталог | выбранные при создании токена | права токена бота |
| Срок | час, продлевается сам | бессрочный | бессрочный |
| Где видно и как отключить | список **Авторизации** на странице **API** | удалить токен на странице **API** | токены бота в его настройках |

Через браузер подключаются программы, которые поддерживают вход по OAuth с документом клиента (Client ID Metadata Document): программа публикует на своём домене документ с именем и адресами возврата, поэтому регистрировать её в Пачке не нужно. Остальные программы, а также те, у которых вход с Пачкой пока не работает или не проверен, подключаются токеном в заголовке.

## Кто может подключить

Подключиться может владелец, администратор, сотрудник и мульти-гость. Гостям доступ к API, а значит и к MCP, не выдаётся.

По умолчанию в пространстве выдавать доступ к API могут только администраторы: настройка **Кто может создавать персональные токены** закрывает и персональные токены, и вход через браузер. Чтобы подключались все сотрудники, Администратор выбирает в ней **Все сотрудники**. Подробнее — в разделе [Кто может создавать токены](/api/authorization#kto-mozhet-sozdavat-tokeny).

## Вход через браузер

<Steps>
  <Step title="Добавьте сервер в программу">
    Укажите адрес `https://mcp.pachca.com/mcp`, команды для каждой программы — ниже. Регистрировать программу в Пачке заранее не нужно.
  </Step>
  <Step title="Войдите">
    Программа откроет страницу Пачки в браузере. Если вы не вошли в Пачку, сначала появится обычный вход.
  </Step>
  <Step title="Подтвердите доступ">
    На экране согласия проверьте имя программы, её домен и пространство и нажмите **Разрешить**. Браузер вернёт вас в программу, и инструменты Пачки появятся в ней.
  </Step>
  <Step title="Проверьте подключение">
    Попросите агента: «Покажи мой профиль в Пачке». Он вызовет `pachca_get_my_card` и ответит вашим именем и ролью.
  </Step>
</Steps>

<ImageCard src="/images/ai-agents/mcp-consent.webp" alt="Экран согласия при подключении Claude Code: «Авторизовать Claude Code?», домен claude.ai, пространство и почта сотрудника, начало списка запрашиваемых разрешений" caption="Экран согласия для программы с MCP" maxWidth={500} />

На экране согласия видно:

- имя программы из её документа клиента и под ним домен, на котором программа опубликовала этот документ, например `claude.ai`;
- пространство и вашу почту: доступ выдаётся в пространство, которое сейчас открыто в браузере;
- **Запрашиваемые разрешения** — права, которые просит программа, обычно весь каталог. Убрать отдельные права на экране нельзя;
- предупреждение, если программа возвращает браузер на этот же компьютер: «Разрешайте, только если вы сами сейчас подключаете … на этом компьютере».

Права из каталога не расширяют ваши возможности. Каждый вызов проверяется по вашей текущей роли, и если роль не позволяет действие, агент получит отказ. Как устроен экран согласия в целом — в разделе [Согласие и отзыв](/guides/oauth/consent).

<Info>Выбора пространства на экране согласия нет. Чтобы подключить другое пространство, переключитесь на него в Пачке и подключитесь снова. Как работать с несколькими пространствами сразу — в разделе [Несколько пространств](#neskolko-prostranstv).</Info>

Программа получает токен на час и продлевает его сама, входить заново не нужно. У каждого подключения свой токен: Claude Code на двух компьютерах — два подключения.

### Claude Code

Сервер вместе со скиллами и командами ставит [плагин «Пачка»](/guides/ai-agents/plugin#claude-code). Если он стоит, сервер добавлять не нужно: выполните `/mcp`, выберите сервер Пачки из плагина и войдите. Из терминала вход начинает команда:

```bash
claude mcp login plugin:pachca:pachca
```

Сервер плагина называется `plugin:pachca:pachca`, команда `claude mcp login pachca` его не найдёт. Сервер с тем же адресом, добавленный вручную, заменит сервер плагина.

Без плагина добавьте сервер:

```bash
claude mcp add --transport http pachca https://mcp.pachca.com/mcp
```

Затем запустите Claude Code, выполните команду `/mcp`, выберите сервер `pachca` и войдите. Из терминала то же делает команда:

```bash
claude mcp login pachca
```

Сервер добавляется в текущий проект. Чтобы он был во всех проектах, добавьте к `claude mcp add` флаг `--scope user`.

Если браузер не открывается, например в сессии по SSH, команда `claude mcp login` сама покажет ссылку, а флаг `--no-browser` включает это принудительно. Подключайтесь по `ssh -t`, откройте ссылку на своём компьютере и нажмите **Разрешить**. Когда команда попросит, вставьте в терминал адрес из строки браузера.

### Claude

На тарифах Free, Pro и Max:

1. В приложении Claude или на claude.ai откройте **Customize** > **Connectors** и нажмите **Add** > **Add custom connector**.
2. Укажите название, например «Пачка», и адрес `https://mcp.pachca.com/mcp`, затем нажмите **Continue**.
3. Проверьте настройки входа, которые нашёл Claude, и нажмите **Continue**.
4. В **Authentication** выберите **Sign in now**, в **OAuth client** выберите **Use Claude's published identity** и нажмите **Add**. Вариант **Register automatically** с Пачкой не работает.
5. Нажмите **Connect** у нового коннектора и войдите.

На тарифе Free можно добавить один такой коннектор. Коннектор работает в чате на claude.ai, в приложении Claude на компьютере и телефоне и в Cowork.

На тарифах Team и Enterprise коннектор добавляет владелец организации Claude: **Organization settings** > **Connectors** > **Add** > **Custom** > **Web**, затем те же шаги. После этого каждый сотрудник открывает **Customize** > **Connectors**, нажимает **Connect** у коннектора Пачки и входит под своей учётной записью.

Claude подключается к Пачке только через вход в браузере. Если в окне коннектора есть раздел **Request headers**, персональный токен туда не указывайте: заголовки общие для всей организации Claude, и все её сотрудники действовали бы в Пачке от вашего имени.

Коннектор появится и в Claude Code, если вы вошли в него через тот же аккаунт claude.ai, в том числе в облачных сессиях. Если в Claude Code стоит плагин «Пачка» или сервер с тем же адресом добавлен вручную, Claude Code работает через них, и в Пачку там нужно войти отдельно. Скиллы вместе с этим сервером даёт [плагин «Пачка»](/guides/ai-agents/plugin#prilozhenie-claude).

### VS Code и GitHub Copilot

Чтобы сервер был во всех проектах, добавьте его командой GitHub Copilot CLI:

```bash
copilot mcp add --transport http pachca https://mcp.pachca.com/mcp
```

Команда запишет сервер в `~/.copilot/mcp-config.json`, этот файл читают и VS Code, и Copilot CLI. В VS Code то же делает команда **MCP: Add Server**: выберите **HTTP**, укажите адрес и имя `pachca`, затем **Global** > **Copilot Global**.

Для одного проекта добавьте сервер в файл `.mcp.json` в корне проекта. Этот же файл читает Claude Code.

```json title=".mcp.json"
{
  "mcpServers": {
    "pachca": {
      "type": "http",
      "url": "https://mcp.pachca.com/mcp"
    }
  }
}
```

VS Code предложит войти при первом запуске сервера. В Copilot CLI войдите командой `/mcp auth pachca`, вход через браузер работает в Copilot CLI 1.0.83 и новее. Сервер из `.mcp.json` проекта Copilot CLI подключает, только если вы доверяете папке. Файл `.vscode/mcp.json` с ключом `servers` тоже работает, но VS Code помечает его устаревшим.

Чтобы подключиться токеном, добавьте в сервер в файле `~/.copilot/mcp-config.json` поле `"headers": { "Authorization": "Bearer ${PACHCA_TOKEN}" }` и задайте переменную `PACHCA_TOKEN` в окружении, из которого запускается VS Code или Copilot CLI. Записи вида `${input:…}` и `${env:…}` в этом файле не работают. Если сервер записан в файл вручную, а не командой `copilot mcp add`, добавьте в него и `"tools": ["*"]`. В `.mcp.json` проекта сервер с заголовком `Authorization` не добавляйте: Claude Code у каждого, кто откроет проект, подключится через него вместо входа через браузер. Подробнее — в разделе [Claude Code без браузера](#claude-code-bez-brauzera).

Сервер вместе со скиллами ставит и [плагин «Пачка»](/guides/ai-agents/plugin#vs-code-i-github-copilot), тогда добавлять сервер вручную не нужно.

### Codex

```bash
codex mcp add pachca --url https://mcp.pachca.com/mcp
```

Команда добавляет сервер и сразу открывает браузер для входа. Если вход прервался, повторите его:

```bash
codex mcp login pachca
```

На компьютере без браузера добавьте к этой команде флаг `--no-browser`: она покажет ссылку, а после подтверждения попросит вставить адрес, на который вернулся браузер.

Подключение общее для Codex CLI, расширения Codex и приложения ChatGPT на компьютере. Сервер вместе со скиллами ставит и [плагин «Пачка»](/guides/ai-agents/plugin#codex), тогда добавлять сервер не нужно: войдите командой `codex mcp login pachca`. Где входить некому, например в CI, подключите Codex [персональным токеном](#codex-s-tokenom).

## Токен в заголовке

Если программа не входит в Пачку через браузер или входить некому, например в CI, подключите её токеном в заголовке. Шаги ниже для персонального токена, [токен бота](#token-bota) подключается так же.

1. Создайте персональный токен на странице **Интеграции** > **API** и выберите права, которые нужны агенту. Подробнее — в разделе [Создание персонального токена](/api/authorization#sozdanie-personalnogo-tokena).
2. Сохраните токен в переменной окружения, например `PACHCA_TOKEN`. Большинство программ читают переменные окружения при запуске, поэтому после этого перезапустите программу.
3. Укажите в настройках программы адрес сервера и заголовок `Authorization: Bearer <токен>`. Ссылку на переменную каждая программа записывает по-своему, примеры ниже.

<Warning>Персональный токен бессрочный и действует от вашего имени. Выдавайте ему только нужные права, храните его в переменной окружения, а не в файле, который попадает в репозиторий. Когда токен больше не нужен, удалите его на странице **API**.</Warning>

Сообщения агента с персональным токеном не помечаются программой. Подробнее — в разделе [Безопасность](/guides/ai-agents/mcp#bezopasnost).

### Cursor

Добавьте сервер в `~/.cursor/mcp.json`, чтобы он был во всех проектах, или в `.cursor/mcp.json` проекта:

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "pachca": {
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer ${env:PACHCA_TOKEN}"
      }
    }
  }
}
```

Cursor подставляет `PACHCA_TOKEN` из окружения, в котором он запущен. Добавьте переменную в профиль оболочки, например в `~/.zshrc`, в Windows задайте её в системных переменных среды. Затем перезапустите Cursor.

```bash
export PACHCA_TOKEN="<токен>"
```

Этот же файл читает Cursor CLI. Состояние серверов в Cursor CLI показывает команда:

```bash
agent mcp list
```

Облачные агенты Cursor переменные с вашего компьютера не видят: для них сервер задаётся в настройках облачных агентов.

Сервер с тем же токеном подключает и [плагин «Пачка»](/guides/ai-agents/plugin#cursor), тогда добавлять сервер вручную не нужно.

### SourceCraft Code Assistant

В чате Code Assistant в VS Code нажмите значок с тремя точками на верхней панели и выберите **MCP-серверы** > **Edit Global MCP**. Добавьте сервер в открывшийся файл `mcp_settings.json`:

```json title="mcp_settings.json"
{
  "mcpServers": {
    "pachca": {
      "type": "streamable-http",
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer <токен>"
      }
    }
  }
}
```

Настройки проекта из `.codeassistant/mcp.json` попадают в репозиторий, поэтому токен держите в глобальных настройках.

### Qwen Code и GigaCode CLI

```bash
qwen mcp add --transport http pachca https://mcp.pachca.com/mcp --header "Authorization: Bearer $PACHCA_TOKEN"
gigacode mcp add --transport http pachca https://mcp.pachca.com/mcp --header "Authorization: Bearer $PACHCA_TOKEN"
```

Первая команда для Qwen Code, вторая для GigaCode CLI. Без `--transport http` сервер запишется как локальный. Команда сохранит сам токен в настройках пользователя: `~/.qwen/settings.json` или `~/.gigacode/settings.json`. Проверьте подключение командой `/mcp`.

В Qwen Code вместо токена можно оставить в файле ссылку на переменную окружения. Адрес Streamable HTTP в этих программах задаёт поле `httpUrl`, поле `url` в них означает транспорт SSE:

```json title="~/.qwen/settings.json"
{
  "mcpServers": {
    "pachca": {
      "httpUrl": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer ${PACHCA_TOKEN}"
      }
    }
  }
}
```

### OpenCode

Добавьте сервер в `~/.config/opencode/opencode.json`, чтобы он был во всех проектах, или в `opencode.json` проекта:

```json title="~/.config/opencode/opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "pachca": {
      "type": "remote",
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer {env:PACHCA_TOKEN}"
      },
      "oauth": false
    }
  }
}
```

OpenCode подставит значение переменной `PACHCA_TOKEN` при запуске. Если переменная не задана, он подставит пустую строку, и сервер ответит отказом `401`. Строка `"oauth": false` отключает попытку входа через браузер. Проверьте подключение:

```bash
opencode mcp list
```

### Devin Desktop

Devin Desktop, бывший Windsurf, подключается к Пачке персональным токеном. Агент Devin Local, с которого начинаются новые вкладки, и прежний агент Cascade берут серверы из одного файла: `~/.config/devin/mcp_config.json`, в Windows `%APPDATA%\devin\mcp_config.json`. Добавьте сервер командой Devin CLI:

```bash
devin mcp add -s user -H "Authorization: Bearer $PACHCA_TOKEN" pachca https://mcp.pachca.com/mcp
```

Команда запишет токен в этот файл в домашней папке, в репозиторий он не попадёт. Если команды `devin` нет, добавьте сервер в файл вручную. В Cascade файл открывается из панели Cascade: меню **…** > **MCPs** > **Open MCP config file**.

```json title="mcp_config.json"
{
  "mcpServers": {
    "pachca": {
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer <токен>"
      }
    }
  }
}
```

Devin Local подключает также серверы из `.mcp.json` проекта и из настроек Claude Code. Сервер Пачки без токена оттуда не подключится. Чтобы Devin не читал эти настройки, выключите `read_config_from.claude` в `~/.config/devin/config.json`.

У Cascade лимит 100 инструментов на все серверы, а Пачка даёт до 90. Лишние инструменты отключите списком `disabledTools` в настройках сервера.

### Cline

В Cline CLI:

```bash
cline mcp add pachca https://mcp.pachca.com/mcp --transport http --header "Authorization: Bearer $PACHCA_TOKEN" --yes
```

Команда сохранит токен в файле `~/.cline/data/settings/cline_mcp_settings.json`. В расширении для VS Code откройте **MCP Servers** > **Configure** > **Configure MCP Servers** и добавьте сервер. Поле `type` обязательно: без него Cline подключится по устаревшему транспорту SSE.

```json
{
  "mcpServers": {
    "pachca": {
      "type": "streamableHttp",
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer <токен>"
      }
    }
  }
}
```

### Kilo Code

Добавьте сервер в `~/.config/kilo/kilo.jsonc`, чтобы он был во всех проектах, или в `kilo.jsonc` проекта:

```json title="~/.config/kilo/kilo.jsonc"
{
  "mcp": {
    "pachca": {
      "type": "remote",
      "url": "https://mcp.pachca.com/mcp",
      "oauth": false,
      "headers": {
        "Authorization": "Bearer {env:PACHCA_TOKEN}"
      }
    }
  }
}
```

Токен Kilo Code возьмёт из переменной окружения `PACHCA_TOKEN`. В расширении для VS Code тот же сервер добавляется в **Settings** > **MCP** > **Add Server** > **Remote (HTTP)**.

### Gemini CLI

```bash
gemini mcp add --scope user --transport http --header 'Authorization: Bearer ${PACHCA_TOKEN}' pachca https://mcp.pachca.com/mcp
```

Одинарные кавычки сохраняют в `~/.gemini/settings.json` ссылку на переменную, а не сам токен. Gemini CLI подставит значение при запуске.

Серверы MCP Gemini CLI подключает только в папке, которой вы доверяете, даже если сервер добавлен для всех проектов. При первом запуске `gemini` в проекте выберите **Trust folder** или выполните в сессии `/permissions trust`. Проверьте подключение командой `/mcp list`.

### Codex с токеном

В CI, в контейнере и везде, где входить некому, подключите Codex персональным токеном. Сохраните токен в переменной окружения `PACHCA_TOKEN` и добавьте сервер:

```bash
codex mcp add pachca --url https://mcp.pachca.com/mcp --bearer-token-env-var PACHCA_TOKEN
codex mcp list
```

С флагом `--bearer-token-env-var` Codex не открывает вход через браузер. В файл `~/.codex/config.toml` попадает только имя переменной, токен Codex читает из окружения при каждом подключении. Вторая команда покажет у сервера `pachca` способ входа `Bearer token`.

Приложение ChatGPT и редактор, запущенные не из терминала, могут не видеть переменную из профиля оболочки. Тогда запишите токен прямо в `~/.codex/config.toml`: в разделе `[mcp_servers.pachca]` замените строку `bearer_token_env_var = "PACHCA_TOKEN"` на `http_headers = { Authorization = "Bearer <токен>" }`. Файл лежит в домашней папке и в репозиторий не попадает.

Сервер с именем `pachca` заменяет сервер из [плагина «Пачка»](/guides/ai-agents/plugin#codex).

### Claude Code без браузера

Там, где входить некому, например в CI, в контейнере или в запуске по расписанию, подключайте Claude Code токеном. Сохраните настройки сервера в файл вне репозитория:

```json title="pachca-mcp.json"
{
  "mcpServers": {
    "pachca": {
      "type": "http",
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer ${PACHCA_TOKEN}"
      }
    }
  }
}
```

Передайте файл флагом `--mcp-config`. Claude Code подставит значение переменной при запуске, и токен не попадёт в файл:

```bash
claude --strict-mcp-config --mcp-config pachca-mcp.json --allowedTools "mcp__pachca" -p "Найди в Пачке обсуждение релиза 2.4 и перескажи решения"
```

Флаг `--strict-mcp-config` отключает остальные серверы, в том числе сервер плагина. Промпт указывайте после `-p`: флаг `--mcp-config` принимает несколько файлов. Флаг `--allowedTools "mcp__pachca"` разрешает инструменты Пачки без вопросов: в запуске с `-p` подтвердить вызов некому. Что агенту можно делать, ограничивают права токена.

<Warning>Не кладите сервер с заголовком `Authorization` в `.mcp.json` репозитория. У каждого, кто откроет проект, он заменит сервер плагина с входом через браузер, а без переменной `PACHCA_TOKEN` не подключится вовсе.</Warning>

На компьютере без браузера, например по SSH, токен не нужен: войдите командой `claude mcp login`, как в разделе [Claude Code](#claude-code).

### Другие программы и платформы

Укажите адрес `https://mcp.pachca.com/mcp`, транспорт Streamable HTTP (иногда он называется HTTP) и заголовок `Authorization` со значением `Bearer <токен>`. Если программа принимает настройки в JSON, они обычно выглядят так:

```json
{
  "pachca": {
    "url": "https://mcp.pachca.com/mcp",
    "headers": {
      "Authorization": "Bearer <токен>"
    }
  }
}
```

Проверьте, как в программе называется поле адреса для Streamable HTTP. В некоторых программах поле `url` означает транспорт SSE, а для Streamable HTTP есть отдельное поле, например `httpUrl` в [Qwen Code и GigaCode CLI](#qwen-code-i-gigacode-cli).

Если программа подключает только локальные серверы (stdio), запустите сервер через мост [mcp-remote](https://github.com/geelen/mcp-remote): он передаёт вызовы на адрес Пачки с вашим токеном.

```json
{
  "mcpServers": {
    "pachca": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://mcp.pachca.com/mcp",
        "--header",
        "Authorization:${PACHCA_AUTH_HEADER}"
      ],
      "env": {
        "PACHCA_AUTH_HEADER": "Bearer <токен>"
      }
    }
  }
}
```

Пробела в аргументе `Authorization:${PACHCA_AUTH_HEADER}` нет намеренно: Cursor, Codex и приложение Claude в Windows портят аргументы с пробелами, а в значении переменной пробел допустим.

### Агент только для чтения

Чтобы агент мог только читать, создайте для него отдельный персональный токен и отметьте в нём только права на чтение и поиск. Список инструментов от этого не изменится, но вызовы, которые меняют данные, получат отказ с кодом `insufficient_scope`.

### Несколько пространств

Одно подключение работает с одним пространством. Чтобы агент работал с несколькими, добавьте сервер в программу несколько раз под разными именами, например `pachca-main` и `pachca-partner`, и в каждом укажите персональный токен, созданный в нужном пространстве. Если программа берёт токен из переменной окружения, заведите для каждого пространства свою переменную, например `PACHCA_TOKEN_MAIN` и `PACHCA_TOKEN_PARTNER`.

## Токен бота

Агенту, который работает без участия сотрудника, например на сервере или в [Yandex AI Studio](#yandex-ai-studio), подойдёт токен бота. Подключение такое же, как [с персональным токеном](#token-v-zagolovke), только в заголовке токен бота.

Агент в Yandex AI Studio или на GigaChat обычно работает на сервере и отвечает всем, кто к нему обращается. С персональным токеном каждый собеседник агента действовал бы от вашего имени, поэтому подключайте такого агента токеном бота.

С токеном бота агент действует от имени бота: видит открытые беседы и каналы пространства и чаты, куда бота добавили, а сообщения пишет от его имени. Набор инструментов у него свой: формы, разворачивание ссылок, история событий, смена адреса своего вебхука и перевыпуск своего токена есть только у токена бота, а черновиков, раздела «Важное» и управления ботами у него нет. Подробнее — в разделе [Какие инструменты получает программа](/guides/ai-agents/mcp-tools#kakie-instrumenty-poluchaet-programma). Где взять токен — в разделе [Токены бота](/guides/bots/tokens), что бот видит — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).

### Yandex AI Studio

Нужны роли на каталог Yandex Cloud:

- `serverless.mcpGateways.editor` и `iam.serviceAccounts.user`, чтобы создать сервер;
- `serverless.mcpGateways.invoker` и `serverless.mcpGateways.anonymousInvoker`, чтобы агент вызывал сервер;
- `ai.canvasAgents.editor`, чтобы собрать агента.

<Warning>Не включайте **Сделать MCP-сервер публичным**: инструменты Пачки с токеном бота сможет вызвать любой, кто знает адрес сервера.</Warning>

1. В AI Studio выберите каталог Yandex Cloud, откройте **Agent Atelier** > **MCP-серверы**, нажмите **Создать MCP-сервер** и выберите **Внешний MCP-сервер**.
2. Укажите имя сервера, например `pachca`, и нажмите **Создать**. Имя должно быть длиной от 3 до 63 символов, начинаться с буквы и не заканчиваться дефисом, в нём допустимы строчные латинские буквы, цифры и дефисы.
3. В поле **URL** укажите адрес `https://mcp.pachca.com/mcp` и выберите транспорт **Streamable HTTP**.
4. В поле **Тип авторизации** выберите **Токен доступа** и добавьте заголовок `Authorization` со значением `Bearer <токен бота>`.
5. Нажмите **Подключиться** и в списке **Инструменты** отметьте только те, что нужны агенту. Нажмите **Сохранить**.
6. Откройте **Agent Atelier** > **Текстовые агенты**, создайте агента или откройте существующего. В поле **MCP-серверы** выберите сервер Пачки и нажмите **Сохранить версию**.

Если агента вызывают через Responses API, а он меняет данные, укажите для сервера Пачки `"require_approval": "always"`: каждый вызов инструмента будет ждать подтверждения. Скиллы Пачки подключаются в том же окне агента, в поле **Навыки**. Подробнее — в разделе [Yandex AI Studio и GigaChat](/guides/ai-agents/plugin#yandex-ai-studio-i-gigachat).

### Агент на GigaChat

Агента на GigaChat собирают в коде на [GigaChain](https://github.com/ai-forever/langchain-gigachat), библиотеках LangChain для GigaChat. Пачку подключает библиотека `langchain-mcp-adapters`:

```bash
pip install langchain langchain-gigachat langchain-mcp-adapters
```

Перед запуском задайте переменные окружения:

- `PACHCA_BOT_TOKEN` — токен бота Пачки;
- `GIGACHAT_CREDENTIALS` — ключ авторизации GigaChat;
- `GIGACHAT_SCOPE` — версия API GigaChat, для компании `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`;
- `GIGACHAT_CA_BUNDLE_FILE` — путь к корневому сертификату Минцифры, если он не установлен в системе: без него запрос к GigaChat не пройдёт проверку SSL.

```python title="agent.py"
import asyncio
import os

from langchain.agents import create_agent
from langchain_gigachat import GigaChat
from langchain_mcp_adapters.client import MultiServerMCPClient


async def main():
    client = MultiServerMCPClient(
        {
            "pachca": {
                "transport": "http",
                "url": "https://mcp.pachca.com/mcp",
                "headers": {"Authorization": f"Bearer {os.environ['PACHCA_BOT_TOKEN']}"},
            }
        }
    )
    # Только нужные агенту инструменты: так он тратит меньше контекста
    needed = {"pachca_search_messages", "pachca_get_thread", "pachca_list_chat_messages"}
    tools = [tool for tool in await client.get_tools() if tool.name in needed]

    # Ключ, версия API и сертификат GigaChat берутся из переменных окружения
    agent = create_agent(GigaChat(model="GigaChat-2-Max"), tools)
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "Найди обсуждение релиза 2.4 и коротко перескажи решения"}]}
    )
    print(result["messages"][-1].content)


asyncio.run(main())
```

Как передать агенту скилл Пачки — в разделе [Yandex AI Studio и GigaChat](/guides/ai-agents/plugin#yandex-ai-studio-i-gigachat).

## Управление подключениями

Подключения через браузер собраны в списке **Авторизации** на странице **Интеграции** > **API**. У программы видно домен, дату подключения, последнее использование и число разрешений, а меню позволяет посмотреть разрешения и отозвать доступ. Когда в Пачке появляются новые права, программа получает их при следующем подключении.

<ImageCard src="/images/ai-agents/mcp-authorizations.webp" alt="Список «Авторизации» на странице «API»: клиент MCP Claude Code с доменом claude.ai и бот «Jira-карточки», даты подключения, последнее использование и число разрешений" caption="Программа с MCP в списке «Авторизации»" maxWidth={832} />

**Отозвать доступ** сразу отключает все подключения этой программы, которые вы выдали: следующий вызов получит `401`. Чужие подключения той же программы это не затрагивает.

Администратор видит доступ программы у каждого сотрудника строкой с типом «Клиент MCP» на вкладке [Все токены](/api/authorization#vse-tokeny-prostranstva) и может отозвать его.

Подключение токеном в заголовке живёт, пока жив токен: удалите персональный токен на странице **API** или токен бота в его настройках.

## Если что-то не работает

| Что видно | Причина и что делать |
|---|---|
| «Доступ к API ограничен администраторами пространства» на экране согласия | Выдавать доступ к API могут только администраторы. Попросите Администратора выбрать **Все сотрудники** в настройке **Кто может создавать персональные токены**. |
| «Гостям доступ к API не выдаётся» | Гость не может подключить MCP. Нужна другая роль в пространстве. |
| Программа предлагает войти, но вход не проходит или просит зарегистрировать клиента | Вход через браузер с Пачкой в этой программе не работает. Подключите её [токеном в заголовке](#token-v-zagolovke). Если Cursor просит войти, хотя токен в настройках указан, он не видит переменную `PACHCA_TOKEN`: проверьте профиль оболочки и перезапустите Cursor. |
| `401` | Токена нет, он истёк или отозван. Подключитесь заново: в Claude Code — командой `/mcp`. С токеном в заголовке проверьте, что токен не удалён и что программа видит переменную `PACHCA_TOKEN`: задайте её и перезапустите программу. |
| `MCP endpoint not found` в Claude Code | Адрес сервера указан неверно. Проверьте командой `claude mcp get pachca`, что адрес ровно `https://mcp.pachca.com/mcp`. |
| В Claude Code нет сервера `plugin:pachca:pachca`, хотя плагин стоит | Сервер с тем же адресом добавлен вручную и заменяет сервер плагина. Найдите его в списке `claude mcp list` и удалите командой `claude mcp remove` с его именем или работайте через него. |
| `403` с кодом `access_denied` при подключении | Токен принадлежит гостю, деактивированному или удалённому сотруднику. |
| Отказ с кодом `insufficient_scope` | У токена нет нужного права. Персональному токену добавьте право в меню токена на странице **API**, токену бота — в его настройках. Подробнее — в разделе [Ошибки авторизации](/api/authorization#oshibki-avtorizatsii). |
| Отказ с кодом `role_forbidden` | Право есть, но ваша роль не позволяет действие. Это правило пространства, повторное подключение не поможет. |
| Отказ с кодом `payment_required` | Пространство превысило лимит сообщений тарифа: пока его не оплатят, большинство методов отвечают отказом. Подробнее — в разделе [Ошибки](/api/errors). |
| Агент не может отправить файл с диска | Не каждая программа даёт агенту загрузить файл с диска, например чат Claude этого не позволяет. Подробнее — в разделе [Как агент отправляет файл](/guides/ai-agents/mcp-tools#kak-agent-otpravlyaet-fayl). |
| В программе нет нужного инструмента | Список зависит от роли, тарифа и типа токена. Какой инструмент кому доступен — в разделе [Инструменты MCP](/guides/ai-agents/mcp-tools). |
| Отказ «Wait N s before repeating» или `429` | Превышен предел вызовов. Подождите указанное время. Пределы — в разделе [MCP-сервер](/guides/ai-agents/mcp#predely). |
| Подключилось не то пространство | Доступ выдаётся в пространство, открытое в браузере. Отзовите подключение, переключитесь на нужное пространство и подключитесь снова. |
