# AI-агенты

Пачка — готовая среда для AI-агентов. Эта страница для команд и разработчиков: чем Пачка уже помогает в работе с агентами, как агента подключить и куда смотреть дальше.

## Пачка как среда для AI-агентов

Упомяните агента в треде — остальное он сделает сам. Агент находится внутри разговора, видит контекст и действует автономно.

- **Агент — участник команды.** Он читает обсуждения, создаёт задачи и присылает результаты. Работу выполняет агент, а отвечает за неё тот, кто его позвал.
- **[Треды](/guides/threads) как единица работы.** Агента зовут в тред, и он отвечает туда же, не засоряя общий чат. Если агент не состоит в чате, он видит только этот тред и сообщение, к которому тред открыт.
- **Сквозные треды.** Упомяните в треде сотрудника, и он увидит тред, даже если не состоит в исходном чате. Один тред — общая точка координации сотрудников и агента.
- **Самостоятельные треды.** Тред можно создать без привязки к чату — как отдельное место для диалога с агентом, куда добавляют только нужных участников.

Технически агент — это бот: его зовут по нику, он получает сообщения через исходящий вебхук и отвечает токеном бота. Как это устроено — в разделах [Взаимодействие с агентом](/guides/ai-agents/interaction) и [Общение с ботом](/guides/bots/conversations).

## Как подключить Пачку к агенту

Чтобы агент выполнял действия в API, ему нужен токен. Агенту или автоматизации без участия сотрудника подойдёт **токен бота** с минимальными правами, агенту на машине сотрудника — вход через браузер в MCP-сервер или в CLI. Какой токен выбрать — в разделе [Авторизация](/api/authorization#kakoy-token-vybrat). В CI и headless-окружении передавайте токен переменной `PACHCA_TOKEN` из секретов — см. [CLI: авторизация](/guides/cli/authentication#ci-i-agenty-headless).

### MCP-сервер

Claude Code, Cursor и другие программы с агентом подключаются к Пачке по адресу и сразу получают инструменты на все методы API. Код писать не нужно, а права те же, что в API: агент видит и делает только то, что можно владельцу токена. Подходит, когда агенту нужна Пачка по ходу работы, а терминала у него нет.

```text
https://mcp.pachca.com/mcp
```

### llms.txt

Самый простой способ для разовых задач. Скопируйте ссылку в промпт агента — он получит сводку API со ссылками на документацию. Подходит, когда нужно быстро попросить агента сделать что-то конкретное в Пачке.

```text title="Пример промпта"
Сделай X, потом Y в Пачке.
Посмотри как надо: https://dev.pachca.com/llms.txt
```

Полная документация в одном файле — [llms-full.txt](/llms-full.txt). Файл большой и целиком в контекст агента обычно не помещается: берите из него нужные разделы. Для постоянной работы предпочтителен CLI — он не нагружает контекст (см. ниже).

### CLI

Самый быстрый и производительный способ, когда у агента есть терминал. Минимальное влияние на контекст агента — не нужно загружать документацию, агент узнаёт возможности через `--help`. Если есть доступ к shell, агент может генерировать скрипты для типовых задач.

```bash
# Без установки — для разовых задач, CI и агентов с временным окружением
npx -y @pachca/cli api ls --token YOUR_ACCESS_TOKEN

# Или глобально — для регулярной работы
npm install -g @pachca/cli
pachca messages create --entity-id 123 --content "Готово"
pachca users list -o json
```

Через CLI доступны и произвольные запросы к любому эндпоинту, и вся документация API прямо в терминале — список методов, их параметры, схемы и полный справочник. Агенту не нужно открывать сайт или грузить документацию в контекст. Подробнее — в разделе [Прямые запросы](/guides/cli/api-requests).

```bash
# Произвольный запрос к любому эндпоинту
pachca api POST /messages -F message[entity_id]=123 -f message[content]="Привет"

# Документация по API прямо в терминале
pachca api ls                         # список эндпоинтов
pachca api POST /messages --describe  # параметры, тело, эквивалентная команда
pachca api GET /messages --spec       # OpenAPI-фрагмент
pachca api POST /messages --docs      # полный markdown-референс
```

### Context7

Сторонний сервис документации, который подключается по MCP. [Context7](https://context7.com) отдаёт актуальную документацию Пачки в контекст агента — только документацию, без действий в API. Действия в Пачке выполняет [MCP-сервер Пачки](/guides/ai-agents/mcp). Подходит, когда вы часто просите агента делать разные задачи в Пачке из промптов и хотите, чтобы у него была свежая документация под рукой.

```bash
claude mcp add context7 https://mcp.context7.com/mcp
```

Для других агентов добавьте MCP-сервер `https://mcp.context7.com/mcp` в настройках. Чтобы агент использовал документацию Пачки, добавьте в промпт `use context7` или настройте это через правила агента.

### OpenAPI-спецификация

Классический вариант для разработчиков. Наиболее полное описание API без дополнительных обвязок — типы, схемы, все эндпоинты. Подходит для кодогенерации (openapi-generator, Kiota, Orval), GPT Actions и когда вы строите собственную интеграцию с API.


### Плагин и Agent Skills

Скиллы — знание о том, как правильно делать задачи в Пачке: куда писать и что подтверждать, как найти и пересказать обсуждение, какой токен выбрать и почему не хватает прав. Справочник по аргументам у агента уже есть в описаниях инструментов MCP-сервера, поэтому скиллы его не повторяют. В Claude Code, приложении Claude, Codex, GitHub Copilot и Cursor скиллы вместе с MCP-сервером и командами ставит плагин «Пачка». В SourceCraft Code Assistant, OpenCode и других агентах скиллы ставятся без плагина.
