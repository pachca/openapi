# AI-агенты

Пачка — готовая среда для AI-агентов. Здесь собрано, как подключить Пачку к агенту, чем Пачка помогает агенту в работе и какую документацию ему дать.

## Как подключить Пачку к агенту

Все способы вызывают одни и те же методы API с правами токена, которым подключён агент. Выбирайте по тому, кто работает с Пачкой и где:

| Кто работает и где | Что подходит |
|---|---|
| Сотрудник в программе с агентом: Claude, Claude Code, Codex, приложение ChatGPT, VS Code, Cursor | [Плагин «Пачка»](#plagin-i-skilly) или [MCP-сервер](#mcp-server). Что выбрать для вашей программы — в разделе [Какой путь выбрать](/guides/mcp/connect#kakoy-put-vybrat). |
| Агент с терминалом, которому важно беречь контекст, а также скрипты и CI | [CLI](#cli) |
| Вы пишете свою интеграцию или сервис | [API и SDK](#api-i-sdk) |
| Агент живёт в Пачке: его зовут по нику в треде или пишут ему в личные сообщения | Бот, подробнее — в разделе [Взаимодействие с агентом](/guides/ai-agents/interaction) |
| Агент в программе на вашем компьютере следит за тредом и отвечает в нём, пока вы заняты другим | Плагин «Пачка» и CLI, подробнее — на странице [Агент следит за тредом](/guides/ai-agents/watch-thread) |
| Сценарий в n8n с узлом AI Agent | [Пачка как инструмент AI Agent](/guides/n8n/advanced#ai-agent) |

### MCP-сервер

Claude Code, Cursor и другие программы с агентом подключаются к Пачке по адресу и получают инструмент на каждый метод API, доступный токену. Код писать не нужно, а права те же, что в API: агент видит и делает только то, что можно владельцу токена. Подходит, когда агенту нужна Пачка по ходу работы, а запускать команды он не может или не должен.

```text
https://mcp.pachca.com/mcp
```

Всё о сервере собрано в отдельном разделе [MCP](/guides/mcp/overview): как он устроен, как подключить программу и какие инструменты получит агент.

### Плагин и скиллы

В Claude Code, приложении Claude, Codex, VS Code и Cursor Пачку подключают и плагином «Пачка»: одной установкой он подключает MCP-сервер и добавляет скиллы и команды. Скиллы — знание о том, как правильно делать задачи в Пачке: куда писать и что подтверждать, как найти и пересказать обсуждение, какой токен выбрать и почему не хватает прав. Они работают с MCP-сервером, CLI и API, а в программы без плагина ставятся отдельно.

### CLI

Подходит агенту, у которого есть терминал. Документацию в контекст загружать не нужно: агент узнаёт команды из `--help` и тратит меньше контекста, чем с MCP. Если агент может запускать команды, он напишет скрипт для типовой задачи.

Справочник API в CLI работает до входа: `api ls`, `--describe`, `--spec` и `--docs` читают встроенную спецификацию без токена и в API не обращаются. Так агент изучает методы ещё до `pachca auth login`.

```bash
# Справочник API
npx -y @pachca/cli api ls                         # список методов
npx -y @pachca/cli api POST /messages --describe  # параметры, тело, эквивалентная команда
npx -y @pachca/cli api GET /messages --spec       # фрагмент OpenAPI
npx -y @pachca/cli api POST /messages --docs      # полный справочник метода в Markdown
```

Для регулярной работы CLI устанавливают и входят в Пачку. Кроме команд для каждого метода, есть произвольный запрос к любому методу, подробнее — в разделе [Прямые запросы](/guides/cli/api-requests).

```bash
npm install -g @pachca/cli
pachca auth login
pachca messages create --entity-id 123 --content "Готово"
pachca users list -o json

# Произвольный запрос к любому методу
pachca api POST /messages -F 'message[entity_id]=123' -f 'message[content]=Привет'
```

### Токен и доступ агентов

Каждый способ подключения выдаёт агенту обычный токен API. Поэтому отдельного выключателя MCP нет: подключение агентов решают те же две настройки пространства, что и доступ к API, подробнее — в разделе [Кто может создавать токены](/api/authorization#kto-mozhet-sozdavat-tokeny). По умолчанию персональные токены и вход через браузер есть только у администраторов, а ботов, токен которых тоже подходит агенту, создают и сотрудники.

## Пачка как среда для AI-агентов

Упомяните агента в треде — остальное он сделает сам. Такой агент — бот Пачки: он находится внутри разговора, видит контекст и действует автономно.

- **Агент — участник команды.** Он читает обсуждения, ставит напоминания и присылает результаты. Работу выполняет агент, а отвечает за неё тот, кто его позвал.
- **[Треды](/guides/threads) как единица работы.** Агента зовут в тред, и он отвечает туда же, не засоряя общий чат. У треда одна тема и свой контекст, как у отдельного чата с агентом. Обсуждение в треде обычно укладывается в несколько дней и несколько десятков сообщений, поэтому агент читает его целиком и не теряет нить, а беседа или личные сообщения длятся без конца, и темы в них сменяют друг друга.
- **Доступ по треду.** Если агента нет в закрытом чате, из этого чата он видит только свой тред и сообщение, к которому тред открыт. Открытую беседу или канал агент читает целиком и без добавления, подробнее — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).
- **Сквозные треды.** Упомяните в треде сотрудника, и он увидит тред, даже если не состоит в исходном чате. Так упоминание работает по умолчанию. От чего это зависит — в разделе [Участники треда](/guides/threads#uchastniki-treda). Один тред — общая точка координации сотрудников и агента.
- **Самостоятельные треды.** Тред можно создать без привязки к чату — как отдельное место для диалога с агентом, куда добавляют только нужных участников.

Агента зовут по нику, он получает сообщения через исходящий вебхук и отвечает токеном бота. Как это устроено — в разделах [Взаимодействие с агентом](/guides/ai-agents/interaction) и [Общение с ботом](/guides/bots/conversations).

## Документация для агента

Агенту, который пишет код под API или разбирается, как устроена Пачка, нужна документация. Её можно отдать несколькими способами.

### llms.txt

Самый простой способ дать агенту документацию: скопируйте ссылку в промпт, и он получит сводку API, способы подключения и ссылки на страницы. Подходит, когда агент пишет код под API или разово разбирается, как что-то устроено.

```text title="Пример промпта"
Напиши обработчик исходящего вебхука Пачки.
Документация: https://dev.pachca.com/llms.txt
```

Полная документация в одном файле — [llms-full.txt](/llms-full.txt). Файл большой и целиком в контекст агента обычно не помещается: берите из него нужные разделы. Для постоянной работы подключите MCP-сервер или CLI: так агенту не нужно искать и загружать страницы документации.

</Info>

Наиболее полное описание API без дополнительных обвязок: типы, схемы, все методы. Подходит для кодогенерации на языках, для которых нет [SDK](/guides/sdk/overview), и для своих инструментов. Запросы вручную удобно пробовать в [коллекции Postman](/pachca.postman_collection.json).

```text
https://dev.pachca.com/openapi.yaml
```
