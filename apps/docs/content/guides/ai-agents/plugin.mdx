# Плагин

Плагин «Пачка» — необязательный способ подключить Пачку в Claude Code, приложении Claude, Codex, VS Code с GitHub Copilot и Cursor. Одной установкой он ставит [MCP-сервер](/guides/mcp/overview) и [скиллы](/guides/ai-agents/skills). Без плагина то же дают шаги на странице [Подключение к MCP](/guides/mcp/connect): сервер по адресу и скиллы одной командой.

Что даёт плагин сверх этих шагов:

| Что | Как |
|---|---|
| Одна установка | Сервер и скиллы ставятся вместе. Войти в Пачку нужно так же, как без плагина. |
| Обновление скиллов | Codex ставит свежую версию плагина при каждом запуске, Claude Code и приложение Claude после включения автообновления. В VS Code и Copilot её ставит команда. Без плагина скиллы обновляет `npx skills update`. |
| Приложение Claude | Скиллы ставятся без загрузки архивов, а на тарифах Team и Enterprise владелец организации Claude ставит плагин сразу всем. |

Инструменты плагин не хранит, их отдаёт сервер. Скиллы командой `npx skills add` в программу с плагином не ставьте, иначе каждый скилл окажется поставлен дважды.

Установка: [Claude Code](#claude-code), [приложение Claude](#prilozhenie-claude), [Codex](#codex), [VS Code и GitHub Copilot](#vs-code-i-github-copilot), [Cursor](#cursor). В Cursor сервер плагина подключается персональным токеном, в остальных программах вход через браузер.

Кто может входить через браузер и создавать персональные токены, решает настройка пространства. Что написать Администратору при отказе, сказано в разделе [Кто может подключить](/guides/mcp/connect#kto-mozhet-podklyuchit).

Что попросить агента после установки — в разделе [Что можно поручить агенту](/guides/ai-agents/overview#chto-mozhno-poruchit-agentu).

## Claude Code

```bash
claude plugin marketplace add pachca/openapi --sparse .claude-plugin plugins
claude plugin install pachca@pachca
```

Первая команда добавляет маркетплейс, то есть каталог плагинов Пачки в репозитории, а вторая ставит плагин. Флаг `--sparse` скачивает из репозитория только папки `.claude-plugin` и `plugins`. Внутри сессии то же делают команды `/plugin marketplace add pachca/openapi` и `/plugin install pachca@pachca`. Плагин, установленный из терминала, загрузится в следующей сессии, а в открытой сессии выполните `/reload-plugins`. Чтобы новые версии плагина приходили сами, сразу включите автообновление, как описано в разделе [Обновления](#obnovleniya).

В расширении Claude Code для VS Code введите `/plugins`, добавьте `pachca/openapi` на вкладке **Marketplaces** и нажмите **Install** у плагина на вкладке **Plugins**. В приложении Claude на вкладке **Code** нажмите **+** у поля ввода и выберите **Add plugins**: плагин появится в списке, если маркетплейс уже добавлен из терминала или VS Code. Терминал, VS Code и вкладка **Code** на одном компьютере читают одни настройки, поэтому плагин достаточно поставить один раз.

Только скиллы, без MCP-сервера, ставит команда из раздела [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov) с агентом `claude-code`. В облачных сессиях Claude Code плагин не загружается. Пачка доступна там через коннектор, подключённый в [приложении Claude](/guides/mcp/connect#claude), или через сервер из файла `.mcp.json` в репозитории.

### Вход в Пачку

Выполните `/mcp`, выберите сервер Пачки из плагина и войдите через браузер. Из терминала войдите командой `claude mcp login plugin:pachca:pachca`. Если браузер не открывается, например по SSH, команда покажет ссылку, как описано в разделе [Claude Code](/guides/mcp/connect#claude-code). Что видно на экране согласия, сказано в разделе [Вход через браузер](/guides/mcp/connect#vhod-cherez-brauzer).

Проверьте подключение: попросите «Покажи мой профиль в Пачке», и агент ответит вашим именем и ролью. Затем попросите «Перескажи тред» со ссылкой на любой тред.

### Если сервер уже добавлен вручную

Сервер плагина не подключается, если сервер с тем же адресом уже добавлен командой `claude mcp add` или в `.mcp.json`. Claude Code работает через сервер, добавленный вручную, поэтому инструменты не задваиваются. Чтобы перейти на сервер плагина, удалите ручной:

```bash
claude mcp remove pachca
```

Так же действует сервер с заголовком `Authorization`, даже если переменная с токеном не задана: Пачка тогда не подключится, а войти через браузер Claude Code не предложит. Где держать такой сервер, сказано в разделе [Claude Code с токеном](/guides/mcp/connect#claude-code-s-tokenom).

### Обновления

Новая версия плагина выходит, когда меняются его файлы, а что в ней изменилось, видно на странице [Обновления](/updates). Поставить её можно командой:

```bash
claude plugin update pachca@pachca
```

Автообновление маркетплейса `pachca` по умолчанию выключено. Чтобы его включить, откройте `/plugin`, на вкладке **Marketplaces** выберите `pachca` и нажмите **Enable auto-update**. Новая версия загрузится в следующей сессии или после `/reload-plugins`.

## Приложение Claude

Плагин работает в приложении Claude на тарифах Pro, Max, Team и Enterprise. Он ставится в аккаунт Claude один раз и доступен в чате на claude.ai, в приложении Claude на компьютере и телефоне и в Cowork. На тарифе Free плагинов нет, там Пачку подключают [коннектором](/guides/mcp/connect#claude).

На тарифах Pro и Max коннектор Пачки добавляется с вкладки плагина на шаге 4, поэтому отдельно в **Customize** > **Connectors** его добавлять не нужно.

<Steps>
  <Step title="Включите выполнение кода">
    Скиллам нужно выполнение кода. На тарифах Pro и Max включите **Code execution and file creation** в **Settings** > **Capabilities**. На тарифах Team и Enterprise этот переключатель и **Skills** включает владелец организации Claude.
  </Step>
  <Step title="Добавьте маркетплейс">
    Откройте **Customize** > **Plugins**, нажмите **Add** > **Add marketplace**, выберите **Add from a repository** и укажите `pachca/openapi`. Маркетплейс — каталог плагинов в репозитории.
  </Step>
  <Step title="Установите плагин">
    На вкладке **Discover** выберите плагин Pachca и нажмите **Add**.
  </Step>
  <Step title="Подключите Пачку">
    Откройте плагин и перейдите на вкладку **Connectors**. Что сделать, зависит от состояния сервера Пачки:

    - **Not added** — нажмите **Add**, а затем **Connect**
    - **Not connected** — коннектор уже есть в аккаунте, нажмите **Connect**
    - **Connected** — Пачка уже подключена, переходите к проверке

    После **Connect** войдите в Пачку и подтвердите доступ на экране согласия. На тарифах Team и Enterprise, если сервер Пачки в состоянии **Not added**, попросите владельца организации Claude добавить его, как в разделе [Для всей организации](#dlya-vsey-organizatsii).
  </Step>
  <Step title="Проверьте подключение">
    В новом чате попросите «Покажи мой профиль в Пачке». Затем попробуйте просьбу «Что я пропустил в Пачке со вчерашнего дня?».
  </Step>
</Steps>

Скиллы плагина появятся в **Customize** > **Skills** и включаются и выключаются вместе с ним. Свежую версию подтягивает кнопка **Check for updates** у маркетплейса `pachca`. Чтобы обновления приходили сами, включите у маркетплейса **Sync automatically**.

В Claude Code 2.1.273 и новее плагин из аккаунта скачивается при запуске, если вы вошли в Claude Code через аккаунт Claude. Загрузится он после `/reload-plugins` в той сессии, где скачался, или при следующем запуске. Если вы входили на более ранней версии, выполните `/login` ещё раз и перезапустите Claude Code. Если плагин уже установлен командой `claude plugin install`, Claude Code использует эту копию. В Пачку в Claude Code нужно войти отдельно, как в разделе [Вход в Пачку](#vhod-v-pachku).

### Для всей организации

На тарифах Team и Enterprise сотрудники не добавляют коннекторы сами. Сначала владелец организации Claude добавляет сервер Пачки, как в разделе [Claude](/guides/mcp/connect#claude). Затем сотрудники ставят плагин по шагам выше, если владелец не выключил **User-created skills** в **Organization settings** > **Plugins & skills** > **Policy**.

Чтобы плагин сразу был у всех, владелец создаёт закрытый репозиторий на GitHub с файлом `.claude-plugin/marketplace.json`, который ссылается на папку плагина в открытом репозитории Пачки, и подключает его в **Organization settings** > **Plugins & skills** > **Add** > **Sync from GitHub**. Затем на вкладке **Inventory** выбирает для плагина **Default access** > **Installed by default**. Свежую версию подтягивает кнопка **Re-sync**.

```json title=".claude-plugin/marketplace.json"
{
  "name": "pachca-company",
  "owner": { "name": "Ваша компания" },
  "plugins": [
    {
      "name": "pachca",
      "source": {
        "source": "git-subdir",
        "url": "https://github.com/pachca/openapi.git",
        "path": "plugins/pachca"
      }
    }
  ]
}
```

Каждый сотрудник нажимает **Connect** у сервера Пачки на вкладке **Connectors** плагина и входит под своей учётной записью.

## Codex

Плагин ставит в Codex MCP-сервер и скиллы. Он работает в Codex CLI и в Codex в приложении ChatGPT на компьютере.

```bash
codex plugin marketplace add pachca/openapi --sparse .agents/plugins --sparse plugins/pachca
codex plugin add pachca@pachca
codex mcp login pachca
```

Первая команда добавляет каталог плагинов Пачки, вторая ставит плагин, третья открывает браузер для входа в Пачку. Вход через браузер работает в Codex 0.148.0 и новее: на более ранней версии Codex отвечает `Dynamic client registration not supported`, тогда обновите Codex. Флаг `--sparse` скачивает из репозитория только папки каталога и плагина. Это важно: при каждом изменении репозитория Codex скачивает каталог заново, а без флага это был бы весь репозиторий. Скиллы и инструменты Пачки появятся в новой сессии Codex. В Codex CLI плагин можно поставить и из каталога командой `/plugins`.

Проверьте подключение: в новой сессии попросите «Покажи мой профиль в Пачке». Затем попросите «Перескажи тред» со ссылкой на любой тред.

Как войти на компьютере без браузера и как сервер, добавленный вручную, работает рядом с плагином, сказано в разделе [Codex](/guides/mcp/connect#codex). Там, где входить некому, например в CI, подключите сервер персональным токеном, как в разделе [Codex с токеном](/guides/mcp/connect#codex-s-tokenom).

При каждом запуске Codex проверяет каталог и сам ставит свежую версию плагина. У плагина старше 1.0.5 Codex обрезает список инструментов Пачки на середине. Обновить плагин сразу можно командой:

```bash
codex plugin marketplace upgrade pachca
```

Новая версия заработает в новой сессии Codex.

Расширение Codex для редактора плагины не ставит. Для него поставьте скиллы командой из раздела [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov) с агентом `codex` и подключите сервер, как в разделе [Codex](/guides/mcp/connect#codex).

## VS Code и GitHub Copilot

Плагин подключает MCP-сервер и скиллы в VS Code с GitHub Copilot и в GitHub Copilot CLI. В чате VS Code в среде Copilot, которая выбрана по умолчанию с версии 1.143, выполните:

```text
/plugin marketplace add pachca/openapi
/plugin install pachca@pachca
```

Из терминала то же делают команды GitHub Copilot CLI:

```bash
copilot plugin marketplace add pachca/openapi
copilot plugin install pachca@pachca
```

Установленный так плагин VS Code подхватывает сам.

Если команды `/plugin` в чате нет, проверьте настройку `chat.plugins.enabled`: её может выключить администратор организации. Плагином управляют там же, где его поставили: плагин из команды `/plugin` в панели расширений не виден.

VS Code предложит войти в Пачку через браузер при первом запуске сервера. В Copilot CLI войдите командой `/mcp auth pachca`.

Проверьте подключение: попросите в чате «Покажи мой профиль в Пачке». Затем попросите «Перескажи тред» со ссылкой на любой тред.

Плагин, поставленный из чата VS Code, обновляет команда `/plugin update pachca` в чате. Плагин, поставленный из терминала, обновляет команда:

```bash
copilot plugin update pachca
```

Сервер с именем `pachca`, добавленный вручную, Copilot заменяет сервером плагина, поэтому отдельно его добавлять не нужно. Если скиллы уже поставлены командой `npx skills add`, Copilot берёт их вместо скиллов плагина. Удалите их, чтобы скиллы обновлялись вместе с плагином.

## Cursor

Плагин «Пачка» ставит в Cursor MCP-сервер и скиллы. Сервер плагина в Cursor подключается [персональным токеном](/guides/mcp/connect#token-v-zagolovke) из переменной окружения `PACHCA_TOKEN`. Сообщения агента с персональным токеном выглядят как написанные вами вручную.

<Steps>
  <Step title="Создайте токен и перезапустите Cursor">
    Создайте персональный токен и сохраните его в переменной окружения `PACHCA_TOKEN`, как в разделе [Токен в заголовке](/guides/mcp/connect#token-v-zagolovke). Чтобы проверять сообщения перед отправкой, добавьте токену права на черновики из раздела [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi) и просите агента готовить [черновики](/guides/ai-agents/drafts). Затем закройте все окна Cursor и откройте его снова: переменные окружения Cursor читает при запуске.
  </Step>
  <Step title="Установите плагин в Cursor">
    В редакторе откройте **Customize** на боковой панели, в списке источников выберите **Add Marketplace** > **Import from Github** и укажите `https://github.com/pachca/openapi`. Затем найдите плагин Pachca, нажмите **Install** и выберите область **User**, чтобы плагин работал во всех проектах. В Cursor CLI добавьте маркетплейс командой ниже, затем в сессии агента выполните `/plugin` и установите плагин `pachca`.

    ```bash
    agent plugin marketplace add https://github.com/pachca/openapi
    ```

    Если плагин «Пачка» уже стоит в Claude Code, этот шаг можно пропустить: Cursor подключит его сам, как сказано ниже.

  </Step>
  <Step title="Проверьте подключение в Cursor">
    Попросите агента «Покажи мой профиль в Пачке», и он ответит вашим именем и ролью. Если Cursor предлагает войти в сервер Пачки, что делать, сказано в разделе [Если что-то не работает](/guides/mcp/connect#esli-chto-to-ne-rabotaet). Когда подключение работает, попросите «Перескажи тред» со ссылкой на любой тред.
  </Step>
</Steps>

Если плагин «Пачка» стоит в Claude Code, Cursor подключает его сам, пока включена настройка **Include Third-Party Plugins, Skills, and Other Configs** в **Settings** > **Agents** > **Third-Party Imports**. Токен в `PACHCA_TOKEN` нужен и в этом случае.

В Cursor сервер плагина называется `plugin-pachca-pachca`. Сервер Пачки в `mcp.json` с плагином не нужен, уберите его.

Без плагина поставьте скиллы командой из раздела [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov) с агентом `cursor` и подключите сервер, как в разделе [Cursor](/guides/mcp/connect#cursor).
