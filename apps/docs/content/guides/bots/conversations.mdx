# Общение с ботом

Бот работает там же, где работают сотрудники: в личных сообщениях, беседах, каналах и тредах. Сотрудник пишет боту в личные сообщения, зовёт его по нику в обсуждении или пишет команду в чате, а бот отвечает там, где его позвали. Здесь — что настроить, как бот узнаёт о сообщениях и понимает, что обращаются к нему, как разбирает команды, куда отвечает и откуда берёт контекст разговора.

## Где бот общается

- **Личные сообщения** — сотрудник пишет боту, или бот пишет первым
- **Беседы и каналы** — бота добавляют участником, и он получает сообщения чата и всех его тредов
- **Треды** — бота добавляют участником треда, а публичного зовут и упоминанием прямо в обсуждении, и он получает сообщения этого треда

Так работают и [AI-агенты](/guides/ai-agents/overview): агента зовут по нику в чате или треде, а отвечает он тредом.

Кто может добавить бота или написать ему и что бот видит в каждом случае — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).

## Как бот узнаёт о сообщениях

О новых сообщениях бот узнаёт по [исходящему вебхуку](/guides/webhook/overview) с событием **Новые сообщения** (`message_new`). Какие сообщения приходят, решает режим:

- **Любые сообщения** — все сообщения из чатов и тредов, где состоит бот. Нужен боту, который отвечает в личных сообщениях или на упоминание.
- **Начинающиеся с команд** — только сообщения, первое слово которых есть в списке команд, например `/task`. Подходит боту, которого вызывают командой, подробнее в разделе [Команды](#komandy).

Отдельного режима «только упоминания» нет: бот получает все сообщения и сам решает, обращаются ли к нему. Новый бот слушает только команды, а их список пуст, поэтому режим нужно выбрать. Подробнее о режимах — в разделе [Настройка и типы событий](/guides/webhook/events#soobscheniya).

## Когда отвечать

В личных сообщениях к боту обращаются всегда. В беседах, каналах и тредах сотрудники пишут друг другу, и бот, который отвечает на каждое сообщение, мешает. Обычно бот отвечает:

- **В личных сообщениях** — на каждое сообщение: у них `entity_type` равен `"user"`
- **На упоминание** — в тексте сообщения (`content`) есть упоминание бота
- **На команду** — сообщение начинается с команды бота, подробнее в разделе [Команды](#komandy)
- **На продолжение разговора** — например, в треде, где кроме бота только один сотрудник, можно отвечать и без упоминания

Состав треда показывает метод [Информация о чате](GET /chats/{id}) с `chat_id` из события.

Свои сообщения бот пропускает: включите **Игнорировать свои сообщения** или сравнивайте `user_id` из события с идентификатором бота.

Упоминание, которое сотрудник вставил в приложении Пачки, приходит в `content` как `@` и имя бота, например `@Кай`. С ником, как `@kai_bot`, оно приходит из сообщений, отправленных через API. Ищите обе формы целым словом вне кода: проверка подстроки срабатывает и на более длинный ник вроде `@kai_bot_team` или `@kai_bot-dev`, и на упоминание внутри кода, которое Пачка упоминанием не считает. Имя бота лучше выбрать такое, которого нет у сотрудников, иначе `@Кай` совпадёт и с `@Кай Смирнов`.

```typescript title="Обращаются ли к боту"
const BOT_ID = 7890 // id бота
const BOT_NAME = "Кай" // имя бота: first_name из профиля
const BOT_NICKNAME = "kai_bot" // ник бота

const escape = (s: string) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")
const NICK_CHAR = "[\\p{L}\\p{N}_-]" // символы, которые продолжают ник
// @имя или @ник целым словом: @kai_bot_team и @kai_bot-dev не подходят
const MENTION = new RegExp(
  `(?<![\\p{L}\\p{N}_])@(?:${escape(BOT_NAME)}|${escape(BOT_NICKNAME)})(?!${NICK_CHAR}|\\.${NICK_CHAR})`,
  "u",
)

function isAddressed(event: { user_id: number; entity_type: string; content: string }) {
  if (event.user_id === BOT_ID) return false // своё сообщение
  if (event.entity_type === "user") return true // личные сообщения
  const text = event.content
    .replace(/`{3}[\s\S]*?`{3}/g, " ") // блоки кода
    .replace(/`[^`\n]*`/g, " ") // код в строке
  return MENTION.test(text) // позвали по имени или по нику
}
```

Упоминания в пересланном сообщении никого не зовут, а событие не говорит, что сообщение переслано. Если это важно, получите сообщение методом [Информация о сообщении](GET /messages/{id}) и пропустите его, когда поле `forwarding` не `null`.

Свой `id`, имя и ник бот узнаёт методом [Информация о профиле](GET /profile) со своим токеном, а `id` есть и на вкладке **API** в карточке бота. Текст в `content` — markdown, который Пачка собирает из сообщения: в нём бывают цитаты и списки. Подробнее — в разделе [Разметка в исходящих вебхуках](/guides/markdown#razmetka-v-ishodyaschih-vebhukah).

## Команды

В режиме **Начинающиеся с команд** бот получает только сообщения, которые начинаются с одной из его команд. Как Пачка сравнивает первое слово с командами и почему слэш не обязателен — в разделе [Команды](/guides/webhook/events#komandy). Остальное бот делает сам:

- **Разбирает аргументы.** Всё, что после команды, приходит в том же `content`, например `/task Подготовить отчёт до пятницы`.
- **Понимает упоминание перед командой.** Сообщение `@kai_bot /help` начинается с упоминания, поэтому в режиме команд не приходит. Если бота зовут и так, выберите режим **Любые сообщения** и убирайте упоминание перед разбором, как в примере ниже.
- **Отвечает там, где написали команду.** Команды приходят из личных сообщений, бесед, каналов и тредов, а куда отвечать в каждом случае, сказано в разделе [Куда отвечать](#kuda-otvechat).

```typescript title="Разбор команды"
const COMMANDS = new Set(["/task", "/help"]) // те же слова, что в списке команд бота
// Упоминание бота в начале сообщения: MENTION из примера выше
const LEADING_MENTION = new RegExp(`^\\s*${MENTION.source}\\s*`, "u")

function parseCommand(content: string) {
  const text = content.replace(LEADING_MENTION, "") // «@kai_bot /help» → «/help»
  const match = text.trim().match(/^(\S+)\s*([\s\S]*)$/)
  if (!match || !COMMANDS.has(match[1])) return null
  return { command: match[1], args: match[2] } // args — всё после команды, с переносами строк
}

parseCommand("/task Подготовить отчёт\nдо пятницы")
// → { command: "/task", args: "Подготовить отчёт\nдо пятницы" }
```

Список команд хранится в настройках бота, и сотрудникам его показывает сам бот. Добавьте в список `/help` и отвечайте на неё перечнем команд с примерами. В личных сообщениях бот в режиме **Любые сообщения** может присылать этот перечень в ответ на любой текст без команды.

## Куда отвечать

Отвечайте там, откуда пришло сообщение. Это видно по `entity_type` и `entity_id` в событии:

| Откуда сообщение | `entity_type` | `entity_id` | Как ответить |
| --- | --- | --- | --- |
| Личные сообщения | `user` | Идентификатор сотрудника | С теми же `entity_type` и `entity_id` |
| Беседа или канал | `discussion` | Идентификатор чата | Тредом к сообщению: методом [Новый тред](POST /messages/{id}/thread) с `id` сообщения, затем ответ с `entity_type: "thread"` и `id` треда. Можно и прямо в чат — с теми же `entity_type` и `entity_id`. |
| Тред | `thread` | Идентификатор треда | С теми же `entity_type` и `entity_id`. `parent_message_id` с `id` сообщения добавит к ответу цитату. |

```json title="Событие: бота позвали в треде"
{
  "type": "message",
  "event": "new",
  "id": 1245830,
  "entity_type": "thread",
  "entity_id": 334455,
  "chat_id": 9020,
  "user_id": 2345,
  "content": "@kai_bot собери сводку по релизу",
  "created_at": "2026-09-24T09:30:00.000Z",
  "url": "https://app.pachca.com/chats/9020?message=1245830",
  "thread": { "message_id": 1245817, "message_chat_id": 9012 },
  "webhook_timestamp": 1790242200
}
```

Поле `thread` показывает, к какому сообщению и в каком чате открыт тред. Боту для ответа часто нужны история треда и это родительское сообщение — как их прочитать, в разделе [Контекст разговора](#kontekst-razgovora).

В беседе или канале ответ тредом не теряется в ленте и не мешает остальным. Если у сообщения тред уже есть, метод [Новый тред](POST /messages/{id}/thread) вернёт его.

```bash title="Ответ тредом на сообщение из канала"
# Тред к сообщению 1245817: если он уже есть, вернётся он же
curl -X POST https://api.pachca.com/api/shared/v1/messages/1245817/thread \
  -H "Authorization: Bearer $BOT_TOKEN"

# Ответ в тред с id из предыдущего ответа
curl -X POST https://api.pachca.com/api/shared/v1/messages \
  -H "Authorization: Bearer $BOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "message": {
      "entity_type": "thread",
      "entity_id": 334455,
      "content": "Смотрю, через минуту пришлю сводку"
    }
  }'
```

Пока бот готовит ответ, поставьте на сообщение реакцию методом [Добавление реакции](POST /messages/{id}/reactions) и снимите её методом [Удаление реакции](DELETE /messages/{id}/reactions) после ответа: сотрудник сразу видит, что бот работает. Для агентов есть реакция `agent-thinking` с таймером — подробнее в разделе [Взаимодействие с агентом](/guides/ai-agents/interaction#reaktsiya-agent-thinking).

К ответу можно приложить [кнопки](/guides/buttons), а по нажатию открыть [форму](/guides/forms/overview). Нажатия и отправленные формы приходят событием, если у бота включено **Нажатие кнопок**.

### Что учесть в ответе

- **Разметка.** Ответ пишут в Markdown, список конструкций — в разделе [Форматирование текста](/guides/markdown). Длинный отчёт удобнее прислать файлом `.md` — подробнее в разделе [Оформление ответов](/guides/ai-agents/markdown).
- **Упоминания.** Сотрудника упоминают в тексте как `@nickname` или `<@user_id>`: по идентификатору Пачка сама подставит ник. Упомянутый в треде сотрудник становится участником треда. Чтобы только сослаться на коллегу, передайте `skip_invite_mentions: true`. Кого добавляет упоминание и когда действует флаг, сказано в разделе [Участники треда](/guides/threads#uchastniki-treda).
- **Лимиты.** Отправка сообщений ограничена по частоте и по числу сообщений в один чат за сутки — подробнее в разделе [Лимиты](/api/limits#api).

## Контекст разговора

Бота зовут посреди обсуждения, и одного сообщения с упоминанием или командой часто мало: суть выше по треду или в сообщении, к которому открыт тред. Контекст читают так:

- **История треда или чата** — метод [Список сообщений чата](GET /messages) с `chat_id` из события. Сообщения приходят от новых к старым, а более ранние отдаёт следующая страница по `cursor`.
- **Родительское сообщение треда** — метод [Информация о сообщении](GET /messages/{id}) с `thread.message_id` из события. Если бота позвали в треде, где других сообщений нет, основной контекст — в нём. У самостоятельного треда родительского сообщения нет: `thread.message_id` приходит `null`, и контекст только в сообщениях треда.
- **Сообщение, на которое ответили** — тот же метод с `parent_message_id` из события. Поле заполнено, когда сотрудник ответил с цитатой.
- **Участники и название чата** — метод [Информация о чате](GET /chats/{id}) с `chat_id` из события. По `member_ids` видно, кто ещё участвует в разговоре.

Для этих методов токену нужны права `messages:read` и `chats:read`.

Открытые беседы и каналы бот читает целиком, даже если его туда не добавляли. Если бота добавили только в тред закрытого чата, он видит этот тред и родительское сообщение, а остальную историю чата — нет. Подробнее — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).

## Ответы на сообщения сервиса

Бывает, что разговор начинает сам сервис: бот присылает в чат заявку или уведомление мониторинга, а сотрудник отвечает на это сообщение. Связать ответ с исходным сообщением помогают поля события:

| Как ответил сотрудник | Что в событии |
| --- | --- |
| В треде под сообщением бота | `entity_type: "thread"`, а в `thread.message_id` — `id` сообщения бота |
| Ответом с цитатой в том же чате | `parent_message_id` — `id` сообщения бота |

Сохраните `id` из ответа метода [Новое сообщение](POST /messages) вместе со своим объектом, например номером заявки, и ищите его в этих полях. `thread.message_id` приходит с каждым сообщением треда, а `parent_message_id` внутри треда указывает на сообщение треда, которое процитировали, поэтому проверяйте оба поля.

```typescript title="К какой заявке относится ответ"
const sentMessages = new Map<number, string>() // id сообщения бота → номер заявки, сохранённый при отправке

function findRequest(event: {
  thread?: { message_id: number | null } | null
  parent_message_id?: number | null
}) {
  for (const id of [event.thread?.message_id, event.parent_message_id]) {
    if (id && sentMessages.has(id)) return sentMessages.get(id)
  }
  return undefined // ответ не на сообщение бота
}
```

Чтобы получать такие ответы, боту нужен режим **Любые сообщения**, а сообщение отправляет тот же бот, который слушает чат: события приходят из чатов, где он состоит, и из их тредов. Если сотрудник ответил в личных сообщениях без цитаты, этих полей нет, и ответ сопоставляют с последним сообщением, которое бот отправил этому сотруднику. Когда ответ сводится к выбору из вариантов, удобнее [кнопки](/guides/buttons): событие нажатия приходит с `message_id` сообщения.

## Личные сообщения

Кто может написать боту в личные сообщения, зависит от того, публичный ли бот и есть ли у сотрудника с ним общий чат. Подробнее — в разделе [Доступы к чатам и сообщениям](/guides/bots/access#lichnye-soobscheniya).

<Warning>
  **Личный чат создаётся молча.** Когда сотрудник открывает переписку с ботом, события об этом нет — ни о новом чате, ни о новом участнике. Бот узнаёт о сотруднике только из его первого сообщения, поэтому в личных сообщениях первый ход за сотрудником, если бот не написал сам.
</Warning>

Чтобы начать разговор самому, например поприветствовать нового сотрудника, бот отправляет сообщение методом [Новое сообщение](POST /messages) с `entity_type: "user"` и идентификатором сотрудника в `entity_id`. Где взять идентификаторы сотрудников и чатов — в разделе [Где взять идентификаторы](/api/requests-responses#gde-vzyat-identifikatory).

В личных сообщениях бот просит и доступ, когда ему нужны права самого сотрудника: присылает кнопку авторизации. Это отдельный путь со своими настройками — подробнее в разделах [Авторизация от имени сотрудника](/guides/oauth/overview) и [Чек-лист запуска](/guides/oauth/checklist).
