# Установка

```bash
# Глобальная установка
npm install -g @pachca/cli

# Проверка
pachca --version

# Или без установки
npx -y @pachca/cli users list --token YOUR_ACCESS_TOKEN
```

**Если вы в терминале** — ставьте глобально (`npm i -g`): короткая команда `pachca`, автодополнение, авто-проверка обновлений.

**Если подключаете агента** — используйте `npx -y @pachca/cli`: без установки и без шага «настрой окружение». Агент запускает команду сразу, всегда последняя версия, ничего не нужно поддерживать на машине.

<Info>Флаг `-y` обязателен для агентов и CI. При первом запуске (и после каждого нового релиза, так как берётся последняя версия) `npx` скачивает пакет и в современных версиях npm запрашивает подтверждение установки. В неинтерактивной среде без `-y` команда остановится на этом вопросе и не выполнится.</Info>

## Автодополнение

CLI поддерживает автодополнение для bash, zsh и PowerShell:

```bash
pachca autocomplete zsh
pachca autocomplete bash
pachca autocomplete powershell
```

Команда выводит инструкцию по установке для выбранного шелла.

## Настройки

Установите постоянные значения по умолчанию:

```bash
# Всегда выводить JSON
pachca config set defaults.output json

# Увеличить таймаут
pachca config set defaults.timeout 60

# Показать все настройки
pachca config list
```

Флаги команды всегда имеют приоритет над настройками.

Настройки и профили хранятся в файле `config.toml`. Каталог для него CLI выбирает по первому подходящему правилу:

1. `$PACHCA_HOME/pachca`, если задана переменная `PACHCA_HOME`
2. `$XDG_CONFIG_HOME/pachca`, если задана переменная `XDG_CONFIG_HOME`
3. `%LOCALAPPDATA%\pachca` на Windows
4. `~/.config/pachca` во всех остальных случаях

Полный путь к файлу показывает `pachca doctor`.

## Диагностика

Команда `pachca doctor` проверяет окружение: Node.js, сеть, конфиг, токен и версию CLI.

```bash
pachca doctor

# ✔ Node.js        v20.11.0 (требуется >=20)
# ✔ Сеть           api.pachca.com доступен (142ms)
# ✔ Конфиг         /Users/ivan/.config/pachca/config.toml (права: 600)
# ✔ Хранилище      хранилище ключей ОС, секрет читается
# ✔ Профиль        personal (user: Иван Иванов) — вход через браузер, истекает 30.10.2026, 15:42:10
# ✔ Токен          действителен (11 скоупов)
# ✔ CLI            v2026.10.3 (актуальная версия)
#
# Всё в порядке.
```

`doctor` проверяет тот же токен, с которым работают остальные команды, и находит его в том же [порядке](/guides/cli/authentication#prioritet-tokena). Если токен пришёл из `--token` или `PACHCA_TOKEN`, профиль ему не нужен: проверка профиля пропускается (`skipped`), как и проверка конфига, когда файла нет. Поэтому в CI с одной переменной `PACHCA_TOKEN` команда проходит.

При ошибке хотя бы одной проверки команда завершается с кодом `1` в любом формате вывода. В пайпе и с `-o json` она выводит объект с массивом `checks`, где у каждой проверки есть поле `status` (`ok`, `warning`, `error` или `skipped`): по нему видно, какая проверка не прошла.

## Обновление

В интерактивном терминале CLI проверяет новую версию в фоне, не чаще раза в час, и после команды показывает плашку «Доступна новая версия». В скриптах, CI и с переменной `PACHCA_PROMPT_DISABLED` проверки нет. Для обновления:

```bash
# Обновить до последней версии
pachca upgrade

# Или вручную через npm
npm install -g @pachca/cli

# Посмотреть, что нового
pachca changelog
```

Отключить автоматическую проверку можно переменной `PACHCA_SKIP_NEW_VERSION_CHECK`.

## Удаление

Сначала выйдите из всех профилей, потом удалите пакет: `auth logout` работает, пока CLI установлен.

```bash
# Список профилей
pachca auth list

# Выйти из каждого профиля по очереди
pachca auth logout personal
pachca auth logout bot-notify

# Удалить CLI
npm uninstall -g @pachca/cli
```

`pachca auth logout` удаляет один профиль за вызов, поэтому повторите его для каждого профиля из списка. Выход закрывает вход через браузер на сервере и стирает секрет профиля из хранилища ключей ОС: `npm uninstall` хранилище не трогает. Подробнее — в разделе [Выход](/guides/cli/authentication#vyhod).

Если CLI уже удалили, вход через браузер действует, пока его не отзовут: закройте его действием **Отозвать** в списке [Токены CLI](/guides/cli/authentication#tokeny-cli-v-pachke). Готовые токены продолжают работать и после выхода, удалите их в интерфейсе Пачки.

Файл конфигурации остаётся на диске и после удаления пакета. Удалите его каталог вручную, обычно это `~/.config/pachca`, а другие варианты перечислены в разделе [Настройки](#nastroyki). При заданной `PACHCA_HOME` удаляйте только вложенный каталог `$PACHCA_HOME/pachca`.
