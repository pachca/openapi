# Входящие вебхуки

Входящий вебхук позволяет отправлять сообщения в чаты Пачки от имени бота — достаточно одного HTTP POST-запроса. Вам не нужно работать с API, а гибкость обработки данных обеспечивают шаблонизаторы.

## Как это работает

<Steps>
  <Step title="Создайте бота">
    Откройте **Интеграции** > **Боты** и нажмите **Создать бота**. Подробнее — в разделе [Создание бота](/guides/bots/setup).
  </Step>
  <Step title="Включите вебхук и выберите источник">
    В карточке бота на вкладке **Входящий вебхук** нажмите **Включить** и выберите, что будет присылать данные: GitLab, Grafana или **Свой формат** для любого другого сервиса. Источник можно поменять позже.
  </Step>
  <Step title="Скопируйте адрес вебхука">
    После включения на вкладке появится адрес, на который сервис будет отправлять запросы. Скопируйте его.
  </Step>
  <Step title="Вставьте адрес в настройки внешнего сервиса">
    Укажите скопированный адрес как адрес для уведомлений (webhook URL) в вашей CRM, CI/CD, мониторинге или другом сервисе.
  </Step>
  <Step title="Добавьте бота в нужные чаты">
    Сообщения от вебхука публикуются во все групповые чаты, где состоит бот. Добавьте бота в чаты, в которые хотите получать уведомления. Как это сделать — в разделе [Доступы к чатам и сообщениям](/guides/bots/access#besedy-i-kanaly).
  </Step>
  <Step title="Сервис отправляет POST-запрос">
    При наступлении события сервис отправляет `POST`-запрос с JSON-данными на адрес вебхука. Для своего формата минимальный запрос такой:

    ```json
    {
      "message": "Текст сообщения"
    }
    ```

    Поле `message` содержит текст, который будет опубликован от имени бота. Запросы GitLab и Grafana Пачка разбирает сама, в их настройках достаточно указать адрес.
  </Step>
  <Step title="Сообщение появляется в чате">
    Пачка обрабатывает запрос и публикует сообщение от имени бота во все групповые чаты, где он состоит.
  </Step>
</Steps>

## Настройки

Настройки входящего вебхука находятся на вкладке **Входящий вебхук** в карточке бота и появляются после включения. Кнопка **Удалить вебхук** внизу вкладки выключает его: прежний адрес отвечает `404` на любой запрос, а настройки и шаблон удаляются. Если включить вебхук снова, у него будет новый адрес.

### Источник

- **GitLab** — пуши, пайплайны, merge request и комментарии
- **Grafana** — алерты со скриншотами графиков
- **Свой формат** — любой сервис: JSON и шаблон сообщения

Для GitLab и Grafana Пачка сама разбирает запрос и собирает сообщение, поэтому шаблон нужен только своему формату.

### Шаблон сообщения

По умолчанию Пачка публикует содержимое поля `message` из входящего JSON. Если вместо готового текста вы хотите отправлять произвольную JSON-структуру и гибко формировать сообщение из её полей — выберите **формат шаблона** и заполните **шаблон сообщения**. При пустом шаблоне в сообщение попадает поле `message`.

Пачка поддерживает два шаблонизатора:

- [**Liquid**](https://shopify.github.io/liquid/) — условия, циклы, фильтры (Shopify, open source)
- [**Mustache**](https://mustache.github.io/) — простая подстановка без логики (open source)

<Info>Ссылки выше ведут на полную документацию шаблонизаторов, а ниже — общая информация по форматированию текста и получению данных из JSON-полей.</Info>

Шаблонизатор разбирает входящий JSON и подставляет значения полей в шаблон. Для форматирования текста (жирность, курсив, ссылки, блоки кода и пр.) используйте markdown — полный список поддерживаемых конструкций в разделе [Форматирование текста](/guides/markdown).

```json title="Входящий JSON"
{
  "client": "Иван Петров",
  "amount": 15000,
  "status": "оплачен",
  "project": { "name": "Pachca" }
}
```

```text title="Шаблон Liquid (точечная нотация для вложенных объектов)"
Заказ от {{ client }} на сумму {{ amount }} ₽ — {{ status }}
Проект: {{ project.name }}
```

```text title="Шаблон Mustache (секции для вложенных объектов)"
Заказ от {{ client }} на сумму {{ amount }} ₽ — {{ status }}
{{#project}}Проект: {{ name }}{{/project}}
```

<Info>Mustache также поддерживает точечную нотацию для вложенных объектов `{{ project.name }}`.</Info>

```text title="Результат в чате"
Заказ от Иван Петров на сумму 15000 ₽ — оплачен
Проект: Pachca
```

Liquid также поддерживает:

- **Условия** — `if`, `else`, `elsif`, `unless`, `case`/`when`
- **Циклы** — `for` с параметрами `limit`, `offset`, `reversed`
- **Фильтры строк** — `downcase`, `upcase`, `capitalize`, `truncate`, `replace`, `remove`, `strip`, `escape`, `url_encode`
- **Фильтры чисел** — `plus`, `minus`, `times`, `divided_by`, `round`, `ceil`, `floor`, `abs`
- **Фильтры массивов** — `join`, `first`, `last`, `sort`, `uniq`, `where`, `map`, `size`
- **Фильтры дат** — `date` с форматированием (`%d.%m.%Y`, `%H:%M` и пр.)

<Info>
  После первого запроса на вкладке появляется ссылка **Показать последний полученный объект** с датой получения. Нажмите на неё — откроется окно с содержимым последнего полученного JSON. Используйте его, чтобы определить нужные поля и перенести их в шаблон.
</Info>

### Показывать превью ссылок

Если включено, Пачка разворачивает ссылки из сообщений вебхука в превью — так же, как в обычных сообщениях.

### Поле для верификации

Некоторые сервисы (например, [monday.com](https://monday.com)) при настройке вебхука отправляют проверочный запрос и ожидают получить в ответе определённое поле. Укажите название поля проверки — Пачка ответит JSON-объектом с этим полем и его значением. Для monday.com это слово `challenge`.

## Через API

Все эти настройки можно задать и программно — в объекте `webhook` методов [Новый бот](POST /bots) и [Редактирование бота](PUT /bots/{id}):

- `kind` — источник: `simple` для своего формата, `gitlab` или `grafana`
- `template` — шаблон сообщения
- `template_engine` — шаблонизатор (`liquid` или `mustache`)
- `challenge_key` — поле для верификации
- `link_preview_enabled` — показывать превью ссылок

Текущие значения возвращаются в объекте бота и доступны через метод [Информация о боте](GET /bots/{id}). Если у токена есть скоуп `bots:write` и вы можете управлять токенами бота, этот метод отдаёт и адрес вебхука в поле `webhook.url`, и тело последнего запроса на него в поле `webhook.last_request_body`: по нему видно, что именно прислал сервис. При тех же правах адрес приходит и в ответе методов [Новый бот](POST /bots) и [Редактирование бота](PUT /bots/{id}), отдельный запрос за ним не нужен.

Бот, созданный через API, принимает запросы в своём формате сразу, с шаблонизатором Liquid по умолчанию. Пустой бот, созданный с `empty: true`, входящего вебхука не имеет, пока ему не задали `kind`, а шаблонизатор у него по умолчанию Mustache. Mustache ставится и после удаления входящего вебхука, когда его включают снова. Чтобы шаблон работал на Liquid, передайте `template_engine: "liquid"` вместе с `kind`.

## Ответ вебхука

На принятый запрос вебхук отвечает `200` с коротким текстом в теле, по которому видно, что стало с сообщением (у [проверочного запроса](#pole-dlya-verifikatsii) ответ свой):

| Тело ответа | Что произошло |
| --- | --- |
| `OK` | Сообщение принято и поставлено в очередь на публикацию |
| `empty_message` | Результат шаблона пустой или длиннее 40 000 символов, сообщение не публикуется |
| `syntax_error` | В шаблоне Liquid синтаксическая ошибка, и вместо сообщения в чаты публикуется текст ошибки |

Ответ `OK` ещё не гарантирует публикацию. Результат длиннее 40 000 байт, но не длиннее 40 000 символов, получает `OK` и всё равно не попадает в чат. Не появится сообщение и тогда, когда бот не состоит ни в одном групповом чате. Ошибка в шаблоне Mustache тоже публикуется в чаты текстом ошибки, но вебхук отвечает на неё `OK`.

Запрос, который вебхук не принял, получает код ошибки: `400`, если тело не удалось разобрать, `404`, если адрес вебхука неизвестен или вебхук выключен, `415` для неподдерживаемого формата тела, `422`, если запрос не подходит выбранному источнику (например, GitLab прислал событие, которое Пачка не разбирает), и `429` при превышении лимита запросов.

## Ограничения

<Warning>
  Входящий вебхук не позволяет отправить личное сообщение или указать конкретный чат. Сообщение
  публикуется во **все групповые чаты**, где состоит бот. Для отправки в конкретный чат или личное сообщение
  используйте API-метод [Новое сообщение](POST /messages).
</Warning>

- **Формат запроса** — Пачка принимает тело в форматах `application/json`, `application/x-www-form-urlencoded` и `multipart/form-data`. На запрос с другим заголовком `Content-Type` или без него вебхук отвечает `415` и перечисляет допустимые форматы в тексте ответа, сообщение не публикуется.
- **Максимальная длина сообщения** — 40 000 байт. Для кириллицы 40 000 байт — это около 20 000 символов, поскольку каждый символ занимает два байта. Если результат шаблона превышает лимит, сообщение не будет отправлено.
- **Пустое сообщение** — если шаблон возвращает пустую строку, сообщение не будет отправлено.
- **Ошибка в шаблоне** — если шаблон содержит синтаксическую ошибку, в чат будет отправлено сообщение вида `Ошибка в шаблоне: описание ошибки`.
