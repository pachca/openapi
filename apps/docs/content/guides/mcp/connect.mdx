# Подключение к MCP

<Steps>
  <Step title="Добавьте сервер">
    В настройках MCP программы с агентом добавьте сервер с адресом `https://mcp.pachca.com/mcp`. Как это сделать в вашей программе, сказано в разделе [Программы](#programmy). Если сервер Пачки в программе уже есть, второй не добавляйте: войдите снова, перезапустите программу или удалите сервер и добавьте заново, как сказано в её разделе.
  </Step>
  <Step title="Войдите в Пачку">
    Программа откроет Пачку в браузере. На экране согласия проверьте имя программы и пространство и нажмите **Разрешить**, подробнее — в разделе [Вход через браузер](#vhod-cherez-brauzer). Cursor и программы, которые не входят через браузер, подключаются [персональным токеном](#token-v-zagolovke). Если Пачка пишет «Доступ к API ограничен администраторами пространства», попросите Администратора открыть доступ, как в разделе [Кто может подключить](#kto-mozhet-podklyuchit).
  </Step>
  <Step title="Поставьте скиллы">
    Агент работает и без [скиллов](/guides/ai-agents/skills): правила каждого метода он получает из описаний инструментов. Скиллы учат агента писать коллегам коротко и в тред, а не так, как он отвечает вам в программе, и собирать из вызовов задачу, например читать тред целиком перед пересказом. Пример и подробности — в разделе [Скиллы](/guides/ai-agents/skills). Поставьте их одной командой. Для другой программы замените `claude-code` на её идентификатор, например `codex`, `cursor` или `github-copilot`:

    ```bash
    npx skills add https://dev.pachca.com -g -a claude-code -y
    ```

    Можно попросить об этом и самого агента. Команде нужен Node.js 22.20 или новее, версию показывает `node --version`. Идентификаторы остальных программ и как поставить скиллы в приложение Claude, SourceCraft Code Assistant, GigaCode CLI, DeepSeek Harness и программы без Node.js, сказано в разделе [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov). В Grok Bot скиллы Пачки не ставятся.

    Если плагин «Пачка» стоит в другой программе на этом компьютере, сначала проверьте в разделе [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov), куда ставить скиллы: с флагом `-g` команда часто кладёт их в папку, которую читает и программа с плагином, и там каждый скилл окажется дважды. Агент плагин в другой программе не видит, поэтому перед командой с `-g` он спрашивает, стоит ли плагин «Пачка» в Claude Code, Codex, Cursor или VS Code.

    Скиллы Пачки уже стоят, если в программе есть скилл `pachca-watch-thread`. Прежние скиллы, например `pachca-chats` и `pachca-messages`, удалите в любом случае, а если `pachca-watch-thread` нет, поставьте новые, как в разделе [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov).
  </Step>
  <Step title="Проверьте подключение">
    Попросите агента «Покажи мой профиль в Пачке»: он ответит вашим именем и ролью. Что ещё можно поручить — в разделе [Что можно поручить агенту](/guides/ai-agents/overview#chto-mozhno-poruchit-agentu).
  </Step>
</Steps>

<Info>
  В Claude Code, приложении Claude, Codex, VS Code с GitHub Copilot и Cursor сервер и скиллы можно поставить и одной установкой [плагина «Пачка»](/guides/ai-agents/plugin) вместо шагов 1 и 3. Что он даёт сверх этих шагов, сказано на странице плагина. В приложении Claude на тарифах Team и Enterprise сервер сначала добавляет владелец организации Claude, как в разделе [Claude](#claude).
</Info>

## Кто может подключить

Подключиться может владелец, администратор, сотрудник и мульти-гость. Гость с API не работает, поэтому подключить MCP он не может. Подробнее — в разделе [Роли в пространстве](/guides/permissions#roli-v-prostranstve).

Вход через браузер и персональный токен разрешает настройка пространства **Кто может создавать персональные токены**, а токен бота — настройка **Кто может создавать интеграции**. Значения по умолчанию и что меняет каждая настройка, сказано в разделе [Кто может создавать токены](/api/authorization#kto-mozhet-sozdavat-tokeny).

Если на экране согласия видно «Доступ к API ограничен администраторами пространства», попросите Администратора открыть **Настройки пространства** > **Общие настройки** и выбрать **Все сотрудники** в пункте **Кто может создавать персональные токены**. Как администратору управлять доступом агентов — на странице [Агенты и MCP в пространстве](/guides/agents-access).

## Программы

В каждом разделе сказано, как добавить сервер, войти в Пачку или указать токен и проверить подключение. Claude Code, приложение Claude, VS Code с GitHub Copilot, Codex и Grok Bot входят через браузер. Остальные программы подключаются персональным токеном, как в разделе [Токен в заголовке](#token-v-zagolovke): сначала создайте токен и, если программа берёт его из переменной, задайте её, а потом добавляйте сервер. Скиллы ставятся, как в шаге 3 в начале страницы, если в разделе программы не сказано иначе.

### Claude Code

Если стоит плагин «Пачка», сервер уже добавлен: пропустите команду `claude mcp add` и войдите, как в разделе [Вход в Пачку](/guides/ai-agents/plugin#vhod-v-pachku). Если плагин стоит в Cursor или VS Code, сначала поставьте его и в Claude Code, как сказано в разделе [Установка скиллов](/guides/ai-agents/skills#ustanovka-skillov), и команду `claude mcp add` тоже пропустите.

Добавьте сервер:

```bash
claude mcp add --scope user --transport http pachca https://mcp.pachca.com/mcp
```

Флаг `--scope user` добавляет сервер во все проекты, без него сервер будет только в текущем. Затем запустите Claude Code, выполните команду `/mcp`, выберите сервер `pachca` и войдите. Из терминала то же делает команда `claude mcp login pachca`. Если сервер добавил агент в открытой сессии, войдите сами через `/mcp`, а если сервера `pachca` нет в списке, перезапустите Claude Code.

В облачной сессии Claude Code на claude.ai сервер и скиллы командой не ставьте: после сессии они не сохранятся. Подключите коннектор, как в разделе [Claude](#claude): он появится и в облачных сессиях, если в `.mcp.json` репозитория нет сервера с адресом `https://mcp.pachca.com/mcp`. Если в текущей сессии инструментов Пачки нет, начните новую.

Сервер с тем же адресом, добавленный вручную, заменяет сервер плагина. Если позже поставите плагин, удалите ручной сервер, как в разделе [Если сервер уже добавлен вручную](/guides/ai-agents/plugin#esli-server-uzhe-dobavlen-vruchnuyu).

Если браузер не открывается, например в сессии по SSH, команда `claude mcp login` сама покажет ссылку, а флаг `--no-browser` включает это принудительно. Подключайтесь по `ssh -t`, откройте ссылку на своём компьютере и нажмите **Разрешить**. Когда команда попросит, вставьте в терминал адрес из строки браузера.

Проверьте подключение: в списке `/mcp` сервер Пачки должен быть подключён, а на просьбу «Покажи мой профиль в Пачке» агент должен ответить вашим именем и ролью.

### Claude

Подключённый MCP-сервер Claude называет коннектором. Добавьте его по шагам ниже. На тарифах Pro и Max с плагином «Пачка» коннектор отдельно не добавляйте: он добавляется с вкладки плагина, как в разделе [Приложение Claude](/guides/ai-agents/plugin#prilozhenie-claude).

Шаги коннектора:

1. В приложении Claude или на claude.ai откройте **Customize** > **Connectors** и нажмите **Add** > **Add custom connector**.
2. Укажите название, например «Пачка», и адрес `https://mcp.pachca.com/mcp`, затем нажмите **Continue**.
3. Проверьте настройки входа, которые нашёл Claude, и нажмите **Continue**.
4. В **Authentication** выберите **Sign in now**, в **OAuth client** выберите **Use Claude's published identity** и нажмите **Add**. Вариант **Register automatically** с Пачкой не работает.
5. Нажмите **Connect** у нового коннектора и войдите.

На тарифе Free можно добавить один такой коннектор. Коннектор работает в чате на claude.ai, в приложении Claude на компьютере и телефоне и в Cowork.

На тарифах Team и Enterprise коннектор добавляет владелец организации Claude: **Organization settings** > **Connectors** > **Add** > **Custom** > **Web**, затем те же шаги. После этого каждый сотрудник нажимает **Connect** у коннектора Пачки в **Customize** > **Connectors** или на вкладке **Connectors** плагина и входит под своей учётной записью.

<Warning>Claude подключается к Пачке через вход в браузере. Если в окне коннектора есть раздел **Request headers**, персональный токен туда не указывайте: заголовки общие для всей организации Claude, и все её сотрудники действовали бы в Пачке от вашего имени.</Warning>

Коннектор появится и в Claude Code, если вы вошли в него через тот же аккаунт claude.ai, в том числе в облачных сессиях. Если в Claude Code стоит плагин «Пачка» или сервер с тем же адресом добавлен вручную, Claude Code работает через них, и в Пачку там нужно войти отдельно. В облачной сессии плагин не загружается, поэтому вместо коннектора там работает только сервер с тем же адресом из файла `.mcp.json` в репозитории, если он есть.

Скиллы в приложение Claude ставит плагин «Пачка» вместе с коннектором. Без плагина загрузите архив каждого скилла, как в разделе [Установка вручную](/guides/ai-agents/skills#ustanovka-vruchnuyu): команда `npx skills` в приложении не работает.

Проверьте подключение: в новом чате попросите «Покажи мой профиль в Пачке». Если инструментов Пачки в чате нет, откройте **Customize** > **Connectors** и проверьте коннектор Пачки: если он не подключён, нажмите **Connect** и войдите снова. Если подключён, проверьте в меню инструментов чата, что коннектор Пачки включён. Второй коннектор с тем же адресом не добавляйте.

### VS Code и GitHub Copilot

Сервер быстрее всего добавляется по ссылке [Установить в VS Code](vscode:mcp/install?%7B%22name%22%3A%22pachca%22%2C%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Fmcp.pachca.com%2Fmcp%22%7D).

Чтобы сервер был во всех проектах, добавьте его командой GitHub Copilot CLI:

```bash
copilot mcp add --transport http pachca https://mcp.pachca.com/mcp
```

Команда запишет сервер в `~/.copilot/mcp-config.json`, этот файл читают и VS Code, и Copilot CLI. В VS Code то же делает команда **MCP: Add Server**: выберите **HTTP**, укажите адрес и имя `pachca`, затем **Global** > **Copilot Global**.

Для одного проекта добавьте сервер в файл `.mcp.json` в корне проекта. Этот же файл читает Claude Code.

```json title=".mcp.json"
{
  "mcpServers": {
    "pachca": {
      "type": "http",
      "url": "https://mcp.pachca.com/mcp"
    }
  }
}
```

VS Code предложит войти при первом запуске сервера. Если окно входа не появилось или вход прервался, выполните команду **MCP: List Servers**, выберите `pachca` и запустите сервер снова: там же видно, запущен ли он. В Copilot CLI войдите командой `/mcp auth pachca`, вход через браузер работает в Copilot CLI 1.0.83 и новее. Если сервер добавил агент в открытой сессии Copilot CLI, запустите Copilot CLI заново. Сервер из `.mcp.json` проекта Copilot CLI подключает, только если вы доверяете папке. Файл `.vscode/mcp.json` с ключом `servers` тоже работает, но VS Code помечает его устаревшим.

Чтобы подключиться токеном, добавьте в сервер в файле `~/.copilot/mcp-config.json` поле `"headers": { "Authorization": "Bearer ${PACHCA_TOKEN}" }` и задайте [переменную](#peremennaya-okruzheniya) `PACHCA_TOKEN` в окружении, из которого запускается VS Code или Copilot CLI. Записи вида `${input:…}` и `${env:…}` в этом файле не работают. Если сервер записан в файл вручную без команды `copilot mcp add`, добавьте в него и `"tools": ["*"]`. Сервер с заголовком `Authorization` в `.mcp.json` проекта не добавляйте. Почему — в разделе [Claude Code с токеном](#claude-code-s-tokenom).

Проверьте подключение: попросите агента в чате Copilot «Покажи мой профиль в Пачке». Если потом поставите [плагин «Пачка»](/guides/ai-agents/plugin#vs-code-i-github-copilot), он заменит сервер `pachca`, добавленный вручную, своим.

### Codex

У Codex подключение общее для CLI, расширения и приложения ChatGPT на компьютере, его добавляет одна команда. Сначала проверьте командой `codex mcp list`, нет ли уже сервера `pachca`: если есть, второй не добавляйте.

```bash
codex mcp add pachca --url https://mcp.pachca.com/mcp
```

Команда добавляет сервер и сразу открывает браузер для входа. Вход через браузер работает в Codex 0.148.0 и новее, версию показывает `codex --version`. Если вход прервался, повторите его:

```bash
codex mcp login pachca
```

На компьютере без браузера добавьте к этой команде флаг `--no-browser`: она покажет ссылку, а после подтверждения попросит вставить адрес, на который вернулся браузер. Если сервер добавил агент, вход мог не дождаться браузера: выполните `codex mcp login pachca` в своём терминале и перезапустите Codex.

Если команды `codex` нет, добавьте сервер в настройках. В приложении ChatGPT откройте **Settings** > **MCP servers**, в расширении меню с шестерёнкой > **MCP servers**. Нажмите **Add server**, укажите имя `pachca`, выберите **Streamable HTTP** и адрес `https://mcp.pachca.com/mcp`. Сохраните сервер, нажмите **Restart** в приложении или **Restart extension** в расширении, затем **Authenticate** и войдите в Пачку.

Сервер с именем `pachca`, добавленный вручную, заменяет сервер [плагина «Пачка»](/guides/ai-agents/plugin#codex), а скиллы плагина продолжают работать. Удалять такой сервер не нужно. Где входить некому, например в CI, подключите Codex [персональным токеном](#codex-s-tokenom).

Проверьте подключение: команда `codex mcp list` покажет сервер `pachca`, а на просьбу «Покажи мой профиль в Пачке» агент ответит вашим именем и ролью.

Когда у всех MCP-серверов в Codex вместе больше 100 инструментов, Codex прячет их за поиском инструментов, и агент может решить, что нужного инструмента нет, например отправки сообщения. Попросите его найти инструмент по точному имени: «Найди инструмент `pachca_send_message` и отправь сообщение». По той же причине агент может не увидеть Пачку и при проверке подключения. Если `codex mcp list` показывает сервер `pachca`, заново его не добавляйте. Если в столбце `Auth` у него `Not logged in`, выполните `codex mcp login pachca` в своём терминале и перезапустите Codex. Иначе попросите «Найди инструмент `pachca_get_my_card` и покажи мой профиль в Пачке».

### Grok Bot

Grok Bot подключается к Пачке через вход в браузере, токен не нужен. Сервер Grok Bot добавляет сам по просьбе в чате:

1. В чате Grok Bot попросите «Подключи MCP-сервер `https://mcp.pachca.com/mcp`».
2. Grok Bot добавит сервер и покажет в чате карточку для входа. Нажмите на ней кнопку входа и войдите в Пачку в браузере.
3. На экране согласия проверьте пространство и нажмите **Разрешить**.

Инструменты Пачки появляются со следующего сообщения. Если вход не закончился, нажмите **Reopen** на карточке или откройте **Connect apps** в боковой панели, выберите сервер Пачки и нажмите **Authenticate**. Второй сервер не добавляйте.

Проверьте подключение: попросите «Покажи мой профиль в Пачке». Если инструментов Пачки нет, проверьте состояние сервера в **Connect apps**: при **Needs auth** или **Disconnected** нажмите **Authenticate**, при **Connected** напишите Grok Bot новое сообщение.

Скиллы Пачки в Grok Bot не ставятся: свои скиллы он хранит в библиотеке и сохраняет из задач в чате, а команда `npx skills` ему не подходит. Шаг со скиллами пропустите, правила методов агент получает из описаний инструментов.

### Cursor

Если в списке серверов MCP в Cursor есть `plugin-pachca-pachca`, [плагин «Пачка»](/guides/ai-agents/plugin#cursor) уже подключён: он стоит в Cursor, или Cursor подключил его из Claude Code. Тогда в `mcp.json` сервер не добавляйте, а сервер `pachca`, если он там есть, уберите. Скиллы не ставьте, их ставит плагин. Только создайте токен, задайте `PACHCA_TOKEN` и перезапустите Cursor, как сказано ниже. Если плагин стоит только в Claude Code, а сервера `plugin-pachca-pachca` в списке нет, включите в Cursor подключение плагинов Claude Code, как в разделе [Cursor](/guides/ai-agents/plugin#cursor) страницы плагина, и перезапустите Cursor.

Создайте токен и задайте переменную `PACHCA_TOKEN`, как в разделе [Токен в заголовке](#token-v-zagolovke). Затем добавьте сервер по ссылке [Установить в Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=pachca&config=eyJ1cmwiOiJodHRwczovL21jcC5wYWNoY2EuY29tL21jcCIsImhlYWRlcnMiOnsiQXV0aG9yaXphdGlvbiI6IkJlYXJlciAke2VudjpQQUNIQ0FfVE9LRU59In19) или вручную: в `~/.cursor/mcp.json`, чтобы он был во всех проектах, или в `.cursor/mcp.json` проекта.

### Qwen Code и GigaCode CLI

Создайте токен и задайте переменную `PACHCA_TOKEN`, как в разделе [Токен в заголовке](#token-v-zagolovke), затем откройте новое окно терминала: программа видит только переменные, заданные до её запуска. В Qwen Code добавьте сервер командой:

```bash

```

Одинарные кавычки сохраняют в `~/.qwen/settings.json` только ссылку на переменную, и сам токен в файл не попадает. Qwen Code подставит значение при запуске. В командной строке Windows одинарные кавычки не работают, там возьмите двойные: в ней запись `${PACHCA_TOKEN}` тоже сохранится как есть.

В GigaCode CLI:

```bash
gigacode mcp add --scope user --transport http pachca https://mcp.pachca.com/mcp --header "Authorization: Bearer $PACHCA_TOKEN"
```

Эта команда сохранит в `~/.gigacode/settings.json` сам токен, а не ссылку на переменную, поэтому выполняйте её в терминале, где переменная уже задана. В PowerShell вместо `$PACHCA_TOKEN` укажите `$env:PACHCA_TOKEN`, в командной строке Windows `%PACHCA_TOKEN%`. Если команду выполняет агент, а переменную он не видит, перезапустите программу, как в разделе [Переменная окружения](#peremennaya-okruzheniya). Если сервер уже есть, а инструментов Пачки нет и после перезапуска, в настройках мог сохраниться пустой токен: удалите сервер `pachca` из файла сами и добавьте снова в терминале, где переменная задана.

Сервер, который агент добавил в открытой сессии, программа подхватит только после перезапуска: выйдите из неё и запустите снова в новом окне терминала, открытом после того, как вы задали переменную. Проверьте подключение командой `/mcp`: сервер `pachca` должен быть подключён.

В Qwen Code тот же сервер можно записать в `~/.qwen/settings.json` вручную. Адрес Streamable HTTP в этих программах задаёт поле `httpUrl`, поле `url` в них означает транспорт SSE:

```json title="~/.qwen/settings.json"

    "pachca": {

        "Authorization": "Bearer ${PACHCA_TOKEN}"
      }
    }
  }
}
```

### DeepSeek Harness

Приложение DeepSeek Harness на компьютере подключается к Пачке персональным токеном, а сервер добавляется в файле настроек: раздела MCP в интерфейсе приложения нет. Создайте токен и задайте переменную `PACHCA_TOKEN`, как в разделе [Токен в заголовке](#token-v-zagolovke). Затем откройте файл `~/.dsh/profiles/desktop/cordis.patch.yml`, в Windows `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`. Файл появляется после первого запуска приложения и заканчивается строкой `[]`: замените её блоком ниже. Если строки `[]` нет и в файле уже есть записи, которые начинаются со знака `-`, добавьте блок после них.

```yaml title="~/.dsh/profiles/desktop/cordis.patch.yml"
- insert:
    - id: mcp-pachca
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: pachca
        transport: streamable-http
        url: https://mcp.pachca.com/mcp
        headers:
          Authorization: !!js '`Bearer ${process.env.PACHCA_TOKEN}`'
```

Блок должен начинаться со строки `- insert:`. Без неё приложение принимает запись за правку существующего блока, не находит такого блока и пропускает запись: инструменты Пачки не появятся. Блок, дописанный после строки `[]`, ломает файл, и приложение не запустится. Чтобы обойтись без переменной, вместо строки с `!!js` укажите `Authorization: Bearer <токен>`. Файл лежит в домашней папке и в репозиторий не попадает.

Блок только добавляет сервер Пачки. Остальные записи файла и настройки моделей в приложении не меняйте: Пачка — сервер MCP, а не поставщик моделей, и её адрес или адрес этой страницы в поле Base URL ломает модели. Если подключение поручаете агенту, напишите ему это прямо. Если модели всё же пропали, в Settings → Models удалите добавленных поставщиков, в карточке DeepSeek нажмите Edit, затем Restore defaults и Apply и заново выберите модель DeepSeek в каждом чате.

Правку файла приложение подхватывает само, а новую переменную видит только после перезапуска. Закройте приложение полностью и откройте снова: в macOS сочетанием ⌘Q, в Windows через выход в меню значка в области уведомлений. Если просто закрыть окно, приложение продолжит работать. Если после правки приложение не запускается, откройте файл в редакторе, удалите строку `[]` над блоком или сам блок и запустите приложение снова. Проверьте подключение: откройте новый чат и попросите агента «Покажи мой профиль в Пачке». Ошибку подключения приложение в окне не показывает, поэтому, если инструментов Пачки нет, проверьте блок и переменную, как в разделе [Переменная окружения](#peremennaya-okruzheniya).

Скиллы приложение читает из папки `~/.dsh/skills/`, в Windows `%USERPROFILE%\.dsh\skills\`, и из общей `~/.agents/skills/` и подхватывает новые без перезапуска. Своего имени в команде `npx skills` у DeepSeek Harness нет. Если плагина «Пачка» нет в Codex, Cursor и VS Code, поставьте скиллы командой `npx skills add https://dev.pachca.com -g -a universal -y`: она положит их в `~/.agents/skills/`. Иначе распакуйте скиллы в `~/.dsh/skills/`, как в разделе [Установка вручную](/guides/ai-agents/skills#ustanovka-vruchnuyu).

### Другие программы и платформы

Укажите адрес `https://mcp.pachca.com/mcp`, транспорт Streamable HTTP (иногда он называется HTTP) и заголовок `Authorization` со значением `Bearer <токен>`. Если программа принимает настройки в JSON, они обычно выглядят так:

```json
{
  "pachca": {
    "url": "https://mcp.pachca.com/mcp",
    "headers": {
      "Authorization": "Bearer <токен>"
    }
  }
}
```

Проверьте, как в программе называется поле адреса для Streamable HTTP. В некоторых программах поле `url` означает транспорт SSE, а для Streamable HTTP есть отдельное поле, например `httpUrl` в [Qwen Code и GigaCode CLI](#qwen-code-i-gigacode-cli).

Если программа подключает только локальные серверы (stdio), то есть сама запускает сервер на вашем компьютере, запустите сервер через мост [mcp-remote](https://github.com/geelen/mcp-remote): он передаёт вызовы на адрес Пачки с вашим токеном.

```json
{
  "mcpServers": {
    "pachca": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://mcp.pachca.com/mcp",
        "--header",
        "Authorization:${PACHCA_AUTH_HEADER}"
      ],
      "env": {
        "PACHCA_AUTH_HEADER": "Bearer <токен>"
      }
    }
  }
}
```

Пробела в аргументе `Authorization:${PACHCA_AUTH_HEADER}` нет намеренно: Cursor, Codex и приложение Claude в Windows портят аргументы с пробелами, а в значении переменной пробел допустим.

Проверьте подключение: попросите агента «Покажи мой профиль в Пачке».

## Особые случаи

Подключение там, где входить некому, агент только для чтения и работа с несколькими пространствами сразу.

### Claude Code с токеном

Там, где входить некому, например в CI, в контейнере или в запуске по расписанию, подключайте Claude Code [токеном в заголовке](#token-v-zagolovke). Сохраните настройки сервера в файл вне репозитория:

```json title="pachca-mcp.json"
{
  "mcpServers": {
    "pachca": {
      "type": "http",
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer ${PACHCA_TOKEN}"
      }
    }
  }
}
```

Передайте файл флагом `--mcp-config`. Claude Code подставит значение [переменной](#peremennaya-okruzheniya) `PACHCA_TOKEN` при запуске, и токен не попадёт в файл:

```bash
claude --strict-mcp-config --mcp-config pachca-mcp.json --allowedTools "mcp__pachca" -p "Найди в Пачке обсуждение релиза 2.4 и перескажи решения"
```

Флаг `--strict-mcp-config` отключает остальные серверы, в том числе сервер плагина. Просьбу к агенту указывайте после `-p`: флаг `--mcp-config` принимает несколько файлов. Флаг `--allowedTools "mcp__pachca"` разрешает инструменты Пачки без вопросов: в запуске с `-p` подтвердить вызов некому. Что агенту можно делать, ограничивают права токена. Чтобы проверить подключение, выполните ту же команду с просьбой «Покажи мой профиль в Пачке».

<Warning>Не кладите сервер с заголовком `Authorization` в `.mcp.json` репозитория. У каждого, кто откроет проект, Claude Code подключится через него вместо входа через браузер и вместо сервера плагина, а без переменной `PACHCA_TOKEN` не подключится вовсе.</Warning>

На компьютере без браузера, например по SSH, токен не нужен: войдите командой `claude mcp login`, как в разделе [Claude Code](#claude-code).

### Codex с токеном

В CI, в контейнере и везде, где входить некому, подключите Codex [персональным токеном](#token-v-zagolovke). Сохраните токен в [переменной окружения](#peremennaya-okruzheniya) `PACHCA_TOKEN` и добавьте сервер:

```bash
codex mcp add pachca --url https://mcp.pachca.com/mcp --bearer-token-env-var PACHCA_TOKEN
codex mcp list
```

С флагом `--bearer-token-env-var` Codex не открывает вход через браузер. В файл `~/.codex/config.toml` попадает только имя переменной, токен Codex читает из окружения при каждом запуске сервера. Вторая команда проверяет подключение: она покажет у сервера `pachca` способ входа `Bearer token`.

Codex в приложении ChatGPT и в редакторе, если их открыли не из терминала, может не видеть переменную из профиля оболочки. Тогда запишите токен прямо в `~/.codex/config.toml`: в разделе `[mcp_servers.pachca]` замените строку `bearer_token_env_var = "PACHCA_TOKEN"` на `http_headers = { Authorization = "Bearer <токен>" }`. Файл лежит в домашней папке и в репозиторий не попадает.

### Агент только для чтения

Чтобы агент мог только читать, создайте для него отдельный персональный токен с правами на чтение и поиск. Готовый набор для такого агента — в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi). Список инструментов от этого не изменится, но вызовы, которые меняют данные, получат отказ с кодом `insufficient_scope`.

### Несколько пространств

Одно подключение работает с одним пространством. Чтобы агент работал с несколькими, добавьте сервер в программу несколько раз под разными именами, например `pachca-main` и `pachca-partner`, и в каждом укажите персональный токен, созданный в нужном пространстве. Если программа берёт токен из переменной окружения, заведите для каждого пространства свою переменную, например `PACHCA_TOKEN_MAIN` и `PACHCA_TOKEN_PARTNER`.

## Токен бота

Агенту, который отвечает другим сотрудникам или работает как общий сервис, например на сервере или в [Yandex AI Studio](#yandex-ai-studio), подойдёт токен бота. Подключение такое же, как [с персональным токеном](#token-v-zagolovke), только в заголовке токен бота.

Агент в Yandex AI Studio или на GigaChat обычно работает на сервере и отвечает всем, кто к нему обращается. С персональным токеном каждый собеседник агента действовал бы от вашего имени, поэтому подключайте такого агента токеном бота.

С токеном бота агент действует от имени бота: видит открытые беседы и каналы пространства и чаты, куда бота добавили, а сообщения пишет от его имени. Набор инструментов у него свой, какой — в разделе [Какие инструменты получает программа](/guides/mcp/tools#kakie-instrumenty-poluchaet-programma). Где взять токен — в разделе [Токены бота](/guides/bots/tokens), что бот видит — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).

### Yandex AI Studio

Нужны роли на каталог Yandex Cloud:

- `serverless.mcpGateways.editor` и `iam.serviceAccounts.user`, чтобы создать сервер
- `serverless.mcpGateways.invoker` и `serverless.mcpGateways.anonymousInvoker`, чтобы агент вызывал сервер
- `ai.canvasAgents.editor`, чтобы собрать агента

<Warning>Не включайте **Сделать MCP-сервер публичным**: инструменты Пачки с токеном бота сможет вызвать любой, кто знает адрес сервера.</Warning>

1. В AI Studio выберите каталог Yandex Cloud, откройте **Agent Atelier** > **MCP-серверы**, нажмите **Создать MCP-сервер** и выберите **Внешний MCP-сервер**.
2. Укажите имя сервера, например `pachca`, и нажмите **Создать**. Имя должно быть длиной от 3 до 63 символов, начинаться с буквы и не заканчиваться дефисом, в нём допустимы строчные латинские буквы, цифры и дефисы.
3. В поле **URL** укажите адрес `https://mcp.pachca.com/mcp` и выберите транспорт **Streamable HTTP**.
4. В поле **Тип авторизации** выберите **Токен доступа** и добавьте заголовок `Authorization` со значением `Bearer <токен бота>`.
5. Нажмите **Подключиться** и в списке **Инструменты** отметьте только те, что нужны агенту. Нажмите **Сохранить**. Список инструментов появляется, только когда сервер подключился, поэтому он же проверяет подключение.
6. Откройте **Agent Atelier** > **Текстовые агенты**, создайте агента или откройте существующего. В поле **MCP-серверы** выберите сервер Пачки и нажмите **Сохранить версию**.

Если агента вызывают через Responses API, а он меняет данные, укажите для сервера Пачки `"require_approval": "always"`: каждый вызов инструмента будет ждать подтверждения. Скиллы Пачки подключаются в том же окне агента, в поле **Навыки**. Подробнее — в разделе [Yandex AI Studio и GigaChat](/guides/ai-agents/skills#yandex-ai-studio-i-gigachat).

### Агент на GigaChat

Агента на GigaChat собирают в коде на [GigaChain](https://github.com/ai-forever/langchain-gigachat), библиотеках LangChain для GigaChat. Пачку подключает библиотека `langchain-mcp-adapters`:

```bash
pip install langchain langchain-gigachat langchain-mcp-adapters
```

Перед запуском задайте переменные окружения:

- `PACHCA_BOT_TOKEN` — токен бота Пачки
- `GIGACHAT_CREDENTIALS` — ключ авторизации GigaChat
- `GIGACHAT_SCOPE` — версия API GigaChat, для компании `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`
- `GIGACHAT_CA_BUNDLE_FILE` — путь к корневому сертификату Минцифры, если он не установлен в системе: без него запрос к GigaChat не пройдёт проверку SSL

```python title="agent.py"
import asyncio
import os

from langchain.agents import create_agent
from langchain_gigachat import GigaChat
from langchain_mcp_adapters.client import MultiServerMCPClient


async def main():
    client = MultiServerMCPClient(
        {
            "pachca": {
                "transport": "http",
                "url": "https://mcp.pachca.com/mcp",
                "headers": {"Authorization": f"Bearer {os.environ['PACHCA_BOT_TOKEN']}"},
            }
        }
    )
    # Только нужные агенту инструменты: так он тратит меньше контекста
    needed = {"pachca_search_messages", "pachca_get_thread", "pachca_list_chat_messages"}
    tools = [tool for tool in await client.get_tools() if tool.name in needed]

    # Ключ, версия API и сертификат GigaChat берутся из переменных окружения
    agent = create_agent(GigaChat(model="GigaChat-2-Max"), tools)
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "Найди обсуждение релиза 2.4 и коротко перескажи решения"}]}
    )
    print(result["messages"][-1].content)


asyncio.run(main())
```

Запустите `python agent.py`: если скрипт напечатал пересказ, агент подключился к Пачке. Как передать агенту скилл Пачки — в разделе [Yandex AI Studio и GigaChat](/guides/ai-agents/skills#yandex-ai-studio-i-gigachat).

## Способы подключения

Программа подключается к серверу одним из трёх способов. Чем отличаются типы токенов в целом — в разделе [Какой токен выбрать](/api/authorization#kakoy-token-vybrat).

| | [Через браузер](#vhod-cherez-brauzer) | [Персональный токен](#token-v-zagolovke) | [Токен бота](#token-bota) |
|---|---|---|---|
| Когда подходит | программа умеет входить в Пачку через браузер | программа не входит через браузер или входить некому, а агент действует от вашего имени | агент отвечает другим сотрудникам или работает как общий сервис |
| От чьего имени | сотрудника, который подтвердил вход | владельца токена | бота |
| Как подключить | программа открывает экран согласия Пачки | токен в заголовке `Authorization` | токен в заголовке `Authorization` |
| Права | те, что попросила программа, обычно весь каталог | выбранные при создании токена | права токена бота |
| Срок | час, продлевается сам | бессрочный | бессрочный |
| Как выглядят сообщения | от вашего имени, со значком программы на аватаре | от вашего имени, со значком «Отправлено через API» на аватаре | от имени бота |
| Где видно и как отключить | список **Авторизации** на странице **API** | удалить токен на странице **API** | удалить токен на вкладке **API** в карточке бота |
| Что видит Администратор на вкладке **Все токены** | строку с типом «Клиент MCP» | обычный персональный токен | ничего: токены бота на вкладке **API** в его карточке |

Как подписаны сообщения агента — в разделе [Как выглядят сообщения](/api/authorization#kak-vyglyadyat-soobscheniya).

Через браузер подключаются программы, которые поддерживают стандартный вход OAuth с документом клиента (Client ID Metadata Document): программа публикует на своём домене документ с именем и адресами возврата, поэтому регистрировать её в Пачке не нужно. Вход идёт без секрета клиента: в документе не должно быть `client_secret`, а поле `token_endpoint_auth_method` должно быть пустым или равным `none`. Другой способ в этом поле подходит, только если это не `client_secret_basic` и не `client_secret_post`, а в списке `token_endpoint_auth_methods_supported` есть `none`. Остальные программы, а также те, у которых вход с Пачкой пока не работает или не проверен, подключаются токеном в заголовке.

## Вход через браузер

Программа, которая входит в Пачку через браузер, открывает экран согласия: страницу Пачки, на которой вы разрешаете программе действовать от вашего имени.

<ImageCard src="/images/mcp/mcp-consent.webp" alt="Экран согласия при подключении Claude Code: «Авторизовать Claude Code?», домен claude.ai, пространство и почта сотрудника, запрашиваемые разрешения в свёрнутых категориях с числом прав, предупреждение и кнопки «Отменить» и «Разрешить»" caption="Экран согласия для программы с MCP" maxWidth={500} />

На экране согласия проверьте:

- имя программы из её документа клиента и под ним домен, на котором программа опубликовала этот документ, например `claude.ai`
- пространство и вашу почту: доступ выдаётся в пространство, которое сейчас открыто в браузере
- **Запрашиваемые разрешения** в свёрнутых категориях с числом прав в каждой: обычно это весь каталог, и убрать отдельные права на экране нельзя
- предупреждение, если программа возвращает браузер на этот же компьютер: «Разрешайте, только если вы сами сейчас подключаете … на этом компьютере»

Каждый вызов при этом проверяется по вашей текущей роли, поэтому агент может только то, что можете вы. Подробнее — в разделе [Токен и смена роли](/guides/permissions#token-i-smena-roli). Что ещё видно на экране согласия — в разделе [Экран согласия](/guides/oauth/consent#ekran-soglasiya).

<Info>Выбора пространства на экране согласия нет. Чтобы подключить другое пространство, переключитесь на него в Пачке и подключитесь снова. Как работать с несколькими пространствами сразу — в разделе [Несколько пространств](#neskolko-prostranstv).</Info>

Программа получает токен на час и продлевает его сама, входить заново не нужно. У каждого подключения свой токен: Claude Code на двух компьютерах — два подключения.

## Токен в заголовке

Если программа не входит в Пачку через браузер или входить некому, например в CI, подключите её токеном в заголовке `Authorization`: в этом поле запроса программа передаёт токен серверу. Шаги ниже для персонального токена, [токен бота](#token-bota) подключается так же.

1. Создайте персональный токен на странице **Интеграции** > **API** и выберите права, которые нужны агенту. Готовые наборы для агента, который читает и пишет или только читает, собраны в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi). Как создать токен — в разделе [Создание персонального токена](/api/authorization#sozdanie-personalnogo-tokena). Если страница **API** показывает «Доступ к API ограничен», попросите Администратора открыть доступ, как в разделе [Кто может подключить](#kto-mozhet-podklyuchit).
2. Сохраните токен в [переменной окружения](#peremennaya-okruzheniya) `PACHCA_TOKEN`.
3. Укажите в настройках программы адрес сервера и заголовок `Authorization: Bearer <токен>`. Ссылку на переменную каждая программа записывает по-своему, примеры — в разделе [Программы](#programmy). Некоторые программы сохраняют сам токен в своих настройках в домашней папке, тогда переменная им не нужна. Где в примере стоит `<токен>`, вставьте токен в файл сами, агенту в чат его не отправляйте. Файлы настроек, в которых лежит сам токен, агент не открывает и не выводит: подключение он проверяет просьбой «Покажи мой профиль в Пачке».
4. Полностью закройте программу и откройте снова: в macOS сочетанием ⌘Q. CLI запустите из нового окна терминала.
5. Проверьте подключение: попросите агента «Покажи мой профиль в Пачке». Если инструментов Пачки нет или сервер отвечает `401`, программа не видит токен.

<Warning>Персональный токен бессрочный и действует от вашего имени: сообщения агента с ним уходят под вашим именем. Выдавайте токену только нужные права и не кладите его в файлы, которые попадают в репозиторий. Когда токен больше не нужен, удалите его на странице **API**.</Warning>

### Переменная окружения

Переменная окружения — значение, которое система передаёт программам при запуске. Так токен не попадает в файлы настроек.

В macOS и Linux добавьте строку в профиль оболочки — файл, который терминал читает при запуске: `~/.zshrc` в macOS, `~/.bashrc` в большинстве дистрибутивов Linux.

```bash title="~/.zshrc"
export PACHCA_TOKEN="<токен>"
```

В Windows выполните команду в PowerShell или в командной строке. Она сохранит переменную для вашей учётной записи:

```text title="PowerShell"
setx PACHCA_TOKEN "<токен>"
```

То же можно сделать в окне **Переменные среды**: найдите «переменные среды» в меню **Пуск** и добавьте переменную пользователя `PACHCA_TOKEN`.

Проверьте, что переменная задана: откройте новое окно терминала и выполните `echo $PACHCA_TOKEN` в macOS и Linux, `echo $env:PACHCA_TOKEN` в PowerShell или `echo %PACHCA_TOKEN%` в командной строке Windows. Команда должна вывести токен. Агенту эту проверку не поручайте: она выведет токен в его чат. Агент проверяет переменную, не выводя значения: `[ -n "$PACHCA_TOKEN" ] && echo задана || echo нет` в macOS и Linux, `if ($env:PACHCA_TOKEN) { 'задана' } else { 'нет' }` в PowerShell, `if defined PACHCA_TOKEN (echo yes) else (echo no)` в командной строке Windows. Команды агента видят только переменные, которые были у программы при её запуске. В Windows сохранённую переменную агент проверяет и до перезапуска программы: `if ([Environment]::GetEnvironmentVariable('PACHCA_TOKEN', 'User')) { 'сохранена' } else { 'нет' }` в PowerShell. Если агент переменную не видит, а вы её задали, перезапустите программу, как сказано ниже, а новый токен не создавайте.

Затем закройте программу полностью и откройте снова: в macOS сочетанием ⌘Q, потому что после закрытия окон программа продолжает работать. Уже запущенная программа новую переменную не увидит, а CLI видит её только в новом окне терминала. Если программа, открытая не из терминала, всё равно не видит токен, запустите её из терминала или замените в её настройках в домашней папке ссылку на переменную самим токеном: например, в `~/.cursor/mcp.json` вместо `Bearer ${env:PACHCA_TOKEN}` укажите `Bearer <токен>`. Токен в файл вставьте сами, агенту это не поручайте. Для Codex это описано в разделе [Codex с токеном](#codex-s-tokenom).

## Управление подключениями

Подключения через браузер собраны в списке **Авторизации** на странице **Интеграции** > **API**: там видны разрешения каждой программы и меню, которое отзывает доступ. Подробнее о списке — в разделе [Токены CLI и авторизации](/api/authorization#tokeny-cli-i-avtorizatsii).

<ImageCard src="/images/mcp/mcp-authorizations.webp" alt="Список «Авторизации» на странице «API»: подпись со ссылками на документацию, клиент MCP Claude Code с доменом claude.ai и бот «Jira-карточки», даты подключения, последнее использование и число разрешений" caption="Программа с MCP в списке «Авторизации»" maxWidth={832} />

**Отозвать доступ** сразу отключает все подключения этой программы, которые вы выдали: следующий вызов получит `401`. Чужие подключения той же программы это не затрагивает.

Новые права Пачки программа получает, когда вы снова входите через браузер и подтверждаете их на экране согласия: после отзыва доступа или по команде входа, например `/mcp` в Claude Code. Перезапуск программы и продление токена прав не добавляют. Если в пространстве сотрудникам не разрешено выдавать доступ к API, войти снова сотрудник не сможет, и после отзыва программа останется без подключения.

Администратор видит подключения через браузер у каждого сотрудника строкой «Клиент MCP» на вкладке [Все токены](/api/authorization#vse-tokeny-prostranstva) и может их отозвать. Агент на персональном токене выглядит там обычным персональным токеном, а токены ботов видны только на вкладке **API** в карточке бота, поэтому по списку отличить агента от скрипта нельзя.

Подключение токеном в заголовке живёт, пока жив токен: удалите персональный токен на странице **API** или токен бота на вкладке **API** в карточке бота.

## Если что-то не работает

| Что видно | Причина и что делать |
|---|---|
| «Доступ к API ограничен администраторами пространства» на экране согласия | Сотрудникам в пространстве не разрешено выдавать доступ к API. Попросите Администратора открыть доступ, как в разделе [Кто может подключить](#kto-mozhet-podklyuchit). |
| «Гостям доступ к API не выдаётся» | Гость не может подключить MCP. Нужна другая роль в пространстве. |
| Программа предлагает войти, но вход не проходит или просит зарегистрировать клиента | Вход через браузер с Пачкой в этой программе не работает. Подключите её [токеном в заголовке](#token-v-zagolovke). Если Cursor просит войти, хотя токен в настройках указан, он не видит переменную `PACHCA_TOKEN`: проверьте [переменную](#peremennaya-okruzheniya) и перезапустите Cursor. Подробности ошибки — в панели **Output** (`Cmd+Shift+U` или `Ctrl+Shift+U`) в разделе **MCP Logs**. |
| `401` | Токена нет, он истёк или отозван. Подключитесь заново: в Claude Code — командой `/mcp`. С токеном в заголовке проверьте, что токен не удалён и что программа видит переменную `PACHCA_TOKEN`: задайте её и перезапустите программу. Если сервер добавили командой с `$PACHCA_TOKEN`, когда переменной ещё не было, в настройках сохранился пустой токен: удалите сервер и добавьте снова. |
| `MCP endpoint not found` в Claude Code | Адрес сервера указан неверно. Проверьте командой `claude mcp get pachca`, что адрес ровно `https://mcp.pachca.com/mcp`. |
| Программа не подключается по адресу `dev.pachca.com/mcp` | Это короткий адрес документации о MCP. Сервер работает по адресу `https://mcp.pachca.com/mcp`, его и укажите в программе. |
| В Claude Code нет сервера `plugin:pachca:pachca`, хотя плагин стоит | Сервер с тем же адресом добавлен вручную и заменяет сервер плагина. Найдите его в списке `claude mcp list` и удалите командой `claude mcp remove` с его именем или работайте через него. |
| `403` с кодом `access_denied` при подключении | Доступ владельца токена к пространству приостановлен, или сотрудник удалён. Подробнее — в разделе [Токен и смена роли](/guides/permissions#token-i-smena-roli). |
| Отказ с кодом `insufficient_scope` | У токена нет нужного права, и повтор вызова не поможет. Персональному токену добавьте право в меню токена на странице **API**, токену бота — на вкладке **API** в карточке бота. Подключению через браузер права задаёт программа при входе, экран согласия их только показывает: войдите снова, не ограничивая права, например без флага `--scopes` в Codex. Подробнее — в разделе [Ошибки авторизации](/api/authorization#oshibki-avtorizatsii). |
| Отказ с кодом `role_forbidden` | Право есть, но ваша роль не позволяет действие. Это правило пространства, повторное подключение не поможет. |
| Отказ с кодом `payment_required` | Пространство превысило лимит сообщений тарифа: пока его не оплатят, большинство методов отвечают отказом. Подробнее — в разделе [Ошибки](/api/errors). |
| Агент не может отправить файл с диска | Не каждая программа даёт агенту загрузить файл с диска, например чат Claude этого не позволяет. Подробнее — в разделе [Как агент отправляет файл](/guides/mcp/tools#kak-agent-otpravlyaet-fayl). |
| В программе нет нужного инструмента | Список зависит от роли, тарифа и типа токена. Какой инструмент кому доступен — в разделе [Инструменты MCP](/guides/mcp/tools). |
| Codex при входе отвечает `Dynamic client registration not supported` | Codex старше 0.148.0 не умеет входить в Пачку через браузер. Обновите Codex или подключите его [персональным токеном](#codex-s-tokenom). |
| Отказ «Wait N s before repeating» или `429` | Превышен предел вызовов. Подождите указанное время. Подробнее — в разделе [Пределы](/guides/mcp/overview#predely). |
| Подключилось не то пространство | Доступ выдаётся в пространство, открытое в браузере. Отзовите подключение, переключитесь на нужное пространство и подключитесь снова. |
