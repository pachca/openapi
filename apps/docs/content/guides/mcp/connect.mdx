# Подключение к MCP

MCP (Model Context Protocol) — протокол, по которому программа с AI-агентом получает инструменты Пачки: агент читает чаты и треды, ищет обсуждения, отправляет сообщения и ставит задачи. Сервер Пачки работает по адресу `https://mcp.pachca.com/mcp`. Что он умеет — в разделе [MCP-сервер](/guides/mcp/overview).

## Какой путь выбрать

Найдите свою программу в таблице и подключите её рекомендуемым путём. [Плагин «Пачка»](/guides/mcp/plugin) одной установкой подключает сервер и добавляет скиллы и команды: скиллы подсказывают агенту, как правильно работать в Пачке, а команды запускают готовые задачи, например сводку пропущенного.

| Программа | Рекомендуемый путь | Вход в Пачку |
|---|---|---|
| Claude Code | [плагин «Пачка»](/guides/mcp/plugin#claude-code) | через браузер |
| Приложение Claude на тарифах Pro и Max | [плагин «Пачка»](/guides/mcp/plugin#prilozhenie-claude) | через браузер |
| Приложение Claude на тарифах Team и Enterprise | [коннектор](#claude) от владельца организации Claude, затем плагин | через браузер |
| Приложение Claude на тарифе Free | [коннектор](#claude) | через браузер |
| Codex CLI и Codex в приложении ChatGPT на компьютере | [плагин «Пачка»](/guides/mcp/plugin#codex) | через браузер |
| Расширение Codex для редактора | [сервер](#codex) и [скиллы без плагина](/guides/mcp/plugin#skilly-bez-plagina) | через браузер |
| VS Code с GitHub Copilot и GitHub Copilot CLI | [плагин «Пачка»](/guides/mcp/plugin#vs-code-i-github-copilot) | через браузер |
| Cursor | [плагин «Пачка»](/guides/mcp/plugin#cursor) | персональный токен |
| SourceCraft Code Assistant, Qwen Code, GigaCode CLI, OpenCode, Devin Desktop, Cline, Kilo Code, Gemini CLI и другие программы | сервер по инструкции для программы ниже и [скиллы без плагина](/guides/mcp/plugin#skilly-bez-plagina) | персональный токен |
| Запуск, где входить некому: автоматические сборки и проверки (CI), контейнер, задача по расписанию | [Claude Code без браузера](#claude-code-bez-brauzera) или [Codex с токеном](#codex-s-tokenom) | персональный токен |
| Агент в Yandex AI Studio или на GigaChat | [сервер с токеном бота](#token-bota) и [скиллы](/guides/mcp/plugin#yandex-ai-studio-i-gigachat) | токен бота |

Плагин подключает тот же сервер, поэтому ставьте что-то одно: плагин или сервер вручную. В Claude Code сервер Пачки, добавленный вручную, заменяет сервер плагина, а в Cursor рядом с плагином он лишний, поэтому перед установкой плагина удалите его. Как плагин уживается с ручным сервером в остальных программах, сказано в разделе программы.

Примеры просьб к агенту после подключения собраны в разделе [Что можно попросить агента](/guides/mcp/overview#chto-mozhno-poprosit-agenta). Описания всех инструментов занимают заметную часть контекста модели, поэтому, если программа позволяет, отключите инструменты, которые агенту не нужны. Подробнее — в разделе [Пределы](/guides/mcp/overview#predely).

## Кто может подключить

Подключиться может владелец, администратор, сотрудник и мульти-гость. Гость с API не работает, поэтому подключить MCP он не может. Подробнее — в разделе [Роли в пространстве](/guides/permissions#roli-v-prostranstve).

Отдельного выключателя MCP нет: MCP работает на тех же токенах, что API и CLI. Вход через браузер и персональный токен разрешает настройка пространства **Кто может создавать персональные токены**, а токен бота — настройка **Кто может создавать интеграции**. По умолчанию персональные токены и вход через браузер есть только у администраторов, а ботов создают и сотрудники. Смена настройки закрывает только новый доступ: подключения и токены, выданные до неё, работают, пока их не отзовут. Подробнее о настройках и об отзыве выданного — в разделе [Кто может создавать токены](/api/authorization#kto-mozhet-sozdavat-tokeny).

Если на экране согласия видно «Доступ к API ограничен администраторами пространства», попросите Администратора открыть **Настройки пространства** > **Общие настройки** и выбрать **Все сотрудники** в пункте **Кто может создавать персональные токены**. Как администратору управлять доступом агентов — на странице [Агенты и MCP в пространстве](/guides/agents-access).

## Способы подключения

Программа подключается к серверу одним из трёх способов. Чем отличаются типы токенов в целом — в разделе [Какой токен выбрать](/api/authorization#kakoy-token-vybrat).

| | [Через браузер](#vhod-cherez-brauzer) | [Персональный токен](#token-v-zagolovke) | [Токен бота](#token-bota) |
|---|---|---|---|
| Когда подходит | программа умеет входить в Пачку через браузер | программа не входит через браузер или входить некому | агент работает без участия сотрудника |
| От чьего имени | сотрудника, который подтвердил вход | владельца токена | бота |
| Как подключить | программа открывает экран согласия Пачки | токен в заголовке `Authorization` | токен в заголовке `Authorization` |
| Права | те, что попросила программа, обычно весь каталог | выбранные при создании токена | права токена бота |
| Срок | час, продлевается сам | бессрочный | бессрочный |
| Как выглядят сообщения | от вашего имени, с иконкой программы на аватаре | как написанные вами вручную | от имени бота |
| Где видно и как отключить | список **Авторизации** на странице **API** | удалить токен на странице **API** | токены бота в его настройках |
| Что видит Администратор на вкладке **Все токены** | строку с типом «Клиент MCP» | обычный персональный токен | ничего: токены бота собраны в его карточке |

Экран согласия — страница Пачки, на которой вы разрешаете программе действовать от вашего имени. Заголовок `Authorization` — поле запроса, в котором программа передаёт токен серверу. Как подписаны сообщения агента — в разделе [Безопасность](/guides/mcp/overview#bezopasnost).

Через браузер подключаются программы, которые поддерживают стандартный вход OAuth с документом клиента (Client ID Metadata Document): программа публикует на своём домене документ с именем и адресами возврата, поэтому регистрировать её в Пачке не нужно. Остальные программы, а также те, у которых вход с Пачкой пока не работает или не проверен, подключаются токеном в заголовке.

## Вход через браузер

<Steps>
  <Step title="Подключите сервер">
    Поставьте плагин «Пачка» или добавьте в программу адрес `https://mcp.pachca.com/mcp`, команды для каждой программы — ниже. Регистрировать программу в Пачке заранее не нужно.
  </Step>
  <Step title="Войдите">
    Программа откроет страницу Пачки в браузере. Если вы не вошли в Пачку, сначала появится обычный вход.
  </Step>
  <Step title="Подтвердите доступ">
    На экране согласия проверьте имя программы, её домен и пространство и нажмите **Разрешить**. Браузер вернёт вас в программу, и инструменты Пачки появятся в ней.
  </Step>
  <Step title="Проверьте подключение">
    Попросите агента: «Покажи мой профиль в Пачке». Он вызовет `pachca_get_my_card` и ответит вашим именем и ролью.
  </Step>
</Steps>

<ImageCard src="/images/mcp/mcp-consent.webp" alt="Экран согласия при подключении Claude Code: «Авторизовать Claude Code?», домен claude.ai, пространство и почта сотрудника, начало списка запрашиваемых разрешений" caption="Экран согласия для программы с MCP" maxWidth={500} />

На экране согласия проверьте:

- имя программы из её документа клиента и под ним домен, на котором программа опубликовала этот документ, например `claude.ai`
- пространство: доступ выдаётся в пространство, которое сейчас открыто в браузере
- предупреждение, если программа возвращает браузер на этот же компьютер: «Разрешайте, только если вы сами сейчас подключаете … на этом компьютере»

Программа обычно просит весь каталог прав, но каждый вызов проверяется по вашей текущей роли, поэтому агент может только то, что можете вы. Подробнее — в разделе [Токен и смена роли](/guides/permissions#token-i-smena-roli). Что ещё видно на экране согласия — в разделе [Экран согласия](/guides/oauth/consent#ekran-soglasiya).

<Info>Выбора пространства на экране согласия нет. Чтобы подключить другое пространство, переключитесь на него в Пачке и подключитесь снова. Как работать с несколькими пространствами сразу — в разделе [Несколько пространств](#neskolko-prostranstv).</Info>

Программа получает токен на час и продлевает его сама, входить заново не нужно. У каждого подключения свой токен: Claude Code на двух компьютерах — два подключения.

### Claude Code

Рекомендуемый путь — [плагин «Пачка»](/guides/mcp/plugin#claude-code): он ставит сервер вместе со скиллами и командами. После установки выполните `/mcp`, выберите сервер Пачки из плагина и войдите. Из терминала вход начинает команда:

```bash
claude mcp login plugin:pachca:pachca
```

Сервер плагина называется `plugin:pachca:pachca`, команда `claude mcp login pachca` его не найдёт.

Без плагина добавьте сервер:

```bash
claude mcp add --transport http pachca https://mcp.pachca.com/mcp
```

Затем запустите Claude Code, выполните команду `/mcp`, выберите сервер `pachca` и войдите. Из терминала то же делает команда `claude mcp login pachca`. Сервер добавляется в текущий проект. Чтобы он был во всех проектах, добавьте к `claude mcp add` флаг `--scope user`.

Сервер с тем же адресом, добавленный вручную, заменяет сервер плагина. Если позже решите поставить плагин, сначала удалите ручной сервер командой `claude mcp remove pachca`.

Если браузер не открывается, например в сессии по SSH, команда `claude mcp login` сама покажет ссылку, а флаг `--no-browser` включает это принудительно. Подключайтесь по `ssh -t`, откройте ссылку на своём компьютере и нажмите **Разрешить**. Когда команда попросит, вставьте в терминал адрес из строки браузера.

Проверьте подключение: в списке `/mcp` сервер Пачки должен быть подключён, а на просьбу «Покажи мой профиль в Пачке» агент должен ответить вашим именем и ролью.

### Claude

Подключённый MCP-сервер Claude называет коннектором. Путь зависит от тарифа Claude:

- **Pro и Max** — поставьте [плагин «Пачка»](/guides/mcp/plugin#prilozhenie-claude). Он даёт скиллы, а коннектор Пачки добавляется с его вкладки **Connectors**, поэтому отдельно коннектор не добавляйте.
- **Free** — добавьте коннектор по шагам ниже. Плагинов на этом тарифе нет.
- **Team и Enterprise** — владелец организации Claude добавляет коннектор по шагам ниже. Затем сотрудники ставят плагин и входят в Пачку под своей учётной записью.

Шаги коннектора:

1. В приложении Claude или на claude.ai откройте **Customize** > **Connectors** и нажмите **Add** > **Add custom connector**.
2. Укажите название, например «Пачка», и адрес `https://mcp.pachca.com/mcp`, затем нажмите **Continue**.
3. Проверьте настройки входа, которые нашёл Claude, и нажмите **Continue**.
4. В **Authentication** выберите **Sign in now**, в **OAuth client** выберите **Use Claude's published identity** и нажмите **Add**. Вариант **Register automatically** с Пачкой не работает.
5. Нажмите **Connect** у нового коннектора и войдите.

На тарифе Free можно добавить один такой коннектор. Коннектор работает в чате на claude.ai, в приложении Claude на компьютере и телефоне и в Cowork.

На тарифах Team и Enterprise коннектор добавляет владелец организации Claude: **Organization settings** > **Connectors** > **Add** > **Custom** > **Web**, затем те же шаги. После этого каждый сотрудник нажимает **Connect** у коннектора Пачки на вкладке **Connectors** плагина или в **Customize** > **Connectors** и входит под своей учётной записью.

Claude подключается к Пачке через вход в браузере. Если в окне коннектора есть раздел **Request headers**, персональный токен туда не указывайте: заголовки общие для всей организации Claude, и все её сотрудники действовали бы в Пачке от вашего имени.

Коннектор появится и в Claude Code, если вы вошли в него через тот же аккаунт claude.ai, в том числе в облачных сессиях. Если в Claude Code стоит плагин «Пачка» или сервер с тем же адресом добавлен вручную, Claude Code работает через них, и в Пачку там нужно войти отдельно.

Проверьте подключение: в новом чате попросите «Покажи мой профиль в Пачке».

### VS Code и GitHub Copilot

Рекомендуемый путь — [плагин «Пачка»](/guides/mcp/plugin#vs-code-i-github-copilot): он подключает сервер, скиллы и команды, а сервер `pachca`, добавленный вручную, заменяет своим. Без плагина сервер быстрее всего добавляется по ссылке [Установить в VS Code](vscode:mcp/install?%7B%22name%22%3A%22pachca%22%2C%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Fmcp.pachca.com%2Fmcp%22%7D): VS Code добавит его и предложит войти при первом запуске сервера.

Чтобы сервер был во всех проектах, добавьте его командой GitHub Copilot CLI:

```bash
copilot mcp add --transport http pachca https://mcp.pachca.com/mcp
```

Команда запишет сервер в `~/.copilot/mcp-config.json`, этот файл читают и VS Code, и Copilot CLI. В VS Code то же делает команда **MCP: Add Server**: выберите **HTTP**, укажите адрес и имя `pachca`, затем **Global** > **Copilot Global**.

Для одного проекта добавьте сервер в файл `.mcp.json` в корне проекта. Этот же файл читает Claude Code.

```json title=".mcp.json"
{
  "mcpServers": {
    "pachca": {
      "type": "http",
      "url": "https://mcp.pachca.com/mcp"
    }
  }
}
```

VS Code предложит войти при первом запуске сервера. В Copilot CLI войдите командой `/mcp auth pachca`, вход через браузер работает в Copilot CLI 1.0.83 и новее. Сервер из `.mcp.json` проекта Copilot CLI подключает, только если вы доверяете папке. Файл `.vscode/mcp.json` с ключом `servers` тоже работает, но VS Code помечает его устаревшим.

Чтобы подключиться токеном, добавьте в сервер в файле `~/.copilot/mcp-config.json` поле `"headers": { "Authorization": "Bearer ${PACHCA_TOKEN}" }` и задайте [переменную](#peremennaya-okruzheniya) `PACHCA_TOKEN` в окружении, из которого запускается VS Code или Copilot CLI. Записи вида `${input:…}` и `${env:…}` в этом файле не работают. Если сервер записан в файл вручную без команды `copilot mcp add`, добавьте в него и `"tools": ["*"]`. В `.mcp.json` проекта сервер с заголовком `Authorization` не добавляйте: Claude Code у каждого, кто откроет проект, подключится через него вместо входа через браузер. Подробнее — в разделе [Claude Code без браузера](#claude-code-bez-brauzera).

Проверьте подключение: попросите агента в чате Copilot «Покажи мой профиль в Пачке».

### Codex

Рекомендуемый путь в Codex CLI и Codex в приложении ChatGPT на компьютере — [плагин «Пачка»](/guides/mcp/plugin#codex): после установки войдите командой `codex mcp login pachca`. Расширение Codex для редактора плагины не ставит, для него добавьте сервер вручную.

У Codex CLI, расширения Codex и приложения ChatGPT на компьютере подключение общее, его добавляет одна команда:

```bash
codex mcp add pachca --url https://mcp.pachca.com/mcp
```

Команда добавляет сервер и сразу открывает браузер для входа. Если вход прервался, повторите его:

```bash
codex mcp login pachca
```

На компьютере без браузера добавьте к этой команде флаг `--no-browser`: она покажет ссылку, а после подтверждения попросит вставить адрес, на который вернулся браузер.

Сервер с именем `pachca`, добавленный вручную, заменяет сервер плагина и работает так же, поэтому удалять его не нужно. Где входить некому, например в CI, подключите Codex [персональным токеном](#codex-s-tokenom).

Проверьте подключение: команда `codex mcp list` покажет сервер `pachca`, а на просьбу «Покажи мой профиль в Пачке» агент ответит вашим именем и ролью.

## Токен в заголовке

Если программа не входит в Пачку через браузер или входить некому, например в CI, подключите её токеном в заголовке. Шаги ниже для персонального токена, [токен бота](#token-bota) подключается так же.

1. Создайте персональный токен на странице **Интеграции** > **API** и выберите права, которые нужны агенту. Готовые наборы для агента, который читает и пишет или только читает, собраны в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi). Как создать токен — в разделе [Создание персонального токена](/api/authorization#sozdanie-personalnogo-tokena).
2. Сохраните токен в [переменной окружения](#peremennaya-okruzheniya) `PACHCA_TOKEN`.
3. Укажите в настройках программы адрес сервера и заголовок `Authorization: Bearer <токен>`. Ссылку на переменную каждая программа записывает по-своему, примеры ниже. Некоторые программы сохраняют сам токен в своих настройках в домашней папке, тогда переменная им не нужна.
4. Полностью закройте программу и откройте снова: переменные окружения программа читает при запуске.
5. Проверьте подключение: попросите агента «Покажи мой профиль в Пачке». Если инструментов Пачки нет или сервер отвечает `401`, программа не видит токен.

<Warning>Персональный токен бессрочный и действует от вашего имени: сообщения агента с ним выглядят как написанные вами вручную. Выдавайте токену только нужные права, храните его в переменной окружения и не кладите в файлы, которые попадают в репозиторий. Когда токен больше не нужен, удалите его на странице **API**.</Warning>

### Переменная окружения

Переменная окружения — значение, которое система передаёт программам при запуске. Так токен не попадает в файлы настроек.

В macOS и Linux добавьте строку в профиль оболочки — файл, который терминал читает при запуске: `~/.zshrc` в macOS, `~/.bashrc` в большинстве дистрибутивов Linux.

```bash title="~/.zshrc"
export PACHCA_TOKEN="<токен>"
```

В Windows выполните команду в PowerShell или в командной строке. Она сохранит переменную для вашей учётной записи:

```text title="PowerShell"
setx PACHCA_TOKEN "<токен>"
```

То же можно сделать в окне **Переменные среды**: найдите «переменные среды» в меню **Пуск** и добавьте переменную пользователя `PACHCA_TOKEN`.

Проверьте, что переменная задана: откройте новое окно терминала и выполните `echo $PACHCA_TOKEN` в macOS и Linux, `echo $env:PACHCA_TOKEN` в PowerShell или `echo %PACHCA_TOKEN%` в командной строке Windows. Команда должна вывести токен. Затем закройте все окна программы и откройте её снова: уже запущенная программа новую переменную не увидит. Если программа, открытая не из терминала, всё равно не видит токен, запустите её из терминала или запишите токен в её настройки, как в разделе программы.

### Cursor

Затем добавьте сервер по ссылке [Установить в Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=pachca&config=eyJ1cmwiOiJodHRwczovL21jcC5wYWNoY2EuY29tL21jcCIsImhlYWRlcnMiOnsiQXV0aG9yaXphdGlvbiI6IkJlYXJlciAke2VudjpQQUNIQ0FfVE9LRU59In19) или вручную: в `~/.cursor/mcp.json`, чтобы он был во всех проектах, или в `.cursor/mcp.json` проекта.

Облачные агенты Cursor переменные с вашего компьютера не видят: для них сервер задаётся в настройках облачных агентов.

### Devin Desktop

        "Authorization": "Bearer <токен>"

Devin Local подключает также серверы из `.mcp.json` проекта и из настроек Claude Code. Сервер Пачки без токена оттуда не подключится. Чтобы Devin не читал эти настройки, выключите `read_config_from.claude` в `~/.config/devin/config.json`.

У Cascade лимит 100 инструментов на все серверы, а Пачка даёт до 93: столько получает владелец на тарифе «Корпорация», остальные роли и токен бота получают меньше. Лишние инструменты отключите списком `disabledTools` в настройках сервера.

### Codex с токеном

В CI, в контейнере и везде, где входить некому, подключите Codex персональным токеном. Сохраните токен в переменной окружения `PACHCA_TOKEN` и добавьте сервер:

```bash
codex mcp add pachca --url https://mcp.pachca.com/mcp --bearer-token-env-var PACHCA_TOKEN
codex mcp list
```

С флагом `--bearer-token-env-var` Codex не открывает вход через браузер. В файл `~/.codex/config.toml` попадает только имя переменной, токен Codex читает из окружения при каждом запуске сервера. Вторая команда проверяет подключение: она покажет у сервера `pachca` способ входа `Bearer token`.

Приложение ChatGPT и редактор, запущенные не из терминала, могут не видеть переменную из профиля оболочки. Тогда запишите токен прямо в `~/.codex/config.toml`: в разделе `[mcp_servers.pachca]` замените строку `bearer_token_env_var = "PACHCA_TOKEN"` на `http_headers = { Authorization = "Bearer <токен>" }`. Файл лежит в домашней папке и в репозиторий не попадает.

Сервер с именем `pachca` заменяет сервер из [плагина «Пачка»](/guides/mcp/plugin#codex), скиллы и команды плагина при этом продолжают работать.

### Claude Code без браузера

Там, где входить некому, например в CI, в контейнере или в запуске по расписанию, подключайте Claude Code токеном. Сохраните настройки сервера в файл вне репозитория:

```json title="pachca-mcp.json"
{
  "mcpServers": {
    "pachca": {
      "type": "http",
      "url": "https://mcp.pachca.com/mcp",
      "headers": {
        "Authorization": "Bearer ${PACHCA_TOKEN}"
      }
    }
  }
}
```

Передайте файл флагом `--mcp-config`. Claude Code подставит значение переменной при запуске, и токен не попадёт в файл:

```bash
claude --strict-mcp-config --mcp-config pachca-mcp.json --allowedTools "mcp__pachca" -p "Найди в Пачке обсуждение релиза 2.4 и перескажи решения"
```

Флаг `--strict-mcp-config` отключает остальные серверы, в том числе сервер плагина. Промпт указывайте после `-p`: флаг `--mcp-config` принимает несколько файлов. Флаг `--allowedTools "mcp__pachca"` разрешает инструменты Пачки без вопросов: в запуске с `-p` подтвердить вызов некому. Что агенту можно делать, ограничивают права токена. Чтобы проверить подключение, выполните ту же команду с промптом «Покажи мой профиль в Пачке».

<Warning>Не кладите сервер с заголовком `Authorization` в `.mcp.json` репозитория. У каждого, кто откроет проект, он заменит сервер плагина с входом через браузер, а без переменной `PACHCA_TOKEN` не подключится вовсе.</Warning>

На компьютере без браузера, например по SSH, токен не нужен: войдите командой `claude mcp login`, как в разделе [Claude Code](#claude-code).

### Другие программы и платформы

Укажите адрес `https://mcp.pachca.com/mcp`, транспорт Streamable HTTP (иногда он называется HTTP) и заголовок `Authorization` со значением `Bearer <токен>`. Если программа принимает настройки в JSON, они обычно выглядят так:

```json
{
  "pachca": {
    "url": "https://mcp.pachca.com/mcp",
    "headers": {
      "Authorization": "Bearer <токен>"
    }
  }
}
```

Проверьте, как в программе называется поле адреса для Streamable HTTP. В некоторых программах поле `url` означает транспорт SSE, а для Streamable HTTP есть отдельное поле, например `httpUrl` в [Qwen Code и GigaCode CLI](#qwen-code-i-gigacode-cli).

Если программа подключает только локальные серверы (stdio), то есть сама запускает сервер на вашем компьютере, запустите сервер через мост [mcp-remote](https://github.com/geelen/mcp-remote): он передаёт вызовы на адрес Пачки с вашим токеном.

```json
{
  "mcpServers": {
    "pachca": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://mcp.pachca.com/mcp",
        "--header",
        "Authorization:${PACHCA_AUTH_HEADER}"
      ],
      "env": {
        "PACHCA_AUTH_HEADER": "Bearer <токен>"
      }
    }
  }
}
```

Пробела в аргументе `Authorization:${PACHCA_AUTH_HEADER}` нет намеренно: Cursor, Codex и приложение Claude в Windows портят аргументы с пробелами, а в значении переменной пробел допустим.

Проверьте подключение: попросите агента «Покажи мой профиль в Пачке».

### Агент только для чтения

Чтобы агент мог только читать, создайте для него отдельный персональный токен с правами на чтение и поиск. Готовый набор для такого агента — в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi). Список инструментов от этого не изменится, но вызовы, которые меняют данные, получат отказ с кодом `insufficient_scope`.

### Несколько пространств

Одно подключение работает с одним пространством. Чтобы агент работал с несколькими, добавьте сервер в программу несколько раз под разными именами, например `pachca-main` и `pachca-partner`, и в каждом укажите персональный токен, созданный в нужном пространстве. Если программа берёт токен из переменной окружения, заведите для каждого пространства свою переменную, например `PACHCA_TOKEN_MAIN` и `PACHCA_TOKEN_PARTNER`.

## Токен бота

Агенту, который работает без участия сотрудника, например на сервере или в [Yandex AI Studio](#yandex-ai-studio), подойдёт токен бота. Подключение такое же, как [с персональным токеном](#token-v-zagolovke), только в заголовке токен бота.

Агент в Yandex AI Studio или на GigaChat обычно работает на сервере и отвечает всем, кто к нему обращается. С персональным токеном каждый собеседник агента действовал бы от вашего имени, поэтому подключайте такого агента токеном бота.

С токеном бота агент действует от имени бота: видит открытые беседы и каналы пространства и чаты, куда бота добавили, а сообщения пишет от его имени. Набор инструментов у него свой: формы, разворачивание ссылок, история событий, смена адреса своего вебхука и перевыпуск своего токена есть только у токена бота, а черновиков, раздела «Важное» и управления ботами у него нет. Подробнее — в разделе [Какие инструменты получает программа](/guides/mcp/tools#kakie-instrumenty-poluchaet-programma). Где взять токен — в разделе [Токены бота](/guides/bots/tokens), что бот видит — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).

### Yandex AI Studio

Нужны роли на каталог Yandex Cloud:

- `serverless.mcpGateways.editor` и `iam.serviceAccounts.user`, чтобы создать сервер
- `serverless.mcpGateways.invoker` и `serverless.mcpGateways.anonymousInvoker`, чтобы агент вызывал сервер
- `ai.canvasAgents.editor`, чтобы собрать агента

<Warning>Не включайте **Сделать MCP-сервер публичным**: инструменты Пачки с токеном бота сможет вызвать любой, кто знает адрес сервера.</Warning>

1. В AI Studio выберите каталог Yandex Cloud, откройте **Agent Atelier** > **MCP-серверы**, нажмите **Создать MCP-сервер** и выберите **Внешний MCP-сервер**.
2. Укажите имя сервера, например `pachca`, и нажмите **Создать**. Имя должно быть длиной от 3 до 63 символов, начинаться с буквы и не заканчиваться дефисом, в нём допустимы строчные латинские буквы, цифры и дефисы.
3. В поле **URL** укажите адрес `https://mcp.pachca.com/mcp` и выберите транспорт **Streamable HTTP**.
4. В поле **Тип авторизации** выберите **Токен доступа** и добавьте заголовок `Authorization` со значением `Bearer <токен бота>`.
5. Нажмите **Подключиться** и в списке **Инструменты** отметьте только те, что нужны агенту. Нажмите **Сохранить**. Список инструментов появляется, только когда сервер подключился, поэтому он же проверяет подключение.
6. Откройте **Agent Atelier** > **Текстовые агенты**, создайте агента или откройте существующего. В поле **MCP-серверы** выберите сервер Пачки и нажмите **Сохранить версию**.

Если агента вызывают через Responses API, а он меняет данные, укажите для сервера Пачки `"require_approval": "always"`: каждый вызов инструмента будет ждать подтверждения. Скиллы Пачки подключаются в том же окне агента, в поле **Навыки**. Подробнее — в разделе [Yandex AI Studio и GigaChat](/guides/mcp/plugin#yandex-ai-studio-i-gigachat).

### Агент на GigaChat

Агента на GigaChat собирают в коде на [GigaChain](https://github.com/ai-forever/langchain-gigachat), библиотеках LangChain для GigaChat. Пачку подключает библиотека `langchain-mcp-adapters`:

```bash
pip install langchain langchain-gigachat langchain-mcp-adapters
```

Перед запуском задайте переменные окружения:

- `PACHCA_BOT_TOKEN` — токен бота Пачки
- `GIGACHAT_CREDENTIALS` — ключ авторизации GigaChat
- `GIGACHAT_SCOPE` — версия API GigaChat, для компании `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`
- `GIGACHAT_CA_BUNDLE_FILE` — путь к корневому сертификату Минцифры, если он не установлен в системе: без него запрос к GigaChat не пройдёт проверку SSL

```python title="agent.py"
import asyncio
import os

from langchain.agents import create_agent
from langchain_gigachat import GigaChat
from langchain_mcp_adapters.client import MultiServerMCPClient


async def main():
    client = MultiServerMCPClient(
        {
            "pachca": {
                "transport": "http",
                "url": "https://mcp.pachca.com/mcp",
                "headers": {"Authorization": f"Bearer {os.environ['PACHCA_BOT_TOKEN']}"},
            }
        }
    )
    # Только нужные агенту инструменты: так он тратит меньше контекста
    needed = {"pachca_search_messages", "pachca_get_thread", "pachca_list_chat_messages"}
    tools = [tool for tool in await client.get_tools() if tool.name in needed]

    # Ключ, версия API и сертификат GigaChat берутся из переменных окружения
    agent = create_agent(GigaChat(model="GigaChat-2-Max"), tools)
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "Найди обсуждение релиза 2.4 и коротко перескажи решения"}]}
    )
    print(result["messages"][-1].content)


asyncio.run(main())
```

Запустите `python agent.py`: если скрипт напечатал пересказ, агент подключился к Пачке. Как передать агенту скилл Пачки — в разделе [Yandex AI Studio и GigaChat](/guides/mcp/plugin#yandex-ai-studio-i-gigachat).

## Управление подключениями

Подключения через браузер собраны в списке **Авторизации** на странице **Интеграции** > **API**: там видны разрешения каждой программы и меню, которое отзывает доступ. Подробнее о списке — в разделе [Токены CLI и авторизации](/api/authorization#tokeny-cli-i-avtorizatsii).

<ImageCard src="/images/mcp/mcp-authorizations.webp" alt="Список «Авторизации» на странице «API»: клиент MCP Claude Code с доменом claude.ai и бот «Jira-карточки», даты подключения, последнее использование и число разрешений" caption="Программа с MCP в списке «Авторизации»" maxWidth={832} />

**Отозвать доступ** сразу отключает все подключения этой программы, которые вы выдали: следующий вызов получит `401`. Чужие подключения той же программы это не затрагивает.

Новые права Пачки программа получает, когда вы снова входите через браузер и подтверждаете их на экране согласия: после отзыва доступа или по команде входа, например `/mcp` в Claude Code. Перезапуск программы и продление токена прав не добавляют. Если в пространстве сотрудникам не разрешено выдавать доступ к API, войти снова сотрудник не сможет, и после отзыва программа останется без подключения.

Администратор видит подключения через браузер у каждого сотрудника строкой «Клиент MCP» на вкладке [Все токены](/api/authorization#vse-tokeny-prostranstva) и может их отозвать. Агент на персональном токене выглядит там обычным персональным токеном, а токены ботов собраны в карточках ботов, поэтому по списку отличить агента от скрипта нельзя.

Подключение токеном в заголовке живёт, пока жив токен: удалите персональный токен на странице **API** или токен бота в его настройках.

## Если что-то не работает

| Что видно | Причина и что делать |
|---|---|
| «Доступ к API ограничен администраторами пространства» на экране согласия | Сотрудникам в пространстве не разрешено выдавать доступ к API. Попросите Администратора открыть доступ, как в разделе [Кто может подключить](#kto-mozhet-podklyuchit). |
| «Гостям доступ к API не выдаётся» | Гость не может подключить MCP. Нужна другая роль в пространстве. |
| Программа предлагает войти, но вход не проходит или просит зарегистрировать клиента | Вход через браузер с Пачкой в этой программе не работает. Подключите её [токеном в заголовке](#token-v-zagolovke). Если Cursor просит войти, хотя токен в настройках указан, он не видит переменную `PACHCA_TOKEN`: проверьте [переменную](#peremennaya-okruzheniya) и перезапустите Cursor. |
| `401` | Токена нет, он истёк или отозван. Подключитесь заново: в Claude Code — командой `/mcp`. С токеном в заголовке проверьте, что токен не удалён и что программа видит переменную `PACHCA_TOKEN`: задайте её и перезапустите программу. |
| `MCP endpoint not found` в Claude Code | Адрес сервера указан неверно. Проверьте командой `claude mcp get pachca`, что адрес ровно `https://mcp.pachca.com/mcp`. |
| Программа не подключается по адресу `dev.pachca.com/mcp` | Это короткий адрес документации о MCP. Сервер работает по адресу `https://mcp.pachca.com/mcp`, его и укажите в программе. |
| В Claude Code нет сервера `plugin:pachca:pachca`, хотя плагин стоит | Сервер с тем же адресом добавлен вручную и заменяет сервер плагина. Найдите его в списке `claude mcp list` и удалите командой `claude mcp remove` с его именем или работайте через него. |
| `403` с кодом `access_denied` при подключении | Доступ владельца токена к пространству приостановлен, или сотрудник удалён. Подробнее — в разделе [Токен и смена роли](/guides/permissions#token-i-smena-roli). |
| Отказ с кодом `insufficient_scope` | У токена нет нужного права. Персональному токену добавьте право в меню токена на странице **API**, токену бота — в его настройках. Подробнее — в разделе [Ошибки авторизации](/api/authorization#oshibki-avtorizatsii). |
| Отказ с кодом `role_forbidden` | Право есть, но ваша роль не позволяет действие. Это правило пространства, повторное подключение не поможет. |
| Отказ с кодом `payment_required` | Пространство превысило лимит сообщений тарифа: пока его не оплатят, большинство методов отвечают отказом. Подробнее — в разделе [Ошибки](/api/errors). |
| Агент не может отправить файл с диска | Не каждая программа даёт агенту загрузить файл с диска, например чат Claude этого не позволяет. Подробнее — в разделе [Как агент отправляет файл](/guides/mcp/tools#kak-agent-otpravlyaet-fayl). |
| В программе нет нужного инструмента | Список зависит от роли, тарифа и типа токена. Какой инструмент кому доступен — в разделе [Инструменты MCP](/guides/mcp/tools). |
| Отказ «Wait N s before repeating» или `429` | Превышен предел вызовов. Подождите указанное время. Пределы — в разделе [MCP-сервер](/guides/mcp/overview#predely). |
| Подключилось не то пространство | Доступ выдаётся в пространство, открытое в браузере. Отзовите подключение, переключитесь на нужное пространство и подключитесь снова. |
