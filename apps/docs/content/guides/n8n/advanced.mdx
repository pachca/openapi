# Продвинутые функции

## Загрузка файлов

<ImageCard src="/images/n8n/file-upload.avif" alt="Настройка загрузки файла в узле Pachca" caption="Ресурс File с параметрами загрузки" maxWidth={960} />

Операция **File** > **Create** загружает файл через двухшаговый S3 upload. n8n выполняет оба этапа сам: запрашивает параметры загрузки через API и загружает файл в хранилище.

Откуда взять файл, задаёт поле **File Source**:

| File Source | Поле | Описание |
|-------------|------|----------|
| **Binary Data** (по умолчанию) | **Input Binary Field** | Файл из бинарного свойства предыдущего узла, например HTTP Request или Read Binary File. По умолчанию свойство называется `data`. |
| **URL** | **File URL** | Узел сам скачает файл по ссылке |

В **Additional Fields** можно задать **File Name** и **Content Type**. Если их не указать, имя возьмётся из бинарных данных или ссылки, а тип — из бинарных данных или расширения файла.

**Пример workflow: загрузка PDF и отправка в чат**

1. **HTTP Request** — скачать файл по URL
2. **Pachca** (File > Create) — загрузить файл, в ответе придут `key`, `file_name`, `content_type` и `size`
3. **Pachca** (Message > Create) — отправить сообщение с файлом: в **Additional Fields** > **Files** укажите **Key**, **Name**, **File Type** и **Size** из ответа предыдущего узла

<Info>Загруженный файл привязывается к сообщению полем **Files** при создании или обновлении сообщения. Файл, который никуда не привязали, в чате не появится.</Info>

Подробнее — в [документации загрузки файлов](/api/file-uploads).

## Загрузка аватара

Операции **Update Avatar** для ресурсов **Profile** и **User** позволяют загружать аватар через `multipart/form-data`.

**Как использовать:**

1. **HTTP Request** или **Read Binary File** — загрузите изображение в бинарное свойство (по умолчанию `data`)
2. **Pachca** (Profile > Update Avatar или User > Update Avatar) — в поле **Input Binary Field** укажите имя бинарного свойства

Для удаления аватара используйте операцию **Delete Avatar** — она не требует параметров (для User — только `userId`).

<Info>Операции с аватарами сотрудников (User > Update/Delete Avatar) требуют прав администратора.</Info>

## Экспорт сообщений

Ресурс **Chat** (операции **Request Export** и **Download Export**) позволяет выгружать сообщения из чатов. Экспорт выполняется асинхронно: вы запрашиваете экспорт, а Пачка присылает уведомление на вебхук, когда архив готов.

**Пример workflow:**

<Steps>
  <Step title="Настройте приём вебхука">
    Создайте отдельный workflow с узлом **Webhook** (встроенный в n8n). Он создаст URL, на который Пачка отправит уведомление о готовности экспорта. Скопируйте этот URL — он понадобится на следующем шаге.
  </Step>
  <Step title="Запросите экспорт">
    В основном workflow добавьте узел **Pachca** с ресурсом **Chat** и операцией **Request Export**. Укажите период (`startAt`, `endAt`) и вставьте URL вебхука из первого шага в поле `webhookUrl`.
  </Step>
  <Step title="Обработайте уведомление">
    Когда экспорт будет готов, Пачка отправит JSON на ваш вебхук:
    ```json
    {
      "type": "export",
      "event": "ready",
      "export_id": 22322,
      "created_at": "2025-03-20T12:33:58Z"
    }
    ```
  </Step>
  <Step title="Скачайте архив">
    В workflow с Webhook-узлом добавьте узел **Pachca** с ресурсом **Chat** и операцией **Download Export**. Передайте `export_id` из данных вебхука в поле **ID**. Архив будет скачан автоматически.
  </Step>
</Steps>

**Ограничения:**
- Максимальный период одной выгрузки: 45 дней (366 дней при указании конкретных чатов)
- Максимум 50 чатов при фильтрации по `chatIds`
- Новый запрос можно сделать только после завершения текущего

Подробнее — в [документации экспорта](/guides/export).

## Кнопки в сообщениях

<ImageCard src="/images/n8n/message-buttons.avif" alt="Настройка кнопок в сообщении в узле Pachca" caption="Кнопки в параметрах сообщения" maxWidth={960} />

Кнопки к сообщению задаются в операциях Message > **Create** и **Update** полем **Button Layout**. По умолчанию в нём стоит **None**, и кнопки не отправляются.

| Button Layout | Как задать кнопки |
|---------------|-------------------|
| **None** | Кнопок нет. При обновлении кнопки сообщения не меняются. |
| **Single Row** | В конструкторе **Buttons**, все кнопки в одной строке |
| **Multiple Rows** | В конструкторе **Buttons**, каждая кнопка в своей строке |
| **Raw JSON** | В поле **Buttons (JSON)**: массив строк, каждая строка — массив кнопок |

В конструкторе у каждой кнопки задаются **Text**, **Type** и, в зависимости от типа, **Data** или **URL**:

| Type | Что делает кнопка |
|------|-------------------|
| **Data (Webhook)** | Отправляет боту событие о нажатии, его принимает Pachca Trigger с событием Button Pressed |
| **URL (Link)** | Открывает ссылку в браузере |

Пример для **Raw JSON**, одна строка из двух кнопок:

```json
[
  [
    { "text": "Открыть сайт", "url": "https://example.com" },
    { "text": "Подтвердить", "data": "confirm_action" }
  ]
]
```

Число кнопок и длина их полей ограничены, подробнее — в разделе [Ограничения](/guides/buttons#ogranicheniya). Чтобы убрать кнопки при обновлении сообщения, выберите **Raw JSON** и укажите пустой массив `[]`.

Подробнее о кнопках, их внешнем виде в чате и обработке нажатий — в [документации кнопок](/guides/buttons).

## Формы

Ресурс **Form** позволяет открывать модальные формы (представления) для пользователей.

**Как это работает:**

1. Сотрудник нажимает Data-кнопку в сообщении бота
2. Бот получает вебхук с `trigger_id`
3. Бот вызывает [Открытие представления](POST /views/open) с `trigger_id` и описанием формы
4. Сотрудник видит модальное окно с полями

**Поля Form > Create:**

| Поле | Описание |
|------|----------|
| **Title** | Заголовок модального окна |
| **Type** | Тип представления, единственное значение — **Modal** |
| **Trigger ID** | `trigger_id` из события о нажатии кнопки. Форму нужно открыть в первые 3 секунды после нажатия, подробнее — в разделе [Сроки ответа](/guides/webhook/handler#sroki-otveta). |
| **Builder Mode** | **Visual Builder** (по умолчанию) — блоки формы собираются в конструкторе **Form Blocks**. **JSON** — массив блоков вставляется в поле **Blocks (JSON)**. |
| **Additional Fields** | **Callback ID**, по которому форму узнают при отправке, **Private Metadata**, **Submit Text** и **Close Text** |

**Пример workflow:** у бота один адрес вебхука, поэтому нажатие кнопки и отправку формы принимает один узел Pachca Trigger с событием **All Events**.

1. **Pachca Trigger** — событие `All Events`
2. **Switch** — разводит события по полю `type`: `button` для нажатия, `view` для отправки формы
3. **Pachca** (Form > Create) — на ветке нажатия открывает форму с `trigger_id` из события и **Callback ID**
4. На ветке отправки — обработка данных формы из поля `data` события, `callback_id` подскажет, какая это форма

Готовый сценарий — в примере [Заявка на отпуск](/guides/n8n/workflows#zayavka-na-otpusk).

Подробнее о формах, типах полей и внешнем виде модального окна в интерфейсе Пачки — в [документации форм](/guides/forms/overview).

## AI-агент

<ImageCard src="/images/n8n/ai-agent-tool.avif" alt="Pachca как инструмент AI Agent в n8n" caption="Pachca Tool в панели инструментов AI Agent" maxWidth={960} />

Оба узла (Pachca и Pachca Trigger) поддерживают `usableAsTool: true` — их можно использовать как инструменты для **AI Agent** в n8n.

**Что это значит:**

- AI Agent может вызывать операции Pachca для выполнения задач
- Примеры: поиск сообщений, отправка ответов, создание задач
- Agent автоматически выбирает подходящую операцию на основе запроса

**Пример: AI-помощник для команды**

<Steps>
  <Step title="Добавьте AI Agent">
    Создайте новый workflow. Добавьте узел **AI Agent** и подключите LLM-модель (OpenAI, Anthropic и др.) через соответствующие Credentials.
  </Step>
  <Step title="Подключите инструменты Pachca">
    Нажмите **+** на входе **Tool** узла AI Agent и добавьте узел **Pachca**. Выберите нужную операцию — например, **Search > Get Many Messages** для поиска по сообщениям. Добавьте ещё один узел Pachca для **Message > Create** — отправки ответов.
  </Step>
  <Step title="Настройте триггер">
    Добавьте **Pachca Trigger** с событием `New Message` на вход workflow. AI Agent будет автоматически отвечать на сообщения пользователей, используя поиск по истории чатов.
  </Step>
</Steps>

AI Agent самостоятельно выбирает подходящий инструмент на основе запроса пользователя — ищет информацию, создаёт задачи или отправляет сообщения.

<Info>Для использования AI Agent необходимо настроить LLM-провайдер (OpenAI, Anthropic и др.) в Credentials n8n.</Info>

## Разворачивание ссылок

Ресурс **Message** с операцией **Unfurl** ставит к ссылкам в сообщениях превью с заголовком, описанием и изображением — например, к ссылкам на задачи во внутреннем трекере.

Сценарий начинается с события **Link Shared** в узле **Pachca Trigger**: бот получает его, когда в любом чате пространства появляется ссылка на один из его доменов. Домены и само событие задаются на вкладке **Исходящий вебхук** в карточке бота, и включить их может только администратор или владелец пространства. Адрес вебхука такого бота тоже прописывают только они: в Pachca Trigger выберите ручной режим или автоматический с персональным токеном администратора. Дальше workflow собирает данные по ссылке и отвечает операцией **Unfurl** — методом [Unfurl (разворачивание ссылок)](POST /messages/{id}/link_previews) по `message_id` из события.

Подробнее — в [документации разворачивания ссылок](/guides/link-previews).

## Журнал безопасности

Ресурс **Security** предоставляет доступ к журналу аудита — списку событий безопасности в пространстве. Журнал доступен владельцу пространства на тарифе «Корпорация», токену нужен скоуп `audit_events:read`.

**Фильтры** в **Additional Fields** операции **Get Many**:

| Фильтр | Описание |
|--------|----------|
| **Event Key** | Тип события из списка, например **User Login** (`user_login`), **Message Created** (`message_created`) или **User Deleted** (`user_deleted`) |
| **Actor ID** | ID сотрудника или бота, совершившего действие |
| **Actor Type** | Тип инициатора. У сотрудников и ботов это `User`, значение сравнивается точно, с учётом регистра. |
| **Entity ID** | ID объекта, над которым совершено действие |
| **Entity Type** | Тип объекта, например `User`, `Chat` или `Message` |
| **Start Time** | Начало периода |
| **End Time** | Конец периода |

Подробнее — в [документации журнала аудита](/guides/audit-events).
