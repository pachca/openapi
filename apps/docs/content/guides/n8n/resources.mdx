# Ресурсы и операции

В расширении Пачки каждый узел **Pachca** работает по модели **Resource → Operation**: вы выбираете ресурс (например, Message) и операцию над ним (например, Create).

## Message

Сообщения: создание, получение, редактирование, удаление, закрепление и открепление.

| Операция | API |
|----------|-----|
| Create | [Новое сообщение](POST /messages) |
| Get Many | [Список сообщений чата](GET /messages) |
| Get | [Информация о сообщении](GET /messages/{id}) |
| Update | [Редактирование сообщения](PUT /messages/{id}) |
| Delete | [Удаление сообщения](DELETE /messages/{id}) |
| Pin | [Закрепление сообщения](POST /messages/{id}/pin) |
| Unpin | [Открепление сообщения](DELETE /messages/{id}/pin) |
| Unfurl | [Unfurl (разворачивание ссылок)](POST /messages/{id}/link_previews) |

**Ключевые параметры Create:** **Entity Type** (Discussion, Thread или User), **Entity ID** (чат, тред или сотрудник), **Content** (текст, Markdown), **Button Layout** с кнопками, а в **Additional Fields** — **Files**, **Parent Message ID** и другие. Как задать кнопки — в разделе [Кнопки в сообщениях](/guides/n8n/advanced#knopki-v-soobscheniyah).

**Сортировка в Get Many:** параметры `sort` (по умолчанию `id`) и `order` (`asc` / `desc`) определяют порядок выдачи сообщений.

## Chat

Чаты: создание, получение, обновление, архивация и разархивация, отметка непрочитанным, аватар.

| Операция | API |
|----------|-----|
| Create | [Новый чат](POST /chats) |
| Get Many | [Список чатов](GET /chats) |
| Get | [Информация о чате](GET /chats/{id}) |
| Update | [Редактирование чата](PUT /chats/{id}) |
| Archive | [Архивация чата](PUT /chats/{id}/archive) |
| Unarchive | [Разархивация чата](PUT /chats/{id}/unarchive) |
| Request Export | [Экспорт сообщений](POST /chats/exports) |
| Download Export | [Скачать архив экспорта](GET /chats/exports/{id}) |
| Get Many Workspace Chats | [Список чатов пространства](GET /company/chats) |
| Mark Unread | [Отметка чата непрочитанным](PUT /chats/{id}/unread) |
| Update Avatar | [Загрузка аватара чата](PUT /chats/{id}/avatar) |
| Delete Avatar | [Удаление аватара чата](DELETE /chats/{id}/avatar) |

**Create** возвращает созданный чат и поля `not_found_member_ids` и `not_found_group_tag_ids`: идентификаторы из **Member IDs**, которых не удалось добавить в чат, и идентификаторы из **Group Tag IDs**, которых нет среди тегов пространства.

**Сортировка в Get Many:** параметры `sort` (`id` или `last_message_at`) и `order` (`asc` / `desc`). Также доступны фильтры `availability`, `lastMessageAtAfter`, `lastMessageAtBefore`.

**Get Many Workspace Chats** отдаёт беседы и каналы всего пространства, включая закрытые, где владелец токена не состоит. Фильтр `Activity` оставляет только активные или только архивные. Доступно владельцу пространства на тарифе «Корпорация».

**Update Avatar** принимает бинарные данные из предыдущего узла, например HTTP Request или Read Binary File. В поле **Input Binary Field** укажите имя бинарного свойства, по умолчанию `data`.

**Экспорт чата** выполняется асинхронно: операция **Request Export** ставит задачу и сразу возвращает её идентификатор в `id`, а **Download Export** скачивает архив по этому номеру, когда он собран. Пока архив собирается, **Download Export** вместо ссылки возвращает ошибку с кодом `export_file_not_found`. О готовности может сообщить и вебхук на `webhookUrl` с тем же номером в `export_id`. Доступно владельцу на тарифе «Корпорация».

## Draft

Черновики и отложенные сообщения: полный CRUD.

| Операция | API |
|----------|-----|
| Create | [Новый черновик](POST /drafts) |
| Get Many | [Список черновиков](GET /drafts) |
| Get | [Информация о черновике](GET /drafts/{id}) |
| Update | [Редактирование черновика](PUT /drafts/{id}) |
| Delete | [Удаление черновика](DELETE /drafts/{id}) |

**Отложенное сообщение** создаётся полем `Schedule` у операции `Create`: в нём
задаётся время первой отправки и правило повтора. Без `Schedule` получается
обычный черновик, который никуда не уйдёт. Отменить отправку можно только
операцией `Delete`.

**Update** снимает ответ на сообщение переключателем **Clear Parent Message ID** в
**Additional Fields**: он отправляет `parent_message_id: null` и действует, даже
если заполнено поле **Parent Message ID**.

**Ресурс работает только с личным токеном.** Скоупы `drafts:read` и
`drafts:write` токенам ботов не выдаются, поэтому с учётными данными бота
операции вернут `403`.

## Bot

Боты: создание, получение, список, редактирование, удаление, аватар, саморегистрация вебхука, токены бота и их права, ротация токена и секрета клиента, история, поток и удаление событий.

| Операция | API |
|----------|-----|
| Create | [Новый бот](POST /bots) |
| Get | [Информация о боте](GET /bots/{id}) |
| Get Many | [Список ботов](GET /bots) |
| Update | [Редактирование бота](PUT /bots/{id}) |
| Delete | [Удаление бота](DELETE /bots/{id}) |
| Update Avatar | [Загрузка аватара бота](PUT /bots/{id}/avatar) |
| Delete Avatar | [Удаление аватара бота](DELETE /bots/{id}/avatar) |
| Update Webhook | [Саморегистрация вебхука бота](PUT /bot/webhook) |
| Recreate Token | [Ротация токена бота](POST /bots/{id}/recreate_token) |
| Recreate Token Self | [Ротация собственного токена бота](POST /bot/recreate_token) |
| Get Many Events | [История событий](GET /webhooks/events) |
| Get Stream | [Поток событий](GET /webhooks/events/stream) |
| Remove Events | [Удаление события истории](DELETE /webhooks/events/{id}) |
| Get Many Workspace Bots | [Список ботов пространства](GET /company/bots) |
| Get Many Tokens | [Список токенов бота](GET /bots/{id}/tokens) |
| Create Token | [Новый токен бота](POST /bots/{id}/tokens) |
| Update Token | [Изменение токена бота](PUT /bots/{id}/tokens/{token_id}) |
| Reissue Token | [Перевыпуск токена бота](POST /bots/{id}/tokens/{token_id}/reissue) |
| Delete Token | [Удаление токена бота](DELETE /bots/{id}/tokens/{token_id}) |
| Get Scopes | [Каталог прав бота](GET /bots/{id}/scopes) |
| Rotate Client Secret | [Ротация секрета клиента](POST /bots/{id}/rotate_client_secret) |

**Update** меняет настройки бота. Поле **Webhook URL** задаёт адрес исходящего вебхука, пустое поле оставляет прежний адрес. Источник входящего вебхука задаёт поле **Kind** в **Additional Fields**: значения **Simple**, **Gitlab** и **Grafana** включают входящий вебхук, если его не было, а **None** удаляет его. Адрес удалённого вебхука перестаёт работать, шаблон и настройки сбрасываются, а при следующем включении бот получает новый адрес.

В **Update** текст `null` в поле **OAuth Client** из **Additional Fields** выключает авторизацию от имени сотрудника: выданные сотрудниками авторизации отзываются, страница бота в витрине удаляется, а собственные токены бота продолжают работать.

**Get Many Workspace Bots** отдаёт всех ботов пространства, включая недоступных владельцу токена для редактирования. У таких ботов в `webhook` заполнены только `name` и `nickname`, остальные настройки приходят пустыми. Доступно владельцу пространства на тарифе «Корпорация».

**Update Avatar** принимает бинарные данные из предыдущего узла так же, как у ресурса Chat: в поле **Input Binary Field** укажите имя бинарного свойства, по умолчанию `data`.

## Пагинация

Все операции Get Many поддерживают автоматическую курсорную пагинацию:

- **Return All** = `true` — получить все результаты автоматически, переключаясь между страницами
- **Return All** = `false` — получить не более **Limit** результатов (по умолчанию 50)

<ImageCard src="/images/n8n/return-all.avif" alt="Переключатель Return All и поле Limit в узле Pachca" caption="Return All и Limit для операции Get Many" maxWidth={960} />

n8n автоматически отправляет повторные запросы с курсором до получения всех данных.

<Info>Для операций со списками (Get Many) рекомендуется использовать **Return All = false** с разумным **Limit**, чтобы избежать долгих запросов при большом объёме данных.</Info>

## Simplify

Операции получения данных (Get, Get Many) поддерживают переключатель **Simplify** (включён по умолчанию). Когда Simplify включён, из ответа API возвращаются только ключевые поля — остальные отбрасываются.

| Ресурс | Ключевые поля |
|--------|---------------|
| Message | `id`, `entity_id`, `chat_id`, `content`, `user_id`, `created_at` |
| Chat | `id`, `name`, `channel`, `public`, `member_ids`, `created_at` |
| User | `id`, `first_name`, `last_name`, `nickname`, `email`, `role`, `suspended` |
| Reminder | `id`, `content`, `kind`, `status`, `priority`, `due_at`, `created_at` |
| Bot | Боты: `id` и `webhook`, в котором лежат имя и никнейм. Токены в **Get Many Tokens**: `id`, `name`, `scopes`, `created_at`, `last_used_at`. События в **Get Many Events**: `id`, `event_type`, `payload`, `created_at`. |
| Group Tag | Теги: `id`, `name`, `users_count`. Сотрудники тега в **Get Many Users**: те же поля, что у User. |
| Reaction | `code`, `name`, `user_id`, `created_at` |

У остальных ресурсов переключатель есть, но ответ приходит полностью. Выражения в следующих узлах, которые ссылаются на поля вне этого списка, при включённом Simplify получат пустые значения. Чтобы получить все поля ответа, выключите **Simplify**.

<Info>Simplify доступен только в v2. В v1 workflow всегда возвращают полный ответ API.</Info>

## Поисковые выпадающие списки

<ImageCard src="/images/n8n/searchable-dropdown.avif" alt="Поисковый выпадающий список Chat ID в узле Pachca" caption="Поиск чата по имени в поле Chat ID" maxWidth={960} />

Поля чата и сотрудника с режимом **From List** показывают список и ищут по названию или имени: начните вводить текст, и n8n покажет подходящие результаты из пространства.

| Поле | Что в списке |
|------|--------------|
| **Chat ID** в Message > Get Many, **ID** в операциях Chat и Chat Member | Чаты |
| **ID** и **User ID** в операциях User, **User ID** в Chat Member | Сотрудники |
| **Entity ID** в Message > Create | Чаты при **Entity Type** = Discussion, сотрудники при User |

Без введённого текста список приходит из методов [Список чатов](GET /chats) и [Список сотрудников](GET /users), с текстом — из [Поиск чатов](GET /search/chats) и [Поиск сотрудников](GET /search/users). Поэтому в списке только то, что доступно токену из Credentials, и токену нужны права на эти методы, например `chats:read` и `search:chats` для чатов. При **Entity Type** = Thread список пуст: укажите id треда в режиме **By ID**. Как найти идентификатор без списка — в разделе [Где взять идентификаторы](/api/requests-responses#gde-vzyat-identifikatory).
