# Триггер

Узел **Pachca Trigger** запускает workflow, когда в Пачке что-то происходит: приходит новое сообщение, сотрудник нажимает кнопку или отправляет форму, меняется состав чата, начинается видеозвонок.

## Поддерживаемые события

В поле **Event** узла выбирается одно из 19 событий или **All Events**. Пачка присылает боту только те события, которые отмечены на вкладке **Исходящий вебхук** в его карточке, поэтому для каждого события ниже указан пункт, который нужно отметить. Отмечать пункты нужно в обоих [режимах регистрации](#kak-registriruetsya-vebhuk): узел прописывает боту только адрес вебхука и список событий не меняет.

### Сообщения и чаты

| Событие в узле | Значение | Пункт на вкладке «Исходящий вебхук» | Когда приходит |
|----------------|----------|-------------------------------------|----------------|
| New Message | `new_message` | Новые сообщения | В чате или треде появилось сообщение |
| Message Updated | `message_updated` | Редактирование и удаление сообщений | Сообщение отредактировали |
| Message Deleted | `message_deleted` | Редактирование и удаление сообщений | Сообщение удалили |
| New Reaction | `new_reaction` | Добавление и удаление реакций | На сообщение поставили реакцию |
| Reaction Deleted | `reaction_deleted` | Добавление и удаление реакций | Реакцию сняли |
| Chat Member Added | `chat_member_added` | Изменение состава участников чатов | В чат добавили участника |
| Chat Member Removed | `chat_member_removed` | Изменение состава участников чатов | Участника удалили из чата |

### Кнопки, формы и ссылки

| Событие в узле | Значение | Пункт на вкладке «Исходящий вебхук» | Когда приходит |
|----------------|----------|-------------------------------------|----------------|
| Button Pressed | `button_pressed` | Нажатие кнопок | Сотрудник нажал Data-кнопку в сообщении бота |
| Form Submitted | `form_submitted` | Нажатие кнопок | Сотрудник отправил форму, которую открыл бот |
| Link Shared | `link_shared` | Отправка ссылок в сообщении (unfurl) | В сообщении появилась ссылка на один из доменов бота |

Отдельного пункта для форм нет: отправка формы приходит вместе с нажатиями кнопок. Пункт для ссылок и домены включает только администратор или владелец пространства, и у бота с этим пунктом адрес вебхука тоже меняют только они. Как настроить для такого бота Pachca Trigger — в разделе [Разворачивание ссылок](/guides/n8n/advanced#razvorachivanie-ssylok).

### Сотрудники

| Событие в узле | Значение | Пункт на вкладке «Исходящий вебхук» | Когда приходит |
|----------------|----------|-------------------------------------|----------------|
| User Invited | `company_member_invite` | Изменение участников пространства | Сотруднику отправили приглашение |
| User Confirmed | `company_member_confirm` | Изменение участников пространства | Сотрудник принял приглашение |
| User Activated | `company_member_activate` | Изменение участников пространства | Сотрудника снова активировали |
| User Updated | `company_member_update` | Изменение участников пространства | Изменились данные сотрудника |
| User Suspended | `company_member_suspend` | Изменение участников пространства | Сотрудника приостановили |
| User Deleted | `company_member_delete` | Изменение участников пространства | Сотрудника удалили |

### Видеозвонки

| Событие в узле | Значение | Пункт на вкладке «Исходящий вебхук» | Когда приходит |
|----------------|----------|-------------------------------------|----------------|
| Video Call Started | `video_call_started` | Начало видеозвонка | В чате или треде начался видеозвонок |
| Video Call Finished | `video_call_finished` | Завершение видеозвонка | Видеозвонок завершился |
| Video Call Recording Ready | `video_call_recording_ready` | Готовность записи видеозвонка | Запись видеозвонка обработана и готова |

### Все события

| Событие в узле | Значение | Пункт на вкладке «Исходящий вебхук» | Когда приходит |
|----------------|----------|-------------------------------------|----------------|
| All Events | `*` | Пункты всех событий, которые разбирает workflow | Любое событие, которое Пачка отправила боту |

### Режим новых сообщений

У пункта **Новые сообщения** два режима. **Любые сообщения** присылает все новые сообщения, **Начинающиеся с команд** — только те, что начинаются с одной из команд бота. Режим действует и на **Message Updated**, а **Message Deleted** приходит в любом режиме.

Новый бот подписан только на новые сообщения в режиме «Начинающиеся с команд» с пустым списком команд, поэтому workflow с **New Message** ничего не получит. Выберите режим «Любые сообщения» или перечислите команды, например `/отпуск`. Как устроены команды — в разделе [Сообщения](/guides/webhook/events#soobscheniya).

<Warning>О сообщениях, реакциях, участниках чатов и видеозвонках бот узнаёт только из чатов, в которых состоит, и из их тредов. Нажатия кнопок приходят только из сообщений самого бота. О сотрудниках бот узнаёт по всему пространству, а о ссылках на свои домены — из любого чата. Подробнее — в разделе [Какие события откуда приходят](/guides/webhook/events#kakie-sobytiya-otkuda-prihodyat).</Warning>

## Как работают вебхуки в Пачке

У бота в Пачке **один слот** для адреса исходящего вебхука. Поэтому:

- На одного бота можно зарегистрировать только **один URL**
- Новая запись полностью перезаписывает предыдущую
- Каждому workflow с Pachca Trigger нужен свой бот: из двух workflow на одном боте события получает тот, чей адрес записан последним
- Несколько событий одним ботом обрабатывает один workflow с событием **All Events** и узлом **Switch**, как в примере [Заявка на отпуск](/guides/n8n/workflows#zayavka-na-otpusk)
- Для тестов и продакшена нужны **разные боты**, иначе тестовый запуск перезапишет адрес продакшена

Pachca Trigger поддерживает два режима настройки: **автоматический** (узел сам регистрирует URL в Пачке при активации workflow) и **ручной** (вы копируете URL и вставляете его в настройки бота сами).

Добавьте узел **Pachca Trigger** в workflow — найдите его через поиск в панели узлов.

## Как регистрируется вебхук

В узле **Pachca Trigger** параметр **Webhook Setup** определяет, кто прописывает адрес вебхука в настройках бота — вы или сам узел:

| Режим | Что делает узел | Когда использовать |
|-------|-----------------|---------------------|
| **Ручной** (по умолчанию) | Не трогает настройки бота. Вы сами копируете Production URL из панели узла и вставляете его в настройки бота в Пачке. | Работает с любым токеном, включая токены ботов. Не может случайно перезаписать слот вебхука. |
| **Автоматический** | При активации workflow регистрирует Production URL в настройках бота, при деактивации — очищает. С **токеном бота** — методом [Саморегистрация вебхука бота](PUT /bot/webhook), без Bot ID: нужны права `profile:read` и `bot_self:webhook:write`. С **персональным токеном** — методом [Редактирование бота](PUT /bots/{id}): нужны скоуп `bots:write`, доступ редактора к боту и Bot ID. | Когда хотите, чтобы n8n сам управлял слотом вебхука бота. |

В обоих режимах события и режим новых сообщений отмечаются на вкладке **Исходящий вебхук** по таблице из раздела [Поддерживаемые события](#podderzhivaemye-sobytiya).

<Warning>Автоматический режим управляет единственным слотом вебхука бота: при активации он перезапишет текущий адрес, при деактивации — очистит. Если слот занят чем-то ещё, используйте ручной режим или отдельного бота для n8n.</Warning>

## Ручной режим

<ImageCard src="/images/n8n/trigger-node.avif" alt="Конфигурация Pachca Trigger с выбором события" caption="Настройка Pachca Trigger" maxWidth={960} />

Режим по умолчанию. Узел не обращается к API Пачки: вы копируете адрес вебхука из n8n и вставляете его в настройки бота в Пачке сами. При деактивации workflow узел тоже ничего не делает со слотом.

<Steps>
  <Step title="Добавьте Pachca Trigger">
    Создайте новый workflow, добавьте узел **Pachca Trigger** и выберите нужное событие. Параметр **Webhook Setup** оставьте в значении **Manual** (это значение по умолчанию).
  </Step>
  <Step title="Скопируйте Production URL">
    В верхней части панели узла n8n показывает два URL:

    - **Test URL** (`/webhook-test/...`) — временный URL, активен только во время ручного теста через кнопку **Listen for test event**
    - **Production URL** (`/webhook/...`) — постоянный URL, работает, пока workflow активен

    Для настройки в Пачке нужен **Production URL**. Нажмите иконку копирования рядом с ним.

    <ImageCard src="/images/n8n/trigger-webhook-urls.avif" alt="Test URL и Production URL в панели узла n8n" caption="Test URL и Production URL в верхней части панели узла" maxWidth={960} />
  </Step>
  <Step title="Вставьте URL в настройки бота в Пачке">
    Откройте карточку бота в Пачке и на вкладке **Исходящий вебхук** укажите скопированный Production URL: при первом включении вебхука кнопкой **Включить**, а если он уже включён — в поле адреса. Подробнее — в разделе [Настройка и типы событий](/guides/webhook/events#obschie-nastroyki).
  </Step>
  <Step title="Отметьте события">
    На той же вкладке отметьте пункт для выбранного события по [таблице событий](#podderzhivaemye-sobytiya). Для **New Message** выберите режим **Любые сообщения** или перечислите команды.
  </Step>
  <Step title="Вернитесь в n8n и активируйте">
    Нажмите **Activate** в n8n. С этого момента бот отправляет события в ваш workflow.
  </Step>
</Steps>

<Warning>В ручном режиме URL в настройках бота вы ставите сами — значит и очищать его тоже нужно самостоятельно. Если вы удаляете workflow или меняете URL, замените адрес на вкладке **Исходящий вебхук** в карточке бота или удалите там вебхук кнопкой **Удалить вебхук** — иначе Пачка будет продолжать отправлять события на недоступный адрес.</Warning>

## Автоматический режим

<Info>Автоматический режим работает и с **токеном бота** (проще всего — саморегистрация, без Bot ID, нужны права `profile:read` и `bot_self:webhook:write`), и с **персональным токеном** (нужны скоуп `bots:write`, доступ редактора к боту и Bot ID).</Info>

<ImageCard src="/images/n8n/trigger-automatic-mode.avif" alt="Pachca Trigger в автоматическом режиме: Webhook Setup = Automatic и поле Bot ID" caption="Автоматический режим: переключатель Webhook Setup и поле Bot ID (нужно только для персонального токена)" maxWidth={960} />

Узел определяет тип токена методом [Свой профиль](GET /profile). **Токен бота** регистрирует свой вебхук сам — методом [Саморегистрация вебхука бота](PUT /bot/webhook), Bot ID не нужен. **Персональный токен** прописывает вебхук выбранному боту методом [Редактирование бота](PUT /bots/{id}) — Bot ID обязателен, потому что персональный токен не привязан к конкретному боту.

Для метода [Свой профиль](GET /profile) токену нужно право `profile:read`. Права токена бота выбирают отдельно для каждого токена, поэтому проверьте, что это право у него отмечено. Если права нет и Bot ID не заполнен, узел не активируется и называет недостающее право. С заполненным Bot ID узел регистрирует вебхук как персональный токен. Что делать в каждом случае — в разделе [Узел не определил тип токена](/guides/n8n/troubleshooting#uzel-ne-opredelil-tip-tokena).

<Steps>
  <Step title="Вставьте токен в Credentials">
    Откройте Pachca API Credentials и в поле **Access Token** вставьте токен. Подойдёт **токен бота** (карточка бота → вкладка **API**) с правами `profile:read` и `bot_self:webhook:write` — тогда бот зарегистрирует вебхук сам. Или **персональный токен** (**Интеграции** → **API**) со скоупом `bots:write`, если его владелец может редактировать целевого бота.
  </Step>
  <Step title="Переключите Webhook Setup на Automatic">
    В узле **Pachca Trigger** выберите нужное событие, затем установите **Webhook Setup** = **Automatic**.
  </Step>
  <Step title="Укажите Bot ID для персонального токена">
    Для **персонального токена** заполните появившееся поле **Bot ID** — ID бота, которому нужно прописать адрес вебхука (это `user_id` на вкладке **API** карточки бота, его же видно в адресе карточки). Для **токена бота** это поле не нужно: бот регистрирует себя сам.
  </Step>
  <Step title="Активируйте workflow">
    Нажмите **Activate** в правом верхнем углу. Узел сам зарегистрирует Production URL в настройках бота, и вебхук бота включится.
  </Step>
  <Step title="Отметьте события в карточке бота">
    Откройте карточку бота в Пачке и на вкладке **Исходящий вебхук** отметьте пункт для выбранного события по [таблице событий](#podderzhivaemye-sobytiya). Для **New Message** выберите режим **Любые сообщения** или перечислите команды. Отметки сохраняются, когда узел очищает и снова прописывает адрес.
  </Step>
</Steps>

При деактивации workflow узел автоматически очищает адрес вебхука в настройках бота — бот перестаёт отправлять события.

<Mermaid
  title="Автоматическая регистрация вебхука"
  chart={`sequenceDiagram
    participant User as Пользователь
    participant n8n
    participant Pachca as Pachca API
    participant Bot as Бот в Пачке

    User->>n8n: Activate workflow
    n8n->>Pachca: GET /profile<br/>(тип токена)
    alt Токен бота
        n8n->>Pachca: PUT /bot/webhook<br/>outgoing_url=n8n_url
    else Персональный токен
        n8n->>Pachca: PUT /bots/{id}<br/>outgoing_url=n8n_url
    end
    Pachca->>Bot: Записать outgoing_url

    loop Для каждого отмеченного события
        Pachca->>n8n: POST outgoing_url<br/>+ payload + signature
        n8n->>n8n: Проверка подписи и запуск workflow
    end

    User->>n8n: Deactivate workflow
    n8n->>Pachca: outgoing_url=""<br/>(очистка)
    Pachca->>Bot: Очистить outgoing_url`}
/>

<Warning>**Если получили 403 Forbidden при активации** — токену не хватает прав. Для **токена бота** добавьте ему права `profile:read` и `bot_self:webhook:write` (карточка бота → вкладка **API** → **Редактировать** в меню токена). Для **персонального токена** нужен скоуп `bots:write` и доступ редактора к указанному боту — проверьте доступы или вернитесь в **Manual**. Тексты ошибок и решения — в разделе [403 Forbidden при активации Pachca Trigger](/guides/n8n/troubleshooting#403-forbidden-pri-aktivatsii-pachca-trigger).</Warning>

## Установка адреса узлом Pachca

Адрес вебхука можно прописать и обычным узлом **Pachca**, прямо из workflow: например, в рамках деплоя или чтобы переключать слот между разными серверами n8n. Этот путь не требует активации workflow с Pachca Trigger.

| Токен в Credentials | Операция | Поля |
|---------------------|----------|------|
| Токен бота с правом `bot_self:webhook:write` | **Bot** → **Update Webhook** | **Outgoing URL** |
| Персональный токен со скоупом `bots:write` и доступом редактора к боту | **Bot** → **Update** | **ID** бота и **Webhook URL** |

Запустите узел вручную или по расписанию. В **Update Webhook** пустая строка в поле адреса очищает слот, а в **Update** пустое поле оставляет адрес как есть. В узле v1 есть только **Bot** → **Update**, поле id бота в нём называется **Bot ID**.

С персональным токеном операция **Update** задаёт и события: в **Additional Fields** укажите **Events** — значения из колонки «Значения в `events`» таблицы [Какие события откуда приходят](/guides/webhook/events#kakie-sobytiya-otkuda-prihodyat) через запятую, например `message_new,button_click`, и **Trigger On** = **All Messages**. Список событий заменяется целиком.

## Тестирование

У бота в Пачке только **один слот** для адреса вебхука, поэтому тестовый запуск требует осторожности: неправильный тест перезаписывает адрес продакшена и ломает живой workflow. В автоматическом режиме Pachca Trigger блокирует **Listen for Test Event**, если workflow уже активен. Это защищает от самого частого сценария. В ручном режиме узел не управляет слотом, и за подмену адреса отвечаете вы. Полная инструкция с тремя способами тестирования и диаграммой — в разделе [Тестирование](/guides/n8n/testing#testirovanie-triggera).

## Безопасность

### Проверка подписи

Для защиты от поддельных запросов вставьте секрет подписи бота в поле **Webhook Signing Secret** в [Credentials](/guides/n8n/setup#nastroyka-credentials). Секрет лежит в поле **Signing secret** на вкладке **Исходящий вебхук** в карточке бота. Pachca Trigger проверяет HMAC-SHA256 подпись каждого запроса по заголовку `pachca-signature` и отклоняет запросы без подписи или с неверной подписью.

Подробнее о механизме подписи — в разделе [Безопасность и обработчик](/guides/webhook/handler#bezopasnost).

<Info>В продакшене всегда заполняйте Webhook Signing Secret: без него узел принимает запросы от кого угодно, кто знает адрес.</Info>

### Ограничение по IP

Укажите в поле **Webhook Allowed IPs** в [Credentials](/guides/n8n/setup#nastroyka-credentials) через запятую адреса, с которых Пачка отправляет вебхуки. Список адресов — в разделе [Безопасность и обработчик](/guides/webhook/handler#bezopasnost), укажите все.

Если поле пустое — проверка IP отключена и запросы принимаются с любого адреса.

<Warning>Ограничение по IP — дополнительная мера. Заголовок `x-forwarded-for` может быть подменён, если n8n не стоит за доверенным reverse proxy. Используйте его вместе с Webhook Signing Secret.</Warning>

### Защита от повторов

Pachca Trigger отклоняет события, у которых метка `webhook_timestamp` в теле запроса старше **5 минут** или больше чем на минуту в будущем. Это защищает от повторной отправки перехваченного запроса (replay-атаки). Если в Credentials заполнен Webhook Signing Secret, отклоняется и событие без метки, а без секрета такое событие принимается.

Пачка ставит метку заново при каждой попытке доставки, поэтому её собственные повторы в это окно укладываются. Отклонить их может только неверное время на сервере n8n: если его часы отстают больше чем на минуту или спешат больше чем на пять.

## Фильтрация событий

Узел запускает workflow только при совпадении с выбранным событием, остальные события он отбрасывает. Один узел слушает одно событие.

<Info>Если нужно обрабатывать несколько событий, выберите **All Events** (`*`) и разведите их узлом **Switch** по полям `type` и `event` из тела события. Поскольку у бота один адрес вебхука, это единственный способ получать разные события одним ботом.</Info>

Готовые сценарии с Pachca Trigger — в разделе [Примеры workflow](/guides/n8n/workflows).
