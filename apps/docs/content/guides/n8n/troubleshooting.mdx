# Устранение ошибок

## Установка расширения

### Расширение не появляется в Nodes panel

**Причина:** verified-ноды Пачки не подключены к instance n8n.

**Решение:**

- **n8n Cloud:** verified-ноды включены по умолчанию. Если в поиске их нет, instance owner мог отключить их в Cloud Admin Panel — попросите включить.
- **Self-hosted:** проверьте переменную `N8N_COMMUNITY_PACKAGES_ENABLED=true` (значение по умолчанию). Подробнее — в [официальных доках n8n](https://docs.n8n.io/hosting/configuration/environment-variables/nodes/).
- **Старая версия n8n** (< 1.0): community-ноды не поддерживаются — обновите n8n до актуальной версии

### Кнопка Install неактивна

**Причина:** verified-ноду может установить только **instance owner** или **admin**.

**Решение:** запросите установку у администратора. После установки нода доступна всем участникам instance — отдельной активации для каждого пользователя не нужно.

## Ошибки авторизации

### Неверный токен (401 Unauthorized)

<ImageCard src="/images/n8n/error-invalid-token.avif" alt="Ошибка 401 при неверном токене" caption="Ошибка авторизации" maxWidth={960} />

**Причина:** указан некорректный или просроченный Access Token.

**Решение:**

1. Откройте **Credentials** и проверьте значение **Access Token**
2. Убедитесь, что токен скопирован целиком, без лишних пробелов
3. Нажмите **Test** — при ошибке создайте новый токен в Пачке
4. Для токена бота: значение показывается только при создании, поэтому потерянный токен перевыпустите в карточке бота на вкладке **API** (**Перевыпустить** в меню токена)
5. Для персонального токена: создайте новый на странице **Интеграции** → **API**

### Недостаточно прав (403 Forbidden)

**Причина:** операция требует более высокий уровень доступа, чем предоставляет текущий токен.

**Решение:**

Доступ к операциям определяют [скоупы](/api/authorization#skoupy) и тип токена. Убедитесь, что у токена есть нужные скоупы и что операция работает с его типом:

| Операция | Требуемые скоупы |
|----------|-----------------|
| Управление сотрудниками (User > Create/Update/Delete) | `users:create`, `users:update`, `users:delete` (доступны администраторам и владельцам) |
| Журнал безопасности (Security > Get Many) | `audit_events:read` (доступен владельцу пространства на тарифе «Корпорация») |
| Управление тегами (Group Tag > Create/Update/Delete) | `group_tags:write` (доступен администраторам и владельцам) |
| Автоматическая регистрация вебхука в Pachca Trigger | `profile:read` и `bot_self:webhook:write` (токен бота) или `bots:write` (персональный токен) |
| Отправка сообщений (Message > Create) | `messages:create` |
| Чаты (Chat > Create/Update) | `chats:create`, `chats:update` |
| Напоминания (Task > Create/Update/Delete) | `tasks:create`, `tasks:update`, `tasks:delete` |
| Формы (Form > Create, Submit Response) | `views:write`, только с токеном бота |
| Разворачивание ссылок (Message > Unfurl) | `link_previews:write`, только с токеном бота |
| История и поток событий (Bot > Get Many Events, Get Stream, Remove Events) | `webhooks:events:read`, `webhooks:events:delete`, только с токеном бота |
| Черновики (Draft) и «Важное» (Important Message) | `drafts:read`, `drafts:write`, `important_messages:read`, `important_messages:write`, только с персональным токеном |

Набор прав для типового сценария n8n — в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi), остальное — в разделе [Авторизация](/api/authorization).

### 403 Forbidden при активации Pachca Trigger

**Причина:** узел попытался автоматически прописать Webhook URL, но у токена не хватает прав. Для **токена бота** нужен скоуп `bot_self:webhook:write` (саморегистрация методом [Саморегистрация вебхука бота](PUT /bot/webhook)). Для **персонального токена** — скоуп `bots:write` и доступ редактора к указанному боту (регистрация методом [Редактирование бота](PUT /bots/{id})).

Текст ошибки:

> Pachca rejected bot webhook self-registration (403 Forbidden).

или

> Pachca rejected automatic webhook registration (403 Forbidden).

**Решение:**

1. **Токен бота:** добавьте токену право `bot_self:webhook:write` — в карточке бота на вкладке **API** выберите **Редактировать** в меню токена
2. **Токен бота и заполненный Bot ID:** без права `profile:read` узел принимает токен бота за персональный и прописывает адрес методом [Редактирование бота](PUT /bots/{id}), который токену бота недоступен — добавьте токену право `profile:read` и очистите поле **Bot ID**
3. **Персональный токен:** убедитесь, что владелец токена может редактировать бота — он его создатель или подходит под настройку **Кто может редактировать настройки бота** — и что у токена есть скоуп `bots:write` (**Редактировать** в меню токена на странице **Интеграции** → **API**)
4. Либо переключите **Webhook Setup** = **Manual** и пропишите Production URL в настройках бота самостоятельно — см. [Ручной режим](/guides/n8n/trigger#ruchnoy-rezhim)

### Узел не определил тип токена

**Причина:** в автоматическом режиме узел определяет тип токена методом [Свой профиль](GET /profile), а у токена нет права `profile:read`. Без него и без **Bot ID** узел не активируется.

Текст ошибки:

> The token lacks the profile:read scope, so the node cannot tell a bot token from a personal one.

**Решение:**

1. **Токен бота:** добавьте токену право `profile:read` — в карточке бота на вкладке **API** выберите **Редактировать** в меню токена, затем активируйте workflow заново
2. **Персональный токен:** заполните в узле поле **Bot ID**, подробнее — в разделе [Автоматический режим](/guides/n8n/trigger#avtomaticheskiy-rezhim)
3. Либо переключите **Webhook Setup** = **Manual** — см. [Ручной режим](/guides/n8n/trigger#ruchnoy-rezhim)

## Ошибки лимитов

### Превышение лимита (429 Too Many Requests)

**Причина:** слишком много запросов за единицу времени. Точные числа по типам операций и лимит на входящие вебхуки — на отдельной странице [Лимиты](/api/limits).

**Решение в n8n:**

1. Добавьте узел **Wait** между операциями для замедления
2. Для массовой отправки разбейте элементы на порции узлом **Loop Over Items** и поставьте **Wait** внутри цикла
3. Для массового чтения используйте **Return All** = `false` с ограниченным **Limit**

<Info>При `429` и временных ошибках сервера узел сам повторяет запрос. Правила повторов и случаи, когда узел сразу завершается ошибкой, описаны в разделе [Повторные запросы](/api/limits#povtornye-zaprosy-retry).</Info>

## Ошибки триггера

### Вебхук не приходит

**Возможные причины и решения:**

1. **Событие не отмечено в карточке бота** — в обоих режимах регистрации Пачка присылает только события, отмеченные на вкладке **Исходящий вебхук**, а новый бот не получает даже новых сообщений. Отметьте пункт по таблице из раздела [Поддерживаемые события](/guides/n8n/trigger#podderzhivaemye-sobytiya), а для **New Message** выберите режим «Любые сообщения» или перечислите команды.
2. **Бот не добавлен в чат** — о сообщениях, реакциях, участниках чатов и видеозвонках бот узнаёт только из чатов, в которых состоит. Добавьте бота в нужный чат.
3. **Workflow не активирован** — нажмите **Activate** в правом верхнем углу. Неактивные workflow не принимают вебхуки.
4. **URL не прописан в настройках бота** — в ручном режиме узел не трогает слот вебхука бота. Проверьте, что Production URL указан адресом на вкладке **Исходящий вебхук** в карточке бота. В автоматическом режиме с персональным токеном убедитесь, что в узле указан верный **Bot ID**.
5. **Слот занят другим workflow** — у бота один адрес вебхука, и события получает workflow, чей адрес записан последним. Дайте каждому workflow с Pachca Trigger своего бота или соберите события в одном workflow с событием **All Events**, подробнее — в разделе [Как работают вебхуки в Пачке](/guides/n8n/trigger#kak-rabotayut-vebhuki-v-pachke).
6. **Слот очистил тест** — после **Listen for Test Event** в автоматическом режиме узел оставляет адрес вебхука пустым. Активируйте workflow заново, подробнее — в разделе [Тестирование триггера](/guides/n8n/testing#testirovanie-triggera).
7. **n8n недоступен извне** — при локальной установке Пачка не может отправить вебхук на `localhost`. Используйте туннель или разверните n8n на сервере с публичным адресом, подробнее — в разделе [Локальная разработка](/guides/n8n/testing#lokalnaya-razrabotka).

### Ошибка подписи (Signature Mismatch)

**Причина:** значение поля **Webhook Signing Secret** в Credentials не совпадает с секретом бота в Пачке. Секрет меняется, например, когда вебхук удаляют кнопкой **Удалить вебхук**.

**Решение:** скопируйте поле **Signing secret** с вкладки **Исходящий вебхук** в карточке бота и вставьте его в поле **Webhook Signing Secret** в Credentials.

## Ошибки данных

### Entity ID не найден

**Причина:** указан несуществующий ID чата, пользователя или сообщения.

**Решение:**

- Для чатов: выберите чат в режиме **From List** или найдите его операцией **Search** > **Get Many Chats**
- Для сотрудников: выберите сотрудника в режиме **From List** или найдите его операцией **Search** > **Get Many Users**
- Для сообщений: убедитесь, что сообщение не было удалено

Где взять идентификаторы вручную — в разделе [Где взять идентификаторы](/api/requests-responses#gde-vzyat-identifikatory).

### Бот не может отправить сообщение

**Причина:** бот не является участником целевого чата.

**Решение:** добавьте бота в чат. Бот может отправлять сообщения только в те чаты, в которых он состоит.

## Ошибки форм

### Форма не открывается

**Причина:** форму по `trigger_id` из события `button_pressed` нужно открыть методом [Открытие представления](POST /views/open) в первые **3 секунды**, позже форма не откроется. Подробнее — в разделе [Сроки ответа](/guides/webhook/handler#sroki-otveta).

**Решение:**

1. Убедитесь, что узел **Form > Create** стоит сразу после триггера, без долгих операций между ними
2. Не используйте узел **Wait** между получением `trigger_id` и открытием формы
3. Дополнительную логику выполняйте после отправки формы

Подробнее о формах — в [документации форм](/guides/forms/overview).

## Ошибки пагинации

### Возвращаются не все данные

**Причина:** API возвращает данные постранично. Если **Return All** выключен, вы получаете только первую страницу (по умолчанию до 50 записей).

**Решение:**

1. Включите **Return All** = `true` в настройках узла — n8n автоматически пройдёт по всем страницам через cursor-based пагинацию
2. Если нужен ограниченный набор — используйте **Return All** = `false` и укажите нужное число в поле **Limit**
3. Для больших объёмов данных учитывайте [лимиты API](#oshibki-limitov) — при Return All n8n делает несколько запросов последовательно
