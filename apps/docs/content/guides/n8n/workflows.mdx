# Примеры workflow

Ниже — готовые сценарии, которые можно воспроизвести в n8n. Все они используют узел **Pachca**, а сценарии, которые отвечают на события в Пачке, используют ещё и **Pachca Trigger**.

<Warning>У бота один адрес исходящего вебхука, поэтому каждому workflow с Pachca Trigger нужен свой бот. Подробнее — в разделе [Как работают вебхуки в Пачке](/guides/n8n/trigger#kak-rabotayut-vebhuki-v-pachke).</Warning>

После импорта сценария с Pachca Trigger отметьте его события на вкладке **Исходящий вебхук** в карточке бота. Нужные пункты названы у каждого сценария, а полная таблица — в разделе [Поддерживаемые события](/guides/n8n/trigger#podderzhivaemye-sobytiya).

## Уведомления из внешнего сервиса

Внешний сервис — мониторинг, CI/CD, CRM или форма на сайте — отправляет запрос на адрес узла **Webhook** в n8n, а узел **Pachca** публикует сообщение в чат, выбранный по содержимому запроса. Pachca Trigger здесь не участвует, поэтому адрес исходящего вебхука и отмеченные события боту не нужны.

**Как работает:**

1. **Webhook** — принимает `POST`-запрос сервиса, тело запроса доступно в `$json.body`
2. **Switch** — выбирает чат по полю `level`: `critical` уходит в чат дежурных, остальное — в общий чат алертов
3. **Pachca** (Message > Create) — публикует в выбранный чат заголовок из поля `title` и текст из поля `text`

Запрос, на который рассчитан workflow:

```bash title="Тестовый запрос к workflow"
curl -X POST "https://N8N_HOST/webhook/pachca-alerts" \
  -H "Content-Type: application/json" \
  -d '{"level": "critical", "title": "База недоступна", "text": "db-1 не отвечает три минуты"}'
```

Поля `level`, `title` и `text` — пример. У настоящего сервиса поля свои: нажмите **Listen for test event** в узле Webhook, отправьте из сервиса тестовый запрос на его Test URL и подставьте в Switch и Pachca поля, которые пришли в Output.

**Вариант с CRM:** в настройках CRM укажите Production URL узла Webhook как адрес уведомлений, например о новой сделке. В Switch разведите сделки по воронке или ответственному, а в узле Pachca соберите сообщение из полей сделки. Если CRM присылает только идентификатор сделки, поставьте перед Pachca узел HTTP Request, который запросит сделку через API CRM.

1. **Pachca Trigger** — событие `Chat Member Added`

## Пересылка сообщений между каналами

Автоматическая пересылка сообщений из одного чата в другой.

<ImageCard src="/images/n8n/workflow-forward.avif" alt="Workflow пересылки сообщений" caption="Пересылка сообщений между каналами" maxWidth={960} />

**Как работает:**

1. **Pachca Trigger** — событие `New Message` (в исходном канале)
2. **IF** — пропускает только сообщения из исходного чата
3. **Pachca** (Message > Create) — отправка в целевой канал с указанием автора

**Когда полезно:** дублирование важных новостей в общие каналы, агрегация обсуждений.

## Напоминание о задачах

Ежедневная проверка просроченных задач с уведомлением в чат.

<ImageCard src="/images/n8n/workflow-reminder.avif" alt="Workflow напоминания о задачах" caption="Напоминание о просроченных задачах" maxWidth={960} />

**Как работает:**

1. **Schedule Trigger** — запуск по будним дням в 10:00
2. **Pachca** (Task > Get Many) — получение списка задач
3. **IF** — фильтр: только невыполненные и просроченные (дедлайн раньше текущего момента)
4. **Pachca** (Message > Create) — сообщение в чат о каждой просроченной задаче

**Что можно добавить:** одно сообщение со списком через узел Aggregate, личные уведомления ответственным, группировка по проектам.

## Согласование с кнопками

Запрос на согласование через сообщение с кнопками и обработка ответа.

<ImageCard src="/images/n8n/workflow-approval.avif" alt="Workflow согласования с кнопками" caption="Согласование с Data-кнопками" maxWidth={960} />

**Как работает:**

1. **Manual Trigger** или **Webhook** — инициация запроса
2. **Pachca** (Message > Create) — отправка сообщения с кнопками «Согласовать» / «Отклонить»
3. **Pachca Trigger** (в отдельном workflow) — событие `Button Pressed`
4. **Switch** — маршрутизация по `data` из нажатой кнопки
5. **Pachca** (Message > Update) — обновление исходного сообщения с результатом: кнопки убираются пустым списком `[]` в **Button Layout** > **Raw JSON**

**Пример кнопок:**

```json
[
  [
    { "text": "Согласовать", "data": "approve" },
    { "text": "Отклонить", "data": "reject" }
  ]
]
```

Этот JSON вставляется в поле **Buttons (JSON)** при **Button Layout** = **Raw JSON**. Подробнее о кнопках — в разделе [Продвинутые функции](/guides/n8n/advanced#knopki-v-soobscheniyah).

## Мониторинг и алерты

Периодическая проверка состояния и отправка алерта при аномалиях.

<ImageCard src="/images/n8n/workflow-monitoring.avif" alt="Workflow мониторинга с алертами" caption="Мониторинг с отправкой алертов в Пачку" maxWidth={960} />

**Как работает:**

1. **Schedule Trigger** — проверка каждые 5 минут
2. **HTTP Request** — запрос к внешнему API или сервису
3. **IF** — проверка: статус не 200 или сервис не ответил. В HTTP Request включены **Full Response** и **Never Error**, а при ошибке соединения узел продолжает работу, поэтому до IF доходит любой исход
4. **Pachca** (Message > Create) — отправка алерта в канал мониторинга

**Что можно добавить:** проверка нескольких сервисов, графики через разворачивание ссылок, эскалация в личные сообщения.

## Заявка на отпуск

Сценарий с кнопками, формой и согласованием в треде: бот принимает заявку через модальную форму и отправляет её руководителю на согласование.

**Как работает:** у бота один адрес вебхука, поэтому весь сценарий — один workflow с одним **Pachca Trigger** на событие `All Events`. Узел **Switch** разводит события по четырём веткам:

1. **Команда `/отпуск`** (новое сообщение) — **Pachca** (Message > Create) отправляет в тот же чат сообщение с Data-кнопкой «Создать заявку»
2. **Нажатие «Создать заявку»** — **Pachca** (Form > Create) открывает форму с полями «Дата начала», «Дата окончания», «Комментарий». `trigger_id` берётся из события кнопки, `callbackId` формы — `vacation_form`
3. **Отправка формы** (`callback_id` = `vacation_form`) — **Pachca** (Message > Create) отправляет заявку в чат руководителя с кнопками «Согласовать» и «Отклонить». В `data` кнопок записан id сотрудника
4. **Решение руководителя** — **Pachca** (Message > Update) убирает кнопки, **Pachca** (Thread > Create) заводит тред под заявкой, **Pachca** (Message > Create) пишет решение в тред, ещё один Message > Create сообщает его сотруднику в личные сообщения

**Что задействовано:** триггер, кнопки, формы, треды, условная логика.

<Info>Подробнее о кнопках — в разделе [Кнопки в сообщениях](/guides/n8n/advanced#knopki-v-soobscheniyah), о формах — в разделе [Формы](/guides/n8n/advanced#formy).</Info>

  Команда, форма, заявка руководителю и решение в треде
</Card>

<Info>После импорта замените Credentials и `CHAT_ID_HR` во всех узлах Pachca. Боту нужен доступ к чату руководителя. На вкладке **Исходящий вебхук** отметьте пункты «Новые сообщения» и «Нажатие кнопок», а для новых сообщений выберите режим «Начинающиеся с команд» с командой `/отпуск` или режим «Любые сообщения».</Info>

## AI-ассистент

Бот, использующий AI для ответов на вопросы на основе истории чата.

<ImageCard src="/images/n8n/ai-agent-tool.avif" alt="Настройка AI Agent с Pachca Tool" caption="AI Agent с инструментами Pachca" maxWidth={960} />

**Как работает:**

1. **Pachca Trigger** — событие `New Message`
2. **AI Agent** — обработка запроса с LLM
3. **Pachca** (Search > Get Many Messages) — как Tool для поиска информации
4. **Pachca** (Message > Create) — как Tool для отправки ответа

На вкладке **Исходящий вебхук** отметьте пункт «Новые сообщения» в режиме «Любые сообщения» и включите «Игнорировать свои сообщения», чтобы бот не отвечал на собственные ответы.

<Info>Для использования AI Agent необходимо настроить LLM-провайдер (OpenAI, Anthropic и др.) в n8n. Подробнее — в разделе [Продвинутые функции](/guides/n8n/advanced#ai-agent).</Info>
