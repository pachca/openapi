# Теги

Тег в Пачке — это именованная группа сотрудников: «Дизайн», «Питер», «Дежурные». Отметьте тегом нужных людей — и дальше зовите сразу всех: тег упоминают в сообщении и привязывают к чату.

Тег живёт в пространстве и не привязан к конкретному чату, поэтому один и тот же тег работает сразу везде, где он нужен. Когда состав команды меняется, достаточно поправить тег — чаты подтянутся сами.

## Теги в чате

Привяжите тег к каналу, и все сотрудники тега окажутся в этом канале. Дальше состав поддерживается сам: добавили человеку тег — он появился во всех чатах тега, сняли тег — вышел из них. Так состав чатов следует за структурой команды, и расставлять людей по чатам вручную не нужно.

Тег привязывают к беседе или каналу — к чатам, у которых есть состав участников. Чат при этом должен быть активным: в архивном чате теги не меняются.

За привязку отвечают методы [Добавление тегов](POST /chats/{id}/group_tags) и [Исключение тега](DELETE /chats/{id}/group_tags/{tag_id}). Оба относятся к составу участников и требуют скоуп `chat_members:write`. Текущие теги чата приходят в поле `group_tag_ids` объекта чата, и его же можно передать сразу при вызове [Новый чат](POST /chats).

| Что нужно | Как |
| --- | --- |
| Создать чат сразу с тегами | [Новый чат](POST /chats), поле `group_tag_ids` |
| Добавить теги в существующий чат | [Добавление тегов](POST /chats/{id}/group_tags) |
| Убрать тег из чата | [Исключение тега](DELETE /chats/{id}/group_tags/{tag_id}) |
| Узнать теги чата | [Информация о чате](GET /chats/{id}), поле `group_tag_ids` |

<Info>Добавление тега применяется в самом запросе, а исключение выполняется фоново. Сразу после успешного `DELETE` участники какое-то время ещё приходят в методе [Список участников чата](GET /chats/{id}/members).</Info>

## Упоминание тега

Тег упоминается в тексте сообщения как `@Дизайн` — так же, как сотрудник. Уведомление получит каждый сотрудник тега, который состоит в этом чате.

В треде упоминание работает шире: сотрудники тега добавляются в сам тред, даже если в родительском чате их нет. Так тег собирает нужных людей в обсуждение одной строкой. Отключается это параметром `skip_invite_mentions` метода [Новое сообщение](POST /messages) — подробнее в руководстве по [тредам](/guides/threads).

Упоминания разбираются в момент отправки, поэтому тег, добавленный в текст позже методом [Редактирование сообщения](PUT /messages/{id}), уведомление не рассылает.

## Теги у сотрудника

Набор тегов сотрудника — это поле `list_tags` в методах [Новый сотрудник](POST /users) и [Редактирование сотрудника](PUT /users/{id}). В поле передаются названия тегов, а не идентификаторы, и присланный массив заменяет прежний набор целиком. Остальные поля сотрудника при этом можно не присылать.

- **Названия создают теги.** Если тега с таким названием в пространстве ещё нет, он создаётся вместе с назначением. Отдельно заводить его методом [Новый тег](POST /group_tags) не нужно.
- **Теги назначаются сотрудникам пространства.** Для гостевых ролей поле не применяется.

<Info>Чтобы добавить сотруднику ещё один тег, прочитайте текущие теги методом [Информация о сотруднике](GET /users/{id}) и отправьте их вместе с новым. Если прислать только новый, прежние теги снимутся, а сотрудник выйдет из их чатов.</Info>

Назначение и снятие тега пишутся в [журнал аудита](/guides/audit-events) событиями `user_added_to_tag` и `user_removed_from_tag`.

## Как убрать из чата участника, которого добавил тег

Сотрудник, попавший в чат по тегу, остаётся в чате, пока действует тег. Поэтому убирают его через тег, а не через список участников:

- снять с сотрудника тег через `list_tags` — тогда он выйдет из всех чатов этого тега;
- убрать тег из чата методом [Исключение тега](DELETE /chats/{id}/group_tags/{tag_id}) — тогда выйдут все, кто попал в чат по этому тегу.

Если сотрудника добавили в чат два тега, после снятия одного он остаётся: второй продолжает действовать.

<Info>Методы для отдельных участников такого сотрудника из чата не выводят: [Выход из беседы или канала](DELETE /chats/{id}/leave) отвечает `403`, а [Исключение пользователя](DELETE /chats/{id}/members/{user_id}) отвечает `204` и оставляет состав прежним. Если вы меняете состав чатов из кода, проверяйте результат по [Списку участников чата](GET /chats/{id}/members).</Info>

## Удаление тега и исключение тега из чата

Названия у операций похожие, а результат разный.

| Операция | Что происходит с участниками чатов |
| --- | --- |
| [Исключение тега](DELETE /chats/{id}/group_tags/{tag_id}) | Выходят из чата все, кого в нём держал только этот тег |
| [Удаление тега](DELETE /group_tags/{id}) | Остаются во всех чатах, но уже сами по себе, без тега |

Создатель чата остаётся в своём чате в обоих случаях.

## Названия

Название задаётся при создании и меняется методом [Редактирование тега](PUT /group_tags/{id}).

- Не длиннее 255 символов.
- Уникально в пространстве без учёта регистра: «Дизайн» и «дизайн» — один и тот же тег.
- Без символа `@` и не равно `here` или `all` — эти слова заняты системными упоминаниями.

Пробелы по краям обрезаются, а одно и то же название, присланное дважды, считается за один тег.

## Поиск тега по названию

По идентификатору тег отдаёт метод [Информация о теге](GET /group_tags/{id}). Когда известно только название, теги ищутся параметром `names` метода [Список тегов сотрудников](GET /group_tags): он принимает до 100 названий за один запрос.

```http title="Идентификаторы двух тегов одним запросом"
GET /api/shared/v1/group_tags?names[]=Дизайн&names[]=Питер
```

<Info>Поле `users_count` объекта тега считает действующих сотрудников, а [Список сотрудников тега](GET /group_tags/{id}/users) отдаёт всех, включая деактивированных. Поэтому число в `users_count` может быть меньше, чем длина списка.</Info>

## Права

| Действие | Кому доступно |
| --- | --- |
| Читать теги и их состав | Владелец, Администратор, Сотрудник, бот |
| Создавать, переименовывать и удалять теги | Владелец, Администратор |
| Менять теги сотрудника | Владелец, Администратор |
| Привязывать теги к чату и снимать их | Участник беседы или канала |

Какие скоупы доступны каждой роли — в руководстве [Права и роли](/guides/permissions).

## Теги в журнале аудита

Действия с тегами попадают в [журнал аудита](/guides/audit-events) шестью событиями.

| Событие | Когда |
| --- | --- |
| `tag_created` | Создан тег |
| `tag_deleted` | Удалён тег |
| `user_added_to_tag` | Сотруднику назначен тег |
| `user_removed_from_tag` | С сотрудника снят тег |
| `tag_added_to_chat` | Тег привязан к чату |
| `tag_removed_from_chat` | Тег отвязан от чата |

Актором в событиях `user_added_to_tag` и `user_removed_from_tag` выступает сам сотрудник, а инициатор изменения приходит в `details.initiator_id`.
