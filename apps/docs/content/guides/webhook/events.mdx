# Настройка и типы событий

Все настройки исходящего вебхука собраны на вкладке **Исходящий вебхук** в карточке бота. Пока вебхук выключен, на вкладке одна кнопка **Включить**: она спрашивает URL вашего сервера, а остальные настройки появляются после включения.

<ImageCard src="/images/outgoing-webhook.webp" alt="Вкладка «Исходящий вебхук» в карточке бота: адрес, подпись, история, свои сообщения и список событий" caption="Вкладка «Исходящий вебхук» в карточке бота" maxWidth={792} />

## Общие настройки

- **Webhook URL** — адрес, на который Пачка отправляет события. Подходит только публичный адрес `http` или `https`: локальные и внутренние адреса не принимаются, для разработки подойдёт туннель.
- **Signing secret** — ключ HMAC-SHA256 для проверки подписи из заголовка `Pachca-Signature`. Появляется после включения вебхука. Подробнее — в разделе [Безопасность и обработчик](/guides/webhook/handler).
- **Сохранять историю событий** — бот сохраняет все исходящие вебхуки в очередь, и их можно получить через API. Подробнее — в разделе [Поллинг](/guides/webhook/polling).
- **Игнорировать свои сообщения** — не получать вебхуки о сообщениях, отправленных самим ботом, и о реакциях, которые он сам поставил или снял. Реакции других участников на сообщения бота приходят всегда. Предотвращает зацикливание, когда бот реагирует на собственные сообщения. Нажатия кнопок обрабатываются всегда, вне зависимости от этой настройки.

Кнопка **Удалить вебхук** внизу вкладки отключает вебхук: события перестают доставляться, история событий, режим новых сообщений и «Игнорировать свои сообщения» возвращаются к начальным значениям, а **Signing secret** выпускается новый. Если включить вебхук снова, он, как новый, подписан на новые сообщения.

## Какие события откуда приходят

События отмечают в списке на той же вкладке. Большинство приходит из чатов, где состоит бот, и из их тредов. Тред, куда бота добавили без родительского чата, — тоже такой чат.

| Событие на вкладке | Значения в `events` | Откуда приходит |
| --- | --- | --- |
| **Новые сообщения** | `message_new` | Чаты, где состоит бот, и их треды |
| **Редактирование и удаление сообщений** | `message_update`, `message_delete` | Чаты, где состоит бот, и их треды |
| **Добавление и удаление реакций** | `reaction_new`, `reaction_delete` | Чаты, где состоит бот, и их треды |
| **Нажатие кнопок** | `button_click` | Нажатия кнопок в сообщениях самого бота и отправка форм, которые он открыл |
| **Изменение состава участников чатов** | `chat_member_add`, `chat_member_remove` | Чаты, где состоит бот, и их треды |
| **Изменение участников пространства** | `company_member_invite`, `company_member_confirm`, `company_member_suspend`, `company_member_activate`, `company_member_delete`, `company_member_update` | Всё пространство |
| **Отправка ссылок в сообщении (unfurl)** | `message_link_shared` | Все чаты пространства, только ссылки на домены бота |
| **Начало видеозвонка**, **Завершение видеозвонка**, **Готовность записи видеозвонка** | `video_call_started`, `video_call_finished`, `video_call_recording_ready` | Чаты, где состоит бот, и их треды |

## Через API

Те же настройки задаются в объекте `webhook` метода [Редактирование бота](PUT /bots/{id}) или сразу при создании методом [Новый бот](POST /bots), а текущие значения возвращаются в объекте бота:

| Настройка | Поле |
| --- | --- |
| **Webhook URL** | `outgoing_url`, пустая строка отключает вебхук |
| События | `events` — значения из таблицы выше |
| Режим новых сообщений | `trigger_on`: `all_messages` или `commands` |
| Команды | `commands` — список команд, вместе через запятую не длиннее 255 символов |
| **Сохранять историю событий** | `events_history_enabled` |
| **Игнорировать свои сообщения** | `ignore_self_messages` |
| Домены для ссылок | `unfurl_domains` |

Персональному токену для этого нужен скоуп `bots:write` и доступ к настройкам бота. Бот может и сам прописать свой адрес собственным токеном — методом [Саморегистрация вебхука бота](PUT /bot/webhook) со скоупом `bot_self:webhook:write`, без участия администратора: так, например, [n8n](/guides/n8n/trigger) регистрирует свой адрес. Боту с включённым [разворачиванием ссылок](/guides/link-previews) адрес меняет только администратор или владелец, и саморегистрация вернёт ошибку.

## Сообщения

В настройках доступны два отдельных пункта:

- **Новые сообщения** — создание сообщений
- **Редактирование и удаление сообщений** — изменение текста или файлов и удаление сообщений

Для новых сообщений доступны два режима отслеживания:

- **Любые сообщения** — все новые сообщения, включая треды
- **Начинающиеся с команд** — только сообщения, первое слово которых совпадает с одной из команд, например `/help` или `/deploy`. Команды перечисляются через запятую, совпадение проверяется точно, с учётом регистра. Полезно, если вы не хотите получать поток событий, а вам нужно вызвать сценарий только по требованию пользователя.

Режим действует и на редактирование: в режиме «Начинающиеся с команд» о правке приходят только сообщения, которые начинаются с команды. Удаления приходят всегда.

<Info>Режим «Любые сообщения» присылает событие и для сообщений без текста, например только с файлом или картинкой. Режим «Начинающиеся с команд» для них не сработает, потому что команда определяется по первому слову текста, которого в таком сообщении нет.</Info>

<Warning>Новый бот стоит в режиме «Начинающиеся с команд» с пустым списком команд и о новых сообщениях не узнаёт. Так у ботов, созданных и в интерфейсе, и методом [Новый бот](POST /bots) без `trigger_on`. Выберите режим «Любые сообщения» или перечислите команды. Подробнее — в разделе [Общение с ботом](/guides/bots/conversations).</Warning>

<SchemaBlock name="MessageWebhookPayload" />

<Info>Payload содержит только основные поля сообщения: текст, автора, чат, ответ и тред. По payload нельзя определить, есть ли у сообщения вложение: у сообщения без текста (например, только с файлом) поле `content` придёт пустой строкой. Вложения, реакции, кнопки, информацию о пересланном сообщении и другие поля получите методом [Информация о сообщении](GET /messages/{id}) по полю `id`. Для события `delete` метод по-прежнему отвечает `200`, но возвращает уже очищенную запись: `content` пустой, вложения и реакции удалены, заполнено поле `deleted_at`. В списке сообщений такая запись не возвращается.</Info>

## Реакции

Вебхук отправляется при добавлении или удалении реакции на сообщение.

<SchemaBlock name="ReactionWebhookPayload" />

<Info>Payload содержит все данные реакции. Если нужен контекст, получите сообщение методом [Информация о сообщении](GET /messages/{id}) по `message_id` или автора методом [Информация о сотруднике](GET /users/{id}) по `user_id`.</Info>

## Нажатие кнопок

Вебхук отправляется при нажатии `Data`-кнопки в сообщении от бота. После получения вы можете изменить или удалить кнопки методом [Редактирование сообщения](PUT /messages/{id}) или ответить пользователю методом [Новое сообщение](POST /messages). Подробнее — в разделе [Кнопки в сообщениях](/guides/buttons).

<SchemaBlock name="ButtonWebhookPayload" />

<Info>Payload содержит данные нажатой кнопки. Полное сообщение получите методом [Информация о сообщении](GET /messages/{id}) по `message_id`.</Info>

## Заполнение формы

Вебхук отправляется при отправке пользователем заполненной формы ([представления](/guides/forms/overview)). Подробнее об обработке результатов — в разделе [Обработка форм](/guides/forms/handling). Если у бота не задан адрес исходящего вебхука, ответить на это событие можно методом [Ответ на отправку формы](POST /views/{view_id}/submit_response) по `view_id` и `submit_id` из payload.

<Info>Поле `chat_id` фиксируется в момент **открытия** формы (нажатия кнопки), а не её отправки: если форма провисела открытой долго, поле всё равно ссылается на чат с кнопкой.</Info>

<SchemaBlock name="ViewSubmitWebhookPayload" />

<Info>Payload содержит все заполненные поля формы в `data`, дополнительных запросов не требуется. При необходимости получите автора методом [Информация о сотруднике](GET /users/{id}) по `user_id`.</Info>

## Изменение участников чатов

Вебхук отправляется при изменении состава участников чата.

<Info>Когда сотрудник впервые открывает личную переписку с ботом, события нет — ни об изменении участников, ни о новом чате. Бот узнаёт о сотруднике из его первого сообщения.</Info>

<SchemaBlock name="ChatMemberWebhookPayload" />

<Info>Payload содержит только идентификаторы. Полные данные сотрудников получите методом [Информация о сотруднике](GET /users/{id}) по каждому `user_id`, а сам чат — методом [Информация о чате](GET /chats/{id}) по `chat_id`.</Info>

## Изменение участников пространства

Вебхук отправляется, когда участника пространства приглашают, он принимает приглашение, его приостанавливают, снова активируют или удаляют, а также когда меняются его данные. Добавлять бота в чат не нужно.

<SchemaBlock name="CompanyMemberWebhookPayload" />

<Info>Payload содержит только идентификаторы сотрудников. Полные данные получите методом [Информация о сотруднике](GET /users/{id}) по каждому `user_id`.</Info>

## Отправка ссылок

Вебхук отправляется при появлении в сообщении ссылки на один из доменов бота — из любого чата пространства, добавлять бота в чаты не нужно. Событие **Отправка ссылок в сообщении (unfurl)** и его домены (до 5, через запятую) включает только администратор или владелец пространства. После получения вы можете воспользоваться методом [Unfurl (разворачивание ссылок)](POST /messages/{id}/link_previews) и создать предпросмотр ссылки в сообщении. Подробнее — в разделе [Разворачивание ссылок](/guides/link-previews).

<SchemaBlock name="LinkSharedWebhookPayload" />

<Info>Payload содержит обнаруженные ссылки. Полное сообщение получите методом [Информация о сообщении](GET /messages/{id}) по `message_id`.</Info>

## Видеозвонки

Вебхук отправляется о видеозвонках. Поле `event` в payload различает три события: `started` (звонок начался), `finished` (звонок завершился) и `recording_ready` (запись готова). Набор полей payload зависит от события.

<SchemaBlock name="VideoCallWebhookPayload" />

<Info>Для события `finished` payload содержит список участников с временем подключения и выхода, для `recording_ready` — ссылку на файл записи, её размер и длительность. Полные данные участников получите методом [Информация о сотруднике](GET /users/{id}) по каждому `user_id`, а чат — методом [Информация о чате](GET /chats/{id}) по `chat_id`.</Info>
