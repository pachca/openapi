title: 'MCP-сервер, плагин «Пачка», раздел «Важное» и перевод в гости'
---

Появился MCP-сервер Пачки: Claude Code, Cursor и другие программы с AI-агентами подключаются по адресу `https://mcp.pachca.com/mcp` и получают инструмент на каждый метод API. Права те же, что в API, а программу, подключённую через браузер, видно в списке «Авторизации» на странице «API». Через браузер входят Claude Code, приложение Claude, VS Code с GitHub Copilot, Codex и приложение ChatGPT на компьютере, а Cursor и многие другие программы подключаются персональным токеном. Подробнее — в разделах [MCP-сервер](/guides/mcp/overview) и [Подключение к MCP](/guides/mcp/connect).

Скиллы для AI-агентов написаны заново: теперь это знание о том, как правильно делать задачи в Пачке. Куда писать и когда спрашивать перед действием, как найти и пересказать обсуждение, какой токен выбрать и почему не хватает прав. Справочник по аргументам агент берёт из описаний инструментов MCP-сервера и `pachca <команда> --help`. В Claude Code, приложении Claude, Codex, VS Code с GitHub Copilot и Cursor скиллы вместе с MCP-сервером ставит плагин «Пачка», в нём же команды для сводки пропущенного, пересказа треда, дайджеста, объявления и задач по итогам обсуждения. В SourceCraft Code Assistant, OpenCode и другие агенты восемь скиллов ставятся без плагина. Страницы «Сценарии», файл Arazzo и команда `pachca guide` убраны, их роль взяли скиллы. Подробнее — в разделе [Плагин и скиллы](/guides/mcp/plugin).

Через API можно вести личный раздел «Важное»: получать список отмеченных сообщений, добавлять в него сообщение и убирать оттуда. Отметку видит только сам сотрудник, и она остаётся после выхода из чата. Методы работают с токеном сотрудника, токену бота они недоступны. У сообщений в ответах API появилось поле `important`. У добавления и удаления свой [лимит](/api/limits).

Были добавлены новые методы:

- [Список важных сообщений](GET /important_messages)
- [Добавление сообщения в важные](POST /important_messages)
- [Удаление сообщения из важных](DELETE /important_messages/{id})

Методом [Редактирование сотрудника](PUT /users/{id}) сотрудника или мульти-гостя можно перевести в гости, указав чат, в котором он останется. Перевод снимает все теги, выводит из остальных бесед и каналов и отзывает все токены сотрудника, включая доступы, выданные ботам и программам с MCP. Повышение роли ничего из этого не возвращает. Подробнее — в разделе [Перевод в гости](/guides/permissions#perevod-v-gosti).

Бот без публичного адреса может получать события сразу, как они происходят: по ссылке в формате Server-Sent Events. Так он успевает ответить на нажатие кнопки или отправку формы. Подробнее — в разделе [События в реальном времени](/guides/webhook/polling#sobytiya-v-realnom-vremeni).

Был добавлен новый метод:

- [Поток событий](GET /webhooks/events/stream)

Ещё изменения:

- [Новый чат](POST /chats) отвечает `422` с кодом `blank` на пустое название и возвращает в `meta` идентификаторы тегов, которых нет в пространстве.
- [Новый тег](POST /group_tags) и [Редактирование тега](PUT /group_tags/{id}) отвечают `400` с кодом `blank` на пустое название.
- Методы [Новый бот](POST /bots), [Редактирование бота](PUT /bots/{id}), [Ротация токена бота](POST /bots/{id}/recreate_token) и [Ротация секрета клиента](POST /bots/{id}/rotate_client_secret) отдают адрес входящего вебхука и секрет подписи при тех же правах, что [Информация о боте](GET /bots/{id}).
- Создатель нового самостоятельного треда становится его владельцем: исключает участников и удаляет чужие сообщения. Подробнее — в разделе [Права в треде](/guides/threads#prava-v-trede).
- [Экспорт сообщений](POST /chats/exports) отвечает `422` с кодом `too_long` на список больше 50 чатов и `422` с кодом `invalid` на дату не в формате YYYY-MM-DD.
- При правке сообщения файл, переданный с тем же `key`, остаётся прежним вложением с тем же `id` и названием. Размер файла можно не передавать: Пачка возьмёт его из хранилища.
- Метод [Скачивание файла](GET /files/{id}) отдаёт любое вложение, которое видно токену: защищённое — запросу из безопасного контура, остальные — всегда, кроме файла, в котором антивирус нашёл вирус. Запрос `HEAD` на тот же адрес отдаёт размер и имя файла без скачивания. Подробнее — в разделе [Ссылка на скачивание](/api/file-uploads#ssylka-na-skachivanie).
- Событие `update` о сообщении приходит и без правки, например когда сообщение добавили в «Важное». Подробнее — в разделе [Сообщения](/guides/webhook/events#soobscheniya).
- Чат, сообщение, тред, файл и экспорт другого пространства отвечают `404`, как несуществующие.
- Курсор, который метод не может прочитать, отвечает `400` с кодом `invalid`. Подробнее — в разделе [Пагинация](/api/pagination).
- Эмодзи статуса в текстовой форме принимается и возвращается с U+FE0F.
- Ошибка, не привязанная к полю, приходит с `system` в `key`, а ошибки параметров — с именем поля и кодом `required`, `blank`, `in`, `min_length`, `max_length` или `invalid`. Отказ в правах на разворачивание ссылок приходит как `400` с кодом `forbidden`.
- В журнале аудита отзыв токенов при переводе в гости отмечен `reason: guest_downgrade`, а `limit` в деталях поиска через API — запрошенный размер страницы.
- Сообщения, отправленные после входа в CLI через браузер, помечены подсказкой «Отправлено через «Pachca CLI»».
- SDK, CLI и n8n повторяют ошибки `500`, `502`, `503` и `504` только у запросов GET, PUT и DELETE, а ответ `504` с кодом `timeout` возвращают сразу, без повторов. Подробнее — в разделе [Повторные запросы](/api/limits#povtornye-zaprosy-retry).
- SDK отдаёт ответ с ошибкой без тела или не в JSON обычной ошибкой `ApiError`, а у каждой `ApiError` появился код статуса ответа. Подробнее — в разделе [Обработка ошибок](/guides/sdk/typescript#obrabotka-oshibok).
- Команда `pachca auth logout` закрывает вход через браузер на сервере и тогда, когда сохранённый токен уже истёк. Подробнее — в разделе [Выход](/guides/cli/authentication#vyhod).

Были обновлены следующие методы: [Редактирование сотрудника](PUT /users/{id}), [Новый чат](POST /chats), [Новый тег](POST /group_tags), [Редактирование тега](PUT /group_tags/{id}), [Новый бот](POST /bots), [Редактирование бота](PUT /bots/{id}), [Ротация токена бота](POST /bots/{id}/recreate_token), [Ротация секрета клиента](POST /bots/{id}/rotate_client_secret), [Саморегистрация вебхука бота](PUT /bot/webhook), [Новый самостоятельный тред](POST /threads), [Экспорт сообщений](POST /chats/exports), [Новое сообщение](POST /messages), [Редактирование сообщения](PUT /messages/{id}), [Скачивание файла](GET /files/{id}), [Новый свой статус](PUT /profile/status), [Новый статус сотрудника](PUT /users/{user_id}/status), [Журнал аудита событий](GET /audit_events), [История событий](GET /webhooks/events).

Документация точнее описывает, как работает API:

- Сортировка `order` в методах [Список чатов](GET /chats) и [Список сообщений чата](GET /messages) работает только вместе с `sort`.
- [Добавление реакции](POST /messages/{id}/reactions) ставит кастомный эмодзи пространства по его имени в `name`.
- Повтор отложенного сообщения из метода [Новый черновик](POST /drafts) считается по UTC: время и день повтора берутся из даты первой отправки так, как они записаны.
- Кнопка со ссылкой работает в сообщении любого отправителя, а кнопка с `data` — только в сообщении бота.
- [Список напоминаний](GET /tasks) без фильтра по чатам возвращает все напоминания активных чатов сотрудника, в том числе чужие.
- [Редактирование напоминания](PUT /tasks/{id}) заменяет список ответственных целиком.
- Напоминание на весь день задаётся сроком ровно на 23:59:59 нужного дня: при другом времени срока Пачка показывает это время и у напоминания с `all_day`.
- [Поиск сообщений](GET /search/messages) без фильтра по чатам не ищет в тредах личных чатов и в самостоятельных тредах.
- [Архивация чата](PUT /chats/{id}/archive) удаляет из чата гостей, а мульти-гости в нём остаются.
- [Экспорт сообщений](POST /chats/exports) отклоняет адрес вебхука, недоступный из интернета, кодом `invalid_webhook_url`, и экспорт тогда не запускается. Подробнее — в разделе [Экспорт сообщений](/guides/export).
- Адресом возврата OAuth может быть собственная схема приложения, например `com.example.app:/oauth`, а фрагмент `#…` в адресе не допускается. Подробнее — в разделе [Включение](/guides/oauth/setup#vklyuchenie).
