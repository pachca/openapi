# Отметка чата прочитанным

**Метод**: `PUT`

**Путь**: `/chats/{id}/read`

> **Скоуп:** `chats:mark_read`

Отмечает чат прочитанным для владельца токена до последнего сообщения на момент запроса, как если дочитать его до конца в интерфейсе. Прочитанными станут и сообщения, пришедшие уже после того, как вы получили историю. Чтобы оставить новые сообщения непрочитанными, после вызова отметьте чат методом [Отметка чата непрочитанным](/api/chats/mark-unread).

Метод обнуляет счётчик непрочитанного и снимает отметку непрочитанного упоминания «@» и ручную отметку «Непрочитанное». Чат пропадает из непрочитанных чатов, а тред из непрочитанных тредов. Так же это работает в архивном чате и с выключенными уведомлениями, и ни архив, ни уведомления метод не меняет. Треды чата — отдельные чаты: каждый тред отмечают по его `chat_id`.

Остальные участники видят свои сообщения прочитанными, а владелец токена появляется в [Списке прочитавших сообщение](/api/read-member/list-readers) у всех сообщений до конца чата. С персональным токеном это выглядит так, будто чат прочитал сам сотрудник. С токеном бота чат отмечается прочитанным для бота, и авторы увидят «Прочитано», даже если сообщения не открыл ни один сотрудник. Отправка сообщения тоже двигает позицию чтения, но «Прочитано» у чужих сообщений появляется только после этого метода.

В ответе приходит `last_read_message_id`, позиция чтения после вызова. В чате без сообщений она `null`, и метод ничего не меняет. Повторный запрос ничего не меняет и не рассылает событие о прочтении повторно.

Работает в беседах, каналах, личных чатах и тредах, где владелец токена состоит, и никуда его не добавляет: тред передают его `chat_id`. Открытый чат или доступный тред, где владелец токена не состоит, и чат другого пространства отвечают `404`. Закрытый чат, где владелец токена не состоит, отвечает `403`, в том числе владельцу и администраторам пространства. `403` отвечают и недоступный тред, и открытый чат, где не состоит мульти-гость. У метода свой [лимит](/api/limits) на частоту запросов.

## Параметры

### Path параметры

- `id: integer, int32` (required) — Идентификатор чата (беседы, канала, личного чата или чата треда)


## Пример запроса

```bash
curl -X PUT "https://api.pachca.com/api/shared/v1/chats/334/read" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

## Ответы

### 200: The request has succeeded.

**Схема ответа:**

- `data: object` (required) — Позиция чтения владельца токена в чате
  - `last_read_message_id: integer, int32` (required, nullable) — Идентификатор последнего прочитанного сообщения. `null`, если в чате нет сообщений. Последнее сообщение чата учитывается, даже если его удалили, поэтому это может быть идентификатор удалённого сообщения, которого нет в списке сообщений. Пример: `1194275`

**Пример ответа:**

```json
{
  "data": {
    "last_read_message_id": 1194275
  }
}
```

### 401: Access is unauthorized.

**Схема ответа при ошибке:** `OAuthError`. Поля и коды описаны в разделе [Ошибки](/api/errors).

**Пример ответа:**

```json
{
  "error": "invalid_token",
  "error_description": "Access token is missing"
}
```
