# Запросы и ответы

## Базовый URL

Все запросы к API отправляются по HTTPS:

```text
https://api.pachca.com/api/shared/v1
```

## Заголовки

| Заголовок | Значение | Когда нужен |
|-----------|----------|-------------|
| `Authorization` | `Bearer YOUR_ACCESS_TOKEN` | Все методы, кроме обмена кода на токен и отзыва токена |
| `Content-Type` | `application/json; charset=utf-8` | Запросы POST и PUT с телом в JSON |

Подробнее о типах токенов и скоупах — в разделе [Авторизация](/api/authorization).

Несколько методов принимают тело в другом формате:

- Загрузка аватара сотрудника, бота или чата (например, [Загрузка своего аватара](/api/profile/update-avatar)) — форма `multipart/form-data`
- [Обмен кода на токен](/api/oauth/exchange-token) и [Отзыв токена](/api/oauth/revoke-token) — `application/x-www-form-urlencoded`, как требует OAuth 2.0, а приложение подтверждает себя секретом клиента
- [Получение подписи, ключа и других параметров](/api/files/uploads) вызывается без тела, а сам файл уходит в хранилище на адрес `direct_url` формой `multipart/form-data` и без заголовка `Authorization`: подробнее — в разделе [Загрузка файлов](/api/file-uploads)

## Запросы из браузера

API вызывают с сервера, из скрипта или из [CLI](/guides/cli/overview). Запрос из JavaScript на странице вашего сайта браузер заблокирует: запросы с других сайтов (CORS) API разрешает только веб-приложению Пачки. Режим `no-cors` не поможет: ответ останется недоступен странице. Публичный CORS-прокси ответ отдаст, но токен пройдёт через чужой сервер.

Токен в коде веб-страницы прочитает любой посетитель. Поэтому страница отправляет запросы на ваш сервер, а он хранит токен и вызывает API.

## Тело запроса

Параметры передаются в формате JSON, кодировке UTF-8. Для методов, работающих с сущностями, тело оборачивается в корневой ключ с именем сущности:

```json
{
  "message": {
    "entity_id": 12345,
    "content": "Привет!"
  }
}
```

> Обёртка используется не во всех методах — точную структуру тела смотрите в описании каждого метода.


### Пример запроса

**Создание сотрудника**

```bash
curl "https://api.pachca.com/api/shared/v1/users" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "user": {
    "first_name": "Олег",
    "last_name": "Петров",
    "email": "olegp@example.com",
    "phone_number": "+79001234567",
    "nickname": "olegpetrov",
    "department": "Продукт",
    "title": "CIO",
    "role": "user",
    "list_tags": [
      "Product",
      "Design"
    ],
    "chat_ids": [
      12345
    ],
    "custom_properties": [
      {
        "id": 1678,
        "value": "Санкт-Петербург"
      }
    ]
  }
}'
```


## Формат ответа

Ответы возвращаются в формате JSON, кодировке UTF-8.

### Одиночный объект

Успешный ответ содержит данные в объекте `data`:

```json
{
  "data": {
    "id": 12,
    "first_name": "Олег",
    "last_name": "Петров",
    "email": "olegp@example.com"
  }
}
```

### Список с пагинацией

Списочные методы возвращают массив `data` и блок `meta.paginate` с курсорами и флагами:

```json
{
  "data": [
    { "id": 1, "name": "Общий" },
    { "id": 2, "name": "Проект" }
  ],
  "meta": {
    "paginate": {
      "next_page": "eyJpZCI6MTAsIl9rZCI6Im4ifQ",
      "prev_page": "eyJpZCI6MSwgIl9rZCI6InAifQ",
      "has_next": true,
      "has_prev": false
    }
  }
}
```

Подробнее — в разделе [Пагинация](/api/pagination).

### Ответы другой формы

Несколько методов отвечают без обёртки `data` или без `meta`. Форма ответа каждого метода указана в его описании.

- [Получение подписи, ключа и других параметров](/api/files/uploads) возвращает поля для загрузки, в том числе `direct_url`, прямо в корне ответа
- [Добавление реакции](/api/reactions/add) возвращает реакцию без обёртки `data`
- [Список дополнительных полей](/api/custom-properties/list) возвращает массив `data` без `meta`: список приходит целиком
- [Каталог прав бота](/api/bots/list-scopes) возвращает поля `scopes`, `groups` и `presets` на верхнем уровне
- [Ответ на отправку формы](/api/views/submit-response) возвращает `{"success": true}`
- [Обмен кода на токен](/api/oauth/exchange-token) возвращает поля токена на верхнем уровне, как принято в OAuth 2.0, а [Отзыв токена](/api/oauth/revoke-token) — пустой объект
- [Скачивание файла](/api/files/get) отдаёт сам файл, а [Скачать архив экспорта](/api/chats/download-export) отвечает `302` со ссылкой на архив
- [Открытие представления](/api/views/open) отвечает `201` без тела

### Пустой ответ

Удаление и действия, которым нечего вернуть (добавление участников, закрепление, архивация), отвечают `204 No Content` без тела.

### Ошибка

При ошибке возвращается одна из двух структур в зависимости от типа ошибки:

```json title="Ошибка запроса (400 или 422)"
{
  "errors": [
    {
      "key": "image",
      "value": null,
      "message": "Поле обязательно для заполнения",
      "code": "blank",
      "payload": null
    }
  ]
}
```

Ошибки в параметрах запроса приходят в массиве `errors` с названием поля в `key` и кодом в `code`. Пропущенный обязательный параметр, как в примере, даёт `422`. Неверное значение одни методы отклоняют с `422`, другие с `400`, например напоминания и редактирование чата. Структура тела у обоих кодов одна, поэтому обрабатывайте их одинаково.

```json title="Ошибка авторизации (401)"
{
  "error": "invalid_token",
  "error_description": "Access token is invalid"
}
```

Подробнее — в разделах [Ошибки](/api/errors) и [Лимиты](/api/limits).

## Соглашения

| Соглашение | Пример |
|------------|--------|
| Имена полей — `snake_case` | `first_name`, `entity_id`, `created_at` |
| Даты и время — ISO 8601 | `2024-01-15T07:30:00.000Z` |
| Идентификаторы объектов — целые числа | `"id": 12345` |
| Пустые значения — `null` | `"nickname": null` |
| Логические поля — `boolean` | `"suspended": false` |

Часть идентификаторов приходит строками: `id` в [истории событий](/api/bots/list-events), `id`, `entity_id`, `actor_id` и часть полей `details` в [журнале аудита](/api/security/list), идентификаторы форм `trigger_id`, `view_id`, `submit_id` и `callback_id`, `client_id` авторизации от имени сотрудника и `id` позиций в [каталоге прав бота](/api/bots/list-scopes). Тип каждого поля указан в описании метода.

В ответах время всегда приходит в UTC: с буквой `Z` на конце и ровно тремя знаками долей секунды. В запросах можно присылать и смещение — `2024-01-15T10:30:00.000+03:00` будет понято правильно. Время без смещения считается за UTC: пояс из карточки сотрудника на разбор входящих значений нигде не влияет. Поэтому время, названное сотрудником («в три часа»), переводите в UTC или присылайте со смещением сами.

Одно исключение — `start_date` в повторяющемся расписании отложенного сообщения: повтор идёт по часам UTC, подробнее — в разделе [Отложенное сообщение](/guides/ai-agents/drafts#otlozhennoe-soobschenie).

## Где взять идентификаторы

Идентификаторы стоят в путях методов и в полях вроде `entity_id`. Большинство из них видно в ссылке веб-приложения Пачки, остальные возвращают методы API.

| Объект | В ссылке веб-приложения | Через API |
|--------|-------------------------|-----------|
| Чат | Число из пути `/chats/{id}`: в `https://app.pachca.com/chats/12345` это `12345` | [Список чатов](/api/chats/list), [Поиск чатов](/api/search/list-chats) по названию, поле `chat_id` в событиях [исходящего вебхука](/guides/webhook/overview) |
| Сотрудник | Число из параметра `user_id` в ссылке на профиль | [Список сотрудников](/api/users/list), [Поиск сотрудников](/api/search/list-users), свой — [Свой профиль](/api/profile/get) |
| Бот | Поле `user_id` на вкладке **API** в карточке бота: в методах API это `id` бота | Поле `id` в ответах [Новый бот](/api/bots/create) и [Список ботов](/api/bots/list), сам бот получает свой `id` методом [Свой профиль](/api/profile/get) |
| Сообщение | Число из параметра `message` в ссылке на сообщение, у сообщения в треде — из параметра `sidebar_message` | Поле `id` в ответе [Новое сообщение](/api/messages/create), в [Списке сообщений чата](/api/messages/list) и в событии о новом сообщении |
| Тред | Число из параметра `thread_id` в ссылке на самостоятельный тред, у треда под сообщением в ссылке стоит `thread_message_id` (подробнее — ниже) | Поле `thread` в ответе [Информация о сообщении](/api/messages/get), ответ метода [Новый тред](/api/threads/add) |
| Тег | Число из параметра `tag_id` в адресе, пока открыт тег | [Список тегов](/api/group-tags/list) |

Личное сообщение адресуют идентификатором сотрудника с `entity_type: "user"`, идентификатор личного чата для этого не нужен.

У треда два идентификатора. `id` треда передают в `entity_id` с `entity_type: "thread"`, чтобы написать в тред. `chat_id` треда — идентификатор его чата: по нему читают сообщения треда методом [Список сообщений чата](/api/messages/list), добавляют участников и тоже пишут в тред с `entity_type: "discussion"`. Параметр `thread_message_id` в ссылке на тред — идентификатор сообщения, под которым открыт тред, а сам тред приходит в поле `thread` этого сообщения.

## Тестирование API

### Scalar

Онлайн-клиент с интерфейсом для тестирования всех методов API прямо в браузере — без установки. Достаточно вставить токен и отправить запрос.

- [Открыть Scalar API Client](https://client.scalar.com/?url=https://dev.pachca.com/openapi.yaml) — Браузерный клиент на основе OpenAPI-спецификации. Бесплатно, без регистрации.


> **Внимание:** Браузерный клиент Scalar отправляет запросы через прокси-сервер `proxy.scalar.com` — это необходимо из-за ограничений браузера (CORS). Токен проходит через сервер Scalar, но [по их заявлению](https://github.com/scalar/scalar) данные не логируются. Scalar — проект с открытым исходным кодом (MIT), включая код прокси. Если вы хотите избежать передачи токена через сторонний сервер, используйте Postman или Bruno — они работают локально и отправляют запросы напрямую.


### Postman / Bruno

Коллекция содержит все методы API с примерами запросов и настроенной авторизацией. Совместима с:

- **Postman** — *File > Import*
- **Bruno** (open-source альтернатива) — *File > Import > Postman Collection*

```plaintext title="Коллекция Postman/Bruno"
https://dev.pachca.com/pachca.postman_collection.json
```

- [Скачать коллекцию](/pachca.postman_collection.json) — Файл в формате Postman Collection v2.1, совместим с Postman и Bruno.
