# Удаление сотрудника

**Метод**: `DELETE`

**Путь**: `/users/{id}`

> **Скоуп:** `users:delete`

Убирает сотрудника из пространства. Отменить это нельзя: вернуть его можно только новым приглашением, и это будет уже другой сотрудник.

Что происходит: он выходит из всех бесед и каналов, кроме личных переписок, с него снимаются все теги, напоминания, где он был единственным ответственным, удаляются, а из остальных он убирается. Написанные им сообщения и файлы остаются на месте.

Владельца пространства удалить нельзя — метод ответит `403`. Повторный вызов отвечает `404`: удалённого сотрудника метод уже не находит.

Если сотрудник уходит в отпуск или увольнение ещё не финальное, пользуйтесь методом [Редактирование сотрудника](/api/users/update) с `suspended: true`. Приостановка обратима и сохраняет чаты, теги и напоминания.

## Параметры

### Path параметры

- `id: integer, int32` (required) — Идентификатор пользователя


## Пример запроса

```bash
curl -X DELETE "https://api.pachca.com/api/shared/v1/users/12" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

## Ответы

### 204: There is no content to send for this request, but the headers may be useful. 

### 401: Access is unauthorized.

**Схема ответа при ошибке:** `OAuthError`. Поля и коды описаны в разделе [Ошибки](/api/errors).

**Пример ответа:**

```json
{
  "error": "invalid_token",
  "error_description": "Access token is missing"
}
```

### 402: Client error

**Схема ответа при ошибке:** `ApiError`. Поля и коды описаны в разделе [Ошибки](/api/errors).

**Пример ответа:**

```json
{
  "errors": [
    {
      "key": "field.name",
      "value": "invalid_value",
      "message": "Поле не может быть пустым",
      "code": "blank",
      "payload": null
    }
  ]
}
```

### 403: Access is forbidden.

**Схема ответа при ошибке:** `ApiError` или `OAuthError`. Поля и коды описаны в разделе [Ошибки](/api/errors).

**Пример ответа:**

```json
{
```
