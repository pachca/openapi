# AI-агенты

Пачка — готовая среда для AI-агентов. Эта страница для команд и разработчиков: чем Пачка уже помогает в работе с агентами, как агента подключить и куда смотреть дальше.

## Пачка как среда для AI-агентов

Упомяните агента в треде — остальное он сделает сам. Агент находится внутри разговора, видит контекст и действует автономно.

- **Агент — участник команды.** Он читает обсуждения, создаёт задачи и присылает результаты. Работу выполняет агент, а отвечает за неё тот, кто его позвал.
- **[Треды](/guides/threads) как единица работы.** Агента зовут в тред, и он отвечает туда же, не засоряя общий чат. Если агент не состоит в чате, он видит только этот тред и сообщение, к которому тред открыт.
- **Сквозные треды.** Упомяните в треде сотрудника, и он увидит тред, даже если не состоит в исходном чате. Один тред — общая точка координации сотрудников и агента.
- **Самостоятельные треды.** Тред можно создать без привязки к чату — как отдельное место для диалога с агентом, куда добавляют только нужных участников.

Технически агент — это бот: его зовут по нику, он получает сообщения через исходящий вебхук и отвечает токеном бота. Как это устроено — в разделах [Взаимодействие с агентом](/guides/ai-agents/interaction) и [Общение с ботом](/guides/bots/conversations).

## Как подключить Пачку к агенту

Все способы вызывают одни и те же методы API с правами токена, которым подключён агент. Выбирайте по тому, кто работает с Пачкой и где:

| Кто работает и где | Что подходит |
|---|---|
| Сотрудник в программе с агентом: Claude, Claude Code, Codex, приложение ChatGPT, VS Code, Cursor | [MCP-сервер](#mcp-server), а в Claude Code, приложении Claude, Codex, VS Code и Cursor — [плагин «Пачка»](#plagin-i-skilly) с ним внутри |
| Агент с терминалом, которому важно беречь контекст, а также скрипты и CI | [CLI](#cli) |
| Вы пишете свою интеграцию или сервис | [API и SDK](#api-i-sdk) |
| Агент живёт в Пачке: его зовут по нику в треде или пишут ему в личные сообщения | Бот, подробнее — в разделе [Взаимодействие с агентом](/guides/ai-agents/interaction) |
| Сценарий в n8n с узлом AI Agent | [Пачка как инструмент AI Agent](/guides/n8n/advanced#ai-agent) |

Агенту нужен токен. Какой выбрать для агента на машине сотрудника, агента без участия сотрудника или CI — в разделе [Какой токен выбрать](/api/authorization#kakoy-token-vybrat).

### MCP-сервер

Claude Code, Cursor и другие программы с агентом подключаются к Пачке по адресу и получают инструмент на каждый метод API, доступный токену. Код писать не нужно, а права те же, что в API: агент видит и делает только то, что можно владельцу токена. Подходит, когда агенту нужна Пачка по ходу работы, а запускать команды он не может или не должен.

```text
https://mcp.pachca.com/mcp
```

Всё о сервере собрано в отдельном разделе [MCP](/guides/mcp/overview): как он устроен, как подключить программу и какие инструменты получит агент.

- [MCP-сервер](/guides/mcp/overview) — Как устроен, права, безопасность и пределы
- [Подключение к MCP](/guides/mcp/connect) — Вход через браузер и токен в заголовке для разных программ
- [Инструменты MCP](/guides/mcp/tools) — Все инструменты: метод API, кому доступен и пометка


### CLI

Подходит агенту, у которого есть терминал. Документацию в контекст загружать не нужно: агент узнаёт команды из `--help` и тратит меньше контекста, чем с MCP. Если есть доступ к shell, агент может написать скрипт для типовой задачи.

```bash
# Справка по API без входа и без токена
npx -y @pachca/cli api ls                         # список методов
npx -y @pachca/cli api POST /messages --describe  # параметры, тело, эквивалентная команда

# Для регулярной работы
npm install -g @pachca/cli
pachca auth login
pachca messages create --entity-id 123 --content "Готово"
pachca users list -o json
```

Через CLI доступны и произвольные запросы к любому методу, и вся документация API прямо в терминале: список методов, их параметры, схемы и полный справочник. Подробнее — в разделе [Прямые запросы](/guides/cli/api-requests).

```bash
# Произвольный запрос к любому методу
pachca api POST /messages -F 'message[entity_id]=123' -f 'message[content]=Привет'

# Документация по API прямо в терминале
pachca api GET /messages --spec       # OpenAPI-фрагмент
pachca api POST /messages --docs      # полный markdown-референс
```

- [@pachca/cli](https://www.npmjs.com/package/@pachca/cli) — Пакет на npm
- [Руководство CLI](/guides/cli/overview) — Установка, авторизация, скрипты и CI, полный справочник команд

### Плагин и скиллы

Скиллы — знание о том, как правильно делать задачи в Пачке: куда писать и что подтверждать, как найти и пересказать обсуждение, какой токен выбрать и почему не хватает прав. Они работают с MCP-сервером, CLI и API. Плагин «Пачка» ставит их вместе с MCP-сервером и командами, а в программы без плагина скиллы ставятся отдельно.

- [Плагин и скиллы](/guides/mcp/plugin) — Установка плагина и скиллов в Claude Code, Claude, Codex, VS Code, Cursor и другие агенты, команды плагина и все скиллы


## Документация для агента

Агенту, который пишет код под API или разбирается, как устроена Пачка, нужна документация. Её можно отдать несколькими способами.

### llms.txt

Самый простой способ дать агенту документацию: скопируйте ссылку в промпт, и он получит сводку API, способы подключения и ссылки на страницы. Подходит, когда агент пишет код под API или разово разбирается, как что-то устроено.

```text title="Пример промпта"
Напиши обработчик исходящего вебхука Пачки.
Документация: https://dev.pachca.com/llms.txt
```

Полная документация в одном файле — [llms-full.txt](/llms-full.txt). Файл большой и целиком в контекст агента обычно не помещается: берите из него нужные разделы. Для постоянной работы подключите MCP-сервер или CLI: так агенту не нужно искать и загружать страницы документации.

- [llms.txt](/llms.txt) — Краткая сводка документации со ссылками на страницы
- [llms-full.txt](/llms-full.txt) — Полная документация в одном файле, из которого агент берёт нужные разделы


> Любая страница документации доступна в Markdown: добавьте `.md` к адресу страницы, например `/guides/webhook/overview.md`, или запросите её с заголовком `Accept: text/markdown`. Главная страница в Markdown — `/index.md`.


### OpenAPI-спецификация

Наиболее полное описание API без дополнительных обвязок: типы, схемы, все методы. Подходит для кодогенерации на языках, для которых нет [SDK](/guides/sdk/overview), и для своих инструментов. Запросы вручную удобно пробовать в [коллекции Postman](/pachca.postman_collection.json).

```text
https://dev.pachca.com/openapi.yaml
```

- [OpenAPI-спецификация](/openapi.yaml) — OpenAPI 3.0 — типы, схемы, все методы
