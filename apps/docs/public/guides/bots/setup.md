# Создание бота

Бота можно создать двумя способами:

- **Через интерфейс** — в разделе **Интеграции** > **Боты**. Подходит для ручной настройки: у каждой возможности бота своя вкладка в его карточке.
- **Через API** ([Новый бот](/api/bots/create)) — программно, без интерфейса. Подходит для автоматизации: завести бота из своего сервиса или скрипта и сразу получить `access_token`.

> **Внимание:** Создавать ботов могут администраторы и сотрудники, а владелец пространства может оставить это только администраторам. Подробнее — в разделе [Кто может создавать токены](/api/authorization#kto-mozhet-sozdavat-tokeny).


## Создание бота через интерфейс

> **Внимание:** Создание и настройка ботов через интерфейс доступны в веб-версии и десктопном приложении Пачки. В мобильных приложениях (iOS и Android) эта возможность недоступна.


Откройте **Интеграции** > **Боты** и нажмите **Создать бота**. В диалоге два поля:

- **Название** — имя бота в чатах и в его профиле.
- **Ник для @упоминаний** — можно оставить пустым, тогда ник соберётся из названия. Ник уникален в пространстве и оканчивается на `_bot`.

![Диалог создания бота с полями «Название» и «Ник для @упоминаний»](/images/bots/bot_new.webp)

*Создание бота*


После создания откроется карточка бота. Бот создаётся без токенов и вебхуков, а каждая возможность включается на своей вкладке, когда понадобится. Чаще всего сразу нужны три шага:


  ### Шаг 1. Выпустите токен

На вкладке **API** нажмите **Создать токен**, задайте название и права. Значение токена показывается один раз: скопируйте его до закрытия окна. Подробнее — в разделе [Токены бота](/guides/bots/tokens).


  ### Шаг 2. Настройте доступ

На вкладке **Основное** решите, кто может добавлять бота в чаты и кто может его редактировать, и нужен ли публичный бот. Там же меняются имя, аватар и ник. Подробнее — в разделе [Настройки бота](/guides/bots/settings).


  ### Шаг 3. Включите исходящий вебхук

Чтобы бот узнавал о сообщениях и нажатиях кнопок, на вкладке **Исходящий вебхук** нажмите **Включить**, укажите URL своего сервера и отметьте события. Для новых сообщений выберите режим: новый бот слушает только команды, а их список пуст. Подробнее — в разделе [Первый диалог с ботом](/guides/bots/first-contact).


### Вкладка «Управление»

![Список ботов на вкладке «Управление»: название, создатель, число авторизаций, дата создания и последнее использование](/images/bots/bots_management.webp)

*Вкладка «Управление»*


На вкладке **Управление** собраны боты, которых вы можете редактировать: созданные вами и те, чьи настройки открывают вам доступ. Для каждого видны создатель, число сотрудников, [авторизовавших бота](/guides/oauth/overview), дата создания и когда бот последний раз обращался к API или получал вебхук. Из меню бота открываются его профиль и карточка, там же бота можно удалить.

## Создание бота через API

Бота можно создать программно методом [Новый бот](/api/bots/create) — без интерфейса. Это удобно, когда нужно завести бота из своего сервиса или скрипта.


  ### Шаг 1. Отправьте запрос на создание

Передайте параметры бота в объекте `bot.webhook`: имя, никнейм, Webhook URL, список событий и команды. Никнейм должен заканчиваться на `_bot`.

Обязательное поле одно — имя. Его и никнейм можно передать и на уровне `bot`, тогда объект `bot.webhook` не нужен: `{"bot": {"name": "Бот задач"}}` создаст бота с настройками вебхука по умолчанию.

По умолчанию `trigger_on` равен `commands`, а список команд пуст, поэтому о новых сообщениях бот не узнает. Если бот должен отвечать на сообщения, передайте `trigger_on: "all_messages"` или перечислите команды в `commands`.

Ограничение одним чатом задаётся полем `single_chat` только при создании: метод [Редактирование бота](/api/bots/update) его не меняет. В интерфейсе то же ограничение переключается в любой момент.


  ### Шаг 2. Сохраните access_token

В ответе вы получите `access_token` бота — сразу сохраните его. Повторно значение не показывается ни в интерфейсе, ни через API: потерянный токен перевыпускают. Вместе с токеном придёт `id` бота (его `user_id`).


Бот, созданный через API, сразу принимает запросы на входящий вебхук в своём формате, с шаблонизатором Liquid. Подробнее — в разделе [Входящие вебхуки](/guides/incoming-webhooks).

## Жизненный цикл через API

Получить параметры существующего бота можно методом [Информация о боте](/api/bots/get), а изменить — методом [Редактирование бота](/api/bots/update). Бот может и сам прописать `URL` своего исходящего вебхука собственным токеном — методом [Саморегистрация вебхука бота](/api/bots/update-webhook), без участия администратора.

- [Список ботов](/api/bots/list) — боты, доступные вам для редактирования, с поиском по имени в параметре `query`. Полный перечень ботов пространства доступен Владельцу отдельным методом, см. [Права и роли](/guides/permissions#inventarizatsiya-botov-prostranstva).
- [Ротация токена бота](/api/bots/recreate-token) и [Ротация собственного токена бота](/api/bots/recreate-token-self) — перевыпуск токена. Подробнее — в разделе [Токены бота](/guides/bots/tokens#tokeny-cherez-api).
- [Удаление бота](/api/bots/delete) — токены отзываются, бот исключается из чатов, его вебхуки удаляются.

Изменения настроек бота попадают в [журнал аудита](/guides/audit-events): смена прав токена, настроек вебхука и авторизации, перевыпуск токена и удаление бота.
