# Токены бота

Токен бота — ключ, которым ваш код обращается к [API](/guides/quickstart) от имени бота: отправляет сообщения, читает чаты, открывает формы. Токены выпускаются на вкладке **API** в карточке бота. Там же указан `user_id` бота: это его `id` в методах API.

```http title="Заголовок авторизации"
Authorization: Bearer <токен бота>
```

## Выпуск токена

![Вкладка «API» в карточке бота: user_id и список токенов бота с кнопкой «Создать токен»](/images/bots/bot_tokens.webp)

*Вкладка «API» в карточке бота*


  ### Шаг 1. Создайте токен

На вкладке **API** нажмите **Создать токен** и задайте название — по нему токен узнаётся в списке, например по имени сервиса, который им пользуется.


  ### Шаг 2. Выберите права

Права задаются на каждый токен отдельно. Выдавайте минимально необходимые: токен для уведомлений не должен уметь удалять сообщения.


  ### Шаг 3. Скопируйте значение

Значение токена показывается один раз, сразу после создания. Скопируйте его до закрытия окна — повторно его не покажут ни в интерфейсе, ни через API.


Токены бота не имеют срока жизни: токен работает, пока его не перевыпустят, не удалят или пока не удалят самого бота.

## Несколько токенов

У бота может быть несколько токенов, у каждого своё название и свои права. Удобно выпускать отдельный токен на каждый сервис, который работает от имени бота: если один из них скомпрометирован или больше не нужен, его отзывают, не трогая остальные.

В списке у каждого токена видны начало значения, число выданных разрешений и когда токен последний раз использовался. Меню токена позволяет:

- **Список разрешений** — посмотреть, что токену разрешено
- **Редактировать** — изменить название и права. Новые права действуют сразу, выпускать токен заново не нужно.
- **Перевыпустить** — старое значение перестаёт работать сразу, новое показывается один раз, а название и права сохраняются
- **Удалить** — токен перестаёт работать, восстановить его нельзя. Если токеном пользовались недавно, диалог удаления предупредит об этом.

## Права токена

Права определяют, какие методы API можно вызывать этим токеном. Круг данных они не расширяют: бот видит открытые каналы и чаты, куда его добавили, какие бы права ни были у токена. Подробнее — в разделе [Доступы к чатам и сообщениям](/guides/bots/access).

Часть прав есть только у ботов:

- `bot_self:webhook:write` — бот сам меняет адрес своего исходящего вебхука методом [Саморегистрация вебхука бота](/api/bots/update-webhook). Так делает, например, [n8n](/guides/n8n/trigger) в автоматическом режиме.
- `bot_self:write` — бот сам перевыпускает свой токен методом [Ротация собственного токена бота](/api/bots/recreate-token-self).

Права для черновиков, управления ботами и другие права, которые выдаются только персональным токенам, боту недоступны. Полная таблица прав по ролям — в разделе [Доступные скоупы](/api/authorization#dostupnye-skoupy). Проверить права текущего токена можно методом [Информация о токене](/api/oauth/token-info).

## Токены через API

Метод [Новый бот](/api/bots/create) создаёт бота вместе с токеном и возвращает его в поле `access_token` один раз. Права этого токена задаются полем `scopes`, а если его не передать, бот получит набор по умолчанию.

Перевыпустить токен можно двумя методами. [Ротация токена бота](/api/bots/recreate-token) — перевыпуск токена чужому боту персональным токеном (скоуп `bots:write`). [Ротация собственного токена бота](/api/bots/recreate-token-self) — бот перевыпускает токен сам себе (право `bot_self:write`). Прежнее значение перестаёт работать сразу, новое приходит в ответе один раз.

> В интерфейсе у бота может быть несколько токенов, а методы API работают с одним из них: с тем, что в списке идёт без имени, а если такого нет — с самым старым. К нему относятся `access_token` в ответе, поле `scopes` и ротация токена. Остальные токены бота управляются в интерфейсе.


## Если токен утёк

Перевыпустите токен кнопкой **Перевыпустить** или методом ротации: старое значение перестанет работать в ту же секунду. Затем обновите токен в сервисах, которые им пользуются. Если токен больше не нужен, удалите его.

Токен в руках — это доступ ко всем данным бота. Не храните его в коде и репозиториях, передавайте через переменные окружения и хранилища секретов. Помните, что токены бота может выпустить каждый, кто редактирует бота: круг редакторов задаётся на вкладке **Основное** — подробнее в разделе [Настройки бота](/guides/bots/settings#kto-mozhet-redaktirovat-nastroyki-bota).
