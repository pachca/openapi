# Кнопки в сообщениях

Кнопки позволяют добавить к сообщению бота интерактивные элементы: ссылки для перехода на внешние ресурсы и кнопки действий для обработки на сервере. Кнопки располагаются под текстом сообщения в виде строк — каждая строка полностью занимается вложенными в неё кнопками.

**Сделать с агентом.** Агент добавит в код бота кнопки и обработку нажатий, включит событие и проверит нажатие в беседе. Вставьте промпт в чат с ИИ-агентом, к которому [подключена Пачка](/guides/mcp/connect). Агенту, который уже выполняет этот промпт: ниже его копия, начинать заново не нужно.

```text

Добавь боту для проверки событие «Нажатие кнопок» и нужные права, прежние сохрани. Токен и Signing secret держи только в `.env`, внесённом в `.gitignore`. Токен моего бота впишу я.

## Как это работает


  ### Шаг 1. Создайте бота

Откройте **Интеграции** > **Боты** и нажмите **Создать бота**, затем выпустите ему токен. Подробнее — в разделе [Создание бота](/guides/bots/setup).


  ### Шаг 2. Отправьте сообщение с кнопками

Используйте метод [Новое сообщение](/api/messages/create) с полем `buttons` — массив строк, каждая из которых содержит массив кнопок.


  ### Шаг 3. Настройте исходящий вебхук

Для обработки Data-кнопок на вкладке **Исходящий вебхук** в карточке бота нажмите **Включить** и отметьте событие **Нажатие кнопок**. Затем выберите, как сервер получает события: на **Webhook URL** или из истории событий, подробнее в разделе [Как получать события](/guides/webhook/events#kak-poluchat-sobytiya).


  ### Шаг 4. Обработайте нажатие

При нажатии Data-кнопки бот получает вебхук с данными кнопки. Ответьте на него и дайте обратную связь: отредактируйте сообщение, отправьте новое или откройте [форму](/guides/forms/overview). Подробнее — в разделе [Обработка нажатий](#obrabotka-nazhatiy).

### URL-кнопки

URL-кнопка открывает указанную ссылку. При нажатии отображается модальное окно с подтверждением перехода. В нём можно отметить, чтобы ссылки на этот домен и его поддомены дальше открывались без подтверждения.

```json
{
  "text": "Все мои проекты",
  "url": "https://example.com/projects"
}
```

![Подтверждение перехода по ссылке](/images/buttons/buttons_url_confirm.webp)

*Подтверждение перехода по ссылке*


### Data-кнопки

Data-кнопка отправляет данные на сервер через [исходящий вебхук](/guides/webhook/overview). При нажатии бот получает вебхук с информацией о кнопке, сообщении и сотруднике, который её нажал, что позволяет реализовать любую логику обработки.

```json
{
  "text": "👍 Согласиться",
  "data": "vote_yes"
}
```

## Отправка кнопок

Сообщения с кнопками отправляют токеном бота: нажатие Data-кнопки приходит событием только тому боту, который отправил сообщение. Сами кнопки передаются методом [Новое сообщение](/api/messages/create) в поле `buttons`. Поле представляет собой массив строк, каждая из которых содержит массив кнопок. В одной строке можно комбинировать URL-кнопки и Data-кнопки.

**Сообщение с кнопкой**

```bash
curl "https://api.pachca.com/api/shared/v1/messages" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "message": {
    "entity_type": "discussion",
    "entity_id": 334,
    "content": "Вчера мы продали 756 футболок (что на 10% больше, чем в прошлое воскресенье)",
    "buttons": [
      [
        {
          "text": "Подробнее",
          "url": "https://example.com/details"
        }
      ]
    ]
  }
}'
```


> Метод [Редактирование сообщения](/api/messages/update) также поддерживает поле `buttons`. Для удаления всех кнопок передайте пустой массив `[]`.


## Обработка нажатий

Для получения событий о нажатиях Data-кнопок настройте [исходящий вебхук](/guides/webhook/overview) и включите событие **Нажатие кнопок**.

При нажатии кнопки бот получает вебхук:

#### ButtonWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"button"`
  Значения: `button` — Для кнопки всегда button
- `event: string` (required) — Тип события. Пример: `"click"`
  Значения: `click` — Нажатие кнопки
- `message_id: integer, int32` (required) — Идентификатор сообщения, к которому относится кнопка. Пример: `1245817`
- `trigger_id: string` (required) — Уникальный идентификатор события. Время жизни — 3 секунды. Может быть использован, например, для открытия представления пользователю. Пример: `"a1b2c3d4-5e6f-7g8h-9i10-j11k12l13m14"`
- `data: string` (required) — Данные нажатой кнопки. Пример: `"button_data"`
- `user_id: integer, int32` (required) — Идентификатор пользователя, который нажал кнопку. Пример: `2345`
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором была нажата кнопка. Пример: `9012`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


Ответьте на вебхук кодом `200`, а долгую работу делайте после ответа. Если в первые три секунды сервер ответит кодом ошибки и не откроет форму, сотрудник увидит уведомление **Ошибка при отправке данных**. Пачка ждёт ответа на нажатие до 30 секунд, а `trigger_id` для формы действует 3 секунды — все сроки в разделе [Сроки ответа](/guides/webhook/handler#sroki-otveta).

После получения события бот может:

- **Изменить сообщение** с кнопками методом [Редактирование сообщения](/api/messages/update): убрать кнопки, добавить новые или обновить текст. Нужно право `messages:update`.
- **Ответить там, где нажали кнопку**, методом [Новое сообщение](/api/messages/create): передайте `chat_id` из события в `entity_id` без `entity_type`. Если кнопка была в треде, ответ попадёт в тред, подробнее в разделе [Комментарии в тред](/guides/threads#kommentarii-v-tred).
- **Открыть форму** методом [Открытие представления](/api/views/open) с `trigger_id` из события. Нужно право `views:write`, подробнее в разделе [Формы](/guides/forms/overview).

Права `messages:update` и `views:write` входят в набор интерактивного бота — подробнее в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi).

## Ограничения

- Максимальное количество кнопок в сообщении — 100
- Максимальное количество строк с кнопками — 32
- Количество кнопок в строке — от 1 до 8
- Максимальная длина `text` на кнопке — 255 символов
- Максимальная длина `data` у кнопки — 255 символов
- Максимальная длина `url` у кнопки — 1024 символа
- У кнопки заполнено ровно одно из полей `url` и `data` — оба сразу или ни одного дают ошибку `wrong_params`

Строка кнопок в интерфейсе не переносится, поэтому даже разрешённые восемь штук
на узких экранах читаются плохо — держите в ряду пять-шесть.
