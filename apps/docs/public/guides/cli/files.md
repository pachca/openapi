# Файлы

Команда `pachca upload` автоматически получает подпись через `POST /uploads` и загружает файл на S3 — не нужно вручную копировать 7 параметров подписи:

```bash
# Загрузить файл
pachca upload photo.jpg

# Из stdin
cat data.csv | pachca upload -
```

Команда возвращает `key` — используйте его в поле `files[].key` при [создании сообщений](/api/messages/create):

```bash
# Загрузить файл и отправить в чат
KEY=$(pachca upload photo.jpg -o json | jq -r '.key')
pachca messages create --entity-id 123 --content "Фото" --files "[{\"key\":\"$KEY\",\"name\":\"photo.jpg\"}]"
```

> Для низкоуровневого контроля доступна команда `pachca files direct-url` — она отправляет multipart-запрос на указанный URL с параметрами подписи.


## Скачивание

Обычное вложение скачивается по ссылке из поля `url` сообщения — она прямая, и CLI для этого не нужен.

Команда `pachca files get` нужна вложениям, у которых прямой ссылки нет: в `url` таких файлов стоит адрес API. Так отдаются зашифрованные файлы и отправленные из безопасного контура пространства — подробнее в руководстве [Шифрование и безопасный контур](/guides/data-protection).

```bash
# Сохранить вложение по его идентификатору
pachca files get 3560 --save ./report.pdf

# Превью документа вместо самого файла
pachca files get 3560 --target pdf_preview --save ./preview.pdf
```

Путь в `--save` обязателен: команда пишет файл на диск, а не в вывод. Токену нужен скоуп `files:read`.
