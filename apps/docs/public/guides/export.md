# Экспорт сообщений

> **Внимание:** Доступно только на тарифе **Корпорация**. Для работы с экспортом токен должен иметь скоупы `chat_exports:write` и `chat_exports:read`, доступные только владельцу пространства.


Экспорт сообщений — это архив с файлами в формате `JSON`, где собраны сообщения из чатов пространства за выбранный период. У каждого сообщения указаны автор, время отправки, текст и реакции. Скачать архив может только тот, кто заказал выгрузку, и только в течение 7 дней с момента запроса.

По выгрузке можно считать сообщения и реакции в общих чатах, оценивать вовлечённость сотрудников и нагрузку на каждого из них, смотреть, сколько в пространстве активных чатов и обсуждений.

## Что попадает в архив

- Чаты, где за период есть сообщения: открытые, закрытые и архивные. Чаты без сообщений за период в архив и в список `chats.json` не попадают.
- Треды сообщений, отправленных за период. Ответы треда выгружаются целиком, в том числе отправленные после конца периода, и лежат в файле того дня, когда отправлено исходное сообщение. Тред, исходное сообщение которого отправлено до начала периода, в архив не попадает.
- Личные переписки по умолчанию в ограниченном виде. У сообщения есть автор и время отправки, а в поле `content` вместо текста приходит `-`. Треды личных переписок не выгружаются. Выгрузку личных переписок с текстом и тредами для пространства включает поддержка Пачки по запросу владельца.

Вложения в архив не попадают, а пересланные сообщения в нём не отражаются.

## Как это работает


  ### Шаг 1. Запросите экспорт

Для запроса экспорта используйте метод [Экспорт сообщений](/api/chats/request-export). Укажите период не длиннее 45 дней и, если нужно, список чатов: с ним период может быть до 366 дней. Если нужны данные за более долгий срок, после завершения одной выгрузки запросите следующую с новым диапазоном дат. Остальные ограничения и коды ошибок собраны в разделе [Ограничения и ошибки](#ogranicheniya-i-oshibki).

Экспорт выполняется асинхронно. Чтобы сразу получить номер выгрузки, передайте заголовок `Prefer: return=representation`: ответ придёт со статусом `202` и номером в `data.id`. Без заголовка ответ пустой, со статусом `204`. SDK, CLI и нода n8n передают этот заголовок сами.

Когда архив готов, заказавший получает письмо и уведомление в Пачке. Чтобы о готовности узнала программа, передайте адрес в `webhook_url`: на него придёт `JSON` с информацией о готовом экспорте. Без вебхука программа может проверять готовность по номеру из ответа.

#### Вебхук о готовой выгрузке

- `type: string` (required) — Тип объекта. Пример: `"export"`
  Значения: `export` — Для выгрузки всегда export
- `event: string` (required) — Тип события. Пример: `"ready"`
  Значения: `ready` — Архив собран
- `export_id: integer, int32` (required) — Идентификатор экспорта: по нему архив отдаёт метод [Скачать архив экспорта](/api/chats/download-export). Пример: `22322`
- `created_at: date-time` (required) — Дата и время заказа выгрузки (ISO-8601). Пример: `"2025-03-20T12:33:58Z"`


  ### Шаг 2. Скачайте готовый архив

Возьмите номер выгрузки из ответа на запрос или из поля `export_id` вебхука и передайте его в методе [Скачать архив экспорта](/api/chats/download-export). Пока архив собирается, метод отвечает `404` с кодом `export_file_not_found`: повторите запрос позже.

Через 7 дней после запроса архив удаляется. Метод по-прежнему отвечает `302`, но хранилище по ссылке возвращает ошибку: в этом случае закажите выгрузку заново.


  ### Шаг 3. Изучите структуру архива

Архив состоит из папок, каждая папка соответствует чату. Название папки состоит из имени чата и его `ID`, например `Design_12925828`, а у личной переписки вместо имени чата стоят имена собеседников через дефис. Внутри папки лежат `JSON`-файлы, по одному на каждый день, когда в чате были сообщения. Имя файла — дата в формате ДД-ММ-ГГГГ, например `15-01-2025.json`.

Рядом с папками лежит файл `chats.json` со списком чатов, которые попали в экспорт. Файл не создаётся, если при запросе экспорта передать `skip_chats_file` со значением `true`.

```
├── Design_12925828/
│   ├── 15-01-2025.json
│   ├── 16-01-2025.json
│   └── 17-01-2025.json
├── Marketing_12925901/
│   ├── 15-01-2025.json
│   └── 16-01-2025.json
├── Development_12926012/
│   ├── 15-01-2025.json
│   ├── 16-01-2025.json
│   └── 17-01-2025.json
└── chats.json
```


#### Структура данных в JSON-файлах сообщений

- `id: integer` — Идентификатор сообщения. Пример: `12345`
- `created_at: date-time` — Дата и время создания сообщения (ISO-8601, UTC+0). Пример: `"2024-01-15T10:30:00.000Z"`
- `deleted_at: date-time` (nullable) — Дата и время удаления сообщения. Возвращается как null, если сообщение не удалено.
- `content: string` — Текст сообщения. В личных переписках вместо текста приходит `-`, если поддержка Пачки не включила для пространства их полную выгрузку. Пример: `"Привет! Как дела?"`
- `thread_id: integer` (nullable) — Идентификатор треда сообщения. Возвращается как null, если у сообщения нет комментариев.
- `reactions: array of object` — Массив списка реакций
  - `user_id: integer` — Идентификатор пользователя, который добавил реакцию
  - `created_at: string` — Дата и время добавления реакции (ISO-8601, UTC+0)
  - `code: string` — Emoji символ реакции. Пример: `"👍"`
- `user: object` — Информация об авторе сообщения
  - `id: integer` — Идентификатор пользователя
  - `role: string` — Тип автора
    Значения: `member` — пользователь, `bot` — бот
  - `name: string` — Имя
  - `last_name: string` — Фамилия
  - `email: string` — Электронная почта
  - `tags: array of string` — Массив тегов, привязанных к пользователю
- `chat: object` — Информация о чате, в котором было написано сообщение
  - `id: integer` — Идентификатор чата
  - `name: string` — Название чата
  - `personal: boolean` — Тип чата
    Значения: `true` — личный чат, `false` — групповой чат
  - `owner: object` — Информация о владельце чата
    - `id: integer` — Идентификатор пользователя
    - `role: string` — Тип владельца
      Значения: `member` — пользователь, `bot` — бот
    - `name: string` — Имя
    - `last_name: string` — Фамилия
    - `email: string` — Электронная почта
    - `tags: array of string` — Массив тегов
  - `tags: array of string` — Массив тегов, привязанных к чату
- `thread: object` (nullable) — Тред, в котором находится сообщение. Возвращается как null, если сообщение находится не в треде.
  - `id: integer` — Идентификатор треда
  - `message_id: integer` — Идентификатор сообщения, под которым был начат тред
  - `message_chat_id: string` — Идентификатор чата, в котором был начат тред


Список в файле `chats.json` представляет собой массив объектов чатов. Структура каждого объекта чата описана ниже.

#### Структура объекта чата в массиве файла chats.json

- `id: integer` — Идентификатор чата. Пример: `67890`
- `personal: boolean` — Тип чата
  Значения: `true` — личный чат, `false` — групповой чат
- `name: string` — Название. Пример: `"Рабочий чат"`
- `owner_id: integer` — Идентификатор пользователя, создавшего чат. Пример: `123`
- `members: array of object` — Массив объектов участников чата
  - `id: integer` — Идентификатор пользователя
  - `role: string` — Роль в чате
    Значения: `owner` — создатель, `admin` — админ, `editor` — редактор, `member` — участник/подписчик
- `created_at: date-time` — Дата и время создания чата (ISO-8601, UTC+0). Пример: `"2024-01-10T08:00:00.000Z"`
- `updated_at: date-time` — Дата и время обновления чата (ISO-8601, UTC+0). Пример: `"2024-01-15T12:00:00.000Z"`


## Ограничения и ошибки

- период одной выгрузки — до 45 дней, а с указанием конкретных чатов до 366 дней, и дата конца не раньше даты начала: на другой период метод отвечает `422` с кодом `invalid_date_range`
- максимальное количество запрашиваемых чатов — 50, на больший список метод отвечает `422` с кодом `too_long`
- даты начала и конца периода передаются в формате YYYY-MM-DD, иначе метод отвечает `422` с кодом `invalid`
- следующий запрос экспорта пространство может отправить через 90 секунд после предыдущего независимо от того, завершился он или ещё идёт, а более ранний вернёт `422` с кодом `rate_limit`
- запрос, отклонённый из-за параметров (периода, списка чатов или формата даты), эту паузу не запускает

Адрес в `webhook_url` должен быть доступен из интернета по `http` или `https`. Иначе запрос отклоняется с `422` и кодом `invalid_webhook_url`, и экспорт не запускается. Адрес с ошибкой в записи, без хоста, с другой схемой или с IP-адресом из приватного диапазона отклоняется до паузы между запросами экспорта, и исправленный запрос можно отправить сразу. Имя хоста, у которого нет адреса в DNS или которое ведёт на приватный адрес (например, `localhost`), проверяется уже после того, как запрос запустил эту паузу, поэтому исправленный запрос получится отправить только через 90 секунд. Если вебхук не пришёл, проверьте доступность адреса снаружи.
