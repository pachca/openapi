# Обработка форм

## Открытие представления

Чтобы открыть модальное окно, бот вызывает метод [Открытие представления](/api/views/open) с `trigger_id` из вебхука о нажатии кнопки. `trigger_id` подтверждает, что окно открывается по действию сотрудника, и быстро истекает.

> **Внимание:** `trigger_id` действует **3 секунды**: открывайте представление сразу после получения нажатия, а долгую работу делайте потом. Все сроки — в разделе [Сроки ответа](/guides/webhook/handler#sroki-otveta).


Токену бота нужно право `views:write`. Оно входит в набор интерактивного бота — подробнее в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi).

## Получение результатов

Когда сотрудник заполняет и отправляет форму, Пачка присылает исходящий вебхук на **Webhook URL** того бота, который отправил сообщение с кнопкой, открывшей форму. Адрес задаётся на вкладке **Исходящий вебхук** в карточке бота.

Отправку формы бот получает, только если у него включено событие **Нажатие кнопок** (`button_click`). Добавлять бота в чат для этого не нужно: вебхук приходит тому боту, который открыл форму.

На вебхук бот быстро отвечает: закрывает представление или показывает ошибки под полями, подробнее в разделе [Закрытие и отображение ошибок](#zakrytie-i-otobrazhenie-oshibok). Бот без адреса исходящего вебхука отвечает отдельным методом — подробнее в разделе [Ответ через журнал событий](#otvet-cherez-zhurnal-sobytiy).

Вебхук содержит то, что бот заложил при открытии представления (`private_metadata` и `callback_id`), чат, где нажали кнопку (`chat_id`), и значения заполненных полей.

Каждый исходящий вебхук защищён с помощью подписи, основанной на хешировании содержимого. Подробнее об этом — в разделе [Безопасность](/guides/webhook/handler#bezopasnost).

#### ViewSubmitWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"view"`
  Значения: `view` — Для формы всегда view
- `event: string` (required) — Тип события. Пример: `"submit"`
  Значения: `submit` — Отправка формы
- `callback_id: string` (required, nullable) — Идентификатор обратного вызова, указанный при открытии представления. `null`, если при открытии формы он не был указан. Пример: `"timeoff_request_form"`
- `private_metadata: string` (required, nullable) — Приватные метаданные, указанные при открытии представления. `null`, если при открытии формы они не были указаны. Пример: `"{\"timeoff_id\":4378}"`
- `chat_id: integer, int32` (required, nullable) — Идентификатор чата, в котором была нажата кнопка, открывшая форму. Фиксируется при открытии формы, а не при её отправке. Пример: `9012`
- `user_id: integer, int32` (required) — Идентификатор пользователя, который отправил форму. Пример: `1235523`
- `view_id: string` (required) — Идентификатор представления. Нужен боту без адреса исходящего вебхука, чтобы ответить методом [Ответ на отправку формы](/api/views/submit-response). Пример: `"01KAJZ2XDSS2S3DSW9EXJZ0TBV"`
- `submit_id: string` (required) — Идентификатор отправки формы. Нужен боту без адреса исходящего вебхука, чтобы ответить методом [Ответ на отправку формы](/api/views/submit-response). Пример: `"791a056b-006c-49dd-834b-c633fde52fe8"`
- `data: Record<string, object>` (required) — Данные заполненных полей представления. Ключ — `name` блока, значение — введённые данные. У блока `file_input` значение приходит массивом объектов с полями `name`, `size` и `url`, ссылка действует 2 часа.
  **Структура значений Record:**
  - Тип значения: `any`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1755075544`


```json title="Пример вебхука о заполнении формы"
{
    "type": "view",
    "event": "submit",
    "private_metadata": "{\"timeoff_id\":4378}",
    "callback_id": "timeoff_request_form",
    "chat_id": 9012,
    "user_id": 1235523,
    "view_id": "01KAJZ2XDSS2S3DSW9EXJZ0TBV",
    "submit_id": "791a056b-006c-49dd-834b-c633fde52fe8",
    "data": {
        "date_start": "2025-07-01",
        "date_end": "2025-07-14",
        "request_doc": [
            {
                "name": "request.png",
                "size": 19153,
                "url": "<url>"
            }
        ],
        "accessibility": "phone_only",
        "info": "Поеду в сибирь на свадьбу лучшего друга",
        "newsletters": ["new_tasks", "project_updates"],
        "team": "success",
        "time": "22:00"
    },
    "webhook_timestamp": 1755075544
}
```

Значение блока `file_input` приходит массивом объектов с полями `name`, `size` и `url`. Расширение файла проверяйте у себя: список `filetypes` подставляется в фильтр окна выбора файла.

> **Внимание:** Скачивайте файл сразу после получения вебхука. Прямая ссылка действует **2 часа**, а сам файл хранится **сутки** с момента отправки формы, после чего удаляется. Если файл нужен дольше, скачайте его по ссылке и сохраните у себя.


### Ответ в чат

Поле `chat_id` — чат, где нажали кнопку, открывшую форму. Чтобы написать результат туда же, отправьте [Новое сообщение](/api/messages/create) с этим `chat_id` в `entity_id` без `entity_type`: если кнопка была в треде, сообщение попадёт в тред. Подробнее — в разделе [Комментарии в тред](/guides/threads#kommentarii-v-tred). Ответ на вебхук закрывает форму, а сообщение в чат можно отправить после него.

```bash title="Результат формы в чат, где нажали кнопку"
curl -X POST https://api.pachca.com/api/shared/v1/messages \
  -H "Authorization: Bearer $BOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "message": {
      "entity_id": 9012,
      "content": "Заявка на отпуск с 1 по 14 июля отправлена руководителю"
    }
  }'
```

## Закрытие и отображение ошибок

Получив вебхук об отправке формы, бот сохраняет значения или сначала проверяет их и возвращает ошибки под полями.

Ответьте на вебхук за **3 секунды**: кодом `2xx`, чтобы закрыть представление, или кодом `400` либо `422` со списком ошибок. При другом коде или если ответ не пришёл в срок, сотрудник получит ошибку отправки в интерфейсе Пачки. Значения полей сохранятся, и **сотрудник повторит попытку отправки формы**. Каждая попытка приходит отдельным вебхуком: `view_id` у неё прежний, а `submit_id` новый. Все сроки — в разделе [Сроки ответа](/guides/webhook/handler#sroki-otveta).

### Отображение ошибок

Чтобы показать сотруднику ошибки в конкретных полях, ответьте кодом `400` или `422`, а в теле передайте объект `errors`: ключ — `name` поля, значение — текст ошибки.

#### Тело ответа с указанием текста ошибки для каждого поля

- `errors: object` — JSON карта ошибок для полей, где каждый ключ - name поля представления.
  - `name: string` (max length: 2000) — Текст ошибки, который отобразится под полем красным цветом


```http title="Пример ответа на вебхук для отображения ошибок"
HTTP/1.1 400 Bad Request
Server: nginx/1.14.2
Date: Wed, 22 Apr 2025 12:32:29 GMT
Content-Type: application/json; charset=utf-8
Transfer-Encoding: chunked
Connection: close
ETag: W/"4d63aae1430a3bbd35e95e3db6b364df"
Cache-Control: max-age=0, private, must-revalidate
X-Request-Id: 12f8a05c-c5cf-4a79-8d2f-f82cc477c410
X-Runtime: 0.117503
Vary: Origin
X-Rack-CORS: miss; no-origin

{
    "errors": {
        "date_end": "Дата окончания отпуска не может быть меньше даты начала",
        "request_doc": "В заявлении не найдена электронная подпись"
    }
}
```

### Закрытие представления

Чтобы закрыть представление без ошибок, ответьте любым кодом `2xx`, например `200`. Тело ответа не нужно.

```http title="Пример ответа на вебхук для закрытия представления"
HTTP/1.1 200 OK
Server: nginx/1.14.2
Date: Wed, 22 Apr 2025 12:32:29 GMT
Content-Type: text/plain; charset=utf-8
```

## Ответ через журнал событий

Этот раздел нужен, только если у бота не задан адрес исходящего вебхука. Отвечать на вебхук такому боту некуда, поэтому при включённой истории событий событие `view_submit` забирают методом [История событий](/api/bots/list-events), а ответ отправляется методом [Ответ на отправку формы](/api/views/submit-response). Значения `view_id` и `submit_id` берутся из payload события.

Если адрес вебхука задан, пользуйтесь обычным ответом на вебхук: он проще и не требует опроса журнала.

Чтобы не опрашивать журнал, бот без адреса вебхука может получать события сразу по ссылке из метода [Поток событий](/api/bots/get-stream). Подробнее — в разделе [События в реальном времени](/guides/webhook/polling#sobytiya-v-realnom-vremeni).

Нажатие на кнопку такой бот тоже забирает из журнала. Чтобы успеть открыть форму по `trigger_id`, получайте события из потока — подробнее в разделе [Сроки ответа](/guides/webhook/handler#sroki-otveta).

> **Внимание:** Ответить нужно за **5 секунд** с момента отправки формы, иначе сотрудник получит ошибку отправки, а значения полей сохранятся для повторной попытки.


Тело запроса без поля `errors` закрывает представление как успешно отправленное. С полем `errors` — показывает ошибки под соответствующими полями, как и ответ `400` или `422` на исходящий вебхук.

```json title="Пример ответа с ошибками полей"
{
    "submit_id": "791a056b-006c-49dd-834b-c633fde52fe8",
    "errors": {
        "date_end": "Дата окончания отпуска не может быть меньше даты начала",
        "request_doc": "В заявлении не найдена электронная подпись"
    }
}
```

```json title="Пример ответа для закрытия представления"
{
    "submit_id": "791a056b-006c-49dd-834b-c633fde52fe8"
}
```

Ответ на отправку принимается один раз: первый успешный вызов забирает ожидающую отправку, и повторный вызов с той же парой `view_id` и `submit_id` уже ничего не меняет. И в этом случае, и когда пять секунд истекли, метод отвечает `410` с кодом `submit_expired`.
