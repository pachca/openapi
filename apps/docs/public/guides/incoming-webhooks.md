# Входящие вебхуки

Входящий вебхук позволяет отправлять сообщения в чаты Пачки от имени бота — достаточно одного HTTP POST-запроса. Вам не нужно работать с API, а гибкость обработки данных обеспечивают шаблонизаторы.


## Как это работает


  ### Шаг 1. Создайте бота

Откройте **Интеграции** > **Боты** и нажмите **Создать бота**. Подробнее — в разделе [Боты](/guides/bots/overview).


  ### Шаг 2. Включите вебхук и выберите источник

В карточке бота на вкладке **Входящий вебхук** нажмите **Включить** и выберите, что будет присылать данные: GitLab, Grafana или **Свой формат** для любого другого сервиса. Источник можно поменять позже.


  ### Шаг 3. Скопируйте адрес вебхука

После включения на вкладке появится адрес, на который сервис будет отправлять запросы. Скопируйте его.


  ### Шаг 4. Вставьте адрес в настройки внешнего сервиса

Укажите скопированный адрес как адрес для уведомлений (webhook URL) в вашей CRM, CI/CD, мониторинге или другом сервисе.


  ### Шаг 5. Добавьте бота в нужные чаты

Сообщения от вебхука публикуются во все групповые чаты, где состоит бот. Добавьте бота в чаты, в которые хотите получать уведомления — через настройки чата или через API-метод [Добавление пользователей](/api/members/add).


  ### Шаг 6. Сервис отправляет POST-запрос

При наступлении события сервис отправляет `POST`-запрос с JSON-данными на адрес вебхука. Для своего формата минимальный запрос такой:

```json
{
  "message": "Текст сообщения"
}
```

Поле `message` содержит текст, который будет опубликован от имени бота. Запросы GitLab и Grafana Пачка разбирает сама, в их настройках достаточно указать адрес.


  ### Шаг 7. Сообщение появляется в чате

Пачка обрабатывает запрос и публикует сообщение от имени бота во все групповые чаты, где он состоит.


## Настройки

Настройки входящего вебхука находятся на вкладке **Входящий вебхук** в карточке бота и появляются после включения. Кнопка **Удалить вебхук** внизу вкладки выключает его: адрес перестаёт принимать запросы, а настройки и шаблон удаляются.

### Источник

- **GitLab** — пуши, пайплайны, merge request и комментарии
- **Grafana** — алерты со скриншотами графиков
- **Свой формат** — любой сервис: JSON и шаблон сообщения

Для GitLab и Grafana Пачка сама разбирает запрос и собирает сообщение, поэтому шаблон нужен только своему формату.

### Шаблон сообщения

По умолчанию Пачка публикует содержимое поля `message` из входящего JSON. Если вместо готового текста вы хотите отправлять произвольную JSON-структуру и гибко формировать сообщение из её полей — выберите **формат шаблона** и заполните **шаблон сообщения**. При пустом шаблоне в сообщение попадает поле `message`.

Пачка поддерживает два шаблонизатора:

- [**Liquid**](https://shopify.github.io/liquid/) — условия, циклы, фильтры (Shopify, open source)
- [**Mustache**](https://mustache.github.io/) — простая подстановка без логики (open source)

> Ссылки выше ведут на полную документацию шаблонизаторов, а ниже — общая информация по форматированию текста и получению данных из JSON-полей.


Шаблонизатор разбирает входящий JSON и подставляет значения полей в шаблон. Для форматирования текста (жирность, курсив, ссылки, блоки кода и пр.) используйте markdown — полный список поддерживаемых конструкций в разделе [Форматирование текста](/guides/markdown).

```json title="Входящий JSON"
{
  "client": "Иван Петров",
  "amount": 15000,
  "status": "оплачен",
  "project": { "name": "Pachca" }
}
```

```text title="Шаблон Liquid (точечная нотация для вложенных объектов)"
Заказ от {{ client }} на сумму {{ amount }} ₽ — {{ status }}
Проект: {{ project.name }}
```

```text title="Шаблон Mustache (секции для вложенных объектов)"
Заказ от {{ client }} на сумму {{ amount }} ₽ — {{ status }}
{{#project}}Проект: {{ name }}{{/project}}
```

> Mustache также поддерживает точечную нотацию для вложенных объектов `{{ project.name }}`.


```text title="Результат в чате"
Заказ от Иван Петров на сумму 15000 ₽ — оплачен
Проект: Pachca
```

Liquid также поддерживает:

- **Условия** — `if`, `else`, `elsif`, `unless`, `case`/`when`
- **Циклы** — `for` с параметрами `limit`, `offset`, `reversed`
- **Фильтры строк** — `downcase`, `upcase`, `capitalize`, `truncate`, `replace`, `remove`, `strip`, `escape`, `url_encode`
- **Фильтры чисел** — `plus`, `minus`, `times`, `divided_by`, `round`, `ceil`, `floor`, `abs`
- **Фильтры массивов** — `join`, `first`, `last`, `sort`, `uniq`, `where`, `map`, `size`
- **Фильтры дат** — `date` с форматированием (`%d.%m.%Y`, `%H:%M` и пр.)

> После первого запроса на вкладке появляется ссылка **Показать последний полученный объект** с датой получения. Нажмите на неё — откроется окно с содержимым последнего полученного JSON. Используйте его, чтобы определить нужные поля и перенести их в шаблон.


### Показывать превью ссылок

Если включено, Пачка разворачивает ссылки из сообщений вебхука в превью — так же, как в обычных сообщениях.

### Поле для верификации

Некоторые сервисы (например, [monday.com](https://monday.com)) при настройке вебхука отправляют проверочный запрос и ожидают получить в ответе определённое поле. Укажите название поля проверки — Пачка ответит JSON-объектом с этим полем и его значением. Для monday.com это слово `challenge`.

## Настройка через API

Все эти настройки можно задать программно, без интерфейса — методами [Новый бот](/api/bots/create) и [Редактирование бота](/api/bots/update):

- `template` — шаблон сообщения
- `template_engine` — шаблонизатор (`liquid` или `mustache`)
- `challenge_key` — поле для верификации
- `link_preview_enabled` — показывать превью ссылок

Текущие значения возвращаются в объекте бота и доступны через метод [Информация о боте](/api/bots/get).

Бот, созданный через API, принимает запросы в своём формате сразу, с шаблонизатором Liquid по умолчанию. Источники GitLab и Grafana выбираются только в интерфейсе.

## Ограничения

> **Внимание:** Входящий вебхук не позволяет отправить личное сообщение или указать конкретный чат. Сообщение
  публикуется во **все групповые чаты**, где состоит бот. Для отправки в конкретный чат или личное сообщение
  используйте API-метод [Новое сообщение](/api/messages/create).


- **Максимальная длина сообщения** — 40 000 байт. Для кириллицы это около 20 000 символов, поскольку каждый символ занимает два байта. Если результат шаблона превышает лимит, сообщение не будет отправлено.
- **Пустое сообщение** — если шаблон возвращает пустую строку, сообщение не будет отправлено.
- **Ошибка в шаблоне** — если шаблон содержит синтаксическую ошибку, в чат будет отправлено сообщение вида `Ошибка в шаблоне: описание ошибки`.

**Входящие вебхуки — 10 / 1 сек** Считается отдельно по `webhook_url`.
