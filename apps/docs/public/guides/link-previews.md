# Разворачивание ссылок

Unfurling — это создание превью ссылки в сообщении. Когда сотрудник отправляет ссылку на один из отслеживаемых доменов, бот получает вебхук, извлекает данные по URL из вашего сервиса и отправляет превью обратно в Пачку. В результате все участники чата видят заголовок, описание и изображение — даже если у них нет доступа к ресурсу.

**Сделать с агентом.** Агент создаст бота для превью ссылок, напишет обработчик и проверит его на ссылке в новой беседе. Вставьте промпт в чат с ИИ-агентом, к которому [подключена Пачка](/guides/mcp/connect). Агенту, который уже выполняет этот промпт: ниже его копия, начинать заново не нужно.

```text
Сделай мне бота, который разворачивает ссылки, по странице https://dev.pachca.com/guides/link-previews.md. Скачай её: `curl -sL https://dev.pachca.com/guides/link-previews.md`. Инструмент для веба отдаёт пересказ, бери его, только если нет терминала. Если не вышло ничего, остановись и скажи.

Если у тебя нет инструментов Пачки, сначала подключи её по странице https://dev.pachca.com/guides/mcp/connect.md, потом я пришлю тебе этот запрос ещё раз.

1. Спроси, как назвать бота, какие домены разворачивать и на чём писать обработчик.
2. Предупреди, что бот получит ссылки на эти домены из всех чатов. После моего «да» создай бота с токеном, событием о ссылке, доменами и историей событий, без адреса вебхука.
3. В этой папке напиши обработчик: на событие о ссылке он отправляет превью методом со страницы. Заголовок и описание пока бери из адреса ссылки, запрос к моему сервису добавлю я. Токен и Signing secret запиши только в `.env`, файл добавь в `.gitignore`.
4. Запусти в фоне обработчик и пересылку событий командой из шага «Подключите обработчик» страницы https://dev.pachca.com/guides/webhook/deploy.md, оба с переменными из `.env`.
5. Создай беседу, отправь в неё ссылку на мой домен и спроси, появилась ли карточка.
6. Перечисли, что создано и как выключить событие.

Такого бота создаёт только администратор или владелец пространства. Если мешают права или настройки, не обходи: скажи, что мешает и кто это изменит. Чего не можешь сам, например запустить код, дай мне готовыми командами.
```

## Как это работает


  ### Шаг 1. Создайте бота

Откройте **Интеграции** > **Боты** и нажмите **Создать бота**. Подробнее — в разделе [Создание бота](/guides/bots/setup).


  ### Шаг 2. Включите исходящий вебхук

В карточке бота на вкладке **Исходящий вебхук** нажмите **Включить**: вебхук включится вместе с историей событий. Чтобы события приходили на ваш сервер запросами, в карточке **Как получать события** укажите **Webhook URL** и нажмите **Сохранить**. Подробнее — в разделе [Как получать события](/guides/webhook/events#kak-poluchat-sobytiya).


  ### Шаг 3. Включите событие и укажите домены

В карточке **Какие события создавать** в группе **Ссылки** отметьте **Отправка ссылок в сообщении (unfurl)**, перечислите в поле **Домены** через запятую до 5 доменов, ссылки на которые бот будет отслеживать, и нажмите **Сохранить**. Бот получает ссылки из всех чатов пространства, поэтому добавлять его в чаты не нужно, а включать и выключать событие, задавать домены, менять адрес исходящего вебхука, включать историю событий и удалять вебхук у такого бота может только администратор или владелец пространства. Через API это событие `message_link_shared` в поле `events` и домены в `unfurl_domains` метода [Редактирование бота](/api/bots/update).


  ### Шаг 4. Обработайте вебхук

При появлении ссылки на отслеживаемый домен бот получит вебхук с массивом `links`. Каждый объект содержит `url`, `domain` и `skip: boolean` — если `skip` равен `true`, автор сообщения скрыл превью для этой ссылки и бот не должен создавать превью. Извлеките данные из вашего сервиса по оставшимся URL.


  ### Шаг 5. Отправьте превью

Вызовите метод [Unfurl (разворачивание ссылок)](/api/messages/unfurl), передав заголовок, описание и изображение для каждой ссылки. Метод принимает только токен бота с правом `link_previews:write`.

## Правила распознавания доменов

- Формат: `example.com` или `subdomain.example.com`
- Протокол не указывается — отслеживаются и `http`, и `https`
- Поддомены включаются автоматически: `example.com` покрывает `sub.example.com`
- Пути и параметры не учитываются — проверяется только домен
- Вместо домена можно указать IPv4-адрес или `localhost`, порт указать нельзя

## Вебхук о ссылке

При появлении ссылки на отслеживаемый домен бот получает вебхук с типом `message` и событием `link_shared`:

#### LinkSharedWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"message"`
  Значения: `message` — Для разворачивания ссылок всегда message
- `event: string` (required) — Тип события. Пример: `"link_shared"`
  Значения: `link_shared` — Обнаружена ссылка на отслеживаемый домен
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором обнаружена ссылка. Пример: `23438`
- `message_id: integer, int32` (required) — Идентификатор сообщения, содержащего ссылку. Пример: `268092`
- `links: array of object` (required) — Массив обнаруженных ссылок на отслеживаемые домены
  - `url: string` (required) — URL ссылки. Пример: `"https://example.com/page1"`
  - `domain: string` (required) — Домен ссылки. Пример: `"example.com"`
  - `skip: boolean` (required) — Признак того, что автор сообщения скрыл превью для этой ссылки. Если `true` — бот не должен создавать превью. Пример: `false`
- `user_id: integer, int32` (required) — Идентификатор отправителя сообщения. Пример: `2345`
- `entity_type: string` (required) — Тип сущности, к которой относится сообщение со ссылкой
  Значения: `discussion` — Беседа или канал, `thread` — Тред, `user` — Пользователь
- `entity_id: integer, int32` (required, nullable) — Идентификатор сущности: беседы или канала, треда. В личной переписке `null`: бот в ней не участвует, и собеседника ему не раскрывают. Пример: `23438`
- `thread: object` (required) — Тред, в котором отправлено сообщение со ссылкой. `null`, если сообщение отправлено не в треде.
  - `message_id: integer, int32` (required, nullable) — Идентификатор сообщения, к которому был создан тред. `null` у треда без сообщения-родителя — такие создаёт [Новый самостоятельный тред](/api/threads/create). Пример: `12345`
  - `message_chat_id: integer, int32` (required, nullable) — Идентификатор чата сообщения, к которому был создан тред. `null` у треда без сообщения-родителя. Пример: `67890`
- `source: string` — Через что отправлено сообщение со ссылкой токеном сотрудника, так же, как поле `source` в объекте сообщения. В записях истории событий, сохранённых до появления поля, его нет.
  Значения: `application` — Через программу, которой сотрудник выдал доступ: Pachca CLI, клиент MCP или бота с авторизацией от имени сотрудника, `personal_token` — Персональным токеном сотрудника
- `application: object` — Программа, через которую отправлено сообщение со ссылкой, так же, как поле `application` в объекте сообщения. В записях истории событий, сохранённых до появления поля, его нет.
  - `id: integer, int32` (required) — Идентификатор программы. Пример: `4812`
  - `name: string` (required) — Название программы, как в подсказке «Отправлено через …» на аватаре: «Pachca CLI», название клиента MCP или имя бота. У старых сообщений тоже приходит текущее название. Клиент MCP задаёт название сам в документе, который публикует на своём домене, поэтому программу узнают по `id`. Пример: `"Pachca CLI"`
- `created_at: date-time` (required) — Дата и время создания сообщения (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Пример: `"2024-09-18T19:53:14.000Z"`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1726685594`


Поля `entity_type`, `entity_id` и `thread` — те же, что в вебхуке о новом сообщении: по ним видно, в беседе, канале, треде или личной переписке отправлена ссылка. Бот не состоит в этом чате, поэтому в личной переписке `entity_id` приходит `null`. Поля `source` и `application` тоже те же: по ним видно, что сообщение со ссылкой отправила программа токеном сотрудника, например агент через MCP.

Ссылки из сообщений другого бота приходят, только пока у того включено [Показывать превью ссылок](/guides/incoming-webhooks#pokazyvat-prevyu-ssylok) (`link_preview_enabled`). Настройка стоит на вкладке **Входящий вебхук**, но действует на все сообщения бота: и отправленные через вебхук, и отправленные через API. По умолчанию она включена и снова включается после удаления входящего вебхука, поэтому ссылки от бота без входящего вебхука обычно приходят. Ссылки из своих сообщений бот не получает, если у него включено «Игнорировать свои сообщения». Исключение — бот в режиме `trigger_on: unfurl`: на ссылки эта настройка у него не действует.

## Создание превью

Для создания превью используйте метод [Unfurl (разворачивание ссылок)](/api/messages/unfurl), передав `message_id` из вебхука.

Тело запроса — объект `link_previews`, где каждый ключ — URL из массива `links` вебхука:

**Unfurl (разворачивание ссылок)**

```bash
curl "https://api.pachca.com/api/shared/v1/messages/194275/link_previews" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "link_previews": {
    "https://example.com/articles/123": {
      "title": "Статья: Отправка файлов",
      "description": "Пример отправки файлов на удаленный сервер",
      "image_url": "https://example.com/img/landing.png",
      "image": {
        "key": "attaches/files/93746/e354fd79-9jh6-f2hd-fj83-709dae24c763/${filename}",
        "name": "files-to-server.jpg",
        "size": 695604
      }
    }
  }
}'
```


Поля `title` и `description` обязательны для каждой ссылки, изображение можно не передавать.

Изображение можно указать двумя способами:

- **По ссылке** — параметр `image_url` с публичным URL изображения
- **Загрузкой файла** — параметр `image` с данными, полученными через метод [Загрузка файла](/api/files/direct-url). Если указаны оба параметра, `image` является приоритетным.

> **Внимание:** Если среди переданных URL будет ошибка (URL отсутствует в сообщении, домен не указан в настройках бота или изображение `image` загружено в другом пространстве), запрос не будет выполнен — не будет создано ни одного превью, а в ответе придёт `wrong_params`.

  Ссылку, для которой автор сообщения скрыл превью, запрос пропускает без ошибки, а остальные превью из того же запроса создаются.


> Веб-версия и десктопное приложение показывают в сообщении до пяти превью — те, у которых есть заголовок, описание или изображение.
