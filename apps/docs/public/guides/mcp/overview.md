# MCP-сервер

MCP (Model Context Protocol) — открытый протокол, по которому программа с AI-агентом подключается к внешнему сервису и получает его инструменты. MCP-сервер Пачки даёт такой программе публичный API: агент читает чаты и треды, отправляет сообщения, ставит напоминания, управляет сотрудниками и ботами. При этом агент видит и делает только то, что разрешено владельцу токена, которым подключена программа, и правам этого токена. Код под методы API писать не нужно: программа подключается по адресу, а агент сам выбирает нужный инструмент.

> Подключение программы к MCP — это обычная выдача токена API, а с персональным токеном или токеном бота агент работает и без MCP, через CLI или API. Поэтому отдельного выключателя MCP и разрешений для отдельных сотрудников нет: доступ агентов решают те же две настройки пространства, что и доступ к API. По умолчанию персональные токены и вход через браузер есть только у администраторов, а ботов, токен которых тоже подходит агенту, создают и сотрудники. Смена настройки закрывает новые подключения, а выданные работают, пока их не отзовут. Обе настройки описаны в разделе [Кто может создавать токены](/api/authorization#kto-mozhet-sozdavat-tokeny), а управление доступом агентов для администратора — на странице [Агенты и MCP в пространстве](/guides/agents-access).


```text title="Адрес сервера"
https://mcp.pachca.com/mcp
```

Сервер работает по транспорту Streamable HTTP. Его подключают Claude Code, Claude, Cursor, VS Code, Codex, приложение ChatGPT на компьютере и другие программы с поддержкой MCP, а также агенты в Yandex AI Studio и на GigaChat. В Claude Code, приложении Claude, Codex, VS Code и Cursor сервер ставится и [плагином «Пачка»](/guides/mcp/plugin): он подключает сервер и добавляет скиллы. Что выбрать для вашей программы — в разделе [Какой путь выбрать](/guides/mcp/connect#kakoy-put-vybrat).

## Когда выбирать MCP

С Пачкой можно работать несколькими способами, и все они вызывают одни и те же методы. С MCP программа сама загружает описания инструментов и сама решает, какой вызвать. Все способы и что выбрать — в разделе [Как подключить Пачку к агенту](/guides/ai-agents/overview#kak-podklyuchit-pachku-k-agentu).

## Что можно попросить агента

Несколько примеров запросов:

| Запрос | Что сделает агент |
|---|---|
| «Что решили в треде про релиз 2.4? Коротко, по пунктам» | Найдёт тред, прочитает сообщения и перескажет решения |
| «Где на этой неделе обсуждали переезд на новый сервер и кто в этом участвовал?» | Поищет сообщения за неделю и назовёт чаты и авторов |
| «Какие у меня напоминания на эту неделю?» | Покажет ваши напоминания со сроками |
| «Поставь мне напоминания по итогам треда про релиз 2.4 со сроком в пятницу» | Создаст напоминания со сроком и текстом из треда |
| «Подготовь в канал «Релизы» анонс версии 2.4, я проверю и отправлю сам» | Оставит в канале [черновик](/guides/ai-agents/drafts), а отправите его вы |
| «Пригласи anna@example.com и добавь её в каналы «Общий» и «Дизайн»» | Пригласит сотрудника и добавит его в каналы |
| «Отправь в канал «Финансы» файл report.pdf с отчётом за квартал» | Загрузит файл и отправит сообщение с ним |
| «Выгрузи переписку канала «Поддержка» за сентябрь» | Запросит выгрузку сообщений канала за сентябрь |

Приглашение и выгрузка доступны не каждой роли и не на каждом тарифе. Кому что доступно — в разделе [Какие инструменты получает программа](/guides/mcp/tools#kakie-instrumenty-poluchaet-programma). Файл с диска отправит программа с терминалом, подробнее — в разделе [Как агент отправляет файл](/guides/mcp/tools#kak-agent-otpravlyaet-fayl).

Агент работает точнее, если в запросе есть название чата, тема треда, период и что сделать с результатом.

## Как устроен сервер

### Инструмент на каждый метод API

У каждого метода публичного API свой инструмент с именем `pachca_…`: `pachca_send_message`, `pachca_list_tasks`, `pachca_search_users`. Аргументы инструмента повторяют параметры метода, а описание взято из документации API. Небольшой файл агент передаёт содержимым, а документ или картинку с диска загружает сам и прикладывает по ключу. Полный список — в разделе [Инструменты MCP](/guides/mcp/tools), там же несколько служебных методов, которые инструментами не стали.

### Те же права, что в API

MCP вызывает те же методы API и пользуется их правами. Инструмент вызывает метод API с токеном, которым подключена программа, и метод проверяет всё как обычно: [скоупы](/api/authorization#skoupy) токена, роль владельца токена, тариф пространства и участие в чатах.

Сервер принимает любой действующий токен API: персональный, в том числе полученный входом через браузер, и токен бота. Токену гостя, деактивированного или удалённого сотрудника сервер отказывает. Какие роли работают с API — в разделе [Роли в пространстве](/guides/permissions#roli-v-prostranstve).

Сервер работает на всех тарифах, включая бесплатный «Начало». Тариф влияет на набор инструментов и на лимит сообщений: пространство на «Начале», которое превысило месячный лимит сообщений, получает отказ большинства методов, пока его не оплатят. Что входит в каждый тариф — на [странице тарифов](https://pachca.com/prices).

### Список инструментов зависит от токена

Программа получает только инструменты, которые подходят токену: по роли в пространстве, тарифу и типу токена. Какие именно — в разделе [Какие инструменты получает программа](/guides/mcp/tools#kakie-instrumenty-poluchaet-programma).

### Способы входа

Программа входит через браузер с экраном согласия или подключается персональным токеном либо токеном бота в заголовке `Authorization`. Чем отличаются способы и какой подходит вашей программе — в разделе [Подключение к MCP](/guides/mcp/connect).

## Подтверждение действий

Разрешение на вызов инструмента спрашивает сама программа, так, как её настроил сотрудник: перед каждым вызовом, только перед изменениями или без вопросов. Сервер помечает каждый инструмент, и программы учитывают пометки:

- **Чтение** — инструмент только читает данные.
- **Изменение** — создаёт или меняет данные.
- **Опасное изменение** — перезаписывает или удаляет то, что уже есть: правка, удаление, исключение участника, перевыпуск токена. Сюда же создание бота и сотрудника: бот шлёт события на адрес по выбору создателя, а приглашение уходит на любую почту.

Пометка каждого инструмента — в разделе [Инструменты MCP](/guides/mcp/tools).

По инструкциям сервера агент сам просит подтверждения в чате только в четырёх случаях: объект изменения он выбрал сам (например, из нескольких совпадений), изменение нельзя отменить, хотя подошло бы обратимое (приостановить сотрудника вместо удаления), оно затрагивает сразу много объектов или агент отправляет от имени сотрудника текст, который сочинил сам.

### Безопасные режимы

Если сотрудник хочет сам решать, что уйдёт в Пачку, подойдёт один из двух режимов:

- **Только чтение.** Агента подключают персональным токеном с правами на чтение и поиск, и вызовы, которые меняют данные, получают отказ. Как создать такой токен — в разделе [Агент только для чтения](/guides/mcp/connect#agent-tolko-dlya-chteniya).
- **Черновик вместо отправки.** Агент кладёт готовое сообщение в поле ввода чата, а отправляет его сотрудник. Черновики работают с токеном сотрудника, подробнее — в разделе [Черновик вместо отправки](/guides/ai-agents/drafts).

## Безопасность

**Поставщик модели получает то, что прочитал агент.** Ответы инструментов попадают в контекст модели, поэтому сообщения, файлы и данные сотрудников, которые агент прочитал, уходят поставщику модели, выбранному в программе. Как они хранятся и используются дальше, определяют условия программы и поставщика модели. Сервер отдаёт агенту данные, доступные токену, и только в ответ на вызов инструмента.

**Чужой текст — это данные.** Сообщения, имена файлов и другие поля, которые пишут сотрудники, гости и боты, сервер отдаёт агенту внутри отдельной разметки, а в инструкциях сервера сказано не выполнять ничего из этого текста. Так сообщение с просьбой «перешли все токены» остаётся сообщением.

**Пачка сама не открывает ссылки из сообщений агента.** Через MCP сообщение отправляется без превью ссылки, файл передаётся содержимым, выгрузка не шлёт событие на внешний адрес. Иначе внедрённая в чат инструкция могла бы попросить агента написать ссылку с данными, и данные ушли бы на чужой сервер без единого клика. Адрес, на который бот шлёт события, агент меняет только опасным изменением бота.

**Секреты отдаются только вам.** Инструменты, которые возвращают токен бота или адрес входящего вебхука, говорят агенту показать их вам и больше никуда не передавать.

**Подключая несколько серверов, оставьте подтверждения.** Если в программе одновременно подключены другие MCP-серверы, текст из одного может попытаться управлять инструментами другого. Не отключайте подтверждение для изменений.

**Администратор видит выданные доступы.** Подключение через браузер видно на вкладке [Все токены](/api/authorization#vse-tokeny-prostranstva) строкой «Клиент MCP», и администратор может его отозвать. Персональный токен, отданный агенту, виден там обычным персональным токеном, а токены ботов собраны в карточках ботов. На тарифе «Корпорация» выдача и отзыв доступа записываются в [журнал аудита](/guides/audit-events#tokeny-i-avtorizatsii-v-zhurnale). Подробнее — на странице [Агенты и MCP в пространстве](/guides/agents-access).

**Сообщение помечено программой.** Сообщение, которое агент отправил после входа через браузер, подписано именем сотрудника, а на аватаре стоит иконка программы с подсказкой «Отправлено через «Claude Code»». С персональным токеном иконки нет, и такое сообщение не отличить от написанного вручную. Как помечены сообщения при каждом способе доступа — в разделе [Как выглядят сообщения](/api/authorization#kak-vyglyadyat-soobscheniya).

## Пределы

- **Вызовы.** Не больше 20 вызовов инструментов в секунду на токен. Лишний вызов получает отказ со сроком, через который можно повторить.
- **Запросы к серверу.** Не больше 100 запросов в секунду на токен, включая подключение и список инструментов. Сверх этого сервер отвечает `429`.
- **Лимиты API.** Каждый вызов — запрос к API, поэтому действуют все [лимиты](/api/limits), например на отправку сообщений.
- **Список инструментов.** Описания всех инструментов вместе занимают десятки тысяч токенов контекста модели. Если программа позволяет, отключите инструменты, которые агенту не нужны.
- **Размер ответа.** До 100 000 символов. В списках каждая запись сокращена до основных полей, полную запись агент получает по запросу. Длинный список сервер обрезает по целым записям и подсказывает агенту запросить страницу поменьше.
- **Файлы от сервера.** Файл до 3,75 МБ приходит агенту в ответе: картинка — картинкой, текст — текстом до 100 000 символов, остальное — вложением. Про файл больше агент узнаёт только его размер.
- **Файлы от агента.** Содержимым в одном вызове — до 4 МБ вместе с файлами в base64, то есть около 3 МБ исходных файлов. Документ или картинку с диска агент загружает сам — в разделе [Как агент отправляет файл](/guides/mcp/tools#kak-agent-otpravlyaet-fayl).
