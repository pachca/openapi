# Авторизация от имени сотрудника

Обычно бот работает своими правами: видит чаты, в которые его добавили, и пишет как бот. Но многим автоматизациям нужны права конкретного сотрудника: собрать сводку по его чатам, завести задачу от его имени, присылать ему задачи из трекера и отвечать на них прямо из Пачки. Для этого сотрудник авторизует бота — выдаёт ему свои права, и дальше бот работает от его имени.

Механизм — OAuth 2.0 с кодом авторизации: бот отправляет сотрудника на экран согласия, получает код и обменивает его на токен, которым вызывает API от имени сотрудника.

## Где включается

Авторизация включается на вкладке **OAuth** в карточке бота: там выдаются `client_id` и `client_secret`, задаются адреса возврата и набор прав, который бот попросит у сотрудника. Подробнее — в разделе [Настройка бота](/guides/oauth/setup).

## Как это выглядит для сотрудника


  ### Шаг 1. Сотрудник пишет боту

Находит бота в [витрине](/guides/bots/showcase) или в поиске и пишет ему, например `/start`.


  ### Шаг 2. Бот присылает кнопку

В ответ бот отправляет сообщение с кнопкой авторизации. Кнопка — обычная ссылка на экран согласия.


  ### Шаг 3. Сотрудник соглашается

На экране согласия видны имя бота, пространство и запрашиваемые права. Сотрудник нажимает **Разрешить**.


  ### Шаг 4. Бот получает токен

Браузер возвращается на адрес вашего сервера с кодом, сервер обменивает код на токен сотрудника. В витрине у бота появляется отметка **Подключено**.


Как собрать кнопку и обменять код — в разделе [Получение токена](/guides/oauth/flow).

## Ограничения

- **Только своё пространство.** Авторизовать бота может сотрудник того же пространства, где создан бот.
- **Гостям недоступно.** Гость не может авторизовать бота, а мульти-гость может, как и сотрудник. Если владелец пространства разрешил работу с API только администраторам, авторизация закрыта и сотрудникам, и мульти-гостям.
- **Роль урезает права.** Право из набора, недоступное роли сотрудника, работать не будет: вызов с таким токеном вернёт `403`.
- **Набор прав один.** Бот не выбирает права при каждой авторизации: запрашивается ровно то, что задано в его настройках.
