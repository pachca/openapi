# Настройка и типы событий

Все настройки исходящего вебхука собраны на вкладке **Исходящий вебхук** в карточке бота. Пока вебхук выключен, на вкладке одна кнопка **Включить**: она спрашивает URL вашего сервера, а остальные настройки появляются после включения.

![Вкладка «Исходящий вебхук» в карточке бота: адрес, подпись, история, свои сообщения и список событий](/images/outgoing-webhook.webp)

*Вкладка «Исходящий вебхук» в карточке бота*


## Общие настройки

- **Webhook URL** — адрес, на который Пачка отправляет события. Подходит только публичный адрес `http` или `https`: локальные и внутренние адреса не принимаются, для разработки подойдёт туннель.
- **Signing secret** — ключ HMAC-SHA256 для проверки подписи из заголовка `Pachca-Signature`. Появляется после включения вебхука. Подробнее — в разделе [Безопасность и обработчик](/guides/webhook/handler).
- **Сохранять историю событий** — бот сохраняет все исходящие вебхуки в очередь, и их можно получить через API. Подробнее — в разделе [Поллинг](/guides/webhook/polling).
- **Игнорировать свои сообщения** — не получать вебхуки о сообщениях, отправленных самим ботом, и о реакциях, которые он сам поставил или снял. Реакции других участников на сообщения бота приходят всегда. Предотвращает зацикливание, когда бот реагирует на собственные сообщения. Нажатия кнопок обрабатываются всегда, вне зависимости от этой настройки.

Кнопка **Удалить вебхук** внизу вкладки отключает вебхук: события перестают доставляться, история событий, режим новых сообщений и «Игнорировать свои сообщения» возвращаются к начальным значениям, а **Signing secret** выпускается новый. Если включить вебхук снова, он, как новый, подписан на новые сообщения.

## Какие события откуда приходят

События отмечают в списке на той же вкладке. Большинство приходит из чатов, где состоит бот, и из их тредов. Тред, куда бота добавили без родительского чата, — тоже такой чат.

| Событие на вкладке | Значения в `events` | Откуда приходит |
| --- | --- | --- |
| **Новые сообщения** | `message_new` | Чаты, где состоит бот, и их треды |
| **Редактирование и удаление сообщений** | `message_update`, `message_delete` | Чаты, где состоит бот, и их треды |
| **Добавление и удаление реакций** | `reaction_new`, `reaction_delete` | Чаты, где состоит бот, и их треды |
| **Нажатие кнопок** | `button_click` | Нажатия кнопок в сообщениях самого бота и отправка форм, которые он открыл |
| **Изменение состава участников чатов** | `chat_member_add`, `chat_member_remove` | Чаты, где состоит бот, и их треды |
| **Изменение участников пространства** | `company_member_invite`, `company_member_confirm`, `company_member_suspend`, `company_member_activate`, `company_member_delete`, `company_member_update` | Всё пространство |
| **Отправка ссылок в сообщении (unfurl)** | `message_link_shared` | Все чаты пространства, только ссылки на домены бота |
| **Начало видеозвонка**, **Завершение видеозвонка**, **Готовность записи видеозвонка** | `video_call_started`, `video_call_finished`, `video_call_recording_ready` | Чаты, где состоит бот, и их треды |

## Через API

Те же настройки задаются в объекте `webhook` метода [Редактирование бота](/api/bots/update) или сразу при создании методом [Новый бот](/api/bots/create), а текущие значения возвращаются в объекте бота:

| Настройка | Поле |
| --- | --- |
| **Webhook URL** | `outgoing_url`, пустая строка отключает вебхук |
| События | `events` — значения из таблицы выше |
| Режим новых сообщений | `trigger_on`: `all_messages` или `commands` |
| Команды | `commands` — список команд, вместе через запятую не длиннее 255 символов |
| **Сохранять историю событий** | `events_history_enabled` |
| **Игнорировать свои сообщения** | `ignore_self_messages` |
| Домены для ссылок | `unfurl_domains` |

Персональному токену для этого нужен скоуп `bots:write` и доступ к настройкам бота. Бот может и сам прописать свой адрес собственным токеном — методом [Саморегистрация вебхука бота](/api/bots/update-webhook) со скоупом `bot_self:webhook:write`, без участия администратора: так, например, [n8n](/guides/n8n/trigger) регистрирует свой адрес. Боту с включённым [разворачиванием ссылок](/guides/link-previews) адрес меняет только администратор или владелец, и саморегистрация вернёт ошибку.

## Сообщения

В настройках доступны два отдельных пункта:

- **Новые сообщения** — создание сообщений
- **Редактирование и удаление сообщений** — изменение текста или файлов и удаление сообщений

Для новых сообщений доступны два режима отслеживания:

- **Любые сообщения** — все новые сообщения, включая треды
- **Начинающиеся с команд** — только сообщения, первое слово которых совпадает с одной из команд, например `/help` или `/deploy`. Команды перечисляются через запятую, совпадение проверяется точно, с учётом регистра. Полезно, если вы не хотите получать поток событий, а вам нужно вызвать сценарий только по требованию пользователя.

Режим действует и на редактирование: в режиме «Начинающиеся с команд» о правке приходят только сообщения, которые начинаются с команды. Удаления приходят всегда.

> Режим «Любые сообщения» присылает событие и для сообщений без текста, например только с файлом или картинкой. Режим «Начинающиеся с команд» для них не сработает, потому что команда определяется по первому слову текста, которого в таком сообщении нет.


> **Внимание:** Новый бот стоит в режиме «Начинающиеся с команд» с пустым списком команд и о новых сообщениях не узнаёт. Так у ботов, созданных и в интерфейсе, и методом [Новый бот](/api/bots/create) без `trigger_on`. Выберите режим «Любые сообщения» или перечислите команды. Подробнее — в разделе [Общение с ботом](/guides/bots/conversations).


#### MessageWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"message"`
  Значения: `message` — Для сообщений всегда message
- `id: integer, int32` (required) — Идентификатор сообщения. Пример: `1245817`
- `event: string` (required) — Тип события
  Значения: `new` — Создание, `update` — Обновление, `delete` — Удаление
- `entity_type: string` (required) — Тип сущности, к которой относится сообщение
  Значения: `discussion` — Беседа или канал, `thread` — Тред, `user` — Пользователь
- `entity_id: integer, int32` (required) — Идентификатор сущности, к которой относится сообщение. Пример: `5678`
- `content: string` (required) — Текст сообщения. Пример: `"Текст сообщения"`
- `user_id: integer, int32` (required) — Идентификатор отправителя сообщения. Пример: `2345`
- `created_at: date-time` (required) — Дата и время создания сообщения (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Пример: `"2025-05-15T14:30:00.000Z"`
- `changed_at: date-time` (nullable) — Дата и время последнего изменения сообщения (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. У неотредактированного сообщения совпадает с датой создания. `null` у сообщений, отправленных до появления этого поля. Пример: `"2025-05-15T14:35:00.000Z"`
- `url: string` (required) — Прямая ссылка на сообщение. Пример: `"https://app.pachca.com/chats/9012?message=1245817"`
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором находится сообщение. Пример: `9012`
- `parent_message_id: integer, int32` (nullable) — Идентификатор сообщения, к которому написан ответ. `null`, если сообщение не является ответом на другое сообщение. Пример: `3456`
- `thread: object` — Тред, в котором отправлено сообщение. `null`, если сообщение отправлено не в треде. В отличие от поля `thread` в объекте сообщения REST API, здесь описывается тред, внутри которого находится сообщение.
  - `message_id: integer, int32` (required, nullable) — Идентификатор сообщения, к которому был создан тред. `null` у треда без сообщения-родителя — такие создаёт [Новый самостоятельный тред](/api/threads/create). Пример: `12345`
  - `message_chat_id: integer, int32` (required, nullable) — Идентификатор чата сообщения, к которому был создан тред. `null` у треда без сообщения-родителя. Пример: `67890`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


> Payload содержит только основные поля сообщения: текст, автора, чат, ответ и тред. По payload нельзя определить, есть ли у сообщения вложение: у сообщения без текста (например, только с файлом) поле `content` придёт пустой строкой. Вложения, реакции, кнопки, информацию о пересланном сообщении и другие поля получите методом [Информация о сообщении](/api/messages/get) по полю `id`. Для события `delete` метод по-прежнему отвечает `200`, но возвращает уже очищенную запись: `content` пустой, вложения и реакции удалены, заполнено поле `deleted_at`. В списке сообщений такая запись не возвращается.


## Реакции

Вебхук отправляется при добавлении или удалении реакции на сообщение.

#### ReactionWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"reaction"`
  Значения: `reaction` — Для реакций всегда reaction
- `event: string` (required) — Тип события
  Значения: `new` — Создание, `delete` — Удаление
- `chat_id: integer, int32` (required, nullable) — Идентификатор чата, в котором находится сообщение. Поле всегда присутствует в payload. В редких случаях (например, если сообщение было удалено к моменту отправки вебхука) может быть `null`. Пример: `9012`
- `message_id: integer, int32` (required) — Идентификатор сообщения, к которому относится реакция. Пример: `1245817`
- `code: string` (required) — Emoji символ реакции. Пример: `"👍"`
- `name: string` (required) — Название реакции. Пример: `"thumbsup"`
- `user_id: integer, int32` (required) — Идентификатор пользователя, который добавил или удалил реакцию. Пример: `2345`
- `created_at: date-time` (required) — Дата и время добавления реакции (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Поле присутствует и для события удаления реакции. Пример: `"2025-05-15T14:30:00.000Z"`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


> Payload содержит все данные реакции. Если нужен контекст, получите сообщение методом [Информация о сообщении](/api/messages/get) по `message_id` или автора методом [Информация о сотруднике](/api/users/get) по `user_id`.


## Нажатие кнопок

Вебхук отправляется при нажатии `Data`-кнопки в сообщении от бота. После получения вы можете изменить или удалить кнопки методом [Редактирование сообщения](/api/messages/update) или ответить пользователю методом [Новое сообщение](/api/messages/create). Подробнее — в разделе [Кнопки в сообщениях](/guides/buttons).

#### ButtonWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"button"`
  Значения: `button` — Для кнопки всегда button
- `event: string` (required) — Тип события. Пример: `"click"`
  Значения: `click` — Нажатие кнопки
- `message_id: integer, int32` (required) — Идентификатор сообщения, к которому относится кнопка. Пример: `1245817`
- `trigger_id: string` (required) — Уникальный идентификатор события. Время жизни — 3 секунды. Может быть использован, например, для открытия представления пользователю. Пример: `"a1b2c3d4-5e6f-7g8h-9i10-j11k12l13m14"`
- `data: string` (required) — Данные нажатой кнопки. Пример: `"button_data"`
- `user_id: integer, int32` (required) — Идентификатор пользователя, который нажал кнопку. Пример: `2345`
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором была нажата кнопка. Пример: `9012`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


> Payload содержит данные нажатой кнопки. Полное сообщение получите методом [Информация о сообщении](/api/messages/get) по `message_id`.


## Заполнение формы

Вебхук отправляется при отправке пользователем заполненной формы ([представления](/guides/forms/overview)). Подробнее об обработке результатов — в разделе [Обработка форм](/guides/forms/handling). Если у бота не задан адрес исходящего вебхука, ответить на это событие можно методом [Ответ на отправку формы](/api/views/submit-response) по `view_id` и `submit_id` из payload.

> Поле `chat_id` фиксируется в момент **открытия** формы (нажатия кнопки), а не её отправки: если форма провисела открытой долго, поле всё равно ссылается на чат с кнопкой.


#### ViewSubmitWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"view"`
  Значения: `view` — Для формы всегда view
- `event: string` (required) — Тип события. Пример: `"submit"`
  Значения: `submit` — Отправка формы
- `callback_id: string` (required, nullable) — Идентификатор обратного вызова, указанный при открытии представления. `null`, если при открытии формы он не был указан. Пример: `"timeoff_request_form"`
- `private_metadata: string` (required, nullable) — Приватные метаданные, указанные при открытии представления. `null`, если при открытии формы они не были указаны. Пример: `"{\"timeoff_id\":4378}"`
- `chat_id: integer, int32` (required, nullable) — Идентификатор чата, в котором была нажата кнопка, открывшая форму. Фиксируется при открытии формы, а не при её отправке. Пример: `9012`
- `user_id: integer, int32` (required) — Идентификатор пользователя, который отправил форму. Пример: `1235523`
- `view_id: string` (required) — Идентификатор представления. Нужен боту без адреса исходящего вебхука, чтобы ответить методом [Ответ на отправку формы](/api/views/submit-response). Пример: `"01KAJZ2XDSS2S3DSW9EXJZ0TBV"`
- `submit_id: string` (required) — Идентификатор отправки формы. Нужен боту без адреса исходящего вебхука, чтобы ответить методом [Ответ на отправку формы](/api/views/submit-response). Пример: `"791a056b-006c-49dd-834b-c633fde52fe8"`
- `data: Record<string, object>` (required) — Данные заполненных полей представления. Ключ — `name` блока, значение — введённые данные. У блока `file_input` значение приходит массивом объектов с полями `name`, `size` и `url`, ссылка действует 2 часа.
  **Структура значений Record:**
  - Тип значения: `any`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1755075544`


> Payload содержит все заполненные поля формы в `data`, дополнительных запросов не требуется. При необходимости получите автора методом [Информация о сотруднике](/api/users/get) по `user_id`.


## Изменение участников чатов

Вебхук отправляется при изменении состава участников чата.

> Когда сотрудник впервые открывает личную переписку с ботом, события нет — ни об изменении участников, ни о новом чате. Бот узнаёт о сотруднике из его первого сообщения.


#### ChatMemberWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"chat_member"`
  Значения: `chat_member` — Для участника чата всегда chat_member
- `event: string` (required) — Тип события
  Значения: `add` — Добавление, `remove` — Удаление
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором изменился состав участников. Пример: `9012`
- `thread_id: integer, int32` (nullable) — Идентификатор треда. `null`, если участники добавлены в обычный чат или канал, а не в тред. Пример: `5678`
- `user_ids: array of integer` (required) — Массив идентификаторов пользователей, с которыми произошло событие. Пример: `[2345,6789]`
- `created_at: date-time` (required) — Дата и время события (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ssZ. В этом вебхуке время приходит без долей секунды, в отличие от остальных. Пример: `"2025-05-15T14:30:00Z"`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


> Payload содержит только идентификаторы. Полные данные сотрудников получите методом [Информация о сотруднике](/api/users/get) по каждому `user_id`, а сам чат — методом [Информация о чате](/api/chats/get) по `chat_id`.


## Изменение участников пространства

Вебхук отправляется, когда участника пространства приглашают, он принимает приглашение, его приостанавливают, снова активируют или удаляют, а также когда меняются его данные. Добавлять бота в чат не нужно.

#### CompanyMemberWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"company_member"`
  Значения: `company_member` — Для участника пространства всегда company_member
- `event: string` (required) — Тип события
  Значения: `invite` — Приглашение, `confirm` — Подтверждение, `update` — Обновление, `suspend` — Приостановка, `activate` — Активация, `delete` — Удаление
- `user_ids: array of integer` (required) — Массив идентификаторов пользователей, с которыми произошло событие. Пример: `[2345,6789]`
- `created_at: date-time` (required) — Дата и время события (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ssZ. В этом вебхуке время приходит без долей секунды, в отличие от остальных. Пример: `"2025-05-15T14:30:00Z"`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


> Payload содержит только идентификаторы сотрудников. Полные данные получите методом [Информация о сотруднике](/api/users/get) по каждому `user_id`.


## Отправка ссылок

Вебхук отправляется при появлении в сообщении ссылки на один из доменов бота — из любого чата пространства, добавлять бота в чаты не нужно. Событие **Отправка ссылок в сообщении (unfurl)** и его домены (до 5, через запятую) включает только администратор или владелец пространства. После получения вы можете воспользоваться методом [Unfurl (разворачивание ссылок)](/api/messages/unfurl) и создать предпросмотр ссылки в сообщении. Подробнее — в разделе [Разворачивание ссылок](/guides/link-previews).

#### LinkSharedWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"message"`
  Значения: `message` — Для разворачивания ссылок всегда message
- `event: string` (required) — Тип события. Пример: `"link_shared"`
  Значения: `link_shared` — Обнаружена ссылка на отслеживаемый домен
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором обнаружена ссылка. Пример: `23438`
- `message_id: integer, int32` (required) — Идентификатор сообщения, содержащего ссылку. Пример: `268092`
- `links: array of object` (required) — Массив обнаруженных ссылок на отслеживаемые домены
  - `url: string` (required) — URL ссылки. Пример: `"https://example.com/page1"`
  - `domain: string` (required) — Домен ссылки. Пример: `"example.com"`
  - `skip: boolean` (required) — Признак того, что автор сообщения скрыл превью для этой ссылки. Если `true` — бот не должен создавать превью. Пример: `false`
- `user_id: integer, int32` (required) — Идентификатор отправителя сообщения. Пример: `2345`
- `entity_type: string` (required) — Тип сущности, к которой относится сообщение со ссылкой
  Значения: `discussion` — Беседа или канал, `thread` — Тред, `user` — Пользователь
- `entity_id: integer, int32` (required, nullable) — Идентификатор сущности: беседы или канала, треда. В личной переписке `null`: бот в ней не участвует, и собеседника ему не раскрывают. Пример: `23438`
- `thread: object` (required) — Тред, в котором отправлено сообщение со ссылкой. `null`, если сообщение отправлено не в треде.
  - `message_id: integer, int32` (required, nullable) — Идентификатор сообщения, к которому был создан тред. `null` у треда без сообщения-родителя — такие создаёт [Новый самостоятельный тред](/api/threads/create). Пример: `12345`
  - `message_chat_id: integer, int32` (required, nullable) — Идентификатор чата сообщения, к которому был создан тред. `null` у треда без сообщения-родителя. Пример: `67890`
- `created_at: date-time` (required) — Дата и время создания сообщения (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Пример: `"2024-09-18T19:53:14.000Z"`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1726685594`


> Payload содержит обнаруженные ссылки. Полное сообщение получите методом [Информация о сообщении](/api/messages/get) по `message_id`.


## Видеозвонки

Вебхук отправляется о видеозвонках. Поле `event` в payload различает три события: `started` (звонок начался), `finished` (звонок завершился) и `recording_ready` (запись готова). Набор полей payload зависит от события.

#### VideoCallWebhookPayload

- `type: string` (required) — Тип объекта. Пример: `"video_call"`
  Значения: `video_call` — Для видеозвонков всегда video_call
- `event: string` (required) — Тип события
  Значения: `started` — Видеозвонок начался, `finished` — Видеозвонок завершился, `recording_ready` — Запись видеозвонка готова
- `video_room_id: integer, int32` (required) — Идентификатор видеозвонка. Пример: `9012`
- `chat_id: integer, int32` (required) — Идентификатор чата, в котором проходит видеозвонок. Пример: `23438`
- `owner_id: integer, int32` (required) — Идентификатор пользователя, начавшего видеозвонок. Пример: `2345`
- `thread: object` — Объект с параметрами треда, если видеозвонок проходит в треде. `null`, если звонок не в треде.
  - `id: integer, int32` (required) — Идентификатор треда. Пример: `12345`
  - `chat_id: integer, int32` (required) — Идентификатор чата треда. Пример: `67890`
  - `message_id: integer, int32` (required, nullable) — Идентификатор сообщения, к которому создан тред. `null` у треда без сообщения-родителя — такие создаёт [Новый самостоятельный тред](/api/threads/create). Пример: `268092`
  - `message_chat_id: integer, int32` (required, nullable) — Идентификатор чата сообщения, к которому создан тред. `null` у треда без сообщения-родителя. Пример: `23438`
- `started_at: date-time` — Дата и время начала звонка (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Присутствует для событий started и finished. Пример: `"2025-05-15T14:30:00.000Z"`
- `finished_at: date-time` — Дата и время завершения звонка (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Присутствует для события finished. Пример: `"2025-05-15T14:45:00.000Z"`
- `duration: integer, int32` — Длительность в секундах. Для события finished — длительность звонка, для recording_ready — длительность записи. Пример: `900`
- `members: array of object` — Список участников звонка. Присутствует для события finished.
  - `user_id: integer, int32` (required) — Идентификатор участника. Пример: `2345`
  - `joined_at: date-time` (required) — Дата и время первого подключения к звонку (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Пример: `"2025-05-15T14:30:00.000Z"`
  - `left_at: date-time` (required) — Дата и время выхода из звонка (ISO-8601, UTC+0) в формате YYYY-MM-DDThh:mm:ss.sssZ. Если участник оставался в звонке до его завершения, совпадает с временем окончания звонка. Пример: `"2025-05-15T14:45:00.000Z"`
- `recording_id: integer, int32` — Идентификатор записи. Присутствует для события recording_ready. Пример: `4567`
- `file_id: integer, int32` (nullable) — Идентификатор файла записи. Присутствует для события recording_ready. `null`, если файл ещё не привязан. Пример: `89012`
- `url: string` — Прямая ссылка на файл записи. Присутствует для события recording_ready. Пример: `"https://api.pachca.com/files/89012"`
- `size: integer, int64` — Размер файла записи в байтах. Присутствует для события recording_ready. Пример: `10485760`
- `webhook_timestamp: integer, int32` (required) — Дата и время отправки вебхука (UTC+0) в формате UNIX. Пример: `1747574400`


> Для события `finished` payload содержит список участников с временем подключения и выхода, для `recording_ready` — ссылку на файл записи, её размер и длительность. Полные данные участников получите методом [Информация о сотруднике](/api/users/get) по каждому `user_id`, а чат — методом [Информация о чате](/api/chats/get) по `chat_id`.
