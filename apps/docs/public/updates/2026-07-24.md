# Самостоятельные треды и аудит видеозвонков

_24 июля 2026_

Появился метод [Новый самостоятельный тред](/api/threads/create) — создание треда, не связанного с сообщением. Тело запроса не требуется, создатель становится единственным участником треда. Метод требует скоуп `threads:create`. Поскольку у такого треда нет исходного сообщения, поля `message_id` и `message_chat_id` в объекте треда теперь могут возвращаться как `null` — это касается всех методов работы с тредами.

- [Новый самостоятельный тред](/api/threads/create)

В журнале аудита появились типы событий видеозвонков: `video_call_started`, `video_call_finished` и `video_call_recording_ready`. Их можно фильтровать параметром `event_key`. В деталях события возвращаются `chat_id`, длительность и (для записи) размер файла.

- [Журнал аудита событий](/api/security/list)

### SDK v1.0.27

- Метод `Новый самостоятельный тред` (`POST /threads`) — создание треда без привязки к сообщению
- У модели `Thread` поля `message_id` и `message_chat_id` стали nullable (`null` для самостоятельного треда)
- Журнал аудита: типы событий `video_call_started`, `video_call_finished`, `video_call_recording_ready` и модели деталей `AuditDetailsVideoCall`, `AuditDetailsVideoCallRecording`

### CLI v2026.7.1

- `pachca threads create` — создание самостоятельного треда без привязки к сообщению
- Примеры в `--help` больше не смешиваются между командами с общим путём

### n8n Node v2.0.15

- `Thread`: операция `Create a standalone thread` — создание треда без привязки к сообщению
- `Security`: в фильтр событий добавлены `video_call_started`, `video_call_finished`, `video_call_recording_ready`
