# Архивные чаты в списке, OAuth-клиент бота и проверка entity_type

_05 августа 2026_

Список чатов научился отдавать архивные. По умолчанию, как и раньше,
возвращаются только активные чаты, а параметр `archived` добавляет к ним
архивные — при любом значении `availability`. Отличить один от другого можно по
новому полю `archived` объекта чата: оно приходит во всех ответах с чатом,
независимо от параметров запроса.

- [Список чатов](/api/chats/list)
- [Информация о чате](/api/chats/get)

У бота появились параметры OAuth-клиента. Их можно задать при создании и
редактировании бота объектом `oauth_client`, а в ответе они приходят в
одноимённом поле: идентификатор клиента, сокращённый вид его секрета,
признак конфиденциальности, адреса возврата и запрашиваемые скоупы. Секрет
конфиденциального клиента целиком возвращается один раз — в ответе на создание,
в поле `client_secret`.

- [Новый бот](/api/bots/create)
- [Редактирование бота](/api/bots/update)
- [Информация о боте](/api/bots/get)
- [Список ботов](/api/bots/list)

Скоуп `group_tags:read` стал доступен роли «Сотрудник» и токенам ботов — теги в
API теперь видны тем же, кому они видны в интерфейсе.

Неизвестное значение `entity_type` при отправке сообщения больше не приводит к
отправке в чат со случайно совпавшим идентификатором: метод отвечает `400` с
кодом `invalid`. Регистр значения по-прежнему не важен.

- [Новое сообщение](/api/messages/create)

В журнале аудита появились три типа событий: изменение параметров OAuth-клиента
бота, выдача клиенту доступа к данным пользователя и отзыв такого доступа.
Состав деталей каждого — в гайде [Журнал аудита событий](/guides/audit-events).

- [Журнал аудита событий](/api/security/list)

### SDK v1.2.0

- Поле `webhook` в запросах `POST /bots` и `PUT /bots/{id}` стало необязательным
- Поле `archived` в модели чата и одноимённый параметр запроса в методе `Список чатов` (`GET /chats`)
- Поле `oauth_client` в модели бота и в запросах `POST /bots` и `PUT /bots/{id}`, модели `BotOAuthClient` и `BotOAuthClientRequest`
- Поле `client_secret` в ответе метода `Новый бот` (`POST /bots`)
- Значения `bot_oauth_client_updated`, `oauth_authorization_granted` и `oauth_authorization_revoked` в `AuditEventKey` и модели их деталей
- Скоуп `group_tags:read` доступен ролям `user` и `bot`

### CLI v2026.8.1

- `pachca chats list` — флаг `--archived` для выдачи архивных чатов вместе с активными
- `pachca bots create` и `pachca bots update` — флаг `--oauth-client` с параметрами OAuth-клиента бота
- `pachca security list` — фильтр `--event-key` принимает `bot_oauth_client_updated`, `oauth_authorization_granted` и `oauth_authorization_revoked`

### n8n Node v2.0.18

- `Chat`: операция `Get Many` — поле `Archived` для выдачи архивных чатов вместе с активными
- `Bot`: операции `Create` и `Update` — поле `OAuth Client` с параметрами OAuth-клиента бота
- `Security`: фильтр событий пополнился значениями `Bot OAuth Client Updated`, `OAuth Authorization Granted` и `OAuth Authorization Revoked`
- `Group Tag`: у операций чтения тегов убрана пометка о необходимости прав администратора — скоуп `group_tags:read` доступен сотрудникам и ботам
- JSON-поля разбираются перед отправкой запроса и больше не уходят в API строкой. Некорректный ввод падает на ноде с понятным сообщением, а не возвращается ошибкой валидации из API. Затрагивает `Message: Unfurl` (поле `Link Previews`) и новое поле `OAuth Client`
