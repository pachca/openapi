# Раздел «Интеграции», авторизация от имени сотрудника и мульти-гость в API

_24 сентября 2026_

В Пачке обновился раздел **Интеграции**: боты пространства и их карточки с
настройками, токенами и вебхуками, витрина ботов и страница **API** с
персональными токенами, входами в CLI и авторизациями. Документация ботов
собрана заново под этот раздел: [Обзор](/guides/bots/overview),
[Создание бота](/guides/bots/setup), [Настройки бота](/guides/bots/settings),
[Токены бота](/guides/bots/tokens),
[Первый диалог с ботом](/guides/bots/first-contact) и
[Витрина](/guides/bots/showcase).

В документации появился новый раздел
[Авторизация от имени сотрудника](/guides/oauth/overview). Он про ботов,
которые работают с данными сотрудника его правами: сотрудник один раз
соглашается на экране согласия, и дальше бот действует от его имени в Пачке и
в связке с другими сервисами. Раздел описывает
[настройку бота](/guides/oauth/setup), [получение токена](/guides/oauth/flow),
[согласие и отзыв доступа](/guides/oauth/consent).

Мульти-гость теперь работает с API наравне с сотрудником: создаёт
персональные токены, входит в CLI и авторизует ботов. Через API он видит то
же, что в интерфейсе, — подробнее в разделе
[Мульти-гость в API](/guides/permissions#multi-gost-v-api).

Настройка бота «Кто может добавлять бота в чаты» теперь действует и в API. Если
она не разрешает вам добавить бота, запрос на добавление участников или
создание чата отклоняется целиком.

Ник бота теперь проверяется и при правке через методы сотрудников: он должен
оканчиваться на `_bot` и быть уникальным в пространстве.

Были обновлены следующие методы:

- [Добавление пользователей](/api/members/add)

- [Редактирование сотрудника](/api/users/update)
- [Список сотрудников](/api/users/list)
- [Список тегов](/api/group-tags/list)

### n8n Node v2.1.4

- README: где взять токен бота и персональный токен — теперь раздел «Интеграции»: «Боты» для бота, «API» для персонального
- `Bot`: значение `Anyone` поля `Who Can Add` описано как публичный бот, которого гости и мульти-гости не добавляют
- `Message` и `Task`: подсказки к полю `Content` и к фильтру `Chat IDs` описывают, что меняется для мульти-гостя

### CLI v2026.9.2

- `pachca auth login` — вход через браузер передаёт имя устройства, по которому вход узнаётся в списке токенов CLI
- `pachca guide`: сценарии разворачивания ссылок и поллинга описывают раздел «Интеграции» — событие ссылок с доменами и история событий без Webhook URL
- `pachca messages create`, `messages update` и `tasks list`: подсказки к `--content` и `--chat-ids` описывают, что меняется для мульти-гостя

### SDK v1.4.1

- Значение `bot_add_denied` в `ValidationErrorCode` — так `Добавление пользователей` (`POST /chats/{id}/members`) и `Новый чат` (`POST /chats`) отвечают на бота, которого вам не разрешает добавить его настройка «Кто может добавлять бота в чаты»
