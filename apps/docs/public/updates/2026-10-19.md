# Номер выгрузки в ответе и аватар бота

_19 октября 2026_

Метод [Экспорт сообщений](/api/chats/request-export) может сразу вернуть номер выгрузки: с заголовком `Prefer: return=representation` он отвечает статусом `202` и номером в теле. По этому номеру архив забирают методом [Скачать архив экспорта](/api/chats/download-export), когда сборка закончится, и вебхук для этого не нужен. SDK, CLI и нода n8n передают заголовок сами. Подробнее — в разделе [Экспорт сообщений](/guides/export).

Аватар бота теперь можно поставить и убрать через API. Это доступно тем, кто может редактировать настройки бота.

Были добавлены новые методы:

- [Загрузка аватара бота](/api/bots/update-avatar)
- [Удаление аватара бота](/api/bots/remove-avatar)

Обмен кода на токен и отзыв токена описаны в справочнике методов, рядом с остальными методами API. В SDK у них появились свои методы, а ссылку для кнопки авторизации и пару PKCE SDK собирает сам. Как пройти авторизацию от имени сотрудника целиком — в разделе [Получение токена](/guides/oauth/flow).

- [Обмен кода на токен](/api/oauth/exchange-token)

- Бесплатное пространство отправляет ограниченное число писем-приглашений за сутки. Подробнее — на странице [Лимиты](/api/limits).
- Редактирование сотрудника применяется целиком: если новая почта занята, остальные поля тоже не меняются.
- В тег можно добавить только бота, которого может добавить в чат любой сотрудник. Подробнее — в разделе [Бот в тегах](/guides/bots/settings#bot-v-tegah).

- Ответ `429` методов API при превышении лимитов приходит в `JSON`, как остальные ошибки. Подробнее — на странице [Лимиты](/api/limits).

- Списки и поиск отвечают ошибкой на нецелое число записей на странице. Подробнее — на странице [Пагинация](/api/pagination).

### n8n Node v2.2.0

- `Chat`: операция `Request Export` сразу возвращает номер выгрузки в `id` — с ним `Download Export` забирает архив, когда тот соберётся
- `Bot`: операции `Update Avatar` и `Delete Avatar` — аватар бота
- `Bot`: операция `Get` отдаёт в `Webhook` адрес входящего вебхука, секрет подписи и тело последнего запроса, если у токена есть скоуп `bots:write` и вы можете управлять токенами бота
- `Form`: в операции `Create` поля `Close Text` и `Submit Text` по умолчанию пустые — тогда кнопки подписывает Пачка: «Отменить» и «Отправить»
- `Message`: в операции `Create` поле `Content` необязательно — сообщение можно отправить из одних файлов
- `Profile` и `User`: в операции `Update Status` поля `Emoji` и `Title` нужны, только когда статуса ещё нет — продлить статус можно одним `Expires At`

### CLI v2026.10.1

- `pachca chats request-export` выводит номер выгрузки `id`: с ним `pachca chats download-export` забирает архив, когда тот соберётся
- `pachca bots update-avatar` и `bots remove-avatar` — аватар бота
- `pachca bots get`: в `webhook` приходят адрес входящего вебхука `url`, секрет подписи `secret_token` и тело последнего запроса `last_request_body`, если у токена есть скоуп `bots:write` и вы можете управлять токенами бота
- `pachca messages create` отправляет сообщение без `--content`, если к нему приложены файлы
- `pachca profile update-status` и `pachca users update-status`: `--emoji` и `--title` нужны, только когда статуса ещё нет — продлить статус можно одним `--expires-at`

### SDK v1.6.0

- Метод `Экспорт сообщений` (`POST /chats/exports`) возвращает модель `ChatExport` с идентификатором выгрузки: SDK передаёт заголовок `Prefer: return=representation`
- Метод `Скачивание файла` (`GET /files/{id}`) возвращает содержимое файла: `Blob` в TypeScript, `bytes` в Python, `[]byte` в Go, `ByteArray` в Kotlin, `Data` в Swift и `byte[]` в C#
- Класс ошибки SDK выбирает по телу ответа: `ApiError` — для ответа с массивом `errors`, `OAuthError` — для ответа с кодом в поле `error`, в том числе `403` с `insufficient_scope` или `role_forbidden`
- Перечисления в ответах принимают и значения, которых SDK ещё не знает: такое значение приходит как есть. В Kotlin такое перечисление — `value class` со строкой `value`, в Swift — `enum` со случаем `unknown(String)`, в C# — структура со строкой `Value`. В Python такое значение — элемент перечисления с исходной строкой в `value` и `is_known`, равным `False`. Код, который перебирает значения такого перечисления, дописывает ветку для незнакомого: `else` в `when` в Kotlin, `default` или `case .unknown` в `switch` в Swift, а в C# сравнивает через `==` или `switch` по `Value` вместо `case`. Перечисления, которые встречаются только в запросах, прежние.
- Поле `error` в `OAuthError` — перечисление `OAuthErrorCode`. В TypeScript поле — строка, а `OAuthErrorCode` перечисляет её значения.
- Go: ответ `401`, тело которого не разбирается, приходит обычной ошибкой `HTTP 401: …`, как ответы с другими кодами
- Методы `Обмен кода на токен` (`POST /oauth/token`) и `Отзыв токена` (`POST /oauth/revoke`) в сервисе `oauth` — для бота, который получает токен сотрудника
- Функции для кнопки авторизации: ссылка на экран согласия и пара PKCE — `buildAuthorizeUrl` и `createPkce` в TypeScript, в остальных языках по их правилам
- Методы `Загрузка аватара бота` (`PUT /bots/{id}/avatar`) и `Удаление аватара бота` (`DELETE /bots/{id}/avatar`)
- Поля `url`, `secret_token` и `last_request_body` в объекте `webhook` бота — приходят в методе `Информация о боте` (`GET /bots/{id}`)
- Коды ошибок `daily_invites_limit` и `restricted_bot_tag_denied`
- Поле `value` в `ApiErrorItem` принимает любое JSON-значение, как его отдаёт API: строку, число, массив, а иногда логическое значение или объект, например список `id` ботов у кода `bot_add_denied`. Тип поля — `unknown` в TypeScript, `Any` в Python, `any` в Go, `JsonElement` в Kotlin, `AnyCodable` в Swift и `object` в C#.
- Необязательны `content` в `MessageCreateRequest` — для сообщения из одних файлов — и `emoji` с `title` в `StatusUpdateRequest` — для продления статуса одним `expires_at`
- Поле `size` у файла в `MessageCreateRequest` необязательно, как при правке сообщения и в черновике: черновик отправляют, передав `key`, `name` и `file_type` его файлов
- Поля `started_at` и `duration` в `VideoCallWebhookPayload` и `duration` в `AuditDetailsVideoCallFinished` бывают `null` — у звонка, который завершился, так и не начавшись. В Go `StartedAt` — `*string`, как остальные даты, которые бывают `null`.
- Python: запросы правки сотрудника, задачи, бота и сообщения, а также создания бота передают только те поля, которые вы задали
- Python: поле-перечисление в ответе приходит элементом своего перечисления, как в аннотации типа
- Python: необязательный список в ответе разбирается по типу своих элементов, например `members` в `VideoCallWebhookPayload` — список `WebhookVideoCallMember`
- Модель `ExportWebhookPayload` — тело вебхука о готовой выгрузке
- C# и Kotlin: загрузка файла в хранилище и обмен кода на токен идут без заголовка `Authorization`. В C# такой запрос через переданный `HttpClient` с токеном в `DefaultRequestHeaders` уходит через отдельный клиент.

### Generator v1.3.0

- Заголовок запроса с единственным допустимым значением, например `Prefer: return=representation`, сгенерированный метод передаёт сам, а ответ `202` с телом становится его результатом
- Ответ с файлом (`application/octet-stream`) становится результатом метода: сгенерированный метод возвращает содержимое файла в типе своего языка
- Тело `application/x-www-form-urlencoded`: сгенерированный метод передаёт поля запроса формой
- Расширение `x-oauth-authorize-url` у операции: SDK получает функции, которые собирают ссылку авторизации и пару PKCE
- Класс ошибки выбирается по телу ответа, если в спеке есть обе модели ошибок: `ApiError` для массива `errors`, `OAuthError` для кода в поле `error`
- Перечисление, которое встречается в ответе, генерируется открытым: значение не из спеки разбирается без ошибки и сохраняется. Закрытыми остаются перечисления, которые встречаются только в запросах.
- Если поле `error` в `OAuthError` ссылается на перечисление, поле получает тип этого перечисления во всех языках, кроме TypeScript
- Go: ответ `401`, тело которого не разбирается, приходит ошибкой `HTTP 401: …` с причиной через `%w`, как ответы с другими кодами
- Python: поле-перечисление в ответе разбирается в элемент своего перечисления
- Python: необязательный список (`list[X] | None`) в ответе разбирается по типу своих элементов
- Массив в query уходит парами `name[]=value` по расширению `x-query-array: brackets` у параметра. Без расширения значение повторяется под тем же именем: `name=a&name=b`.
- Ссылка на схему-скаляр с ограничениями, например целое от 0 до 6, становится примитивом своего языка, а не моделью
- Объединение простых значений — `anyOf` из строк, чисел, логических значений, массивов и объектов без `$ref` — становится открытым JSON-значением: `unknown` в TypeScript, `Any` в Python, `any` без указателя в Go, `JsonElement` в Kotlin, `AnyCodable` в Swift и `object` в C#
- Go: код успешного ответа берётся из спеки — `200`, `201`, `202` или `204`
- C# и Kotlin: операция без авторизации (`x-requirements: { auth: false }`) уходит без заголовка `Authorization`, даже если токен задан в заголовках клиента по умолчанию
