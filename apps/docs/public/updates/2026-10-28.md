# MCP-сервер, плагин «Пачка», раздел «Важное» и перевод в гости

_28 октября 2026_

Появился MCP-сервер Пачки: Claude Code, Cursor и другие программы с AI-агентами подключаются по адресу `https://mcp.pachca.com/mcp` и получают инструмент на каждый метод API. Права те же, что в API, а программу, подключённую через браузер, видно в списке «Авторизации» на странице «API». Через браузер входят Claude Code, приложение Claude, VS Code с GitHub Copilot, Codex и приложение ChatGPT на компьютере, а Cursor и многие другие программы подключаются персональным токеном. Подробнее — в разделах [MCP-сервер](/guides/mcp/overview) и [Подключение к MCP](/guides/mcp/connect).

Скиллы для AI-агентов написаны заново: теперь это знание о том, как правильно делать задачи в Пачке. Куда писать и когда спрашивать перед действием, как найти и пересказать обсуждение, какой токен выбрать и почему не хватает прав. Справочник по аргументам агент берёт из описаний инструментов MCP-сервера и `pachca <команда> --help`. В Claude Code, приложении Claude, Codex, VS Code с GitHub Copilot и Cursor скиллы вместе с MCP-сервером ставит плагин «Пачка», в нём же команды для сводки пропущенного, пересказа треда, дайджеста, объявления и задач по итогам обсуждения. В SourceCraft Code Assistant, OpenCode и другие агенты восемь скиллов ставятся без плагина. Страницы «Сценарии», файл Arazzo и команда `pachca guide` убраны, их роль взяли скиллы. Семь прежних скиллов тоже убраны: если они у вас стоят, удалите их командой из раздела [Скиллы без плагина](/guides/mcp/plugin#skilly-bez-plagina). Подробнее — в разделе [Плагин и скиллы](/guides/mcp/plugin).

Через API можно вести личный раздел «Важное»: получать список отмеченных сообщений, добавлять в него сообщение и убирать оттуда. Отметку видит только сам сотрудник, и она остаётся после выхода из чата. Методы работают с токеном сотрудника, токену бота они недоступны. У сообщений в ответах API появилось поле `important`. У добавления и удаления свой [лимит](/api/limits).

Были добавлены новые методы:

- [Список важных сообщений](/api/important-messages/list)
- [Добавление сообщения в важные](/api/important-messages/create)
- [Удаление сообщения из важных](/api/important-messages/delete)

Методом [Редактирование сотрудника](/api/users/update) сотрудника или мульти-гостя можно перевести в гости, указав чат, в котором он останется. Перевод снимает все теги, выводит из остальных бесед и каналов и отзывает все токены сотрудника, включая доступы, выданные ботам и программам с MCP. Повышение роли ничего из этого не возвращает. Подробнее — в разделе [Перевод в гости](/guides/permissions#perevod-v-gosti).

Бот без публичного адреса может получать события сразу, как они происходят: по ссылке в формате Server-Sent Events. Так он успевает ответить на нажатие кнопки или отправку формы. Подробнее — в разделе [События в реальном времени](/guides/webhook/polling#sobytiya-v-realnom-vremeni).

Был добавлен новый метод:

- [Поток событий](/api/bots/get-stream)

Ещё изменения:

- [Новый чат](/api/chats/create) отвечает `422` с кодом `blank` на пустое название и возвращает в `meta` идентификаторы тегов, которых нет в пространстве.
- [Новый тег](/api/group-tags/create) и [Редактирование тега](/api/group-tags/update) отвечают `400` с кодом `blank` на пустое название.
- Методы [Новый бот](/api/bots/create), [Редактирование бота](/api/bots/update), [Ротация токена бота](/api/bots/recreate-token) и [Ротация секрета клиента](/api/bots/rotate-client-secret) отдают адрес входящего вебхука и секрет подписи при тех же правах, что [Информация о боте](/api/bots/get).
- Создатель нового самостоятельного треда становится его владельцем: исключает участников и удаляет чужие сообщения. Подробнее — в разделе [Права в треде](/guides/threads#prava-v-trede).
- [Экспорт сообщений](/api/chats/request-export) отвечает `422` с кодом `too_long` на список больше 50 чатов и `422` с кодом `invalid` на дату не в формате YYYY-MM-DD.
- При правке сообщения файл, переданный с тем же `key`, остаётся прежним вложением с тем же `id` и названием. Размер файла можно не передавать: Пачка возьмёт его из хранилища.
- Метод [Скачивание файла](/api/files/get) отдаёт любое вложение, которое видно токену: защищённое — запросу из безопасного контура, остальные — всегда, кроме файла, в котором антивирус нашёл вирус. Запрос `HEAD` на тот же адрес отдаёт размер и имя файла без скачивания. Подробнее — в разделе [Ссылка на скачивание](/api/file-uploads#ssylka-na-skachivanie).
- Событие `update` о сообщении приходит и без правки, например когда сообщение добавили в «Важное». Подробнее — в разделе [Сообщения](/guides/webhook/events#soobscheniya).
- Чат, сообщение, тред, файл и экспорт другого пространства отвечают `404`, как несуществующие.
- Курсор, который метод не может прочитать, отвечает `400` с кодом `invalid`. Подробнее — в разделе [Пагинация](/api/pagination).
- Эмодзи статуса в текстовой форме принимается и возвращается с U+FE0F.
- Ошибка, не привязанная к полю, приходит с `system` в `key`, а ошибки параметров — с именем поля и кодом `required`, `blank`, `in`, `min_length`, `max_length` или `invalid`. Отказ в правах на разворачивание ссылок приходит как `400` с кодом `forbidden`.
- В журнале аудита отзыв токенов при переводе в гости отмечен `reason: guest_downgrade`, а `limit` в деталях поиска через API — запрошенный размер страницы.
- Сообщения, отправленные после входа в CLI через браузер, помечены подсказкой «Отправлено через «Pachca CLI»».
- SDK, CLI и n8n повторяют ошибки `500`, `502`, `503` и `504` только у запросов GET, PUT и DELETE, а ответ `504` с кодом `timeout` возвращают сразу, без повторов. Подробнее — в разделе [Повторные запросы](/api/limits#povtornye-zaprosy-retry).
- SDK отдаёт ответ с ошибкой без тела или не в JSON обычной ошибкой `ApiError`, а у каждой `ApiError` появился код статуса ответа. Подробнее — в разделе [Обработка ошибок](/guides/sdk/typescript#obrabotka-oshibok).
- Команда `pachca auth logout` закрывает вход через браузер на сервере и тогда, когда сохранённый токен уже истёк. Подробнее — в разделе [Выход](/guides/cli/authentication#vyhod).

### CLI v2026.10.3

- Команда `pachca guide` убрана вместе со сценариями: как решать задачи в Пачке, агенту рассказывают скиллы, а флаги каждой команды показывает `pachca <команда> --help`
- Из `--help` команд убран блок примеров со сценариями
- `pachca api ls` и справка `pachca api <МЕТОД> <путь>` с флагами `--describe`, `--spec` и `--docs` работают без входа и без токена: они читают встроенную спецификацию и в API не обращаются
- `pachca important-messages list`, `important-messages create` и `important-messages delete` — раздел «Важное» владельца токена: список отмеченных сообщений, добавление и удаление
- `pachca bots get-stream` — ссылка на поток событий бота
- `pachca users update`: значение `guest` у `--role` вместе с флагом `--chat-ids` переводит сотрудника в гости
- `pachca chats create` предупреждает в stderr об идентификаторах из `--group-tag-ids`, которых нет среди тегов пространства
- В выводе команд с сообщениями появилось поле `important`: сообщение в разделе «Важное» владельца токена
- `pachca auth logout` — после входа через браузер закрывает вход на сервере и при истёкшем токене: сначала обновляет его, потом отзывает свежий
- `pachca auth logout`: `token_revoked: true` значит, что вход на сервере закрыт, в том числе если его закрыли раньше, а при `false` закрыть вход не удалось, и его нужно отозвать в списке «Токены CLI»
- Ответы `500`, `502`, `503`, `504` и сетевую ошибку CLI повторяет до трёх раз только у запросов GET, PUT и DELETE, POST и PATCH после них не повторяются, а `504` с кодом `timeout` (поиск не уложился по времени) приходит ошибкой сразу
- Подсказки при опечатке в команде предлагают только существующие команды, без `pachca skill …`
- Описание флага `--no-retry` уточнено: он отключает повторы после `429`, `5xx` и сетевой ошибки

### SDK v1.7.0

- Поле `limit` в деталях поиска через API (`AuditDetailsSearch`) стало nullable: `null`, когда в запросе не было `limit`
- Ответ `401` без тела в формате OAuth приходит ошибкой `ApiError` с кодом `401`, а ответ в формате OAuth приходит `OAuthError`, как и раньше
- Ответ с ошибкой без тела или не в JSON приходит ошибкой `ApiError` с кодом статуса и пустым списком ошибок: так отвечает метод `Поток событий` (`GET /webhooks/events/stream`) кодом `404`, когда история событий выключена, и прокси страницей при `502`
- Ошибку сервера `5xx` SDK повторяет только у запросов GET, PUT и DELETE, а запрос POST сразу приходит ошибкой: сервер мог успеть его выполнить, и повтор создал бы дубль, например отправил бы сообщение второй раз
- Kotlin: после сетевой ошибки SDK тоже повторяет только запросы GET, PUT и DELETE
- Ответ `504` с кодом `timeout` (поиск или `GET /users` с `query` не уложился по времени) сразу приходит ошибкой `ApiError`, без повторов: тот же запрос, скорее всего, снова не уложится, и его стоит сузить
- У `ApiError` есть код статуса ответа: `status` в TypeScript, `status_code` в Python, `StatusCode` в Go и C#, `statusCode` в Kotlin и Swift
- Методы `Список важных сообщений` (`GET /important_messages`), `Добавление сообщения в важные` (`POST /important_messages`) и `Удаление сообщения из важных` (`DELETE /important_messages/{id}`), значения `important_messages:read` и `important_messages:write` в `OAuthScope`
- Поле `important` в модели `Message`: сообщение в разделе «Важное» владельца токена
- Метод `Поток событий` (`GET /webhooks/events/stream`) и модель `WebhookEventsStream`
- Значение `guest` в `UserRoleInput` и поле `chat_ids` в запросе `Редактирование сотрудника` (`PUT /users/{id}`): перевод сотрудника в гости
- Поле `not_found_group_tag_ids` в `meta` ответа `Новый чат` (`POST /chats`): идентификаторы из `group_tag_ids`, которых нет среди тегов пространства
- Поле `reason` в деталях токена журнала аудита (`AuditDetailsToken`): `guest_downgrade`, когда токен отозван при переводе сотрудника в гости

### Generator v1.3.1

- Ответ `5xx` сгенерированный клиент повторяет только у идемпотентных методов GET, HEAD, OPTIONS, PUT и DELETE, а у POST и PATCH сразу возвращает ошибку: сервер мог успеть выполнить запрос, и повтор создал бы дубль
- Kotlin: после сетевой ошибки клиент тоже повторяет только идемпотентные методы и не повторяет таймауты
- Ответ `504` с кодом ошибки `timeout` сгенерированный клиент возвращает сразу, без повторов, а `504` без этого кода, например от прокси, повторяет, как другие `5xx`
- У `ApiError` есть код статуса ответа: `status` в TypeScript, `status_code` в Python, `StatusCode` в Go и C#, `statusCode` в Kotlin и Swift
- Ответ с ошибкой без тела или не в JSON (`404` без тела, страница прокси при `502`) сгенерированный клиент превращает в `ApiError` с кодом статуса и пустым списком ошибок
- Когда в спеке есть и `ApiError`, и `OAuthError`, класс ошибки ответа `401` тоже выбирает тело: форма OAuth даёт `OAuthError`, а ответ без неё даёт `ApiError` с кодом `401`
