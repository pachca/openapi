# Сквозные руководства по ботам, наборы прав и уточнения API

_30 октября 2026_

В документации появились сквозные руководства. [Первый бот](/guides/bots/first-bot) проводит от создания бота до обработчика, который отвечает сотруднику в тред. [Интерактивный бот](/guides/bots/interactive) собирает команду, ответ в тред, кнопку и форму в одном примере на TypeScript и Python. [Разработка и запуск обработчика](/guides/webhook/deploy) рассказывает, как получать события на своей машине через поток событий или туннель и что проверить перед запуском в работу. Для администратора есть страница [Агенты и MCP в пространстве](/guides/agents-access): кто может подключить агента, где увидеть и отозвать подключения.

Быстрый старт теперь отправляет первое сообщение. Готовые наборы прав для уведомлений, бота-ответчика, интерактивного бота, агента и n8n собраны в разделе [Наборы прав под типовые задачи](/guides/permissions#nabory-prav-pod-tipovye-zadachi), где взять идентификаторы чата, сотрудника, бота и треда — в разделе [Где взять идентификаторы](/api/requests-responses#gde-vzyat-identifikatory), а все сроки ответа бота — в одной таблице [Сроки ответа](/guides/webhook/handler#sroki-otveta).

Ещё изменения:

- Ссылка на поток событий действует от одного до двух часов. В момент `expires_at` сервер присылает `disconnect` и закрывает подключение, поэтому ссылку меняют заранее. Подробнее — в разделе [События в реальном времени](/guides/webhook/polling#sobytiya-v-realnom-vremeni).
- Методом [Редактирование бота](/api/bots/update) можно удалить входящий вебхук: для этого `kind` передают как `null`. При следующем включении у вебхука будет новый адрес. Подробнее — в разделе [Через API](/guides/incoming-webhooks#cherez-api).
- Метод [Открытие представления](/api/views/open) описан с телом ответа, которое он возвращает.
- В описании [Журнала аудита](/api/security/list) перечислены поля деталей, которые API пишет в событиях токенов, авторизаций, ботов и ключей шифрования. Подробнее — в разделе [Журнал аудита](/guides/audit-events).
- У [Нового сообщения](/api/messages/create) два примера тела: минимальный и с кнопкой.
- Голосовое сообщение отправляют токеном сотрудника, боту метод отвечает `403`. Подробнее — в разделе [Загрузка файлов](/api/file-uploads).

### n8n Node v2.2.3

- `File`: в операции `Create` есть поля загрузки `File Source`, `File URL`, `Input Binary Field` и `Additional Fields` с `File Name` и `Content Type`, так что файл загружается по ссылке или из бинарных данных любого поля
- `Bot`: в операции `Update` у поля `Kind` есть значение `None`, которое удаляет входящий вебхук бота
- `Bot`: в операции `Update` поле `Webhook URL` необязательное. Пустое поле оставляет прежний адрес исходящего вебхука, поэтому бота можно переименовать или удалить у него входящий вебхук, не задавая исходящий.
- С `Simplify` операция `Bot` > `Get Many Tokens` оставляет `id`, `name`, `scopes`, `created_at` и `last_used_at`, `Bot` > `Get Many Events` — `id`, `event_type`, `payload` и `created_at`, а `Group Tag` > `Get Many Users` — поля сотрудника
- `Pachca Trigger`: события видеозвонков называются `Video Call Started`, `Video Call Finished` и `Video Call Recording Ready`, значения событий прежние
- `Pachca Trigger`: подсказки ручного и автоматического режима напоминают отметить события на вкладке «Исходящий вебхук» бота и для `New Message` выбрать «Любые сообщения» или перечислить команды
- `Pachca Trigger`: в автоматическом режиме узел определяет тип токена методом `GET /profile` и токену без права `profile:read` с пустым `Bot ID` отвечает ошибкой, которая называет это право и подсказывает, как добавить его токену бота
- `Pachca Trigger`: при пустом `Bot ID` другой сбой метода `GET /profile` возвращает исходную ошибку, а ответ `403` метода `PUT /bots/{id}` после отказа в `profile:read` подсказывает добавить это право токену бота и очистить `Bot ID`
- `Pachca Trigger`: подсказка автоматического режима перечисляет права токена бота — `profile:read` и `bot_self:webhook:write`
- Подсказка поля `Webhook Signing Secret` в учётных данных говорит, где взять Signing secret
- `Form`: операция `Open` возвращает ответ API `{ "success": true }`
- Описания полей следуют API: правило команд бота, `Kind` и `duration_ms` и `file_type` у файлов сообщения и черновика

### CLI v2026.10.4

- Справка `pachca api … --describe` показывает `dlp_rule_id` в деталях события `dlp_violation_detected` строкой, как его отдаёт API
- `pachca upload` принимает флаг `--name`: он задаёт имя файла, которым заканчивается `key`, так что данные из stdin загружаются с расширением и уходят в сообщение под этим именем
- `pachca upload` отклоняет файл, которого нет на диске, до запроса подписи
- `pachca doctor` проверяет тот же токен, что и остальные команды, в том же порядке: `--token`, `--profile`, `PACHCA_TOKEN`, `PACHCA_PROFILE`, активный профиль, поэтому с одной переменной `PACHCA_TOKEN` команда проходит в CI без конфига
- `pachca doctor` при ошибке хотя бы одной проверки завершается с кодом `1` в любом формате вывода, в том числе с `-o json`
- `pachca doctor` без файла конфига показывает путь, по которому его ищет
- `--dry-run` показывает запрос без входа и без `PACHCA_TOKEN`, а токен в заголовке `Authorization` заменён маской
- `pachca files direct-url --dry-run` показывает запрос без заголовка `Authorization`, как он и уходит в хранилище
- Слово `null` во флаге поля, которое принимает `null`, уходит в API как JSON null: `pachca bots update --kind null` удаляет входящий вебхук бота, а `pachca drafts update --parent-message-id null` снимает ответ с черновика
- `pachca auth login` с `--quiet` печатает адрес и код подтверждения при входе через браузер, а флаг убирает только строку ожидания и отчёт о входе
- Пример в справке `pachca auth login` и подсказка при `--token -` без потока ввода передают токен из буфера обмена: `pbpaste | pachca auth login --token -`
- `pachca messages`, `drafts` и `tasks` (`create`, `update`) берут текст из потока ввода, только когда поток не пуст, а с пустым потоком, как у скрипта или агента, отправляют поля из флагов
- Отказ `403` с `role_forbidden` в терминале объясняется словами: право у токена есть, но действие не разрешает роль, поэтому новый вход или токен не помогут. Вывод с `-o json` прежний.
- Объяснение отказа `insufficient_scope` в терминале зависит от источника токена: с `--token` или `PACHCA_TOKEN` команда предлагает `pachca oauth token-info -o json`, а если право есть в сохранённом списке профиля, советует обновить его через `pachca auth status --remote`
- Когда вход через браузер завершён или отозван, сообщение и подсказка `pachca auth login` называют профиль, с которым шла команда
- Эквивалентная команда в справке `pachca api … --describe` повторяет пример запроса из спецификации и работает при копировании
- Пример `pachca api POST /messages` в `--help` передаёт `message[entity_id]` в кавычках и работает при копировании, а описание `pachca api` и ошибка `--describe` для неизвестного пути говорят «метод»
- `pachca views open` выводит ответ API `{ "success": true }`
- Справка команд следует обновлённым описаниям API: удаление входящего вебхука, правило совпадения команд бота, `duration_ms` и `file_type` у файлов, срок ссылки на поток событий и поля деталей журнала аудита

### SDK v1.8.0

- Поле `dlp_rule_id` в деталях события `dlp_violation_detected` (`AuditDetailsDlp`) стало строкой, как его отдаёт API, например `pasport-rf`
- Python: пакет работает на Python 3.10 и новее
- Swift: пакет ставится через Swift Package Manager по адресу репозитория `https://github.com/pachca/openapi`
- Kotlin: библиотека собрана под Java 11 и работает на Java 11 и новее, координаты на JitPack — `com.github.pachca:openapi:1.8.0`
- Go: в запрос `UpdateBot` и `UpdateDraft` попадают только поля, которые вы задали, в том числе `oauth_client` и `webhook.kind` у бота и `parent_message_id` и `schedule` у черновика
- Go: у моделей запроса с полями, которые принимают `null`, есть поле `NullFields`: поле, названное в нём по имени в Go, уходит со значением `null`, например `Kind` в `BotUpdateRequestWebhook` удаляет входящий вебхук
- Метод `openView` возвращает `OpenViewResult` с полем `success`, как отвечает API, а в Go его сигнатура — `OpenView(ctx, request) (*OpenViewResult, error)`
- В деталях событий журнала аудита для токенов, авторизаций, входа в CLI, ботов и их настроек описаны поля, которые пишет API, например `access_token_id`, `access_token_preview`, `application_id`, `webhook_id` и `bot_name`, а смену названия токена бота описывает модель `AuditDetailsTokenNameChange`
- Поле `kind` в запросе редактирования бота принимает `null`, а `client_id` в деталях `oauth_authorization_granted` может прийти `null` в записях до 7 октября 2026 года
- Kotlin, C#, Go, Python и Swift: SDK перебирает варианты деталей события журнала аудита от лучше всего совпавшего по ключам и берёт первый, который разобрался, поэтому запись прежнего формата разбирается вместе с остальной страницей `GET /audit_events`
- Kotlin: поля деталей журнала аудита и событий вебхуков, которые API отдаёт со значением `null`, объявлены nullable, например `tokenName`, `actionMessage`, `actorId` и `callbackId`
- Kotlin: `kotlinx-serialization-json`, `kotlinx-coroutines-core` и `ktor-client-core` приходят в проект вместе с SDK, потому что их типы `JsonElement`, `Flow` и `HttpClient` есть в API SDK
- Kotlin: при `429` без заголовка `Retry-After` паузы между попытками 1, 2 и 4 с, как в остальных SDK, а при `5xx` и сетевой ошибке у GET, PUT и DELETE — 10, 20 и 40 с
- TypeScript: поле `errors` у `ApiError` обязательное, при ответе без тела это пустой массив
- Python: из зависимостей пакета убраны `attrs` и `python-dateutil`, SDK их не использует
- Примеры вызовов методов строятся по примеру тела из спецификации, в TypeScript вызывают методы с `await`, а в Go записаны с пакетом `pachca`
- README пакетов показывают рабочую загрузку файла, обработку ошибок и правило разворачивания тела, а примеры загрузки на Go и C# используют сервис `Files`
- Комментарии в коде следуют обновлённым описаниям API: срок ссылки на поток событий, скачивание выгрузки после 7 дней, правило команд бота, `duration_ms` и `file_type` у файлов

### Generator v1.3.2

- Python: сгенерированный клиент работает на Python 3.10, где нет `enum.StrEnum`, а `datetime.fromisoformat` не принимает время с суффиксом `Z`
- Go: необязательное поле тела запроса попадает в запрос, только когда задано, в том числе поле, которое принимает `null`, а явный `null` отправляет поле `NullFields` модели запроса
- Kotlin, C#, Go, Python и Swift: объединение без дискриминатора перебирает варианты от лучше всего совпавшего по ключам и берёт первый, который разобрался, а ошибку возвращает, только когда не разобрался ни один
- Kotlin: обязательное поле варианта объединения, которое принимает `null`, объявлено nullable, как в обычных моделях
- Kotlin: при `429` без заголовка `Retry-After` клиент ждёт 1, 2 и 4 с, при `5xx` и сетевой ошибке — 10, 20 и 40 с
- TypeScript: поле `errors` у `ApiError` обязательное, это пустой массив, если в теле ответа нет ошибок
- Пример вызова метода с телом строится по примеру тела из спецификации, первому из `examples` или `example`: в нём заданные там поля и обязательные поля модели, а у объединения один подходящий вариант
- Примеры TypeScript вызывают методы с `await`, примеры Go записаны с пакетом `pachca`, датами через `time.Date` и вариантами объединений, примеры Kotlin экранируют `$` в строках, а примеры Swift оборачивают вариант объединения в случай enum
- C#: примеры записывают полностью типы SDK, которые совпадают по имени с типами из неявных `using` .NET, например `Pachca.Sdk.TaskStatus`
