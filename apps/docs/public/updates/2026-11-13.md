# Исходящий вебхук без адреса и промпты для ИИ-агента

_13 ноября 2026_

Вкладка **Исходящий вебхук** в карточке бота включает вебхук без адреса, с историей событий, а **Signing secret** на ней можно скопировать сразу. Адрес можно указать позже, когда сервер будет готов, а до этого забирать события из истории запросом или потоком.

Как выбрать способ получения событий, описано в разделе [Как получать события](/guides/webhook/events#kak-poluchat-sobytiya), это знает и скилл `pachca-bots`.

Почти в каждом разделе руководства появился блок **Сделать с агентом**: готовый промпт, который вы копируете в чат со своим ИИ-агентом, и агент выполняет задачу страницы сам через MCP-сервер Пачки, терминал и файлы проекта. Так можно создать бота, добавить ему кнопки и форму, настроить входящий вебхук и события, подключить авторизацию от имени сотрудника, разложить сотрудников по тегам, найти события в журнале аудита, поставить CLI или SDK и собрать сценарий n8n. Проверки, например обработчика вебхуков перед запуском, агент проходит по чек-листу страницы и правит только после вашего согласия. Шаги для работы вручную остаются на странице ниже. Начать можно с [Быстрого старта](/guides/quickstart).

Ещё изменения:

- В [Интерактивном боте](/guides/bots/interactive#bez-publichnogo-adresa) описан запуск без публичного адреса: события обработчику пересылает команда `pachca bots listen-events`, а на страницах о получении событий она запускается через `npx -y @pachca/cli`, без установки CLI.
- Метод [Unfurl (разворачивание ссылок)](/api/messages/unfurl) принимает только токен бота, а у каждой ссылки нужны и `title`, и `description`.
- [Скачать архив экспорта](/api/chats/download-export) отвечает `302` со ссылкой на архив `zip`, ссылка действует 5 минут.
- Перевод в гости в методе [Редактирование сотрудника](/api/users/update) описан у поля `role`: в тредах администратор и редактор становятся участниками, владелец треда остаётся владельцем.
- Пустой `outgoing_url` в методе [Саморегистрация вебхука бота](/api/bots/update-webhook) стирает адрес, а при включённой истории событий события продолжают в ней сохраняться.
- Вход в надстройку Outlook попадает в [журнал аудита](/guides/audit-events) событиями `oauth_device_authorization_approved` и `oauth_device_authorization_denied` с `token_kind: outlook` и без `application_id`.

### SDK-библиотеки v1.10.0

- В `AuditDetailsDeviceAuthorizationApproved` поле `application_id` необязательное: у входа в надстройку Outlook приложения нет. Код, который читал его как обязательное, нужно поправить
- `token_kind` в деталях входа по коду называет значение `outlook` — вход в надстройку Outlook

### CLI v2026.11.4

- `pachca users update`: у флага роли сказано, что при переводе в гости администратор и редактор тредов становятся участниками, а владелец треда остаётся владельцем
- `pachca bots update-webhook`: пустой адрес стирает URL, а при включённой истории событий события продолжают в ней сохраняться

### n8n Node v2.2.8

- `User` > `Update`: в описании `Role` сказано, что при переводе в гости администратор и редактор тредов становятся участниками
- `Bot`: в описании адреса исходящего вебхука сказано, что пустой адрес стирает URL, а при включённой истории событий события продолжают в ней сохраняться

### MCP-инструменты v1.8.1

- `pachca_update_user`: что делает перевод в гости, теперь сказано у аргумента `role`, и в тредах администратор и редактор становятся участниками, а владелец треда остаётся владельцем
- Пустой `outgoing_url` стирает адрес: события перестают приходить на URL, а при включённой истории событий продолжают в ней сохраняться
- `pachca_get_audit_events`: вход в надстройку Outlook приходит с `token_kind: outlook` и без `application_id`

### Плагин и скиллы v1.0.15

- `pachca-bots`: исходящий вебхук включается без адреса, с историей событий, а способ получения выбирается отдельно: на адрес, из истории запросом или потоком, можно сразу обоими
- `pachca-bots`: Signing secret есть у бота с момента создания, поэтому агент закладывает его в сервер до адреса, а адрес сохраняет, когда домен уже есть в DNS
- `pachca-bots`, `pachca-ai-agent` и `pachca-oauth`: без адреса и истории Пачка не создаёт события для бота, и агент проверяет это первым, когда бот молчит
- `pachca-admin`: запись `oauth_device_authorization_*` с `token_kind: outlook` агент называет входом в надстройку Outlook, а не доступом к API
- В папке скиллов на GitHub есть README со списком скиллов и тем, с чем каждый помогает
