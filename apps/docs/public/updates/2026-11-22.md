# Правка своего профиля

_22 ноября 2026_

Метод [Редактирование своего профиля](/api/profile/update) меняет карточку владельца токена: имя, фамилию, ник, телефон, департамент, должность, часовой пояс и дополнительные поля. Он доступен любому сотруднику и мульти-гостю, право `users:update` для него не нужно. Нужно новое право `profile:write`, у бот-токена его нет.

Почту, роль, теги и приостановку меняет администратор методом [Редактирование сотрудника](/api/users/update). Поле, которое заполняется из SSO, метод не меняет и отвечает `422` с новым кодом `blocked_by_sso`.

Ещё изменения:

- Основной токен бота, созданного методом [Новый бот](/api/bots/create) без `webhook.scopes`, получает набор прав по умолчанию, даже если у бота включена авторизация сотрудников. Права, которые бот запрашивает у сотрудников в `oauth_client.scopes`, на основной токен не влияют.

### SDK-библиотеки v1.10.2

- Метод `Редактирование своего профиля` (`PUT /profile`), модель `ProfileUpdateRequest`, значение `profile:write` в `OAuthScope` и код `blocked_by_sso` в `ValidationErrorCode`

### CLI v2026.11.6

- `pachca profile update` — правка своего профиля: имя, ник, телефон, департамент, должность, часовой пояс и дополнительные поля

### n8n Node v2.2.10

- `Profile`: новая операция `Update` — правка своего профиля

### MCP-инструменты v1.11.0

- `pachca_update_my_card` меняет свою карточку: имя, ник, телефон, департамент, должность, часовой пояс и дополнительные поля. Для него нужно право `profile:write`, у бот-токена его нет.
- `pachca_create_bot`: права, которые бот запрашивает у сотрудников в `oauth_client`, на основной токен не влияют. `pachca_recreate_bot_token` у бота без токенов выпускает основной токен с набором прав по умолчанию.
- В описаниях соседние инструменты названы так, как их видит агент, с префиксом `pachca_`: `pachca_reissue_bot_token`, а не `reissue_bot_token`

### Плагин и скиллы v1.0.17

- `pachca-admin`: сотрудник меняет свою карточку сам, без прав администратора
- `pachca-messaging`: сообщение из нескольких пунктов пишется простыми абзацами с номерами, без жирных заголовков и меток, словами того, что видит читатель. По этим правилам пишется и черновик, который сотрудник сначала хочет увидеть в разговоре.
- `pachca-bots`: права, которые бот запрашивает у сотрудников в `oauth_client.scopes`, на основной токен не влияют
