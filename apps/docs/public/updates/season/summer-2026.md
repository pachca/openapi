### Уточнения в описании API

_27 июля 2026_

Подробнее описали поведение нескольких методов и полей. Работа API не менялась.

Были уточнены следующие методы:

- [Журнал аудита](/api/security/list) — параметр `end_time` включает верхнюю
  границу: выборка за период захватывает событие, попавшее ровно на неё.
- [Мой статус](/api/profile/get-status) и [Статус сотрудника](/api/users/get-status)
  — если статус не установлен, метод отвечает `200` и телом `null`.

Уточнены описания полей моделей:

- У 32 полей описано, в каком случае приходит `null`. Например,
  `last_activity_at` пуст, пока сотрудник ни разу не заходил в Пачку.
- `display_avatar_url` и `display_name` приходят только у сообщений от ботов.
- `name` у реакции заполнено всегда.
- `last_name`, `department` и `title` у незаполненного значения приходят как
  `null` либо как пустая строка.

### SDK v1.0.28

- Поле `details` в журнале аудита (`GET /audit_events`) снова читается. Раньше Go, C#, Swift и Kotlin падали с ошибкой при разборе всего ответа, а Python молча возвращал пустые детали
- Union без общего поля-дискриминатора разбирается по составу полей payload. В Go у такого union появилось поле `Raw` с исходным JSON
- Python: union с несколькими вариантами больше не выбирается «первым в списке» — блоки представлений (`ViewBlockUnion`) не теряют данные
- `display_avatar_url` и `display_name` у сообщения стали опциональными: для сообщений от сотрудников API их не возвращает
- `Reaction.name` больше не nullable
- Уточнены описания полей: у 32 полей сказано, когда API возвращает `null`, и исправлены примеры `callback_id` и `private_metadata` для форм

### Generator v1.1.10

- Дискриминатор union определяется по всем членам сразу: поле принимается, только если литерал есть у каждого. Раньше сканировался только первый член
- Эмиттеры Go, C#, Swift, Kotlin и Python умеют union без дискриминатора — вариант выбирается по составу полей

### CLI v2026.7.2

### Самостоятельные треды и аудит видеозвонков

_24 июля 2026_

Появился метод [Новый самостоятельный тред](/api/threads/create) — создание треда, не связанного с сообщением. Тело запроса не требуется, создатель становится единственным участником треда. - [Журнал аудита событий](/api/security/list)

### Список и удаление ботов, права доступа бота, вебхуки видеозвонков

_07 июля 2026_

Появились методы для управления ботами. Метод [Список ботов](/api/bots/list) возвращает ботов, которые вы можете редактировать, с поиском по имени. Метод [Удаление бота](/api/bots/delete) удаляет бота: прежний токен сразу инвалидируется, бот исключается из чатов, его исходящий вебхук удаляется. Оба метода требуют скоуп `bots:read` и `bots:write` соответственно.

- [Список ботов](/api/bots/list)
- [Удаление бота](/api/bots/delete)

При создании и редактировании бота добавились настройки прав доступа: `who_can_add` — кто может добавлять бота в чаты (`creator`, `creator_admin`, `creator_admin_user`, `anyone`), и `can_edit` — роли, которым, помимо создателя, разрешено редактировать настройки бота (`admin`, `chat_owners`). При создании также можно передать `single_chat` — ограничить бота одной беседой или каналом (личные чаты и треды в ограничение не входят). Все три поля возвращаются в объекте бота.

- [Новый бот](/api/bots/create)
- [Редактирование бота](/api/bots/update)

Появился новый тип исходящего вебхука — события видеозвонков: `video_call_started`, `video_call_finished` и `video_call_recording_ready`. Вебхук приходит для видеозвонков в чатах, где состоит бот. Подробнее о payload — в гайде [Настройка и типы событий](/guides/webhook/events#videozvonki).

В журнале аудита появился тип события `bot_deleted` — удаление бота. Его можно фильтровать параметром `event_key`.

- [Журнал аудита событий](/api/security/list)

В поиске сотрудников у параметра `sort` появилось значение `creation` — сортировка по дате создания (в дополнение к `by_score` и `alphabetical`).

- [Поиск сотрудников](/api/search/list-users)

### Ротация токена бота и новые настройки вебхука

_24 июня 2026_

Токен бота теперь можно перевыпускать через API. Метод [Ротация токена бота](/api/bots/recreate-token) доступен администратору, владельцу компании или создателю бота по скоупу `bots:write`. Метод [Ротация собственного токена бота](/api/bots/recreate-token-self) позволяет боту перевыпустить токен самому себе по скоупу `bot_self:write`. Прежний токен инвалидируется сразу, новый возвращается в ответе один раз — сохраните его.

- [Ротация токена бота](/api/bots/recreate-token)
- [Ротация собственного токена бота](/api/bots/recreate-token-self)

При создании и редактировании бота добавились две настройки вебхука: `ignore_self_messages` — игнорировать входящие сообщения, отправленные самим ботом (защита от зацикливания), и `events_history_enabled` — сохранять историю событий для получения через метод [История событий](/api/bots/list-events). Оба поля также возвращаются в объекте бота.

- [Новый бот](/api/bots/create)
- [Редактирование бота](/api/bots/update)
- [Информация о боте](/api/bots/get)

В журнале аудита появились новые типы событий, связанные с управлением ботами: `bot_token_recreated` (ротация токена), `bot_scopes_updated` (изменение скоупов токена) и `bot_webhook_settings_updated` (изменение настроек вебхука). Их можно фильтровать параметром `event_key`.

- [Журнал аудита событий](/api/security/list)

### Создание ботов через API, голосовые сообщения

_15 июня 2026_

Теперь бота можно создать и получить через API, а не только в интерфейсе. При создании вы получите `access_token` бота — сразу сохраните его, повторно получить токен можно только через интерфейс.

Новые и обновлённые методы для ботов:

- [Новый бот](/api/bots/create)
- [Информация о боте](/api/bots/get)

- [Новое сообщение](/api/messages/create)
- [Редактирование сообщения](/api/messages/update)

В payload вебхука реакции поле `created_at` теперь приходит и при удалении реакции. Также в деталях события аудита DLP поле `action_message` может быть `null`, если у действия правила не задан текст.
