# Контракт приложения с платформой

Часть формата, которую собранное приложение (код из `@pachca/app-sdk`, `@pachca/app-react`, `_generated`) получает от платформы, а не из типов. Фикстуры читают обе стороны: тесты пакетов здесь и тесты платформы (`@pachca/app-sdk/contract/*.json` из установленного пакета). Расхождение роняет тест с напоминанием о подъёме версии.

Менять формат можно только вместе с подъёмом `PROTOCOL` (`src/protocol.ts`) и `AppProtocol` платформы. Расширение (новый код ошибки, новое поле ответа) версию не поднимает, но дополняет фикстуру и её проверку в том же изменении.

- `errors.json`, коды ошибок и их HTTP-статусы: отказ вызова функции, отказы шлюза, коды `fatal`, коды, которые SDK создаёт сам, упавшее задание (`job_failed`), отказы прокси Пачки, ответы HTTP-входов приложения. `AppError` без кода это `app_error` 400, ответ Пачки с ошибкой это `PachcaError` (`name`, `status`, `code`).
- `refs.json`, имя функции в ссылке: `api.<модуль>.<функция>` даёт `_name` вида `<модуль>.<функция>`. Встроенные функции и их вид.
- `jobs.json`, ответ `_jobs.get` (`{state, result, error, runAt, finishedAt}` или `null` для чужого и несуществующего задания) и `_jobs.cancel`.
- `browser-hosts.json`, записи `manifest.browser`, которые проходят и не проходят проверку (`src/hosts.ts` и платформа).
